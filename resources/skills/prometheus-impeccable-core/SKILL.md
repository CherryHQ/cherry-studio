# Prometheus Impeccable core adaptation
This deliberately bounded adaptation implements context discovery, incumbent-surface resolution, mode selection, selective skill routing and phase-boundary evidence integration through the sibling `prometheus-ui-ux` Node runtime.

Read the project protocol or sibling `prometheus-ui-ux/references/UI_UX_PROTOCOL.md`. Resolve the affected application's nearest manifest and read PRODUCT.md, DESIGN.md, .impeccable.md and actual token/component sources. An existing surface is incumbent authority; preserve its identity on refinement. Missing PRODUCT.md does not block a narrow fix. For a new surface establish a concise brief with purpose, audience, mode, tokens, layout and motion.

Use the shared router's `route --input request.json` command to obtain context paths and mode. Marketing → Persuade; operational → Operate; reading → Read; showcase → Experience. Ask only when ambiguity affects correctness.

Finish the full production phase before the shared `phase-boundary` hook. That hook emits required evidence; capture and independent review still require available harness capabilities. It does not pretend those actions ran.

Upstream: pbakaus/impeccable at 9d715cc4f5564a990ca8345abfdd5df6dc9b41c8, Apache-2.0. Native detector, engine context analysis and live-browser instrumentation are **deferred**. See `prometheus-ui-ux/references/deferred-ports.md`. No engine download or full Impeccable parity is provided.
