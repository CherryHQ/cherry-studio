# 找回预览版数据

## 这是怎么回事

alpha/beta 预览版把数据库放在一个正式版不再查看的位置。升级后第一次启动，应用在新位置找不到东西，就从旧备份重建了一个数据库，预览版期间的数据被留在原地——**没有删除，只是没在用**。用户的感受就是"装测试版之后做的全没了"。

正常情况应用启动时会自己处理完。你是兜底：用户当时点了退出、选了另一个后来反悔、或者现在才发现。

## 绝对不能做

**不要移动、改名、复制、删除或打开任何 `.sqlite` 文件。** 应用此刻正开着那个数据库在运行，在它下面动手会直接损坏数据。真正的切换只能在应用启动、还没打开任何东西的时候做。

所以你的工作只有三件：**弄清情况、帮用户做选择、把选择记下来**。

也不要说"已经恢复好了"——要重启之后才生效。

> 关于"不修改用户数据"这条准则：写下面那个标记文件**不算**修改用户数据。它只是记录一个待执行的选择，真正的动作由应用在下次启动时完成，而且全程只改名不删除任何东西。

## 第一步：找到数据目录

| 系统 | 位置 |
|---|---|
| Windows | `%APPDATA%\CherryStudio` |
| macOS | `~/Library/Application Support/CherryStudio` |

用户如果改过数据位置，`~/.cherrystudio/boot-config.json`（Windows 在 `%USERPROFILE%\.cherrystudio\boot-config.json`）的 `app.user_data_path` 里记着真实路径，优先用那个。

找不到就让用户打开 **设置 → 数据** 把路径念给你，不要猜。

## 第二步：读状态文件

读数据目录下的 `prerelease-adoption.status.json`。应用每次启动时会写这个文件：

```json
{ "prereleaseDataAvailable": true, "currentDataInUse": true, "updatedAt": 1785753538638 }
```

- `prereleaseDataAvailable: true` → 有预览版数据可以找回，继续下一步
- **文件不存在，或 `prereleaseDataAvailable: false`** → **没有预览版数据可以找回**。直接说清楚，不要走本流程——用户的问题是别的，走这套也不会有任何变化

你只需要这一个文件，**不要去翻数据目录里的其他内容**。里面是用户的数据库和全部个人数据，本流程一概不需要。

## 第三步：讲清楚，让用户自己选

两份数据只能用一份，**不能合并**——它们是两段不同的时间（一段截止到升级那天，一段从重建之后开始），硬合会凭空造出没发生过的历史。

把两边分别是什么讲明白：

- **预览版数据**：升级那天之前的全部内容
- **当前数据**：升级之后新产生的。如果刚升级不久，这份可能几乎是空的，那选择就很容易

告诉用户**没选的那份会改名留在硬盘上，随时可以换回来**——这能让他没有心理负担。

**让用户自己决定**，不要替他选，也不要默认老数据更值钱。

## 第四步：记下选择

在第一步找到的数据目录里，写一个文件，文件名必须是 `prerelease-adoption.pending.json`：

```json
{ "keep": "prerelease" }
```

想保留升级之后这段时间的数据（或者反悔想换回来），就写 `"current"`。

改动仅此而已。这个文件在下次启动时一定会被消费掉，不管成功与否，所以不会重复触发。

## 第五步：让用户重启

切换发生在启动过程中。让用户**完全退出** Cherry Studio 再重新打开——只关窗口不算。重启后他选的那份就位，另一份仍以改名的形式留在硬盘上。

如果重启后没生效，不要盲目重试。让用户提供应用日志，启动日志里明确记录了走的哪条分支、为什么。

## 有些数据找不回来了

alpha/beta 期间有个缺陷：应用变更表结构时会静默删掉关联记录。在预览版之间升级过的用户，当时就已经丢了一部分，**聊天记录受影响最严重**。

恢复预览版数据库能拿回所有幸存的内容，但拿不回当时被删掉的，其他任何办法也拿不回。如果用户恢复成功后仍然发现少东西，如实告诉他，不要再提供无效的后续步骤。
