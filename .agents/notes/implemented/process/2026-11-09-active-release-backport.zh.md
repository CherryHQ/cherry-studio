# Agent Note: 热修复的回移分支选择

Status: implemented

[English](2026-11-09-active-release-backport.md) | 中文

## Problem

热修复工作流通过匹配 GitHub Release 草稿与发布分支来选择目标。首次成功构建才会创建草稿，所以在此之前合并的热修复需要手动回移。[#24023](https://github.com/CherryHQ/cherry-studio/pull/24023#issuecomment-6738737793) 就遇到了这个问题，当时 v2.2.0 的发布分支已经存在。

## Decision

Cherry Studio 只维护一条活跃发布线。自动回移选择语义版本最高的 `release/v…` 分支，前提是其版本高于所有已发布版本。草稿可有可无。最高版本分支对应版本已发布，或低于某个已发布版本时，工作流跳过回移。

工作流在发布状态锁内选择目标，并在写入前复查目标分支和预期 HEAD。现有回移分支租约、PR 聚合、来源追踪和双语发布说明处理保持不变。

## Alternatives considered

- 要求有匹配的草稿。这会在首次构建故障期间阻止自动回移。
- 使用仓库变量。这会为每轮发布增加一次手动启用步骤。

## Consequences

准备下一版本的分支后，首次构建前即可接收热修复。放弃未发布版本时，需要按发布文档中的流程删除该分支。

## Verification

- AC1 — 定向测试验证有无草稿时均选择同一合格分支。GitHub 只读查询选中了 `release/v2.2.0`。生产环境中的 PR 创建仍需在合并后验证。
- AC2 — 定向测试覆盖语义版本排序、已发布版本和 API 失败。
- AC3 — 定向测试验证写入前发现更高版本目标、发布分支 HEAD 变化或版本已发布时停止。
- AC4 — 发布指南说明目标选择、首次构建恢复及放弃发布的流程。文档检查通过。
