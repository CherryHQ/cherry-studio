# Agent Note: Pi Durable SQLite 图片去重

Status: implemented

[English](2026-11-16-pi-durable-image-storage.md) | 中文

## 问题

Pi Durable 1.5.2 使用带内嵌 Base64 图片的 JSON 记录。同一图片可能出现在历史条目、任务输入及状态和结果、提交记录以及文档修订中。上下文压缩保留历史，重建相同记录无法去除重复图片。

[运行时契约](../../proposed/architecture/2026-10-17-agent-runtime-contract.md) 继续负责运行时边界。产品会话消息仍是投影，不替代原生恢复数据源。本决策只负责原生 SQLite 表示及其迁移。

## 决策

现有 Pi Durable 依赖补丁在原生 SQLite 内实现图片存储，不代表已有上游发布版本或上游 PR。实现保留原有依赖补丁，使用可移植数据库接口；Cherry 仅在校验 backend 身份后调用原生迁移。

Schema 版本 3 增加以 SHA-256 为键的 BLOB 表，以及各记录或修订行上的独立图片引用清单，避免与任意用户 JSON 冲突。二进制字节在 backend 内共享，MIME 元数据保留在各引用处。公开读取精确还原规范 Base64，普通字符串和不规范编码保持内嵌形式。记录值和模型输入保持不变。

SQLite 触发器在写入记录的同一事务中维护引用。接受的写入完成后执行垃圾回收，保留历史修订或祖先条目引用的资源。读取在查询归属行的同一事务中还原资源，并校验哈希。字节缺失或损坏时明确失败，不会重放工具来重建资源。

含图片的文档增量按原序号和版本保存为基线，即使操作只修改图片 data 字段，也能提取图片。可回溯基线继续支持历史读取和分支复制。仅保留最新状态的基线通过原生保留规则替换过时修订。

`openExisting()` 无写入地读取原生 schema 版本 2，提交前必须迁移。桌面端先校验 backend 标记，再调用 `migrateImages()`。Schema 变更追加到原生迁移链。转换以每页 16 行提交，并在引用清单中标记已转换行；中断后留下可读的混合存储，再次打开继续转换。记录 ID、提交序号、文档版本和原生绑定保持不变。普通原生 `open()` 自动升级并转换。旧 schema-2 读取器拒绝版本 3，降级需要兼容备份。

资源留在 backend SQLite 文件中。现有暂停写入并完成检查点的备份边界包含图片，无需独立清单或目录。公开存储读取返回自包含逻辑记录，可传入其他存储。删除 backend 文件也会删除其资源。迁移和资源删除留下可复用的 SQLite 页面，不安排 `VACUUM`，也不使历史过期。

## 考虑过的替代方案

- 独立内容寻址文件需要跨资源发布、备份和孤儿恢复。同库 BLOB 保留事务和备份边界，跨 backend 共享仍不在范围内。
- 不去重的 BLOB 去掉 Base64 开销，但保留重复负载。
- 从产品消息重建或仅保留压缩后的上下文会改变原生恢复和历史分支；重新导入全部图片仍然保留重复。
- 压缩整个 JSON 改变无关内容的编码，却没有赋予图片独立的去重和归属机制。

## 影响

哈希、引用维护和还原增加工作量。还原直接返回解码对象，编码仅复制发生变化的对象路径，避免额外的 Base64 JSON 序列化往返。读取按所选分页批量加载资源，没有整库图片缓存。保留的唯一图片仍随历史增长。产品消息存储和提供商请求大小不变。

一次本地 macOS 合成基准使用 64 条记录和四份不同的 256 KiB 负载。已发布的无补丁 1.5.2 包和补丁包在独立进程中运行。关闭后的数据库字节数分别为 22,532,096 和 1,478,656；补丁库保存四份资源，共 1,048,576 字节。两者的 WAL 在关闭后均为空。写入和读取耗时分别为 66.1/35.7 ms 和 88.5/42.8 ms，峰值 RSS 分别为 115,680 和 132,256 KiB。这是单次诊断运行，不是用户数据库测量，也不是有统计意义的延迟保证。可重复运行的夹具为 `packages/agent-runtime-pi-durable/tests/fixtures/imageStorageBenchmark.mjs`。

## 验证

- AC1 — `pnpm test:agent-runtime-pi-durable packages/agent-runtime-pi-durable/tests/imageStorage.test.ts`：重复的条目、任务、提交和文档图片得到去重，MIME 值和分支历史在重新打开后保持不变。
- AC2 — 同一测试文件验证类似引用的用户 JSON、不规范 Base64、分页读取、仅修改 data 的增量，以及原生 harness 重新打开后模型收到的原始图片输入。
- AC3 — 同一测试文件注入 SQL 失败，在提交前后终止子进程，并损坏或移除资源字节；回滚和重新打开保留完整事务，读取损坏资源时明确失败。
- AC4 — 同一测试文件在一页提交后中断旧库转换，重试后验证历史和提交序号不变，并检查旧版本拒绝新格式；`pnpm test:main src/main/ai/agentSession/__tests__/nativeContext.test.ts` 验证迁移前的 backend 身份和既有原生恢复契约。
- AC5 — 图片存储测试复制已关闭并完成检查点的原生数据库，删除原文件，恢复根会话和分支图片，并将还原的条目传入 MemoryStorage。桌面连接和原生上下文集成测试覆盖未改变的存储生命周期；未运行完整应用备份 UI 或真实提供商验收。
- AC6 — 图片存储测试替换最新文档及任务和提交负载，检查最后引用回收及可回溯和分支图片保留，并通过本地 SQL 绑定运行 Durable Object 适配器和带前缀的 schema。这不是实际 Cloudflare 部署。
- AC7 — `node packages/agent-runtime-pi-durable/tests/fixtures/imageStorageBenchmark.mjs [package-directory]`：相同合成输入完成往返，数据库和 WAL、唯一资源、延迟和进程峰值 RSS 结果如上。
