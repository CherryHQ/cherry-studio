# Agent Note: 输入区展示 Pi Durable 后续消息队列

Status: implemented

[English](2026-11-26-pi-durable-queue.md) | 中文

## 问题

Pi Durable 会话忙碌时，后续消息持久化在原生队列中。用户需要查看和修改等待中的消息。Work 输入区也需要在发起流请求时透传「排队」意图，供 Pi Durable 区分排队和追加到当前轮。

## 决策

Work 输入区立即提交后续消息，并在队列面板按原生顺序显示。原生队列变化或会话恢复时发布当前等待的条目。消息被取用或撤回后移出面板。「排队」和「追加到当前轮」沿用原有发送控件。

桌面端在提交到原生运行时前先保存完整输入。等待期间，输入留在会话分支外。原生运行时取用输入后，桌面端在一个事务里将输入加入分支并预留回复。取用前被中断的输入可以显示为未发送消息。

轮次自然结束时，队列继续自动出队。用户点击停止时，暂停 inbox、写入停止记录和标记中止当前 Run 在同一个事务提交。等待中的后续消息在重启后保留顺序、内容和 ID，仍可编辑、排序或撤回。继续队列会恢复已有条目的出队。空闲时主动发起的新请求可以直接运行，之前的队列继续暂停。

「插入消息」在原生队列事务中把等待中的后续消息改为引导消息，保留提交 ID 和内容。消息移到对话中，等待提示在原生运行时取用时消失。原轮次取用的引导消息归入原回复。如果原轮次先结束，则由下一轮回复。恢复时根据原提交和记录的轮次作出同样的判断。

原生运行时在接收提交的同一事务里登记请求 ID。启动恢复从原后端读取这些 ID，按原生取用顺序同步已持久化的提交。桌面端提交会话更新后才确认该 ID。确认前崩溃时可以重放同一条输入和回复。打开所属会话时检查没有原生回执的已保存输入，包括旧版本保存的输入。

编辑和排序在原生事务内检查操作目标是否仍然有效。修改后的模型输入和会话文本 part 随原来的提交一起被取用。桌面端在实时投影和恢复时按原消息标识更新文本 part。嵌入的引用提示移到编辑后正文的末尾，独立成行。附件和其他消息部分继续保留。拖动以开始时的顺序为准。「移除」在同一个事务里把一条等待的提交记为 `withdrawn` 并移出 inbox。桌面端根据该结果删除已保存的待发草稿。如果在两次写入之间崩溃，重启恢复会完成删除。回复归属与恢复遵循 [Pi Durable 轮次约定](../architecture/2026-11-18-pi-durable-turn-authority.md)。

## 考虑过的替代方案

由渲染进程维护队列会推迟原生接收，渲染进程或应用退出时等待中的消息可能丢失。撤回后重新提交会改变原生提交标识，也可能与消息取用交错。

## 影响

Pi Durable 后续消息在取用前可编辑和排序，队列顺序和编辑结果在应用重启后保留。移除会丢弃等待中的输入，对话中不会出现该消息。Pi 和 Claude Code 保持现有输入区队列行为。

## 验证

- AC1 — Electron 使用保持打开的本地模型请求，显示了三条原生后续消息。重启 Electron 后，在释放当前请求前，面板按保存的顺序显示余下两条。
- AC2 — `agentSessionFollowups.test.ts` 检查带嵌入链接的消息编辑后保留完整 Unicode 字符和单词。`followups.test.ts` 检查原生标识和修改后的模型输入在重开后保留。Electron 中验证编辑保留了原消息标识，重启后历史记录和模型均收到编辑后的文本。
- AC3 — `NativeQueuedFollowups.test.tsx` 检查拖动中途队列变更以及重新拖动成功。`followups.test.ts` 检查过期的编辑和排序请求。Electron 中将第二条拖到第一条之前，确认模型请求按新顺序发出，并拒绝了消息取用后的编辑。
- AC4 — `followups.test.ts` 验证单独移除一条等待中的原生提交。`PiDurableRuntimeConnection.test.ts` 覆盖桌面删除草稿前后的重启恢复。Electron 验证移除后该消息不会出现在对话或重启后的模型请求中。
- AC5 — `useAgentChatRuntimeState.test.tsx` 覆盖发送请求中的「排队」与「追加到当前轮」。`AgentComposer.test.tsx`、`QueuedFollowupsDock.test.tsx` 和 `useFollowupQueue.test.ts` 覆盖原有输入区队列操作。
- AC6 — `followups.test.ts` 重新打开已提交原生停止的会话，验证原来的排队提交得以保留。`piDurableTurnAuthority.test.ts` 验证 Stop 后两条消息跨重启留在队列，新请求可以直接运行，继续队列时每条消息只取用一次并保存各自的回复。
- Regression — `AgentSessionSubmission.test.ts` 覆盖延迟发布到分支、重复取用事件和未发送恢复。`piDurableTurnAuthority.test.ts` 检查等待中的输入不出现在对话正文，Durable 取用后只出现一次。 真实 Electron 的崩溃用例还验证了强制结束 Main 后，排队消息仍保留在 inbox 中，重启后只获得一条回复。`PiDurableRuntimeConnection.test.ts` 覆盖产品写入已提交、原生请求 ID 尚未确认时的取用重放。
