# Agent Note: 智能体会话详情中的桌面控制状态

Status: implemented

[English](2026-11-09-desktop-control-status.md) | 中文

## 问题

当助手正在操作某个桌面应用时，唯一能显示控制的是哪个应用、控制是否仍被持有、以及如何停止的位置是托盘子菜单。智能体会话详情卡片是用户在运行期间本来就在看的地方，却完全没有桌面控制的信息，于是聊天文本成了此刻使用鼠标键盘是否会干扰的唯一线索；要停止正在进行的控制，用户必须先知道托盘菜单存在。

## 决定

智能体会话详情新增桌面控制分组，由 `AgentSessionDetailsSections` 渲染，作为第九个可配置分组（默认可见，位于工作区之后）。每个被当前智能体会话控制的应用占一行：应用名、本地化控制状态，以及仅对 `opening` 与 `active` 行显示的停止操作。`stopping`、`stopped`、`unconfirmed` 行保留可见但不提供停止操作；渲染层不提供重新允许和全部停止。当前会话没有受控应用时，该分组不渲染任何内容。

状态来自对既有 `ComputerUseService` 模型新增的 IPC 投影：`computer_use.get_controls` 返回 `ComputerUseControl[]`，`computer_use.stop_app` 停止单个应用，`computer_use.stop_all` 停止全部控制，`computer_use.controls_changed` 在服务的 `changed` 事件触发时推送完整快照。该桥接由服务在 `onInit` 中注册，因此托盘发起的停止、设置撤销与原生关闭回调都能在不轮询的情况下到达渲染层。渲染层每个详情作用域只保留一个订阅者：先订阅再请求首次快照，事件会整体替换快照（包括空数组），被事件覆盖的首次请求结果被丢弃，首次加载失败按未知处理而不是已释放。

行按精确的智能体所有者身份 `agent:<sessionId>:<agentId>` 过滤；其他会话的控制不显示，且从不使用标签文本作为身份。

两项服务改动支撑验收契约。`stopAll()` 在结束任务前把每个任务的应用身份记入所有者的 `blockedApps`，因此确认完成的全部停止会留下带名字的 `stopped` 行，而不是把它们抹掉；这正是单应用停止早已使用的机制。活动行仍然覆盖记忆行，所以清理期间状态是 `stopping` 或 `unconfirmed`，普通任务正常完成后控件依旧全部移除，`owner.stopped` 继续阻止所有应用（包括尚未出现的应用）。由于托盘渲染同一模型，未改动的托盘菜单在全部停止后也会列出这些被记住的停止行。另外，`stopApp()` 现在在只记录一个没有活动任务的受控应用时也会发出变更通知，避免投影漏掉 `get_controls` 已经报告的行。

## 备选方案

- 仅改进托盘文案：应用内依旧不可见，且仍需先知道托盘菜单存在。
- 在会话详情之外增加常驻指示器：把按会话存在的信息复制到第二个界面，而已记录的产品决定选择了会话详情。
- 渲染层自行保留已释放应用的历史：无法在重挂载或重启后存活，且会与 `get_controls` 不一致。
- 只做投影、不做 `stopAll()` 保留：确认清理会删除身份，导致已释放应用显示为已停止的验收失败。
- 用一条所有者级全部应用行替代逐应用行：只显示聚合状态，不显示哪个应用被释放，也没有可停止的对象。

## 影响

- `stop_app` 返回成功只表示命令已结算，不代表清理已确认；只有推送的快照才能改变行状态，因此界面不会声称一次并未发生的停止。
- `ControlStatus` 不新增取值；等待用户与当前动作仍超出范围，且会同时扩展托盘契约。
- 旧的已保存分组数组会把新分组追加到末尾，默认配置位于工作区之后。隐藏该分组只改变展示，托盘仍是替代入口。
- 每个渲染层语言目录新增九条文案。

## 验证

- AC1 — `src/main/ipc/handlers/__tests__/computerUse.test.ts`：真实路由与服务返回精确的控制投影，严格的 `stop_app` 输入被拒绝且不产生变更，停止一个应用后另一个仍可操作，`stop_all` 阻止所有所有者。
- AC2 — `ComputerUseService.control.test.ts`：确认完成的 `stopAll()` 后两个具名应用仍以 `stopped` 存在；清理期间为 `stopping`，清理失败为 `unconfirmed`，普通正常完成仍然不留下控件。
- AC3 — `TrayService.control.test.ts`：未改动的托盘菜单列出被记住的停止行并沿用既有启用规则，且单应用允许不会解除所有者级阻止。
- AC4 — `useAgentDesktopControls.test.tsx`：事件整体替换快照（含 `[]`），被更新事件覆盖的首次请求成功或失败都被丢弃，首次失败按未知上报并在下个事件恢复。
- AC5 — `AgentSessionDetailsSections.test.tsx`：每个应用显示名称与本地化状态，停止仅对 `opening` 与 `active` 出现，终态行不提供操作，不渲染允许，空快照或仅所有者行时不渲染分组。
- AC6 — `AgentRightPane.test.tsx`：行被限制为 `agent:<sessionId>:<agentId>`，切换会话时待处理的停止仍绑定原应用。
- AC7 — `AgentDetailsCustomize.test.tsx` 与重新生成的 `preferenceSchemas.ts`：旧的八项保存列表在末尾获得一次可见的新分组，隐藏它不会停止任何控制，重置恢复默认顺序。
- AC8 — `i18n-check` 报告 101786 条翻译且无占位符；定向 Oxlint、ESLint、Oxfmt 与渲染层类型检查通过，主进程类型检查只剩该改动未触及文件中的既有报错。
- AC9 — Electron 配合注入投影：截图显示无控制时不出现分组、活动与打开中的行带停止、终态行无停止、其他会话的行被排除、释放后分组消失。
