# Agent Note：知识库文件导入前检查

Status: implemented

[English](2026-11-12-knowledge-format-preflight.md) | 中文

跟踪 [CherryHQ/cherry-studio#18985](https://github.com/CherryHQ/cherry-studio/issues/18985)，替代 [Spec PR #24312](https://github.com/CherryHQ/cherry-studio/pull/24312) 中的设计草案。

## 问题

原有文件导入仅检查扩展名，扫描 PDF 和处理器限制会在开始摄取后才失败，替换操作可能先删除旧资料。

## 决策

统一格式目录供文件选择器、支持表和检查使用。主进程读取实际文件元数据及 PDF 全部页面的文本信息，不发送网络请求，不创建处理任务。扫描和混合 PDF 需要配置文档处理器，检查平台、本地模型、凭据和地址要求，但不保证远程连通性或解析质量。

沿用现有处理器限制：达到字节上限或超过页数上限时拒绝。本地文档处理器的 300 页限制移动到共享预设，由运行时和检查共同使用。本地读取器不新增应用级大小或页数限制。PDF 解析初始化后检查最多 30 秒，并始终销毁解析器。

文件、文件夹和拖放均在提交前显示逐文件结果、所选读取器、有效限制及设置入口。取消不导入；独立文件只导入可用项。文件夹存在受支持但不可用的文件时必须先修复，不支持的文件沿用跳过策略。主进程在取消任务、删除、复制、创建条目或排队前重复检查。携带已处理产物的恢复文件继续使用该产物。

## 备选方案

- 仅前端检查会被直接调用绕过，因此拒绝。
- 不凭空新增全局大小或页数限制。
- 抽样页面会漏掉混合扫描文档，改用完整检查和超时清理。
- 选择文件时验证远程凭据可能泄露文件或消耗额度，因此仅做本地检查。

## 验收与证据

- AC1：导入前逐个说明不支持格式，主进程拒绝。真实文件与前端测试覆盖。
- AC2：复制或排队前检查现有大小及页数限制。真实 PDF 验证字节边界和页数超限。
- AC3：无处理器的空白和混合 PDF 被阻止，提供设置入口。真实 PDF 解析和界面测试覆盖。
- AC4：PPTX 使用本地 anydoc，不受 PDF 处理器影响。已有读取器测试验证路由，不保证复杂排版质量。
- AC5：界面和导入使用相同主进程检查及共享结果码，实际导入再次检查。真实数据库回归验证失败时保留原有笔记。
- AC6：界面支持表、选择器和检查使用同一目录，提供中英文文案，文档检查验证配对。

## 限制与后续

未调用真实远程文档上传或付费嵌入服务。Windows ARM64 无 anydoc 的格式会被阻止，DOC、DOCX、EPUB 保留回退。复杂排版质量属于 [#12854](https://github.com/CherryHQ/cherry-studio/issues/12854) 的格式专项后续。检查后文件仍可能改变，实际读取器和处理器限制继续作为后备校验。
