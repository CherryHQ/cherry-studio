# Agent Note: 主要模型选择入口的弹窗模式

Status: implemented

[English](2026-11-14-model-selector-dialog-mode.md) | 中文

## 问题

锚定在入口旁的模型下拉框浏览长模型列表时空间有限。更大的弹窗适合主要对话和绘图入口，但将记住的弹窗模式应用到表单字段会打断表单操作。

## 决策

`ModelSelector` 默认使用下拉框。只有助手对话控件、智能体对话控件和绘图输入区启用 `allowPresentationSwitch`；它们的底栏可在下拉框和宽 560px、高度最高 560px 的弹窗之间切换。包括表单和翻译在内的其他调用方不显示切换按钮，也不应用保存的弹窗选择。

两种容器复用同一份选择器面板，以及父组件持有的选择、搜索和筛选状态。渲染进程持久缓存键 `ui.model_selector.presentation` 记住主要入口的模式，默认值为 `popover`。表单选择器既不应用也不覆盖该选择。无需数据库迁移。

弹窗在导航栏下方居中，至少保留 16px 间距，并按视口可用空间缩小。模型详情挂载在当前弹窗内部；容器切换时不会将焦点恢复到失效的入口。底栏操作以带内边距的圆角悬停反馈填满剩余宽度，工具图标继承语义前景色状态。

`PageSidePanel` 只在自身弹窗拥有事件且事件尚未被处理时响应 Escape。来自子弹窗的 React portal 事件不能关闭底层侧栏并丢弃其草稿。

## 考虑过的替代方案

- 所有入口都启用弹窗：不采用，因为主要入口保存的选择不能改变嵌入表单的行为。
- 创建原生窗口或第二份模型列表：不采用，因为这项展示改动不需要窗口同步和重复的选择逻辑。
- 在选择器中处理知识库侧栏的 Escape 冲突：不采用，因为侧栏拥有关闭行为，必须尊重嵌套弹窗边界。

## 影响

主要选择器共用一个记住的展示模式；辅助选择器保持下拉式。容器切换可能重置容器内部的滚动或悬停状态，同时保留选择、搜索和筛选状态。用户已明确要求本次跳过方案评审并直接实现。

## 验证

- Regression — `ModelSelector.presentation.test.tsx`：真实弹窗和下拉框基础组件在切换时保留搜索与焦点，重新挂载后记住模式，并让表单保持下拉式且不覆盖已保存的弹窗选择。
- Regression — `page-side-panel.nested-dialog.test.tsx`：Escape 关闭真实子弹窗，同时保持侧栏可用；下一次 Escape 可以关闭侧栏。
- Regression — 定向模型选择器、Cloud 包装层、智能体控件和绘图选择器测试：5 个文件、22 项测试通过；定向侧栏测试：2 个文件、18 项测试通过。
- Regression — Electron：三类主要入口保留模式切换；在保存弹窗选择后，四个默认模型设置字段、智能体创建和翻译仍保持下拉式；520x420 视口下在导航栏下方保留 16px 间距，且底栏可见。
- Regression — Electron 调用方检查覆盖知识库、助手与智能体编辑、CLI 配置、小应用模型槽位、诊断和消息模型选择；最终范围检查确认辅助调用方没有模式切换控件。首次引导和知识库恢复采用组件测试覆盖，未重走对应流程。
