# Agent Note：切换 Agent 模型时的可选可编辑交接

Status: implemented

[English](2026-11-17-optional-editable-model-switch-handoff.md) | 中文

## Problem

在非空 Agent 会话中切换模型会保留对话历史，但新模型可能难以理解较长或只完成了一部分的任务。Issue #18978 要求在切换时提供一份可选的、用户可编辑的任务交接。会话拥有自己的模型选择，见 [会话所有的模型选择](../../implemented/bug-fix/2026-11-14-agent-session-model-ownership.md)。此改动之前，`AgentChat.tsx` 中的模型切换对话框只有"本次应用运行中跳过"复选框；确认后只更新会话模型，没有其他动作。想为新模型提供任务简报的用户没有办法创建，切换来源也不会被记录。

## Decision

- 在现有模型切换确认对话框中新增选项"为新模型创建交接"，默认不勾选。
- 勾选后，由当前模型生成交接内容：目标、决策、已完成工作、待办步骤、相关文件、未解决风险。
- 生成的交接显示在对话框内的可编辑字段中。用户确认或编辑后，切换才完成。
- 确认时，将编辑后的交接作为系统消息持久化到同一会话，并关联一条记录先后模型身份的切换记录。原始消息不被修改或删除。
- 未勾选时，切换行为与现在一致，对话历史仍是上下文来源。
- 切换后的下一轮，新模型通过会话上下文接收编辑后的交接。

## Alternatives considered

- 每次切换都提示交接：被 Issue 否决（"不要为每次切换强制使用"）。
- 不调用 LLM 的确定性摘要：成本低且可离线，但无法可靠提取决策和待办步骤。可作为生成失败时的备选，不在本 Spec 范围内。
- 用交接内容新建会话：保持旧会话干净，但会把对话和文件拆到两个会话中。本轮不采用。
- 仅存为输入框草稿：会丢失来源记录，且不在新模型的上下文中。不采用。

## Consequences

- 原生运行时恢复：会话带有运行时恢复 token 和上下文投影。会话中途插入的系统消息不能使原生恢复失效，也不能被投影丢弃。生产 Pi 桥接与真实 Claude Code SDK 恢复测试验证同一原生会话、既有任务历史以及仅通过系统上下文投递交接。
- 跨运行时切换：切换运行时类型可能改变系统消息的投递方式。交接必须作为上下文送达模型，而不能成为用户轮次。
- 生成成本与延迟：交接调用在切换完成前使用当前模型。生成期间取消，不得切换模型。
- 摘要准确性：可编辑字段是缓解手段；本 Spec 不声称生成的摘要完整。

## Verification

- AC1 — `ModelSwitchHandoffDialog.test.tsx` 与 `AgentChatSettingsPanel.test.tsx` 验证默认不勾选和普通模型更新，不发起生成。
- AC2 — `AgentSessionModelHandoff.test.ts` 验证使用捕获的当前模型生成六个独立必要段落，且预览不持久化。
- AC3 — 对话框、真实 AgentChat 保存路径与 `useSession.test.ts` 保留用户确认的原文并传入原子端点；真实文件数据库测试验证编辑文本逐字持久化。
- AC4 — 数据库测试验证先后模型身份、原始消息不变、原生恢复 token 保留、来源变化拒绝、忙碌运行拒绝以及保存消息失败时回滚。
- AC5 — `PiRuntimeConnection.test.ts` 通过生产桥接在下一模型上恢复真实原生历史并发送已编辑系统上下文。`nativeContract.test.ts` 使用真实 Claude Code SDK 更换模型与系统提示后恢复会话，保留历史且不伪造用户轮次。`settingsBuilder.test.ts` 验证保存的交接进入生产非快照载体。
- AC6 — AgentChat 与对话框渲染测试验证普通不带交接的切换，以及取消时不切换、不新增交接。
- AC7 — 对话框测试验证生成失败可见，且取消勾选后可以正常切换。

- Regression — 真实控件与语言包的英文浅色、窄屏中文深色视觉检查通过。生成与保存是本地测试边界，不代表完整 Electron 验收。原生测试均使用本地脚本服务，不调用付费模型。
