# Agent Note: 元宝搜索设置与结果数量兼容

Status: implemented

[English](2026-10-22-yuanbao-search-settings.md) | 中文

## 问题

仅发送 `Query` 时，现有最大结果数偏好无法向上游请求更多结果。本地黑名单过滤也会消耗已返回的结果名额。腾讯的 `Cnt` 支持以十为步长、最多五十条，`Site` 最多排除五个域名，但极速版不支持 `Cnt`。

## 决策

可移植元宝协议将请求数量向上取到下一个支持的档位，上限为五十，并继续按照本地上限截断响应。协议规范化域名排除项并去重，最多发送五个有效域名，没有域名时不发送 `Site`。

桌面端仅将 `*://*.example.com/*` 形式的完整域名规则转换为上游排除项。精确主机、特定协议、特定路径、正则表达式及其余规则继续由现有本地过滤器执行；将这些规则转换为整个域名的排除项可能删除用户允许的结果。

仅当提供商返回 `InvalidParameter` 且消息明确说明不支持 `Cnt` 时，桌面端才去掉 `Cnt` 重试一次。重试保留相同的凭据、查询、端点、取消信号和 `Site`。其他错误直接向上传递。第二次失败也直接向上传递，不再重试。后续搜索仍会尝试 `Cnt`，不引入账号套餐缓存或设置。协议通过 `useDefaultResultCount` 支持此宿主策略，仍保持单次请求。

## 考虑过的替代方案

- 始终省略 `Cnt` 可以兼容极速版，但无法将结果数量偏好连接到上游服务。
- 添加套餐选择器会重复账号配置，并要求用户持续维护其准确性。
- 对所有参数错误重试可能掩盖无效查询或无关配置错误。
- 从任意黑名单模式中提取域名会使排除范围超出用户规则。

## 影响

每次搜索遇到明确不支持数量参数的错误时，可能多发一次请求。错误消息匹配接受明确的英文和中文形式；未知表述会显式失败，不会触发推测性重试。非 2xx 错误仍作为 HTTP 失败处理，不触发此提供商错误降级。高于五十的上限无法强制上游返回超过五十条结果，本地过滤可能进一步减少结果数量。本次仅衔接 Site 排除；指定站点搜索、Mode 和 Deeplinks 不在本次范围内。
