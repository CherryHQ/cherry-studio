# Agent Note: 在输入框编辑 Pi Durable 排队草稿

Status: implemented

[English](2026-11-28-pi-durable-queued-draft-editing.md) | 中文

## 问题

此前在 Work 编辑 [Pi Durable 排队消息](2026-11-26-pi-durable-queue.md)时，会打开一个只能改正文的弹窗。现有输入框已经可以编辑完整消息草稿，包括附件和引用。原有的正文编辑还要求排队消息已有文本 part。

## 决策

在现有 Work 输入框打开排队草稿，恢复该会话输入框支持的全部草稿内容，包括正文、附件和引用标记。保存时沿用 Work 普通发送的草稿校验和附件准备流程。取消时恢复输入框原有草稿。保存失败时保留正在编辑的内容。

Work 打开编辑器之前，Durable 先把等待中的消息标记为编辑中。队列可以派发它之前的消息，并在该条目处等待。保存时，在同一个原生事务里原地更新消息并解除标记。取消只解除标记，保留最后保存的内容。消息 ID 和队列位置保持一致。解除标记后，队列可以继续先前被编辑挡住的派发，同时遵循独立的 Stop 暂停状态和运行失败策略。

准备好的模型输入和修订后的消息 part 在同一个原生事务中提交。实时投影与恢复一并应用已提交的 part 和托管文件引用。保留的附件沿用原有标识。新加入的托管附件在原生提交到桌面投影之间持续可用。恢复也支持旧版本写入的排队正文编辑。

## 考虑过的替代方案

- 给弹窗加附件控件。这会重复现有输入框负责的草稿编辑和文件处理能力。
- 撤回原消息，再提交编辑后的草稿。这会改变提交标识，消息也可能移到后续条目之后。

## 影响

保存时检查开始编辑时记录的版本和编辑窗口的凭证。窗口关闭或应用重启后，标记仍然有效。原窗口离开后，新窗口可以从最后保存的内容继续编辑。原生存储和桌面存储分别提交。如果桌面错过实时更新，恢复会应用最终的文件引用。排队消息继续沿用现有运行时连接的知识库授权。

## 验证

- AC1 — Electron 中，在 Work 输入框打开仅含附件的排队草稿，增删附件，并在取消和保存后恢复原草稿。
- AC2 — Electron 保存仅含附件的编辑后重新打开补写正文，并在本地模型收到的请求中确认正文和附件。运行时集成测试验证原提交 ID 和保留附件的 part ID。
- AC3 — `PiDurableRuntimeConnection.test.ts` 和 `followups.test.ts` 检查编辑版本冲突，验证原排队提交仍被保留。
- AC4 — `PiDurableRuntimeConnection.test.ts` 验证错过实时投影后恢复完整的已提交 part 和托管文件引用。`followups.test.ts` 检查旧格式的正文编辑记录。
- Regression — `followups.test.ts` 和 `PiDurableRuntimeConnection.test.ts`：上游结束和重启后，正在编辑的消息和后续消息仍在队列中，上一轮回复正常结算。保存可以恢复此前被编辑挡住的派发，同时遵循失败策略。显式恢复须等编辑结束后再派发该条目。
- Regression — Electron 使用本地模拟模型：上一轮回复结束后，队列仍显示编辑中的消息。保存后只发送一次修订内容，后续消息按队列顺序发送。
