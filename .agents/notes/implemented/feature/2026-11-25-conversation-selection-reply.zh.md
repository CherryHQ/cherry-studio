# Agent Note: 引用和回复选中的会话文字

Status: implemented

[English](2026-11-25-conversation-selection-reply.md) | 中文

## 问题

会话引用会保留选中的片段，但无法从引用跳回原消息。用户想回复选中文字时，也要先切到主输入框才能开始写。

## 决策

「引用」使用命令注册表，选区工具栏会反映当前快捷键及其禁用状态。来自消息的引用在现有输入框 token 中带有可选的 `sourceMessageId`。原消息在当前列表中可用时，点击引用会定位并高亮该消息。

「回复」在选区旁打开草稿输入框。「取消」会丢弃这份草稿。「保存」会把引用和回复文字追加到当前会话的主输入框，用户可以检查后连同已有草稿一起发送。当前有可接收回复的普通草稿时，才可保存。草稿接收保留缩进的原始文字后，弹框才关闭。引用内容也可以点击，跳回原消息。

## 考虑过的替代方案

- 从选区弹框发送会增加第二个发送入口，需要单独处理草稿和发送行为。
- 只在工具栏的临时状态保留原消息信息，会在主输入框保存或发送草稿时丢失定位能力。

## 影响

可选的原消息字段会随草稿序列化、消息持久化、同一渲染进程会话内的私有剪贴板复制粘贴，以及跨窗口会话交接保留。没有该字段的旧引用或外部引用仍可正常显示。原消息不在当前消息列表时，点击引用不会跳转。「引用」快捷键沿用现有快捷键设置和重置流程。

## 验证

- Regression — `TextSelectionToolbar.test.tsx` 和 `useCommandShortcuts.test.tsx` 覆盖「引用」的默认和自定义快捷键、禁用时的提示、选区范围、原消息定位、回复缩进，以及在编辑已发送消息、主输入框被替换或保存被拒绝时保留回复。
- Regression — `composerPaste.test.ts` 和 `navigation.test.ts` 验证引用来源在私有剪贴板和会话交接请求中保留。
- Regression — 在 macOS Electron 中用本地测试模型验证了引用和回复会追加到主输入框、保留原有草稿，并从主输入框发送。最终的无标题引用块和可配置快捷键由渲染进程测试覆盖。
