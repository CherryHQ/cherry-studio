# Agent Note: 独立的会话列表排序

Status: implemented

[English](2026-11-18-conversation-list-sort.md) | 中文

## 问题

聊天话题和 Agent 会话的行顺序由分组模式决定。时间分组按活跃时间排序，所有者和工作目录分组按 `orderKey` 排序；聊天右侧面板还有单独的手动排序例外。因此切换分组会在用户未明确选择时改变排序。集合分页始终读取手动顺序，仅对已加载行排序无法把后续页面中最近活跃的会话提到前面。

所有旧行都有 `orderKey`，包括从未拖拽过的行。没有历史拖拽标记。

## 决策

共享会话列表菜单在 Group by 旁边提供 Sort by 子菜单。聊天和 Agent 各自持久化一个独立排序设置，同一类型的各会话列表共用。提供最近更新、创建日期、名称和手动排序。自动排序支持降序和升序；手动排序没有方向控件。分组继续决定区段位置和组顺序。置顶行保留独立的置顶顺序。

最近更新使用 `lastActivityAt`，重命名和排序写入不会让会话提前。自动模式禁用会话行重排；手动模式启用现有合法的组内拖拽和所有者转移。切换分组不改变已保存的排序设置。切换自动排序不会覆盖 `orderKey`。

在填充默认设置之前，`ConversationListSortSeeder` 分别用完整的活跃聊天和 Agent 会话表初始化缺少的排序设置。按 `orderKey ASC, id ASC` 读取行：只要 `createdAt` 出现递增，就说明当前顺序不同于默认的创建时间倒序，选择手动；否则选择最近更新降序。相同创建时间不能作为判断证据。已删除行、置顶行，以及 Agent 的任务和后台会话不参与推断。设置存在后不再推断。这能保留当前自定义顺序，但无法识别已恢复为创建顺序的拖拽，或相关行被删除后的历史行为。

集合查询接受显式排序字段和方向。在游标分页前完成排序，保留置顶优先和 id 升序决胜规则，并把排序选择纳入渲染进程缓存键。侧栏和右侧面板使用相同的组内顺序。省略排序参数时保留现有 API 默认值，避免影响其他使用方。

名称排序共用一个 `Intl.Collator` 比较器，跟随应用语言，使用自然数字排序，忽略大小写、区分重音，并保留标点的排序意义。规范等价的名称以及数字或大小写等价项，在两个方向上都以 id 升序决胜。当前 17 种界面语言使用各自的 ICU/CLDR 规则，覆盖拉丁字母、希腊字母、西里尔字母、泰文、汉字和日文假名；标题中的其他文字也使用同一语言环境的混排规则。日文汉字不会自动转换为读音。

名称查询在查询参数和缓存键中携带经过验证的语言环境。切换应用语言会开始新的分页链。主进程只读取符合条件的未置顶 `(id, name)`，用共享比较器排序并应用名称/id 游标，再按该顺序读取当前页的完整数据。这样无需原生 SQLite ICU 扩展；其他排序继续使用 SQL 分页。置顶和所有领域筛选条件保持现有行为。

无状态的元数据选择和键解析位于 `main/utils/listOrdering.ts`，不依赖数据层。字段选择、默认值、资格筛选查询、SQL 排序和游标组合仍由对应的数据服务负责。

## 考虑过的替代方案

- 将所有非空 `orderKey` 当作拖拽标记：不采用，因为创建时也会分配。
- 根据 `updatedAt` 推断：不采用，因为消息和元数据也会改变它。
- 只对渲染进程已加载行排序：不采用，因为真正的首项可能在后续页面。
- 选择自动排序时改写手动键：不采用，因为切回时必须恢复自定义顺序。

- Unicode 二进制顺序：不用于名称排序，因为它不符合各语言的排序习惯。
- 增加原生 SQLite ICU 扩展：暂不采用，因为当前驱动没有 JavaScript 排序规则注册 API，原生扩展会增加各平台的构建和分发工作。

## 影响

旧数据推断识别的是当前顺序，而非历史操作。导入也可能产生非默认顺序，这类顺序会按手动保留。时间分组仍按活跃时间分桶，行排序作用于桶内。不改写任何已发布的结构迁移，设置初始化不修改会话行。

名称分页每次读取并排序所有匹配的名称/id：占用 O(n) 元数据，进行 O(n log n) 次比较，不加载全部会话内容。ICU 升级可能改变语言排序；切换语言时会刷新对应的分页链。

## 验证

- AC1 — `ConversationListOptionsMenu.test.tsx` 使用真实下拉菜单验证独立控件和方向选择；Electron 在深浅主题和 1024 x 760 窗口展示聊天与 Agent 菜单。
- AC2 — `conversationListSort.test.ts`、`sessionListHelpers.test.ts` 和 Electron 分组切换场景验证排序设置在分组与活跃时间变化时保持独立。
- AC3 — `src/main/data/services/__tests__/conversationListSort.test.ts` 使用生产 SQLite 迁移验证默认与自定义顺序推断、相同时间、空表、排除行和已有设置保留。
- AC4 — 同一数据库测试集验证两个类型的各自动排序方向跨置顶、相同值、空名称和游标标点分页，且不改变手动键。
- AC5 — Electron 将聊天切到手动，在时间组内拖动一行到首位，重载后观察到保存的顺序；自动模式没有启用的可排序行。数据库与渲染进程测试验证手动键和置顶优先级保留。

- AC6 — `src/shared/utils/__tests__/nameOrdering.test.ts` 覆盖全部 17 种界面语言以及阿拉伯语、韩语，自然数字、重音、标点和规范/大小写等价项；数据库及渲染分组测试使用相同比较器。
- AC7 — `useConversationListSorting.test.ts` 验证切换语言后开始新的分页链；数据库测试覆盖领域候选筛选和已删除的锚点；Electron 在两个列表中切换拼音和笔画排序，对比分页 API 结果并检查重新加载后的持久化。
