# Agent Note: 终端目录历史

Status: implemented

[English](2026-10-31-terminal-directory-history.md) | 中文

## 问题

终端仅记住上次的工作目录，在多个项目之间切换时需要反复选择文件夹。

## 决策

本地智能体通过 `feature.code_cli.workspace` 共享终端工作目录与历史。启动时将所选目录移到最前，避免重复记录。首次保存共享设置前，弹窗会合并旧历史，优先使用当前工具保存的目录。工具的旧配置没有历史字段时，才将其工作目录加入历史。

输入框的下拉列表可以选择目录或逐项移除历史记录。移除操作立即保存，不改变当前选择，也不操作磁盘文件。取消弹窗不会撤销用户明确执行的历史移除操作。目录和终端选择仍在启动时保存。

## 考虑过的替代方案

- 按工具记录历史会让用户在切换智能体时重新选择同一个项目。
- 将工作目录和按工具保存的启动设置放在一起，会把目录编辑与模型服务及终端配置耦合起来。

## 影响

无需数据库迁移。终端应用仍按工具保存。再次使用已移除的目录启动时，该目录会重新加入共享历史。

## 验证

- Regression — `LocalAgentTerminalDialog.test.tsx`：选择历史目录后在该目录启动，将其移到最前且不重复记录。
- Regression — `LocalAgentTerminalDialog.test.tsx`：在一个智能体中启动后，另一个智能体打开时沿用相同目录，并使用自己的终端应用。
- Regression — `LocalAgentTerminalDialog.test.tsx`：移除旧目录后，该目录不会重新出现在其他智能体的历史中，当前目录仍保留。
