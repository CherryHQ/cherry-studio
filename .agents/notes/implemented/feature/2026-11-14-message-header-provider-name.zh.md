# Agent Note: 在回复头部的模型旁显示实际服务商

Status: implemented

[English](2026-11-14-message-header-provider-name.md) | 中文

## Problem

助手回复头部会显示实际生成的模型，但不显示提供该模型的服务商。把同一个模型接在多个服务商上的用户，无法判断某条回复来自哪一个。v1 显示的是 `模型 | 服务商`。

每条消息的模型快照已经保存了服务商 id，但没有保存显示名，而自定义服务商的 id 是 UUID。

## Decision

凡是 `MessageHeader` 显示模型标签的位置，都会追加服务商的当前显示名：`模型 | 服务商`。显示名由渲染层用已有的 `useProviderDisplayName` hook 根据消息自身的服务商 id 解析，token 详情卡片已经对同一个 id 这样做。只有在显示模型标签时才发起查询。

多模型标签（fold）布局的头部现在也显示该标签。标签栏只显示模型名而不显示服务商，如果头部仍隐藏模型标签，同一模型经由不同服务商生成的回复就无法区分。

服务商改名后，旧回复的标签随之更新；服务商被删除后只显示模型标签。消息、schema 和 main 进程的写入路径都不变。过长的标签会截断，悬停可看到完整文本。

## Alternatives considered

- 在创建消息时把服务商名冻结进 `ModelSnapshot`。改名或删除后旧标签仍会保留，但需要修改每条消息写入路径和共享类型，并且改名后头部与 token 详情卡片显示的名称会不一致。
- 只在悬停时显示服务商。改动更小，但浏览回复时看不到服务商，而这正是用户怀念的 v1 行为。
- 把服务商追加到助手名后面。这会混淆作者身份与路由信息。
- 把服务商显示在标签栏里，而不是 fold 头部。展开模式下每个标签都会变宽，而且每个标签都要单独查询服务商。

## Consequences

删除自定义服务商后，历史回复中不再显示其名称；若要保留，需要采用快照方案。

在标签（fold）布局中，头部会重复显示选中标签上的模型名。

## Verification

- Regression — `pnpm test:renderer src/renderer/components/chat/messages/frame/__tests__/MessageHeader.test.tsx`：10 个测试通过，覆盖消息自身的服务商优先于当前模型、通过真实服务商 hook 和 SWR，在修改服务商后自动刷新已挂载头部的名称，以及无法解析服务商时只保留模型标签。
