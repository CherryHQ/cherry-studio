# Agent Note: Compact Agent session details card

Status: implemented

English | [中文](2026-11-08-agent-session-details-card.zh.md)

## Problem

Agent session status is registered as a full-height right-panel capability. Even an unavailable context reading occupies an entire inspector column. Its toolbar shortcut also has a separate hover preview, so a small amount of information has two presentations and a click changes the conversation geometry unnecessarily.

The requested reference is T3 Code's content-height thread details card: compact rows, quiet section dividers, an inline card when space permits, and a toolbar-anchored popup otherwise. Only Agent session details are in scope. Files, Browser, Trace, resources and task execution views retain their existing large panels.

This is a new presentation decision. It preserves the data semantics in [Harness-owned context usage](../../proposed/architecture/2026-10-30-agent-context-usage.md) and the work-panel identity rules in [Bind right-panel presentation to its instance](../../implemented/bug-fix/2026-10-31-right-panel-presentation-identity.md). It does not claim to complete either proposal's outstanding acceptance work.

## Decision

### Card and placement

Replace the Status shortcut and its hover preview with one Session details toggle and one content owner. Use the shared Button, Tooltip, Popover, ScrollArea and disclosure primitives from `@cherrystudio/ui`. Follow `DESIGN.md` semantic surfaces, typography, focus and light/dark behavior; do not copy T3's literal colors or introduce a second design system.

The card has a target width of 280 CSS pixels, a 12-pixel outer clearance, a subtle border and rounded container corners. It sizes to its content up to the available height. There is no full-height background, resize handle, large Status heading or card inside a card. Groups use compact rows and dividers; row actions retain usable pointer targets and keyboard focus. Long labels truncate with access to their full text. Overflow scrolls inside the card.

Choose placement from the actual conversation area remaining after sidebars and work panels. When that area can accommodate a readable chat lane plus the card and clearances, place the card below the toolbar at the right edge and reserve its horizontal space in the conversation layout. Shift the message lane and composer together to the left, reducing their width only when necessary; both remain aligned and clear of the card. Closing the inline card releases this space. The card remains content-height, with empty canvas below it, not a full-height sidebar surface. Preserve the user's narrow/full-width preference as the chat lane's sizing policy within the remaining space; full-width chat does not by itself force popup mode.

If the remaining area cannot fit a readable chat lane alongside the card, switch the details control to a non-modal popup anchored below the toggle and aligned to its right edge. Opening this popup overlays the chat without reserving horizontal space or changing message/composer geometry. Constrain both presentations to their available viewport height and scroll overflowing content internally. An inline card may extend beside the composer because their horizontal bounds do not intersect. A wider application window alone is not proof that inline placement fits: an open Files or Browser panel reduces the available conversation area. Reuse shell placement slots where adequate and add only the lane-space integration this behavior requires; keep existing work-panel sizing intact.

### Visibility, focus and identity

Use separate session-scoped intent for inline visibility and transient popup visibility. Inline visibility defaults to enabled; popup visibility defaults to closed. Placement derives from available space, not a separate Pin control. Clicking the toolbar toggle changes visibility for the current presentation; hovering only shows its tooltip. The toggle exposes its accessible name and current expanded state. Inline display does not steal composer focus, and clicking elsewhere does not dismiss it. Popup focus, outside-click dismissal and Escape behavior use the shared Popover contract; keyboard dismissal returns focus to the toggle. Inline Escape dismissal applies only while focus is inside the card, so it does not intercept composer or unrelated panel shortcuts.

When the layout becomes too narrow, suspend the inline presentation while retaining its visibility intent; do not automatically open a popup. The next toggle can explicitly open the popup. When space returns, clear transient popup visibility and restore the remembered inline visibility. If inline details were explicitly hidden, they stay hidden even when a popup had been opened. Closing a popup does not disable future inline display. Preserve a valid focus target during transitions and never mount two copies of live content for alternate layouts. Opening, closing or resizing details must not start a model turn, compact context, or introduce a new polling loop.

Session identity owns inline visibility and disclosure state. Switching sessions or leaving the Agent conversation dismisses transient popups and clears expanded groups. Restore that session's own inline choice on return; a new session uses the inline-enabled default, never another session's choice or content. Retain this choice in existing renderer session UI state for the current window lifetime; restart persistence is outside this change. Missing or pending sessions use the existing readiness contract. Late updates from the previous session must not appear in the new card. Card visibility needs no persisted preference or database migration; the workspace-open shortcut uses the existing customizable shortcut preferences.

Files and Browser remain independently controlled work panels. Opening or closing one recomputes the remaining conversation layout without changing its identity, state or auto-open policy. If enough room remains, inline details and the work panel coexist; otherwise the details toggle opens a popup over the reduced chat area. While a work panel is maximized, suspend inline details and dismiss any popup with the existing toolbar controls. Restoring it restores inline details only when they fit and the session's inline choice is enabled; never restore a popup automatically.

### Content and actions

The default order is workspace, task plan, Subagents, workflows, background shell tasks, other tasks, artifacts, and the existing context usage section. Omit empty task/artifact groups and their dividers. Do not manufacture device, editor, Git, project-script or weekly-quota rows to match the reference screenshot.

The persistent header exposes Customize sections. Reuse the composer toolbar's shared ReorderableList with a separate drag handle, visibility switch, keyboard drag announcements and Restore default. All eight groups are configurable, including currently empty groups. Store the ordered `{ id, visible }` entries in the global `agent.details.sections` Preference; hidden groups keep their position. Both inline and popup layouts consume the same setting across sessions and restarts. Keep the header reachable even when every group is hidden. Add newly introduced groups at their default position after saved entries; ignore retired or duplicate IDs. Hiding a group changes presentation only, never stops tasks or disables the workspace-open shortcut. Context usage retains its existing internal UI.

- Workspace: show the current workspace name as static identity, separate from the directory-open controls. Reveal the full path on hover or keyboard focus instead of rendering a second path line. Reuse `OpenTargetButton` for directory-open actions when a path is available. In details, its menu matches the card width and only changes the persisted default directory tool; the primary icon opens the directory with that tool. Register `CommandOrControl+O` in shortcut settings to open the active session workspace with the selected default tool, including while the details card is closed. Other OpenTargetButton consumers retain their existing open-on-selection behavior. Show the top-bar workspace selector only while the empty conversation allows changing it; once locked, details owns the directory identity and open action. Keep model selection in its current owner; the details row does not introduce a second selector. Label a system workspace using existing product terminology, and omit directory actions when its path is unavailable.
- Task plan: show the current in-progress step and completed/total count from `AgentRightPaneStatus.tasks`; expand to the existing ordered plan. Do not invent a current step when none is in progress. Retain the existing composer progress capsule and its behavior; both views consume the same projection. Spawned processes never enter this completion denominator.
- Subagents: use a distinct section, not a mixed background-task list. Its compact header reports running, pending and failed counts when nonzero. Expand to task title, current activity and status. Show running tasks first, then failures, then pending tasks; preserve source order within each status. Completed and stopped entries live under a nested, initially collapsed finished group. The whole section starts collapsed and is absent when there are no subagents. Use the existing subagent classification, task identity and liveness projection. Unclassified non-shell/non-workflow tasks remain visible in an Other tasks group rather than being relabeled as subagents or discarded.
- Workflows and shell tasks: separate compact groups preserve existing names, activity, available usage metadata, errors and stop operations. They report status counts rather than a completion percentage. Keep their current navigation affordances; do not promise a task-details destination where none exists.
- Artifacts: show a count and expand to the existing deliverable list. Opening a supported file uses the current preview/edit destination and permission checks; unsupported targets retain their existing fallback.

Reuse `AgentContextUsageSummary` and `ContextUsageSummary` unchanged in visual structure: retain their current collapsed label, percentage/meter, disclosure behavior, expanded token totals, model information, segmented bar, category table and resource groups. Do not replace this UI with T3's single-line progress bar or another count-only summary. Adjust only the containing section spacing and remove the old redundant outer card border. Preserve all currently supported information and the same denominator as the composer. A missing reading is explicitly unavailable, not zero; a measured zero remains a valid zero. Compaction and partial/estimated readings retain their existing semantics. Do not replace runtime-owned usage interpretation with renderer estimates or confuse context occupancy with billing/subscription quota.

The current artifact and task actions continue to open their existing work-panel destinations. Dismiss a popup after navigating to a destination and focus that destination; an inline card may remain only if it still fits. Stopping a task does not navigate or dismiss the card. For a task execution view's Back action, retain nested task navigation; at the root, close the task work panel and explicitly open session details instead of requesting the removed Status capability. This return action is a user open intent, so popup placement is allowed if inline placement cannot fit.

### Component and state ownership

The implementation stays within the Agent page and its existing `AgentRightPane` integration boundary, with the following local owners.

- `AgentSessionDetails.tsx`: the toolbar toggle, shared inline/popup content host and session details composition. One live content tree exists at a time. The card consumes session meta, status and existing actions supplied by the Agent owner; no new main-process API is required.
- `AgentSessionDetailsSections.tsx`: workspace, plan, Subagent, workflow, shell and artifact section composition. Reuse or move existing row/action components instead of duplicating stop requests, file opening or task navigation. Keep resource-usage detail rendering in its current shared components.
- `useAgentSessionDetails.ts`: own transient popup/disclosure state and access the existing renderer memory cache for inline visibility keyed by session ID. Missing identity cannot write a cache entry. Clear transient state on identity changes; release subscriptions and resize observation on unmount. Do not maintain a separate task cache or mutable module-level session map.
- `agentSessionDetailsLayout.ts`: a pure fit/inset calculation over measured conversation width and height, with no runtime or DOM access. Start with a 280px card, 12px outer gutters, 32px clearance to chat and a 640px minimum chat lane: inline is eligible at 976px available width and 160px available height. Restore from popup mode at 980px to avoid fractional-width jitter. These are details-specific constants; do not lower or replace the shared work-panel minimum-width policy.
- `AgentChat.tsx` integration: wrap the center content below the existing toolbar in one measured details layout so messages and composer receive the same reserved width. Keep the composer/editor instance mounted across placement changes. Measure the un-inset container, not the child after its own padding, and attach the card to that container's top-right. The existing toolbar slot owns the toggle. Preserve custom center refs, scrolling, message navigation gutter and embedded Agent-page consumers.
- `AgentRightPane.tsx`: keep Files, Browser, Trace, resources and flow panels registered; remove the Status capability and hover preview. Add a details-opening callback to the existing Agent action boundary for root flow Back. Reuse `useAgentRightPaneStatus` and its liveness inputs; move shared projection plumbing only where necessary to avoid duplicate ownership.

Subagent row navigation requires the existing flow capability and a real `toolUseId`; otherwise render a non-clickable row. A stop button is separate from row navigation and is offered only where the existing runtime action is available. Disable duplicate stop submissions while pending, retain the row's authoritative state until the runtime confirms the outcome, and restore the control with existing error feedback on failure. A late completion or stop response remains bound to its originating session/task. `AgentRunTaskStopsProvider` lives in the Agent details scope above both content hosts; pending and accepted stop requests remain keyed by session/task across disclosure, presentation and session navigation, while failed requests become retryable. The toolbar trigger keeps the same component ancestry across placement changes so resize focus restoration targets a connected button.

## Alternatives considered

- Only reduce the inspector width or remove its border: leaves full-height allocation and two competing presentations.
- Use only a popup at every width: simpler, but omits the persistent, unobtrusive inline card requested by the reference.
- Put the card only in pre-existing blank space while keeping chat bounds unchanged: does not match the reference's coordinated message/composer reflow. Reserve layout space for inline details, but reject a full-height inspector surface or draggable extra work pane.
- Redesign all right-side capabilities or copy T3's canvas/density system: exceeds the confirmed scope and risks file editing, browser state and execution navigation.
- Fill the card with new environment or quota features: adds unrelated capabilities without existing data contracts.

## Consequences

Available space depends on sidebar state, message width, navigation gutters, work panels, window size and zoom. Derive fit from the remaining conversation area and minimum readable lane width, not the blank space after applying the card's own inset; otherwise measuring and reserving space can oscillate. Keep message/composer bounds aligned and preserve the existing scroll anchor as layout changes.

Task lists and context resources can be large. Progressive disclosure and bounded scrolling must not hide pending actions or remove error information. Popover dismissal must respect nested menus and dialogs owned by task actions. Session-owned presentation must not reset workspace-owned file state or browser runtime resources.

## Verification

Focused renderer validation ran nine explicit test files with 366 passing tests: `AgentSessionDetails.test.tsx`, `AgentSessionDetailsSections.test.tsx`, `AgentRightPane.test.tsx`, `agentRightPaneProjection.test.ts`, `AgentChatArtifactPane.test.tsx`, `AgentChatLocate.test.tsx`, `AgentComposerSlot.test.tsx`, `AgentComposer.test.tsx` and `AgentContextUsageSummary.test.tsx`. Native acceptance used an isolated macOS Electron profile.

- AC1 — `AgentRightPane.test.tsx` and `AgentChatArtifactPane.test.tsx`: the obsolete Status surface is removed and existing work-panel entry points remain available.
- AC2 — Electron measurements: at 1450 × 900 the 1118px conversation region reserves 324px for details, leaving a 794px lane beside the 280px card; narrow popup placement leaves the 768px lane unchanged. Light/full-width and 125% zoom checks passed without horizontal overflow.
- AC3 — `AgentSessionDetails.test.tsx` and Electron: hide/shrink/open-popup/widen restores the inline choice; outside click, nested-menu Escape, toggle focus and one live content instance were checked.
- AC4 — `AgentSessionDetails.test.tsx` and Electron session switching: inline choices remain session-scoped; readiness, identity and maximization clear transient popup state.
- AC5 — `AgentSessionDetailsSections.test.tsx`, existing task projection tests and Electron fixtures: grouped statuses, finished disclosure, unknown tasks, workspace/plan/artifacts and stop failure/settlement are covered. Forty additional long-label tasks scroll internally to context usage (3971px content inside a 579px viewport).
- AC6 — `AgentContextUsageSummary.test.tsx` and affected composer tests: existing usage states and denominator semantics pass unchanged. Electron confirms expanded totals, categories and resources remain accessible.
- AC7 — `AgentRightPane.test.tsx`, `AgentChatArtifactPane.test.tsx`, `AgentChatLocate.test.tsx` and Electron: existing destinations, nested/root Back, file state and browser/details coexistence are preserved.
- AC8 — `pnpm i18n:check`, `pnpm docs:check`, `pnpm typecheck:web`, `pnpm typecheck:node`, scoped Oxfmt/Oxlint/ESLint and UI theme checks passed. Electron covered both themes and keyboard interaction; ESLint retained four pre-existing warnings.

Task and plan screenshots use DataApi fixtures; conversation/context acceptance uses a local mock provider through the normal Pi runtime. These verify renderer behavior, not external-model task execution. Paid-provider subagent creation/stopping, Windows/Linux native acceptance and release packaging were not rerun. CI is separate from these local checks.
