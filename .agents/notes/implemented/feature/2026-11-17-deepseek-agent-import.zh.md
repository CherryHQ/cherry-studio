# Agent Note: 将 DeepSeek 导出数据导入智能体会话

Status: implemented

[English](2026-11-17-deepseek-agent-import.md) | 中文

## 问题

用户需要将 DeepSeek 账号导出数据导入智能体页面，并在后续对话中让模型使用历史上下文。现有渲染进程 `ImportService` 创建的是助手和话题，仅在那里添加解析器无法满足需求。智能体消息保留产品历史，各 Harness 持有各自的原生执行上下文。

用户提供的 11 月 17 日导出包使用 `export_format_version: 3`、`chat_session_index.json` 和 `chat_sessions/<id>.json`。本地检查发现 106 个会话、500 条消息，其中 14 个会话包含非根兄弟分支。消息使用 `parent_id`，会话通过 `current_message_id` 选择当前消息。五个文件引用包含四张有实际文件的图片和一个缺失内容的文件（`export_path: null`）。消息状态包括 `FINISHED`、`TIMEOUT`、`INCOMPLETE` 和 `CONTENT_FILTER`。这些是样本观察结果，不代表所有 DeepSeek 导出都采用这一结构。私有账号数据和会话内容不得进入仓库测试样本或 PR 附件。

## 决策

### 入口与范围

设置 → 数据 → 导入外部应用数据直接提供 DeepSeek 导入入口，无需选择目标智能体。预览只预留操作和智能体 ID，不创建智能体。确认导入后创建名为 DeepSeek 的新智能体，使用导入器头像与普通 Pi Durable 创建默认值。仅当已配置的默认模型及其提供商已启用且兼容时才继承该模型，否则保持未设置，待用户继续对话时选择。智能体分组菜单不再提供导入入口。用户选择原始 ZIP，查看会话数、消息数和警告，再导入为新建智能体下的新会话。每个源会话对应一个新会话；导入不向已有会话追加内容。目标智能体提供后续对话使用的模型、工作区策略和权限。导入过程不运行模型或工具。

本版支持已观察到的 DeepSeek v3 ZIP 格式，并创建 Pi Durable 智能体。通用 Session 续聊机制独立于导入，支持 Claude Code、Pi 和 Pi Durable。不增加 ChatGPT/Claude 智能体导入，不同步 DeepSeek 账号，不恢复 DeepSeek 身份验证，也不重建导出包中不存在的文件。现有助手导入保持独立。

### 压缩包与内容映射

主进程使用现有压缩包依赖，负责有资源限制的 ZIP 读取与校验。直接读取用户选中的 ZIP，不创建临时或长期保留的副本。随操作保存原始路径和摘要，导入前再次验证摘要。原文件被移动或不可用时，用户须重新选择后再重试。发布前校验 manifest、会话索引、唯一 ID、父子图、选中消息和引用的压缩包条目。拒绝不支持的版本、非法图、规范化后重名路径、绝对路径或路径穿越、链接，以及超过明确条目大小、数量、解压后总大小限制的压缩包。不任意解压路径，不获取远程 URL。逐条读取，不通过 IPC 传送整个压缩包或全部消息正文。

保留标题、原始时间戳、角色、源 ID、父子关系和选中分支。生成新的产品 ID。导入来源元数据保留精确的源时间戳；当源时间相同或倒退时，让产品排序时间沿父子关系至少递增一毫秒，保证分页后连续用户消息仍在回答之前。保留空消息或未成功的源消息作为历史记录，不静默丢弃。它们不得变为待处理输入、可恢复的失败任务或伪造的成功回答。存储原始源状态，并明确映射终态展示状态。将导入回答归属为 DeepSeek，不编造模型版本，不将源 token 计数导入为 Cherry 计费。

将 `REQUEST`、`RESPONSE` 和 `TEMPLATE_RESPONSE` 映射为文本。将 `THINK` 映射为已完成的推理内容，保留可用的耗时。将 `CONTENT_RISK` 保留为可见的历史文本。将 `TOOL_SEARCH`、`TOOL_OPEN` 和 `TOOL_IMAGE_SEARCH` 展示为历史搜索或打开记录，保留查询、URL、标题、摘要和可用结果。搜索、网页访问和图片搜索使用已完成的标准工具 part，带有生成的调用 ID、已知输入和完整输出，与思考按源顺序交替显示。现有工具调用和结果组件展示查询、链接、摘要、源状态和空结果，续聊上下文保留完整的带标签记录。搜索结果不伪装为正文引用，不追加人工引用尾巴或来源列表。导入的失败和空消息展示原始导出状态，不显示运行错误或重试操作。这些已完成的展示记录不会发起新的工具调用。未知片段类型导致校验失败，并指出受影响的会话，不静默丢弃。

通过受管理的文件存储导入可用的 `FILE` 内容，保留稳定的消息引用，使重新打开不依赖原始 ZIP。同一会话内共享附件 ID 的文件描述发生冲突时，在发布前拒绝导入；允许重复引用相同的文件描述。保留缺失文件的元数据，显示警告，并在模型上下文中加入附件不可用的标记。可用文件和图片使用目标 Harness 现有的附件转换及能力和大小限制。非图片附件使用现有智能体附件表示；不支持的内容明确报校验错误，不虚报成功。

### 会话上下文与分支

导入只写入产品消息树和托管附件，不创建原生对话记录、任务、输入提交、检查点或恢复令牌。打开导入会话时沿用普通运行时连接流程，不执行历史工作。

在尚无原生输入的分支首次提交新消息时，`AgentSessionRuntimeService` 通过 `readSessionHistory` 读取选中的祖先前缀。主进程将其作为仅面向模型的 `AgentRuntimeCommand.context` 发送，包含明确标注用户和助手角色、完整思考与工具记录的参考文本，以及托管文件 part。原产品消息不变。历史工具只是数据，不会执行。这是通用 Session 机制，不检查导入来源，也不选择 Harness。驱动沿用现有输入和附件转换，原生输入身份仍绑定原消息。

新建原生上下文以选中的产品位置为锚点，不绑定公共树根，保证兄弟分支独立。后续对话和重新打开时复用普通原生历史，不重复发送产品历史。有原生绑定或恢复身份时仍遵循正常恢复流程，不通过重建历史替换缺失的存储。不为导入的历史回答编造原生 Fork/Edit 检查点，沿用现有资格判定原因。续聊后产生的回答使用正常运行时检查点。

### 发布与失败恢复

通过 IpcApi 访问由主进程持有、具有持久身份和进度的导入操作。渲染进程负责审阅和观察；对话框是否可见不决定操作生命周期。准备托管文件前先持久化操作身份。以导入器 ID 和压缩包摘要标识操作，再以源会话 ID 标识其中的会话。新压缩包创建独立智能体。重新选择同一压缩包时恢复原操作并复用其智能体，重启后也一样。智能体创建与待创建标记在同一事务中提交，因此会话发布失败后重试不会再建一个智能体。已删除的目标智能体不会被静默重建。重试同一压缩包时恢复未完成工作，并报告已导入的会话，不创建重复项。不同压缩包摘要视为独立导入；首版不合并已变化的导出数据。

在一次同步产品数据库事务中发布每个会话的会话记录、消息树、文件引用和完成标记。发布前准备托管文件，其回执保留重试所用的稳定 ID。取消在会话之间或发布前停止，保留已发布会话。准确报告已导入、已存在、失败和剩余数量。保留已发布或可重试工作引用的托管文件条目，不删除无关文件。如果操作身份需要新的产品结构，使用追加迁移。

### 决策与验证归属

主进程智能体会话域负责导入编排、发布和首次提交的上下文。`ConversationImporter` 提供来源标识、预览，以及按会话加载为统一消息结构的接口。`DeepSeekImporter` 负责 ZIP 校验、来源字段、内容映射与附件准备；`AgentImportService` 负责进度、重试回执、产品 ID 与原子发布，不读取 DeepSeek 字段。操作保留 importer ID，确保重试使用同一个适配器；旧操作使用默认导入器。这一小型边界沿用渲染进程导入器分离解析与持久化的方式，为未来迁移 ChatGPT/Claude 提供共同的发布路径，本次不迁移它们。现有运行时驱动负责原生执行与普通输入转换；共享 IPC schema 负责命令和进度；设置页面负责文件选择、预览和结果导航。使用现有 UI 组件、本地化、文件所有权、集中路径和生命周期规则。

用户于 11 月 17 日明确授权跳过 Spec Approval 开始实现，并要求 rebuild 通用且与 Harness 无关。产品发布以会话为单位保持原子性。导入的接纳和等待结束纳入智能体生命周期的备份与恢复写入暂停机制。导入不会复制、修改或删除原 ZIP，已完成的会话依赖托管附件而非 ZIP。

## 考虑过的替代方案

- 仅在助手导入中增加 `DeepSeekImporter` 会进入错误的产品入口，也无法提供智能体上下文。
- 仅写产品消息行会让历史可见，却不会让下一次模型请求获得历史。
- 展平所有分支会混合互斥历史；仅导入选中路径则会静默丢失源消息。
- 重放历史输入会运行模型和工具并改变回答。将历史角色保留为有明确标签的参考数据，附件保留为托管 part，同时在产品存储中保留原分支树。
- 为各 Harness 分别重建原生历史，需要原生文件写入器、检查点映射和跨存储恢复。统一的 Session 参考上下文可以复用现有输入提交契约。

## 后果

样本不是公开 schema 保证，不支持的格式必须明确报错。保留全部分支和图片会增加存储量，并可能超过目标模型上下文限制；遵循现有模型限制和压缩机制，导入器不静默截断。参考上下文将历史角色保留为有明确标签的数据，不赋予原生助手或工具权限。不恢复导入历史的 Fork/Edit 点。无法从此 ZIP 恢复缺失文件。未完成的导入需要原 ZIP，或重新选择摘要相同的副本；已完成的会话不依赖 ZIP。

- AC1 — `ImportMenuSettings.test.tsx` 验证从设置直接打开智能体导入；`AgentImportPopup.test.tsx` 验证预览和重新打开后的进度。现有助手导入保持独立。
- AC2 — `deepseek.test.ts` 和 `deepseekArchive.test.ts` 覆盖图排序、兄弟分支选择、空会话与未命名会话、未知片段、重复路径、链接和限制。先前私有样本校验发现 106 个会话、500 条消息。
- AC3 — 内容测试保留思考、完整搜索记录、源状态和缺失文件标签。导入发布不创建原生上下文，也不提交历史输入。
- AC4 — `sessionHistory.test.ts` 验证无导入元数据的通用选中前缀、连续用户消息顺序、完整工具记录，以及有原生输入后不重复补历史。`PiDurableRuntimeConnection.test.ts` 通过真实运行时和 SQLite 将两个兄弟分支分别发送给脚本服务商，再关闭并重新打开选中的原生会话，检查模型请求。Claude 桌面集成测试验证主进程补入的历史进入真实 SDK 请求。
- AC5 — 历史测试验证普通输入转换保留附件元数据；内容和压缩包测试覆盖托管文件引用、缺失或冲突的文件描述。真实 Claude SDK 请求还验证历史图片字节经现有附件转换发送。续聊使用各 Harness 现有的附件行为。
- AC6 — `AgentImportService.test.ts` 覆盖产品回滚、更换服务实例、去重、取消、暂停与等待结束、提交后通知失败、不复制或修改 ZIP、拒绝已变化的源文件，以及重新选择已移动的 ZIP。还覆盖预览、取消或源文件校验失败时不创建智能体、默认模型可用性，以及更换服务实例和重试均只创建一个智能体。第二种导入器样本验证不含 DeepSeek 元数据的发布与重试；`DeepSeekImporter.test.ts` 验证统一结构转换与缺失文件警告。
- AC7 — 历史测试验证 Claude Code、Pi 和 Pi Durable 的兄弟分支上下文独立，不伪造源检查点。现有运行时和消息服务测试覆盖续聊及正常 Fork/Edit 消费方。
- AC8 — 先前私有样本和 Electron 验收使用的是原生历史实现。简化后的链路使用合成文件数据库和原生运行时测试验证；用户要求测试不抢焦点，因此不重跑 Electron 验收。不提交私有导出文件或会话内容。
