# Agent Note: 将 DeepSeek 导出数据导入智能体会话

Status: implemented

[English](2026-11-17-deepseek-agent-import.md) | 中文

## 问题

用户需要将 DeepSeek 账号导出数据导入智能体页面，并在后续对话中让模型使用历史上下文。现有渲染进程 `ImportService` 创建的是助手和话题，仅在那里添加解析器无法满足需求。智能体消息是展示投影，Pi Durable 在独立的原生存储中持有模型上下文。

用户提供的 11 月 17 日导出包使用 `export_format_version: 3`、`chat_session_index.json` 和 `chat_sessions/<id>.json`。本地检查发现 106 个会话、500 条消息，其中 14 个会话包含非根兄弟分支。消息使用 `parent_id`，会话通过 `current_message_id` 选择当前消息。五个文件引用包含四张有实际文件的图片和一个缺失内容的文件（`export_path: null`）。消息状态包括 `FINISHED`、`TIMEOUT`、`INCOMPLETE` 和 `CONTENT_FILTER`。这些是样本观察结果，不代表所有 DeepSeek 导出都采用这一结构。私有账号数据和会话内容不得进入仓库测试样本或 PR 附件。

## 决策

### 入口与范围

设置 → 数据 → 导入外部应用数据提供 DeepSeek 导入入口。用户通过通用智能体选择器选择目标智能体，再打开导入对话框。智能体分组菜单不再提供导入入口。用户选择原始 ZIP，查看会话数、消息数和警告，再导入为该智能体下的新会话。每个源会话对应一个新会话；导入不向已有会话追加内容。目标智能体提供后续对话使用的模型、工作区策略和权限。导入过程不运行模型或工具。不支持的智能体运行时显示原因，不静默创建普通聊天话题，也不更改智能体类型。

首版支持已观察到的 DeepSeek v3 ZIP 格式和 Pi Durable。不增加 ChatGPT/Claude 智能体导入，不同步 DeepSeek 账号，不恢复 DeepSeek 身份验证，也不重建导出包中不存在的文件。现有助手导入保持独立。

### 压缩包与内容映射

主进程使用现有压缩包依赖，负责有资源限制的 ZIP 读取与校验。发布前校验 manifest、会话索引、唯一 ID、父子图、选中消息和引用的压缩包条目。拒绝不支持的版本、非法图、规范化后重名路径、绝对路径或路径穿越、链接，以及超过明确条目大小、数量、解压后总大小限制的压缩包。不任意解压路径，不获取远程 URL。逐条读取，不通过 IPC 传送整个压缩包或全部消息正文。

保留标题、原始时间戳、角色、源 ID、父子关系和选中分支。生成新的产品 ID。导入来源元数据保留精确的源时间戳；当源时间相同或倒退时，让产品排序时间沿父子关系至少递增一毫秒，保证分页后连续用户消息仍在回答之前。保留空消息或未成功的源消息作为历史记录，不静默丢弃。它们不得变为待处理输入、可恢复的失败任务或伪造的成功回答。存储原始源状态，并明确映射终态展示状态。将导入回答归属为 DeepSeek，不编造模型版本，不将源 token 计数导入为 Cherry 计费。

将 `REQUEST`、`RESPONSE` 和 `TEMPLATE_RESPONSE` 映射为文本。将 `THINK` 映射为已完成的推理内容，保留可用的耗时。将 `CONTENT_RISK` 保留为可见的历史文本。将 `TOOL_SEARCH`、`TOOL_OPEN` 和 `TOOL_IMAGE_SEARCH` 展示为历史搜索或打开记录，保留查询、URL、标题、摘要和可用结果。搜索及打开记录中的 HTTP(S) URL 转换为去重后的 `source-url` 部分，接入现有引用界面；完整搜索记录以不可执行的文本保持可见，并保留在原生上下文中，包括状态和零结果搜索。它们不是可执行工具调用。未知片段类型导致校验失败，并指出受影响的会话，不静默丢弃。

通过受管理的文件存储导入可用的 `FILE` 内容，保留稳定的消息引用，使重新打开不依赖原始 ZIP。同一会话内共享附件 ID 的文件描述发生冲突时，在发布前拒绝导入；允许重复引用相同的文件描述。保留缺失文件的元数据，显示警告，并在模型上下文中加入附件不可用的标记。可用图片以图片形式进入原生上下文，遵循目标模型现有的能力和大小限制。非图片附件使用现有智能体附件表示；不支持的内容明确报校验错误，不虚报成功。

### 原生历史与分支

在 Pi Durable 集成的原生历史边界扩展能力。使用公开原生事务 API（`createConversation`、`appendEntry`、`forkConversation`），写入不会触发执行的应用自有导入条目以及面向模型的消息。不为 `AssistantEntry` 伪造生成任务 ID，不修改原生 SQLite 表，也不通过 `submit` 重放历史用户输入。

分歧路径使用原生会话，分支选择使用现有产品消息树和上下文绑定。初始选择遵循 `current_message_id`，即使导出包中另一个分支出现得更晚也不改变。切换分支后发送新消息必须选取该分支的原生历史前缀。已完成的助手回答边界获得有效的原生检查点；不可用的历史操作继续使用现有明确的资格判定原因。导入的推理和搜索记录是可阅读的历史，不具备原生任务、目标、审批或工具权限。模型上下文保留用户和助手角色；推理及搜索内容使用标记清楚的历史文本，不伪造提供商专属的推理签名或工具结果。

产品会话可见前，必须完成原生准备并验证其上下文。重新打开及后续投影更新必须保留导入的展示记录，不产生重复。现有 [Pi Durable Fork 所有权](../../implemented/feature/2026-11-09-pi-durable-desktop-fork.md)和后端身份规则继续生效；本实现增加外部历史构造能力，不增加第二个运行时所有者。

### 发布与失败恢复

通过 IpcApi 访问由主进程持有、具有持久身份和进度的导入操作。渲染进程负责审阅和观察；对话框是否可见不决定操作生命周期。原生存储和文件准备前先持久化操作身份。以目标智能体、压缩包摘要和源会话 ID 标识每个源会话。重试同一压缩包时恢复未完成工作，并报告已导入的会话，不创建重复项。不同压缩包摘要视为独立导入；首版不合并已变化的导出数据。

在一次同步产品数据库事务中发布每个会话的会话记录、消息树、文件引用、上下文绑定和完成标记。原生存储与产品 SQLite 分别提交：中断后核对已准备的原生身份，不宣称存在跨存储事务。取消在会话之间或发布前停止，保留已发布会话。准确报告已导入、已存在、失败和剩余数量。保留可识别且不会执行的准备结果，直到恢复或能够证明只清理该操作自有资源；不得删除共享原生祖先或无关文件。如果操作身份需要新的产品结构，使用追加迁移。

### 决策与验证归属

主进程智能体会话域负责编排和发布；Pi Durable 适配器负责原生条目与检查点；共享 IPC schema 负责命令和进度；现有智能体 UI 负责选择、预览和结果导航。使用现有 UI 组件、本地化、文件所有权、集中路径和生命周期规则。适度分离解析逻辑，以便使用合成样本测试，不将本功能扩展为通用导入框架。

用户于 11 月 17 日明确授权跳过 Spec Approval 开始实现。原生构建使用公开 Session API，为每条消息提交一个会话前缀，并保存逐节点恢复记录。产品发布以会话为单位保持原子性。导入的接纳和等待结束纳入智能体生命周期的备份与恢复写入暂停机制。冻结 ZIP、准备好的存储和手动清理文件条目为恢复而保留；首版不自动回收导入产物。

## 考虑过的替代方案

- 仅在助手导入中增加 `DeepSeekImporter` 会进入错误的产品入口，也无法提供智能体上下文。
- 仅写产品消息行会让历史可见，却不会让下一次模型请求获得历史。
- 展平所有分支会混合互斥历史；仅导入选中路径则会静默丢失源消息。
- 重放历史输入会运行模型和工具并改变回答。将整个对话作为一条巨大用户消息导入会丢失角色、分支和附件语义。
- 一次支持全部运行时需要分别制定原生历史契约，会将功能范围扩展到已验证的 Pi Durable 基础能力之外。

## 后果

样本不是公开 schema 保证；不支持的格式必须明确报错。保留全部分支和图片会增加存储量，并可能超过目标模型上下文限制；遵循现有模型限制和压缩机制，导入器不静默截断。跨存储恢复和投影核对需要真实运行时证据，不能只依赖解析器测试。原生 SDK 没有通用的公开会话删除 API，因此失败的准备结果可能保留为可识别且不会执行的记录。无法从此 ZIP 恢复缺失文件。首版仅支持 Pi Durable 是明确的兼容性限制。

## 验证

- AC1 — `ImportMenuSettings.test.tsx` 验证目标选择和从设置打开智能体导入；`AgentImportPopup.test.tsx` 验证预览、不支持的运行时，以及重新打开对话框后的进度。Electron 通过新对话框导入并使用正常智能体导航。现有助手导入代码未改动。
- AC2 — `deepseek.test.ts` 和 `deepseekArchive.test.ts` 覆盖父节点排序、兄弟分支选择、空会话与未命名会话、非法图、未知片段、重复路径、链接条目和限制。私有样本通过 106 个会话、500 条消息的汇总断言。
- AC3 — 内容测试保留思考、搜索文本、缺失文件标签和零历史用量。文件数据库导入不启动 Harness 即发布样本全部 500 条消息；原生测试确认新输入提交前没有服务商调用。
- AC4 — `durableImport.test.ts` 关闭并重新打开真实原生 SQLite，重试准备，并向脚本服务商提交各兄弟分支，断言各自上下文。投影测试排除重复的导入展示记录。Electron 在进程重启前后续聊，本机 OpenAI 兼容模拟服务收到历史角色及匹配的原文。
- AC5 — FileManager 集成检查独立图片字节、稳定文件引用和缺失文件标记。Electron 重新打开后，将导入图片以 data URI 发送给本机模拟服务。压缩包测试拒绝重复条目、链接和过大的条目。
- AC6 — `AgentImportService.test.ts` 覆盖产品提交回滚、更换服务实例后重试、去重、立即取消、暂停与等待结束，以及提交后通知失败。原生逐节点恢复记录在关闭与重新打开后仍然有效。Electron 重启后保留已完成操作并继续导入历史。未分别测试每一个写入边界处的强制进程终止。
- AC7 — 发布测试检查选中的原生绑定及导入 Fork 检查点；受影响的 `AgentSessionMessageService` 测试覆盖既有 Fork/Edit 资格。只有成功的源助手消息获得锚点，导入条目不包含可执行的工具或任务记录。
- AC8 — 用户提供的压缩包通过真实文件数据库导入及 Electron 导入：106 个会话、500 条消息、14 个包含非根兄弟分支的会话、四张图片和一个缺失文件。本机模拟服务验证后续文本与图片请求；没有将私有内容发送给外部服务商或提交为测试样本。
