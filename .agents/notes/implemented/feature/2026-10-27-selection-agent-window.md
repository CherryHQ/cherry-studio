# Agent Note: Selection assistant agent window

Status: implemented

English | [中文](2026-10-27-selection-agent-window.zh.md)

## Problem

Selection actions could hand selected text only to an assistant. The [action window](../../../../src/renderer/windows/selection/action/ActionWindow.tsx) shows one answer from an in-memory temporary topic: there is no follow-up, no tool use, and nothing survives closing the window. Requests for agents, MCP tools, follow-up, and history recur in #11838, #9239, #6984, #22680, #10950, #12431, and their stale-closed duplicates.

Agent sessions already provided tools, approvals, workspaces, persistence, and background execution, but their UI was reachable only inside main-window tabs. Two pieces of the agent message list also assumed a TanStack router: the provider link in [ErrorBlock](../../../../src/renderer/components/chat/messages/blocks/ErrorBlock.tsx) and fork-source navigation in [agentMessageListAdapter](../../../../src/renderer/pages/agents/messages/agentMessageListAdapter.tsx). A window without a router could not render them safely.

## Decision

### Product contract

- **Entries.** The built-in toolbar action `ask-agent` opens a compose bar. A custom action may bind to an agent and workspace instead of an assistant; it skips the compose bar and sends its template-expanded prompt immediately. Assistant actions keep the action window unchanged.
- **Sessions.** The first send creates one `conversation` session under the chosen agent and workspace, and nothing is created before that. A bound agent goes through `POST /agent-sessions`. `ask-agent` without a bound agent goes through `ai.agent.assistant_session.create`, which takes an optional workspace and recreates Cherry Assistant if it was deleted. The session is an ordinary agent session: it appears in the main session list and can be continued there. If the main process rejects the first message, for example while a backup restore pauses streams or when the workspace or provider is unusable, it saves nothing; the conversation still opens, and the message returns to its composer with the quote so it can be sent again.
- **Message content.** The selection enters the first message as the composer's existing `quote` token, and custom actions reuse the assistant-action `{{text}}` template rule. Nothing else is added: the compose bar shows the source application but does not send it.
- **Shell.** There is no system title-bar band, and the whole window uses the popover surface. The 44px header is drawn by the app. macOS keeps native traffic lights inside it. Windows and Linux draw a minimize button (tooltip "Collapse to capsule") and a close button. The right side holds open in main window, pin, and opacity.
- **Compose bar → conversation.** The compose bar is 560 wide and sized to its content. It contains the selection, an instruction input, and labels naming the bound agent and workspace. Clicking either label opens the selection settings in the main window, where the binding is changed; an open bar follows the change. On the first send it grows downward into the conversation window (default 560×620, minimum 420×480). When the space below is insufficient, it keeps its bottom edge and grows upward. The conversation area reuses the main-window message rendering, tool cards, and approval composer.
- **Follow-up while running.** In this window, sending during a running turn always steers. The message goes straight to the main process, which persists it at once and then either injects it into the current turn or schedules it as the next turn. The composer's renderer-side follow-up queue is disabled here, because closing the window would silently drop queued items. The queue returns once it has a single main-side owner (#22824).
- **Collapse.** The macOS yellow light, Cmd+M, and the Windows/Linux minimize button collapse a started window into a capsule. With auto-close on, blur collapses windows that are starting, running, or awaiting approval. The compose bar cannot collapse; on macOS its yellow light and Cmd+M show as unavailable. Closing never stops a turn; only Stop does.
- **Capsules.** Capsules stack upward from the bottom-right of the work area of the window's display, staying clear of the Dock and taskbar. A capsule whose display is removed shows on the primary display until that display returns. Capsules that wait on the user (an approval, or an answer an MCP server asked for) sit nearest the corner, followed by starting or running, then done or failed; within a rank the earlier collapse comes first. Each capsule shows the agent and its status: running, step N, needs approval, needs input, done, or failed. At most five are shown; the rest fold into "+N", which expands the stack when clicked; Show less folds it back. An expanded stack taller than the work area scrolls within it. Clicking a capsule restores its window to its previous bounds. Hovering reveals the session title and a close button. Approval is never answered from a capsule. Capsules exist only for the current run of the app.
- **Motion.** On macOS the compose bar animates into the conversation window, collapse shrinks the window toward the capsule corner and fades it out before the capsule appears, and restore grows it back from there. Each animation takes 200 ms. Compose-bar height changes while typing are instant. Windows and Linux switch instantly, as does every platform when the OS prefers reduced motion.
- **Open in main window.** This calls `navigation.focus_or_open_conversation`, closes the mini window and its capsule, and carries the unsent draft into the main composer: its text, quotes and other tokens, attachments, and knowledge base choices.

| State | Blur with auto-close | Minimize | Esc | New selection trigger |
|---|---|---|---|---|
| Compose with draft | Keep | Unavailable | Ignored | Open another window |
| Compose, empty | Close | Unavailable | Close | Replace this window |
| Starting or running | Collapse | Collapse | Stop | Open another window |
| Awaiting approval | Collapse | Collapse | Reject a permission request | Open another window |
| Done or failed, no draft | Close | Collapse | Close | Replace this window |
| Done or failed, with draft | Keep | Collapse | Ignored | Open another window |
| Collapsed | — | — | — | Open another window |

A draft is any unsent text, token, or attachment in the window's input. Pinned windows ignore blur, matching the action window, and a new selection trigger never replaces them. Esc leaves a pending question open: its answers are typed into inputs, and a stray Esc would discard them.

### Ownership

|---|---|---|

A collapsed window keeps its own bounds, which are its restore bounds. Publishes one ordered stack per display from `screen` work areas; ordering and placement are pure functions in `selectionCapsuleLayout.ts`. Owns collapse, restore, close from a capsule, and the animations. |
| Agent window | `WindowType.SelectionAgent`, pooled (standby 1, eager warmup), separate from `SelectionAction` | `wm.hide()` collapses without returning the window to the idle pool; only close releases it. It does not inherit the action window's `selection.action_dismissed` hide semantics. |

The compose bar sets `minimizable` to false. |

Without Accessibility access the result is false. |
| Draft hand-off | `navigation.focus_or_open_conversation` and `agentDraftHandoff` | The route takes an optional draft: text, tokens, attachments, and knowledge base ids. In-memory attachments travel as bytes, because IPC cannot carry a `Blob`. The receiving renderer queues the draft for its session. That session's agent composer takes it when it mounts or its tab is shown again, appends it to its own draft, and remounts around the result. Writing the draft cache directly would not work: a composer in a hidden tab does not read the cache again. |
| Selection action data | `SelectionActionItem` and `SelectionActionSchema` (`@shared/types/selection`) | The stored shape has `runner?` (`default`, `assistant`, or `agent`), `agentId?`, and `agentWorkspace?` (`AgentSessionWorkspaceSource`). In compact mode the icon is dimmed and badged instead. | Settings | `SelectionAssistantSettings` | `ask-agent` shows its default agent beside its name and has a settings dialog for default agent and workspace. Agent-bound custom actions show their agent's name. The custom action modal has the agent choice, agent selector, and workspace selector. |

### Navigation decoupling

- `ErrorBlock` opens the provider settings through the host's `navigateToRoute` capability, which both message-list adapters implement as `openRoute(path, query)`. In the main window this opens or focuses the settings tab instead of replacing the conversation tab. In other windows the `openRoute` IPC fallback opens it in the main window. Hosts without the capability show the provider name as plain text.
- Fork-source navigation is an optional host action, `navigateToForkSource`, of `AgentSessionMessages` and its adapter. The agents page supplies its in-place TanStack `navigate`, so its behavior is unchanged. A host that supplies nothing hides the fork-source link. Sessions created from the selection window are never forks.
- `openRoute` stays a module function. Its local DOM-event bridge with IPC fallback already lets each window decide whether it handles routes.

### Delivery

The Spec merged in #22827. Five implementation layers followed:

1. Navigation decoupling (#22981).
2. Selection action data, defaults and upgrade seeder, settings UI, and `programName` plumbing (#22990).
3. Compose bar, session creation, conversation view, and agent availability on the toolbar and in settings (#23065).
4. State rules, open in main window, and draft hand-off (#23089).
5. Capsules and collapse: capsule window type and layout, blur collapse, and the Windows/Linux button (#23097); macOS native interception, animation, and full-screen restore (this layer).

## Alternatives considered

- **Mount the whole agents page with tabs and a router in the selection window.** Rejected. `AgentChatMain` and the layout require the right-pane scope, the page reads tab and route state, and the selection window would carry main-window chrome it cannot use.
- **Wrap the selection window in a memory router.** Rejected. It hides broken navigation: links would navigate an invisible router and do nothing.
- **Convert `openRoute` to dependency injection everywhere.** Deferred. It is already window-injectable through its event bridge. Only in-place view navigation needs a host, and that has one call site.
- **Call `openRoute` directly in `ErrorBlock`.** Rejected in favor of the host capability. It resolves to the same `openRoute` in both adapters, and keeps the link consistent with the block's "Go to settings" button, which already depends on host capabilities.
- **Reuse the `SelectionAction` pooled window type.** Rejected. Its hide event means "dismissed", and its pool assumes one-shot results. Agent windows must survive hidden as capsules.
- **Keep temporary in-memory topics.** Rejected by the product decision that agent work persists as sessions.
- **Create sessions with `ai.agent.session.reuse_or_create`.** Rejected. It can reuse an empty session the main window is showing as a draft, including Cherry Assistant's seeded empty session.
- **One full-display transparent capsule overlay with click-through.** Rejected. `setIgnoreMouseEvents` forwarding is unavailable on Linux, and toggling hit regions is fragile. One window per capsule was also rejected, because it costs a renderer per pill.
- **Capsules at the top-right.** Rejected. macOS notifications slide in there, and maximized Windows and GNOME windows keep their close buttons there.
- **Listen to Electron `minimize` and restore the window.** Rejected. The event is not cancellable, and the Dock animation would flash first.
- **Hide native traffic lights and draw imitations.** Not needed. It was the fallback in case native interception proved infeasible.
- **Electron's animated `setBounds(bounds, true)`.** Rejected. AppKit runs the animated resize synchronously, about 0.2 s per 150 px, which blocks the main process and with it every window's input.
- **Frame-stepped animation on Windows and Linux.** Deferred until hands-on evaluation. Resizing transparent windows frame by frame risks flicker.
- **A selection-specific message presentation (title-style first message, compact step rows).** Deferred until hands-on evaluation of the reused rendering.
- **Agent and workspace selectors in the compose bar.** Rejected after hands-on evaluation. Their popovers do not fit a transparent window sized to its content. The window must grow before a list opens and shrink after it closes, which moves the bar near the bottom of the screen, and native traffic lights draw over any popover that reaches the header. The binding lives in the selection settings, which the labels open.
- **Keep the renderer follow-up queue in this window.** Rejected until #22824. Closing the window would drop queued items silently, and flushing them during close or asking for confirmation would add an asynchronous close path to work around a queue that lives in the wrong owner.
- **Make agent drafts a shared cache tier for the hand-off.** Rejected. It would change draft synchronization for every window to serve one transfer.
- **Hand off only the draft text.** Rejected. Quotes and attachments would vanish when the mini window closes, even though they are what keeps the window open on blur.
- **Append the source application to the first message.** Rejected after hands-on evaluation. The user neither wrote nor configured that line, so it reads as a stray addition to their own message.
- **Report a missing model only inside the window.** Rejected. The user would open a window that cannot run, while the toolbar can already tell whether the agent has a model.
- **Infer the runner from which id is set.** Rejected. It worked while the choice had two states, but with three runners saving must clear the other fields, so switching away and back loses the earlier choice.

## Consequences

- The minimize interception depends on Electron's internal panel class and its button actions. An Electron upgrade must re-check that the yellow light and Cmd+M still collapse agent windows and still minimize every other window.
- MCP prompts go to the window that started the request. A collapsed agent window keeps its prompt hidden; its capsule shows "Needs input" until the window is restored.
- A pooled window that closes returns to its pool without emitting `closed`. An MCP request pending in a window closed from its capsule therefore waits until its deadline.
- `navigation.focus_or_open_conversation` asks renderers about ownership. Agent windows never claim it, so the main window remains the destination.
- A follow-up sent from this window steers at once and cannot be edited, reordered, or removed afterward, unlike queued items in the main window. This is accepted until #22824.
- Each agent window costs a renderer. Pool caps bound idle windows, but every collapsed session keeps its own alive.
- Each display that showed capsules keeps a hidden capsule host for 10 minutes after its last capsule goes. The first collapse after launch, or after those 10 minutes, still waits for a host to boot.
- The first turn pays runtime start-up. Claude Code prewarms per existing session (`ai.agent.session.prewarm`), but this window creates its session on the first send, so that turn cannot be prewarmed. Pi's connection first waits for the agent's MCP tool catalogs. The window and its capsule therefore show a starting state.
- Built-in Cherry Assistant ships without a model. Until agent onboarding assigns one, the `ask-agent` button new users see on the toolbar is disabled with a hint to set a model.
- The toolbar cannot show tooltips. Its window is too small for an in-page tooltip, and on macOS native `title` tooltips do not appear while Cherry Studio is not the active app. Compact mode therefore cannot explain an unavailable agent action on the toolbar; settings carry the cause.
- Over a full-screen app, Cherry Studio leaves the Dock on macOS. macOS keeps a regular app's windows out of another app's full-screen Space, and the IME candidate panel the system opens for this window cannot opt in. While the window is shown over a full-screen app, from the toolbar or from a capsule, Cherry Studio runs as an accessory process: its Dock icon and Cmd+Tab entry disappear until the window hides or closes.
