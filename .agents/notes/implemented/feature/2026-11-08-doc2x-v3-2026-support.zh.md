# Agent Note：Doc2X v3-2026 文档处理支持

Status: implemented

[English](2026-11-08-doc2x-v3-2026-support.md) | 中文

## 问题

Doc2X 文件处理器原先没有为提供商的 v2 和 v3-2026 PDF API 提供可由用户选择的模型契约。导出请求对所有模型都发送 v2 公式字段，v3-2026 响应中的结构化布局数据也无法进入 Markdown 工件路径。因此用户无法选择模型，表格和重复页眉等布局信息会在文档输出中丢失。

这项改动跨越共享处理器偏好设置 schema、渲染器设置界面、主进程远程轮询、任务上下文持久化和提供商响应 schema。同时需要保持现有用户的 v3-2026 预设行为，除非用户明确选择其他模型。

## 决定

文档转 Markdown 能力支持以下 Doc2X 契约：

- `v3-2026` 仍是预设默认值，设置中可以选择 `v2` 或 `v3-2026`。
- `formulaLevel`（0、1 或 2）和 `mergeCrossPageForms` 是可选能力覆盖项。只有 v3-2026 导出请求发送这些字段；v2 保持文档规定的请求格式。
- 选定模型会发送到 preupload。模型和导出选项会在远程轮询中传递，并写入白名单持久化远程状态，因此重启不会悄悄改变进行中任务的导出行为。旧状态缺少这些字段时，使用恢复后的能力配置作为回退。
- 响应 schema 接受 `version`、`inplace_pages`、页面 Markdown 和可扩展的 `layout.blocks` 数据。`page.md` 仍是页面正文主体。布局块会移除标记的样板内容，在结构化重建时保持阅读顺序，有表格时使用 `table_data.html` 替换 Markdown 表格，并在没有 Markdown 回退内容时生成图形 URL。
- v2 和旧响应继续使用现有 ZIP 工件路径。包含结构化布局数据的 v3-2026 响应使用现有 Markdown 工件持久化。
- 保留独立的实时 E2E 脚本，覆盖两种模型的上传、解析轮询、导出轮询和 ZIP 下载。脚本需要 `DOC2X_API_KEY`，手动运行，不作为 CI 测试。

## 考虑过的替代方案

- **完全从布局块重建每个 v3 页面。** 不采用，因为会丢失提供商 Markdown 中的图片和代码；布局应作为增强层。
- **始终发送 v3 导出字段。** 不采用，因为 v2 API 有独立的文档化请求格式，且必须保持既有 v2 行为兼容。
- **把 v2 设为新的默认值。** 不采用，因为已发布的预设默认使用 v3-2026；改变默认值会静默改变现有用户的输出。
- **把实时提供商调用放入常规 Vitest 套件。** 不采用，因为检查需要真实凭据、外部服务可用、长时间轮询和远程工件下载。确定性的单元测试覆盖转换和请求契约，独立脚本覆盖真实提供商契约。

## 后果

用户可以选择 Doc2X 模型和 v3 导出控制，现有显式覆盖项仍然有效。v3 Markdown 路径会移除提供商标记的样板内容，并在可用时保留提供商 Markdown、表格和图形。v2 路径继续返回下载的 ZIP 工件。持久化远程状态只包含提供商任务标识、公有端点、阶段信息和非敏感的 Doc2X 选项；API key 和签名 URL 永不持久化。

提供商新增的 block 字段或类型仍可通过可扩展 schema 解析，但新增语义可能需要后续渲染器决策。实时 E2E 证据依赖提供商可用、有效凭据和公共 PDF fixture。公式与跨页设置可能影响输出质量、提供商成本或延迟；默认值保持现有 v3-2026 行为。
