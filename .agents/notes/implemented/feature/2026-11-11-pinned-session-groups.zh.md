# Agent Note: 固定工作目录和助手分组

Status: implemented

[English](2026-11-11-pinned-session-groups.md) | 中文

## 问题

工作目录分组无法固定，已固定的助手分组仍留在普通助手分区。常用分组需要统一入口，同时保留访问其任务的能力。

## 决策

工作目录实体复用现有固定服务。在工作目录和助手视图中，将已固定分组移到顶部“已固定”分区，并保留展开任务的能力。单独固定的任务独立于分组固定状态，取消固定分组也不会影响它们。已固定的空分组仍然可见。固定和取消固定命令在上下文菜单中独立成区。

## 考虑过的替代方案

在原分区内置顶分组可以保留旧的助手行为，但常用项目仍分散在多个分区。将分组任务平铺到“已固定”会丢失分组身份和展开能力。因此采用用户选择的统一分区方案。

## 影响

删除工作目录时在同一事务中清理其固定记录，并在提交后发送固定数据失效通知，包括空工作目录。现有通用固定表无需结构迁移。分组拖动不能跨越已固定和未固定分区。时间视图仍然只显示单独固定的任务。

## 验证

- Regression — `Sessions.test.tsx`：覆盖固定工作目录和助手分组、空分组、独立固定任务、分区折叠和取消固定后的恢复。
- Regression — `workdirGroupActions.test.tsx`：覆盖固定与取消固定、变更期间禁用操作，以及工作目录不可用时隐藏操作。
- Regression — `workspacePins.test.ts`：使用生产数据库迁移，覆盖工作目录固定记录的创建、移除及删除空工作目录后的清理。
