# Agent Note: 在按需 E2E 中复现对话重负载

Status: implemented

[English](2026-11-26-conversation-performance-e2e.md) | 中文

## 问题

大量工具调用、超长上下文和大图会同时给流式消息和历史列表带来负载。预先写入消息记录无法覆盖完整链路。

## 决策

在 macOS 按需场景中，用 AIMock 模拟模型和 MCP 边界。应用实际发送消息、执行本地 Bash、读取图片、持久化结果并滚动界面。用例以工具落库数量、实际请求内容和滚动位移为通过条件，记录帧间隔用于排查。

独立的 Work 丰富负载场景通过真实运行时生成 120 轮对话，设置四次 48 调用突发，用实际滚轮翻到最早的用户消息，再点击回到底部按钮返回最新回复。短场景继续用于聚焦验证。

## 考虑过的方案

在共享托管 runner 上设固定帧时间门槛会混入 CPU 调度波动。预先写入助手回复会跳过工具调用和流式响应。

## 影响

现有按需控制器可重复运行此负载。回环代理先观测完整图片请求，仅在交给 AIMock 前替换超限请求中的内联图片。测试配置和生成图片均用于一次性压测。

## 验证

- Regression — 本地生产构建验证真实消息输入、工具落库、侧栏和消息区滚动。托管运行单独验证。见[场景和运行说明](../../../../tests/e2e/ondemand/specs/README.md#conversation-performance)。
