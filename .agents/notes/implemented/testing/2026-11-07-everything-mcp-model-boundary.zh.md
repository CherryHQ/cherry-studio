# Agent Note: 在 Everything MCP 回归中控制模型决策

Status: implemented

[English](2026-11-07-everything-mcp-model-boundary.md) | 中文

## 问题

MCP-01 将服务创建、真实工具执行、持久化和重启，与外部模型是否调用指定工具的决策放在同一个用例中。模型延迟与输出格式差异，使产品集成检查产生不确定性。

## 决策

使用共享的本机回环聊天服务，请求应用实际提供的 Everything `get-sum` 工具。测试模型声明函数调用能力和 128k 上下文窗口，让本用例验证直接工具分发。只有收到真实的数字工具结果后，测试服务才返回最终文本。用例保留界面绑定、持久化输入输出断言和重启重连检查。

## 考虑过的替代方案

- 延长超时或自动重试会增加成本，却无法控制模型决策。
- 伪造 MCP 结果会绕过本用例需要保护的集成链路。

## 影响

模型边界可控，Everything 进程、工具执行和应用状态仍然真实。本用例不评价外部模型质量或延迟工具发现；真实服务聊天用例与工具注册表测试分别负责这些契约。临时模型、助手和话题会在清理阶段删除。

## 验证

- Regression — 共享 HTTP 服务的 28 个测试通过，包括两个已安装 OpenAI 适配器在流式和非流式模式下的可执行函数调用响应。
- Regression — 本机连续三轮 MCP-01 分别以 44.3、37.7 和 39.6 秒通过，每轮均执行真实工具并重启应用；定向控制器门禁通过，所拥有的运行资源清理成功。托管双平台验收仍需单独完成。
