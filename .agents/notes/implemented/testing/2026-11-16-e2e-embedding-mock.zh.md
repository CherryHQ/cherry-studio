# Agent Note: E2E 本地嵌入向量夹具

Status: implemented

[English](2026-11-16-e2e-embedding-mock.md) | 中文

## 问题

知识库回归测试与经过认证的按需 QA 依赖外部嵌入服务的 URL、密钥和模型。网络可用性与凭据影响了对应用索引、检索及持久化的检查。

## 决策

`scripts/e2e/regression/embeddingMock.ts` 提供使用空闲端口的本地回环 OpenAI 兼容嵌入端点。回归测试的 worker 持有该服务，应用重启期间服务持续可用；按需 QA 为经过认证的运行持有该服务，并在清理时关闭，包括失败路径。替代 worker 获得新端口时，持久化的回归测试供应商配置会指向新端口。

每条输入分别获得确定性的 64 维向量。已知回归查询与其来源分块共享一个规范化主题，无关输入则保留不同向量。实现复用 aiMock 的响应构造器和确定性向量生成器。未采用内置嵌入夹具处理器，因为该处理器会给整批输入重复返回同一个向量。

两个控制器与工作流均移除嵌入服务环境配置。聊天和 CherryIN 配置保持原有行为。知识库任务仍需要配置的聊天响应，因此不在聊天 mock 任务白名单内。回归测试注解以及按需 QA 的 JSON/Markdown 报告标明嵌入 mock 的边界。

## 备选方案

- 保留外部嵌入凭据：保留供应商集成覆盖，但也保留网络与凭据依赖。
- 返回单个固定向量：无法区分来源分块与无关内容。
- 将所有知识库流量切换到聊天 mock 模式：还需要聊天夹具，并改变另一处边界。

## 影响

这些测试使用合成相似度验证真实应用的索引、检索、持久化与引用，不证明嵌入模型的质量。未识别的按需 QA 文本会获得确定性向量，但没有语义保证。

## 验证

- Regression — 定向测试通过 AI SDK 请求端点，对英文和中文检索夹具比较来源与干扰项在批量、单条请求中的相似度，同时检查无效请求、重复向量的稳定性和监听端口清理。配置测试验证无需外部嵌入凭据。本机 macOS 执行十个知识库 E2E 用例，其中八个通过。K-01 和 MP-66 通过索引、召回及各自的重启检查，随后因配置的聊天 API Key 无效而在聊天回答步骤失败；回答与引用尚未通过验收。运行未提供外部嵌入环境变量，并已清理其持有的 Electron 实例。
