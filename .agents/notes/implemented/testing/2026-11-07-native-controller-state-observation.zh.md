# Agent Note: 以原生状态确认桌面操作

Status: implemented

[English](2026-11-07-native-controller-state-observation.md) | 中文

## 问题

原生自动化失败掩盖了产品结果。Windows 保存脚本超过了命令行长度限制，地址栏输入可能落到其他前台窗口，配置目录也可能在测试进程的退出回调执行前被删除。macOS 时钟控件在不同系统进程间迁移，并增加了分组容器。通知面板的深度优先检查先遍历内容，再找到同级工具栏；托管环境中的时钟查询还消耗了原有十秒进程预算的大部分时间。

控制器还会在等待二十秒后重启仍正常加载的开发渲染器，而托管环境中的冷启动实际约需四十秒。

托管 macOS 镜像构建会卸载通知中心的 launch agent；本轮观察到的运行器最初没有加载该代理。该服务的 plist 文件名与服务标签不同，因此按文件名推断标签再启用，无法恢复实际代理。

Windows Shell 注册也会解析到应用隔离的 `APPDATA`。Programs 目录缺失时 SDK 无法生成快捷方式；即使生成了私有快捷方式，真实 Shell 也无法识别它。

macOS 的 HTTPS 与本地 HTML 文件可以使用不同默认应用。若以 HTTPS 浏览器登记 HTML 预览，就可能无法追踪实际文件处理应用中的标签页。Safari 关闭最后一个标签后，窗口枚举可能保留仍为真值、但远端对象已不存在的引用；JavaScript 空值检查不足以确认原生对象存在。

托管环境中的 Vite 冷启动依赖优化会在用例执行时重载渲染器。阶段步骤通过 `continue-on-error` 隐藏失败，因此步骤结论成功并不能证明用例通过。Windows 恢复对话框会早于 CDP 出现，新控制台进程也可能早于原生句柄就绪。macOS 无障碍快照还可能短暂无法匹配 AX 与 CG 窗口。

## 决策

- 通过标准输入传递 Unicode PowerShell 保存脚本，输入前确认所拥有的对话框及其地址栏焦点。
- 通过原生 Shell 窗口句柄定位可见的 Windows 通知面板，再查询其 UIA 树；隐藏元数据查询产生的控制台。
- 通过所拥有的管道请求测试进程退出，让出事件循环等待退出事件；仅在重新核实进程归属后升级终止方式。
- 在已知系统菜单进程内按无障碍标识查找 macOS 时钟，包括 MenuBarAgent 的分组控件。先检查当前层级，再深入通知或小组件内容；为原生操作保留三十秒预算，并要求面板实际达到打开或关闭状态。
- 权限观察程序仅用于托管 macOS 临时运行器内已初始化的目录，并在应用清理前停止。
- 显示 macOS 窗口后，最多等待六十秒让开发渲染器完成启动，再考虑替换进程；仍在加载不足以证明进程故障。
- 从 plist 读取通知中心服务标签，记录托管 GUI 服务的原状态，在原生检查期间启用，并通过始终执行的步骤恢复原状态。
- 准备隔离的 Windows Programs 目录。以本轮独占名称向真实开始菜单注册 SDK 生成的原始快捷方式，并在发布前写入校验和归属记录。用例与控制器清理仅删除内容未变的所拥有副本。

- 枚举浏览器窗口的基础类型 ID，读取标签前按 ID 重新获取原生引用。读取标签出现窗口缺失错误时，仅在重新枚举 ID 确认窗口消失且没有新增 ID 后跳过。发现新增 ID 表明快照不完整，将阻止退出。ID 仍存在、权限错误或刷新失败时，清理仍失败并保留归属记录。
- 在预览操作前解析所拥有 HTML 探测文件的默认应用，并以该应用固定标签页归属与清理。仅包含网址的登记仍解析 HTTPS 默认应用；不支持的处理应用在打开外部文件前失败。

- 用绝对 HTTPS 请求为 Cache Storage 准备测试数据，使其兼容开发 HTTP 与构建后的 file URL。仅在助手消息中匹配 Agent 总结；用户提示中也包含该标记。
- 分支应用只构建一次；每次启动、重启和独立 smoke 检查均使用 `electron-vite preview --skipBuild`，并清除继承的开发渲染器 URL。
- 保留阶段失败结论，通过显式取消状态条件继续收集后续阶段结果；凭据脱敏后再生成 GitHub 失败注释。
- 仅允许已知托管测试请求者控制支持的文档、浏览器和文件管理应用；保留临时运行器限制，并拒绝其他请求者或目标。
- 在重新验证 CDP 或主进程 inspector 归属后处理主窗口出现前的对话框，同时检查命令与运行器祖先关系。终止 Electron 仍必须确认 CDP 归属。
- macOS 窗口检查出现歧义时最多重试两次；持续歧义仍阻止清理。
- Windows 缺少控制台窗口或句柄无效的错误 6 仅在读取时视为尚未就绪；输入失败仍抛错。探测本轮所拥有的 cmd 候选，按实际可读取的控制台窗口去重，不再假定最外层 Shell 拥有控制台。读写请求重新核实 PID 与创建时间。
- Windows 清理期间，仅 `ESRCH` 能证明进程在身份查询期间已经退出；将该身份移出终止集合。权限与未知存活状态错误仍阻止清理。记录生命周期阶段和安全身份元数据，不记录无关进程的命令行。
- macOS 进程归属查询与运行器退出发生竞态时，在最多等待现有进程组自然清空的八秒前后，均要求存活状态查询结果明确，随后重新核实归属与端口。SIGKILL 升级拒绝归属时也采用相同的有界观察。运行器退出期间可能短暂可见，观察不授予向未知存活进程发送信号的权限。权限不足与未知存活状态错误仍阻止清理。
- 在失败用例清理移除界面前，保存 HTML 代码模式几何信息和启动窗口状态。诊断仅包含所拥有窗口及内部路由，不记录标题或外部 URL。
- Windows 控制台读取范围覆盖光标与可见区域底部中较低的一行，且不超过缓冲区末尾。原生测试先将光标移至状态栏上方，再标记已就绪。
- CLI 业务提示正文仅输入一次，确认完整回显后单独发送 Return。Windows 仅输入正文时既不发送 Enter，也不发送占位 NUL 事件。外部浏览器预览后恢复所拥有主窗口的焦点，确认代码模式后再检查完整源码。
- macOS CLI 输入前，要求所拥有 Terminal 窗口及选中 tty 匹配，并最多等待五秒确认该窗口获得前台焦点。只发送一次操作；拒绝时仅记录安全的窗口、tty、PID 和按键元数据，不记录 prompt 参数或终端正文。
- Windows 原生确认按钮按语义 Button 控件类型、旧版 Button 类或 TaskDialog 的 CCPushButton 类匹配，同时要求名称精确匹配及所拥有进程 ID。本轮 TaskDialog 提供程序将 OK 控件暴露为 CCPushButton/Pane；保留精确对话框身份和单次调用。
- 分别保留 Windows 恢复后的窗口关闭与原生确认结果。为所拥有进程记录有界、脱敏的原生匹配与调用元数据，诊断快照不代替实际匹配。限制失败后的渲染器清理等待，并同时保留原始与清理错误。
- macOS 保存失败时，记录所拥有面板的 AX PID/role、前台应用身份及激活/raise 结果，不记录标题、内容或输入值。保留原前台归属检查。原生测试覆盖全部 BrowserWindow 隐藏后独立保存的截图保存场景。
- 截图测试使用专用 `CommandOrControl+Alt+Shift+K` 绑定，避开[飞书默认截图绑定](https://www.feishu.cn/hc/zh-CN/articles/258254899042-%E6%8F%90%E5%8F%96%E5%9B%BE%E7%89%87%E4%B8%AD%E7%9A%84%E6%96%87%E5%AD%97)。每次真实触发前，检查所拥有 Electron 进程的 `globalShortcut.isRegistered()` 结果；未注册时不发送按键。遮罩取消、原偏好恢复和所拥有助手删除分别尝试，失败均保留。
- 等待保存面板状态及执行严格前台 PID 检查前，推进 AppKit 主 RunLoop。[Apple 的应用状态契约](https://developer.apple.com/documentation/appkit/nsrunningapplication?language=objc) 要求通过 RunLoop 迭代刷新动态观察值；激活请求被接受本身不能证明键盘归属。每轮 MP-128 使用独立助手和新会话，结束后只删除该助手及其话题。
- MP-17 的 Send 使用 Playwright 的 `noWaitAfter` 选项，随后验证实际错误详情、Retry 和恢复结果。MP-92 在失败清理删除 provider 前保留模型选择器状态与遮罩截图。

## 考虑过的替代方案

- 单纯增加超时无法修复错误窗口输入、超长命令行或进程归属竞态。
- 只接受按键发送或通知历史记录，无法证明可见通知能够被激活。
- 重置开发者权限或按名称终止应用，会越过本轮测试的资源归属边界。
- 取消配置隔离，会使测试接触开发者的凭据与配置。

## 影响

适配器保留平台差异；无法确认原生状态时仍然失败。通知用例继续要求点击真实系统通知并返回已完成的话题。本机执行不会运行托管权限观察程序。
