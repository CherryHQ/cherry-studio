# Agent Note: 在运行中的 Bash 命令旁显示观测到的耗时

Status: implemented

[English](2026-11-13-bash-card-observed-elapsed.md) | 中文

## Problem

一条没有输出的 Bash 调用与卡死的回合无法区分。回复级的进程计时器衡量的是整条回复，无法把等待归因到某条
命令，而 Bash 卡片标题只显示一个状态词。促成这次修改的报告里出现了单条命令内的两段数分钟间隔。仅靠默认
时限覆盖不了这种情况：运行时只在调用未指定超时时间时才应用 120 秒默认值，显式指定的更长时限依然有效，因此
静默命令可能合法地运行数分钟，并且仍然需要看起来是活的。

## Decision

Bash 卡片标题在命令执行期间显示耗时标签，每秒更新一次，位于折叠状态的标题内，无需展开。观测从调用进入执行态
时开始，既不在参数流式期间，也不在等待审批期间。该标签只是观测值：从挂载时刻开始计时，因此重新挂载一个仍在
运行的卡片会重新开始。不从运行时传播执行时间戳。

## Alternatives considered

- 传播开始时间戳可以让重新挂载更准确，但运行时的开始事件不携带时间戳：需要自己捕获并经投影传递，这会为报告
  未提出的场景引入持久化状态。
- 百分比或进度条属于臆造信息；静默命令没有可度量的进度。
- 复用回复级进程计时器会把等待归因到整条回复，而不是这条命令。
- 因为输出静默就告警，会打断正常的静默工作；时限已经对失控命令做了约束。

## Consequences

静默命令可见地存活，并且可以归因到单次调用。计数器如实说明自身局限：重新挂载后从零开始，而不是谎称保持命令
的真实时长。终态卡片与历史卡片不携带走动中的计时器。同一行还带来两点布局事实：渲染命令预览的工具标题会把活动
短语保持为固有宽度，让预览被截断；状态与耗时的簇也保持自身固有宽度，只有当行宽小于簇宽时才换行。低于该宽度
——即比簇宽加上行内间距还窄——标题的溢出裁剪仍会裁掉簇，而不是压缩耗时数值。

## Verification

- AC1 — `AgentExecutionTimeline.test.tsx`：静默的执行中调用显示走动中的标签，初步输出不会重置它，终态移除它，两条调用各自独立计时，重新挂载按设计重新开始观测。
- AC2 — 使用长命令的真实 Electron 运行：标题行测得 540 px 宽、右边缘位于 960 px 窗口内的 x=930，耗时标签绘制在 x=916…930；改动前该行为 650 px 宽、右边缘 x=1040，标签落在视口之外。
- AC3 — `piShellTimeout.test.ts`：在显式 600 秒时限下中止真实的 shell 进程树，会以 `Command aborted` 在收敛预算内结束，不留下存活的子进程 PID，也不产生等待后的哨兵输出。
- Regression — `MessageProcessGroup`、`PlaceholderBlock`、`toolResponse` 与 `AgentToolRenderer` 套件保持通过；本次改动调整的是工具标题的间距，而不是这些套件所断言的取值。
