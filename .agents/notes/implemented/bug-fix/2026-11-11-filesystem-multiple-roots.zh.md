# Agent Note: 支持所有已配置的 filesystem MCP 根目录

Status: implemented

[English](2026-11-11-filesystem-multiple-roots.md) | 中文

## 问题

内置 filesystem MCP 工厂此前只选择第一个目录参数。因此，即使服务器配置了多个目录，也会拒绝后续目录内的绝对路径。传递完整目录列表需要明确的路径包含规则，确保恢复访问时不会放行配置目录以外的路径。

## 决策

`resolveFilesystemBaseDirs` 保留非空 `WORKSPACE_ROOT` 作为唯一根目录。否则，它会去掉目录参数两端的空白、移除空项和重复项，并保留顺序。服务器展开主目录路径，保留绝对根目录，再进行规范化和去重。如果没有剩余目录，则使用 `application.getPath('feature.mcp.workspace')`。它会尝试创建每个根目录，并记录创建失败。

全部七个文件系统工具接收相同的根目录列表。相对路径基于第一个有效根目录解析；未指定路径的列举和搜索也使用该目录。调用方使用绝对路径访问其他根目录，不会跨根目录搜索相对文件名。

`validatePath` 使用现有的缺失路径处理逻辑，对请求路径和每个根目录进行规范化，仅当路径等于至少一个规范化根目录或位于其中时才允许访问。比较保持精确匹配，不做大小写折叠。符号链接目标若位于所有允许根目录之外，则拒绝访问；若目标位于另一个允许根目录内，则属于配置的访问范围。此变更扩展现有路径包含判断，不以公共祖先目录或词法前缀检查替代它。

## 考虑过的替代方案

- 只保留第一个参数：其他配置目录仍会出现已报告的访问失败。
- 允许所有根目录的公共祖先：会暴露用户未配置的同级目录。
- 在所有根目录中搜索相对文件名：重名文件会产生歧义，也会改变现有的首根目录行为。

## 影响

读取和修改工具现在可访问额外配置的根目录。现有单根目录调用和环境变量优先级仍然受支持。默认搜索从第一个根目录开始，不会分别遍历每个配置根目录；跟随符号链接时仍可能访问另一个允许根目录。read、write、edit 和 delete 的相对文件标签使用词法上包含该文件的最具体配置根目录；标签不参与授权检查。

路径规范化与文件操作仍是分离的步骤。此变更不保证防止验证与使用之间发生的并发文件系统替换，也不新增数据库迁移或持久化配置格式。

## 验证

- Regression — 静态检查 `factory.ts`、`filesystem/config.ts`、`filesystem/server.ts`、`filesystem/types.ts` 及全部七个工具处理器，确认配置传递到共享路径包含检查，默认路径仍使用第一个根目录。

- Regression — `pnpm exec vitest run --project main src/main/ai/mcp/servers/filesystem/__tests__/filesystem.test.ts src/main/utils/file/__tests__/path.test.ts`：在 macOS、Node 24.12.0 下，57 项通过，1 项跳过。覆盖额外根目录的读取、写入和列举、首根目录相对路径查找、根目录外访问拒绝，以及既有单根目录路径包含和路径规范化场景。

这些本地测试不能证明打包后的 Electron 或 Windows 行为。搜索测试包含模拟的 ripgrep 输出，未验证真实的 ripgrep 二进制程序。
