# Agent Note: FunASR 兼容版解码器与已有安装

Status: implemented

[English](2026-10-31-funasr-compat-decoder.md) | 中文

## 问题

[Issue #23110](https://github.com/CherryHQ/cherry-studio/issues/23110) 报告了旧版 FunASR Nano int8 解码器出现中文重复循环和幻觉文本的问题。[上游修复](https://github.com/k2-fsa/sherpa-onnx/pull/3493) 切换到 `llm_int8_compat/llm.int8.onnx`。只更新目录中的 URL 和校验值，会让已有安装继续使用旧权重：就绪检查只判断文件存在和最小大小，而两个解码器文件都超过该下限。

## 决策

模型目录固定使用 ModelScope 版本 `ce0975f2a7a8ad6441223db59ce6e1362295ddfe` 的兼容版解码器，安装文件名为 `llm.int8.compat.onnx`。模型包 ID 保持不变。已有安装只需补充该解码器；仅有旧文件时推理拒绝加载，修复后解析到新文件名。下载哈希校验和原子发布仍由现有获取层负责。

旧 Hugging Face 版本仍提供不兼容的文件，因此该文件的来源排除了它及其镜像。模型包的其他文件保留已验证的来源。[本地模型](../../../../docs/references/ai/local-models.md) 负责描述安装行为。

## 考虑过的替代方案

- 只修改 URL 和摘要：已有安装仍通过最小大小检查，继续加载旧解码器。
- 每次查询就绪状态时计算哈希：给反复执行的状态检查增加约 600 MB 的读取，而独立文件名已经可以区分所需版本。
- 替换整个模型包或切换到 FP16：会无谓地重新下载未变更文件，或改变模型的资源需求。
- 扫描时删除旧解码器：把读取路径变成破坏性迁移逻辑，并可能与原生运行时持有的文件句柄冲突。

## 影响

已有旧版安装的用户会看到现有的安装不完整状态，可以重试模型下载。只下载约 600 MB 的解码器。旧解码器不再使用，但仍占用约 600 MB，直到移除模型时删除整个模型包根目录。下载失败时不会回退到不兼容权重。该解码器只有一个已验证的下载来源。量化兼容性与 KV 窗口分段预算仍是两项独立修复。

## 验证

- Regression — `src/main/ai/localModel/installation/__tests__/funasrUpgrade.test.ts`：目录变更前四个用例全部失败；真实文件系统扫描拒绝仅有旧文件或新文件不完整的安装，只请求解码器，并在两代文件共存时解析到兼容版路径。目录检查拒绝旧摘要及来源。
- Regression — 下载的 600,339,316 字节解码器的 SHA-256 与 `7f0c5a508b41474b1b1ec1cdbdefafd2cf8b3642c6915a0a425265b7b7d2c960` 一致。
- 手动 Electron 验证 — 隔离配置使用未变更的模型文件，并以稀疏旧解码器文件构造就绪检查场景，界面显示安装不完整。重试后实际下载兼容版解码器，模型卡片变为已就绪。
- 手动 macOS arm64 转写 — 生产 ASR 服务和工具进程正确转写了官方数学与生物化学样本。远场语音样本仍有识别错误，但没有重复循环。本次修复不新增 E2E 测试。

Windows AVX2 转写验收需要受影响的硬件；文件系统和目录检查不能证明该 CPU 上的识别准确性。
