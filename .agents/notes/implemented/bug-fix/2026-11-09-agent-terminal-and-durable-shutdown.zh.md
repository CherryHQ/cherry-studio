# Agent Note: 暂存回复失败与 Durable 关闭

Status: implemented

[English](2026-11-09-agent-terminal-and-durable-shutdown.md) | 中文

## 问题

回复仍有后台结果未交付时，Main 会暂存原生执行的中间成功。如果一直把第一次成功作为最终结果，后续错误或暂停就会被掩盖。

Pi Durable 共享行为会等待提交的输入被消费。有序关闭会先等待 adapter 已跟踪的调用，再关闭原生 Harness，因此子线程等待正在运行的任务时，关闭流程可能始终无法进入原生取消阶段。另外，如果等到 `native.closed` 才报告来源丢失，致命存储故障就会一直等到工具清理完成才被通知。

## 决策

尚未结算的成功只是暂定结果。后续错误或暂停可以替换它，第一个非成功结果保持权威。现有持久化与结算屏障继续拒绝迟到的终态事件。

共享行为复用已有接纳 Promise，完成原生输入接纳后，仅中止本地消费等待，不中止原生提交。无法确定的接纳回执仍为 unknown，关闭时绝不重新发送输入。正常关闭继续按既有顺序排空已接纳的关联读取、最终观察和归档。

adapter 订阅 SDK 已公开的关闭通知。意外原生关闭会立即封闭访问并以 `source-lost` 关闭观察流，原生清理独立继续。主动关闭仍在最终交付后关闭观察流。不增加 SDK 补丁、额外队列或服务。

## 考虑过的替代方案

- 保留第一个终态：中间成功会掩盖后续失败。
- 在等待所有调用之前关闭原生 Harness：已接纳的关联读取与最终归档交付可能失去存储来源。
- 取消排队提交或在关闭后重发：取消改变已接纳的工作，重发则可能重复执行。
- 只在 `native.closed` 后通知：清理被阻塞时，消费者会继续等待已经失败的来源。

## 影响

故障在存储清理完成前就能传递到产品回复。本地输入等待可以以 unknown/closed 回执结束，同时原始原生输入仍然排队。调用方应核对已有原生事实，不应据此推断取消或重新提交。这些保证覆盖有序关闭与致命来源通知，不证明断电恢复或外部工具副作用恰好执行一次。

## 验证

- Regression — `agentSessionRuntimeState.test.ts`：暂存成功后收到错误或暂停时，以非成功结果结算；迟到成功和结果排空不会重复结算。修复前两种情况都失败。
- Regression — `shutdown.test.ts`：共享行为子线程生成被阻塞时，真实原生 SQLite Harness 可以关闭；重新打开后，原始 steer 仍排队且只有一个原生请求身份。修复前关闭无法完成。
- Regression — `relations.test.ts`：真实 SDK 存储扫描故障发生后，即使工具取消清理被阻塞，也会关闭观察与待决子线程访问。修复前通知会等待清理；正常关闭仍交付已接纳的关联。
- Regression — Electron 与 LongCat AI / LongCat-2.5：真实后台子线程使父回复暂存成功；注入运行时错误后，同一助手消息以错误落盘，输入框结束等待。关闭另一条带有排队 steer 的真实后台子线程后，原生排队记录与一条产品输入均保留。
- Regression — Electron 原生故障注入：阻塞 `beforeClose` 时，运行中的产品会话会在原生清理完成前将助手消息以错误落盘，并使输入框结束等待。桌面注入针对原生故障入口；上面的存储扫描回归覆盖真实 SDK 存储边界。

定向验证通过 262 项 Main 测试与 81 项 Durable 测试，另有三项 Durable 已声明跳过。Node 与包类型检查、包构建均通过。Electron 证据位于 `.context/cherry-electron-dev/terminal-shutdown/`，故障注入与真实供应商请求分别记录。
