# Agent Note: 保留排队 Chat 消息的续接路径

Status: implemented

[English](2026-11-19-queued-chat-continuation.md) | 中文

## 问题

在同一条答复生成时排入的后续消息会捕获同一个父节点。后续发送可能从该节点分叉，导致中间的排队对话在界面消失，模型请求也缺少这些内容。队列暂停时，已经被接受的答复还可能被删除。

## 决策

普通 Chat 接受一条排队发送后，推进捕获了相同活动路径锚点的待发项。发送回执携带 SQLite 写入事务选定的答复 ID。已经从队列取出编辑的匹配项也随之推进。显式预留分支保留各自的目标。

已选答复仍存在时，排队消息从该答复续接。答复被删除后，事务可以从同一话题中该轮仍存活的用户问题继续。该问题也不可用时，按原有失败流程保留队列草稿。

## 考虑过的替代方案

- 读取话题当前活动节点会让之后的分支选择改变已经排队的草稿目标。
- 删除后改用另一个模型的答复会悄悄改变所选上下文。原用户问题是这些答复共享的存活节点。

## 影响

连续排队保留先前轮次的上下文，暂停后另开分支也能保持原队列路径。删除已选答复时保留同组其他答复。待发送项从存活的用户问题继续，请求不带其他答复。Work 保留现有提交契约。

## 验证

- Regression — `PersistentChatContextProvider.test.ts` 验证另选分支或删除答复后的请求历史和持久化父节点，以及两个锚点均不可用时拒绝写入。
- Regression — `useFollowupQueue.test.ts` 验证接受发送后更新编辑返回的草稿，并保留独立预留分支。
- Regression — `chatQueuedFollowupsContext.test.ts` 在隔离 Electron 中用本机模型服务验证连续四轮，以及另开分支后恢复队列。
