# Agent Note: 保留 Claude Code 退出时的捕获证据，避免暴露 stderr

Status: implemented

[English](2026-11-07-claude-code-exit-capture-visibility.md) | 中文

## 问题

Issue #23676 报告 Claude Code 进程以代码 3 退出，而 Work 只显示通用错误。日志能够证明进程退出、诊断参考号以及原因未识别的分类，但不能证明捕获的 stderr 尾部为空，还是包含分类器无法识别的文本。因此，分诊中 stderr“显然为空”的说法并未得到证实。

捕获的尾部可能包含私人路径、凭据或其他用户内容。分类器未识别原因，不足以成为披露这些内容的依据；代码 3 也没有能够确定根本原因的已记录含义。

## 决策

主进程根据用于分类的、去除首尾空白的尾部记录不含内容的布尔值 `stderrCaptured`。进程失败日志携带该布尔值；规范化错误通过序列化和 IPC 传递 `processStderrCaptured`；渲染进程将其呈现为 `stderrCaptured`。原始尾部仅保留在进程诊断和分类内部，不进入规范化错误、日志或 IPC 载荷。

只有分类为 `unknown`、退出代码为数值 3、诊断参考号非空且具有显式布尔值的 Claude Code 未识别原因退出，才使用进程专属标题。说明保留退出代码和参考号，并区分未捕获到非空输出与捕获到输出但无法确定原因。这表述的是捕获证据，而非代码 3 的含义。两种说明都建议重试前检查已完成的工作，并在再次失败时报告代码和参考号。

未识别原因的说明不再使用三行截断，以确保捕获证据和恢复建议可读。已识别分类的说明保留现有截断和标题。

## 考虑过的替代方案

- 记录经过脱敏的 stderr 尾部：拒绝，因为没有能够证明对任意诊断文本都安全的脱敏器。`redactSecretText` 会保留私人路径和独立令牌；中央日志服务不会仅因字段名为 `stderrTail` 就自动对其脱敏。
- 将标题和捕获建议推广到所有未识别原因的退出：暂缓，因为这需要另行决定范围。
- 为退出代码 3 编造特定含义：拒绝，因为没有已记录的退出代码契约能够确立该含义。
- 仅在日志中保留捕获证据：拒绝，因为 #23676 报告的通用 UI 仍会存在。

## 影响

缺少该布尔值的旧载荷保留通用标题。代码 1 和 3221226505、进程启动失败以及已识别的 auth/quota/MCP 分类保留现有呈现和导航行为。该布尔值描述的是捕获并去除首尾空白后的尾部，不保证子进程未产生 stderr，也不保证完整捕获了其全部输出。

#22418 负责 session-id、指纹和重置行为；本修复不改变这些决策。各语言翻译及本中文说明由机器编写，需要母语使用者审校。
