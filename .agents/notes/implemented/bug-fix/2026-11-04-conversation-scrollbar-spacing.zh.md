# Agent Note: 让对话间距不受原生滚动条占位影响

Status: implemented

[English](2026-11-04-conversation-scrollbar-spacing.md) | 中文

## 问题

对话列表同时使用 `scrollbar-color` 和 WebKit 滚动条样式。当标准滚动条属性生效时，Blink 会忽略 WebKit 样式，因此配置的 6px 宽度并不能保证占位也是 6px。随后由平台选择的滚动条模式决定是否扣除视口空间。在 `scrollbar-gutter: stable` 下，透明的占位式滚动条仍会预留空间，覆盖式滚动条则不会。因此，相同的列表内边距会在不同环境中产生不同的可用行宽。

## 决策

UI 包提供基于 Radix 的 `ScrollArea`，使用原生滚动视口和覆盖绘制的纯色滑块。悬停时滑块变宽，但不改变视口尺寸。Radix 负责指针拖动与滚动条显隐，CSS 负责退出动画。资源列表移除重复的滚动条渐变和渐隐计时器。

`DynamicVirtualList` 的内部滚动统一使用 UI 滚动区域，ref 指向原生滚动视口。可排序和不可排序的资源列表都保留根节点负 8px 外边距和视口 8px 内边距。滚动条位于面板边缘，列表行的留白保持一致。

## 考虑过的替代方案

- 修改操作系统偏好：会影响其他应用，且没有修复依赖平台的布局。
- 强制固定 WebKit 滚动条宽度：会改变原生悬停行为，并且需要禁用标准颜色属性。
- 按实测占位扩宽原生滚动容器：虽然能对齐列表行，却会在面板边界裁切滚动条。
- 自行实现指针拖动：重复实现成熟基础组件已有的交互处理。

## 影响

资源列表行不再依赖操作系统原生滚动条的占位。滑块保留纯色外观和悬停变宽效果，不使用渐变。UI 包新增 Radix Scroll Area 依赖。原生滚动、虚拟列表测量和 listbox 键盘处理继续使用同一个视口元素。不需要设置迁移或用户操作。

UI 包常规类型检查对未修改的 Markdown CSS 导入报告 TS2882；仅关闭副作用导入检查后通过。尚未验证原生 Windows 实机、操作系统滚动条模式切换和打包版本。

## 验证

- Regression — 五个定向 renderer 测试文件的 157 个测试通过，覆盖资源列表、实体操作和虚拟列表消费者。
- Regression — 隔离的 macOS Electron 验证了滚轮、滑块拖动、纯色悬停变宽、渐隐中间透明度和稳定行宽；200px 和 360px 面板保留左侧 6px、右侧含边框 6.5px 留白，没有横向溢出。
- Regression — 恢复原有布局配对后，Electron 实测悬停滑块的右侧距面板边缘为 0.5px。
- Regression — Web 类型检查、定向 lint 和改动文件格式检查通过；现有用户配置和操作系统偏好均未改动。
