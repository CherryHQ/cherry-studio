# Agent Note: 持久化存储目录冲突

Status: implemented

[English](2026-11-13-durable-store-directory-collision.md) | 中文

## 问题

目录占据创建中后端预留的 SQLite 文件名时，会阻止持久化轮次启动。`EEXIST` 和 `EISDIR` 不能确定占用项类型。缺少专用身份标识的存储错误可能显示为网络中断。

## 决策

仅针对创建中的后端，发布器在初次 `EEXIST` 或 `EISDIR` 后通过 `lstat` 确认真实目录，并排除符号链接。它将目录移入唯一的同级隔离容器，然后对同一个排他链接重试一次。隔离内容予以保留，绝不删除或自动还原。后端 ID 和定位信息保持不变。

其他 errno 值绝不授权修改占用项。对于观察到的普通文件（无论有效与否）、符号链接及其目标、非创建中的占用项以及重试胜出文件，绝不主动移动、删除、覆盖或重新标记。重试 `EEXIST` 进入严格标记协调。包括 `EEXIST` 在内的隔离故障均为终止性错误。存储错误保留原生诊断信息并获得本地化提示；身份及绑定错误保留现有行为。

## 考虑过的替代方案

递归删除会丢失未知内容。固定备份会发生冲突。更改定位信息需要协调元数据。复制回退无法保留排他且完成初始化后才发布的保证。这些方案均未采用。

## 后果

隔离项会持续积累，须另行检查和管理。日志标明保留路径及终止操作。暂存清理不会掩盖主要错误。初始化和会话关闭先于发布。

`lstat` 加 `rename` 并非原子操作：外部写入者可在重命名前替换目录。这无法保证在该竞态下绝对不会移动文件。
