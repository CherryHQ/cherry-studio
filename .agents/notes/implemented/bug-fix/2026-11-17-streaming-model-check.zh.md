# Agent Note: 模型检测使用已声明的流式能力

Status: implemented

[English](2026-11-17-streaming-model-check.md) | 中文

## 问题

文本模型检测一直使用非流式生成。代理即使能返回有效流，也可能检测失败，而流式客户端正常。仍需验证响应本身：HTTP 成功或首段文本不足以确认模型响应完整结束。Issue #22889 触发了此次调查，报告者的原始代理响应仍未取得。

## 决策

文本检测在模型已有 supportsStreaming 标记为 true 时使用流式，其余保留非流式。复用正常的服务商、凭据、参数和用量处理。内部 Agent 聚合模式消费完整流，仅接受非空文本以及 stop 或 length 终态。错误、空输出、终态不完整和取消均判失败。

默认 15 秒期限覆盖整个检测，包括持续产生内容的流。检测结束时终止内部控制器，释放尚未结束的传输。IPC 仍返回延迟值。设置、渲染进程取消、非文本检测和 Ollama 专用检测保留现有行为。

## 考虑过的替代方案

- 非流式解析失败后重试流式，可能重复请求并掩盖端点不匹配。
- 首段文本到达就判成功，会遗漏后续错误，并把延迟含义改为首个 token 耗时。
- 增加独立的流式与非流式开关，会扩大本次兼容修复的界面范围。

## 影响

已保存的模型能力决定检测协议，检测不会自动识别或改写该能力。延迟仍为完整响应耗时。流式检测不创建聊天历史。合成代理用例通过，不等于确认原报告的故障原因。
