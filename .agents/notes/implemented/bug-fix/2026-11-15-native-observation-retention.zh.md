# Agent Note: 限制原生观察历史的内存保留

Status: implemented

[English](2026-11-15-native-observation-retention.md) | 中文

## Problem

包含大量图片的 Durable 任务在[追踪修复](2026-11-14-agent-trace-memory-recovery.md)后仍会耗尽主进程内存。原生观察者可以积压 100 份完整历史快照才触发普通溢出恢复。每份快照和捕获帧都会被复制，慢消费者因此保留重复图片。Durable 还会为了读取输入或保留发布状态复制完整快照。

合成实验使用预览版 ThreadFeed，阻塞一个消费者后将同一份 2 MiB 图片快照发布 40 次。GC 后保留堆内存增加约 80 MiB，几乎全部位于大对象区。这证明存在保留放大机制；事故 dump 没有直接标识保留堆的具体所有者。

Claude 的配对队列没有经过 ThreadFeed 观察接口。只共享字符串，仍会在立即生成的恢复帧中重复复制全部容器。阻塞观察者，放入 16,000 个工具结果文本块，再发布 40 条控制事实，会在触发条数限制前突破 16 MiB 新增堆预算。

## Decision

即使观察队列已排空，消费者仍保留完整基线；通过序列化深复制，会在 feed、观察者和产品投影间重复分配不可变的图片字符串。将已有的 Claude 历史复制器复用于公共运行时：复制可变容器，保留普通对象的循环引用，共用不可变字符串。非 JSON 值继续使用原生复制。feed 快照、捕获元数据和发生变化的产品消息部分使用该方式，消费者修改隔离和完整载荷保持不变。

保留已有的修改隔离、异步交付、游标屏障、关键帧捕获和条数限制。为每个观察者增加保守估算的 16 MiB 待交付大小预算，不使用 JSON 序列化计量。不可变交付记录的估算会被缓存。大小压力复用已有的 gap / 当前快照恢复路径，并按顺序保留带发布时元数据的关键帧。

允许一份完整的超大帧，尚未启动的观察者也保留首份基线。因此恢复期间的基线、关键帧和最新完整状态可能超过名义预算；限制针对重复的过期大快照，不裁剪单次会话。关键帧积压超过条数或大小许可时明确报告 overflow 和 source-lost，不静默丢弃完成事实。首个回调前发生关闭时仍先交付基线。

ThreadFeed 提供隔离的纯状态视图，供 Durable 查找输入和保留发布状态使用。它不包含消息；完整快照读取和模型历史保持不变。此修复不重发或压缩任务。

Claude 在发布时保留已独立持有的归一化版本和原生元数据，到交付时才复制容器。配对队列只计量额外保留的对象图，排除当前权威基线，共享对象按身份计量一次。保留 16 MiB 限制和单份完整超大帧例外。缓存不可变对象的大小结构，不保留已丢弃的对象图。不重复计量未变历史，也不用最新状态配对旧控制事实。

Claude 关键控制压力无法恢复时，只关闭所属原生执行进程，并在堵塞的观察者之外通知桌面。桌面清空待发送输入，将回复标为失败，再使用已有的会话关闭屏障。原生退出未确认或写入未排空时保留失败态，阻止新建替代连接。其他执行进程仍可使用；普通停止订阅和回调异常不会取消执行。

## Alternatives considered

- 提高 V8 堆上限：按条数限制的多 MiB 快照在实际使用中仍可能无限增长。
- 与消费者共享可修改的正文：破坏观察者和发布者隔离。
- 丢弃终态或裁剪图片历史：丢失费用和完成事实，或改变模型可见数据。
- 只增加 Main 追踪上限：原生观察独立于追踪存在。

## Consequences

大历史的慢观察者更早恢复。不可恢复的关键帧大小压力可能在旧条数限制之前关闭观察；这会明确报告缺口，不会报告成功完成。重新打开原生会话仍可读取完整最新状态。磁盘历史和模型输入保持不变。

## Verification

- Regression — `packages/agent-runtime/tests/observation.test.ts`：在 100 条事件之前按大小恢复，快观察者仍能前进，终态元数据顺序和 drain 屏障得到保留，超大关键帧积压会明确关闭。最先新增的三个用例在修复前失败。
- Regression — `packages/agent-runtime/tests/observation.test.ts`：未启动的观察者先收到基线再收到 source-lost；超大最新快照保持完整；纯状态读取隔离修改且不携带历史消息。
- Regression — 合成 ThreadFeed 实验：同一份 2 MiB / 40 次发布场景，修复后 GC 后额外保留约 2 MiB，修复前约 80 MiB。不涉及用户数据、网络或工具。
- Regression — `observation.test.ts` 与 `MessageProjection.test.ts`：十二个隔离消费者保留完整 4 MiB 图片字符串，GC 后新增堆内存低于 16 MiB；容器复制修复前分别保留约 52 MiB 和 48 MiB。`cloneHistoryData.test.ts` 验证循环引用，隔离数组、类型化数组、日期和错误原因；函数和 Symbol 载荷仍被拒绝。
- Regression — Claude `observation.test.ts`：16,000 块工具结果积压 40 条控制事实，新增堆低于 16 MiB，且不关闭观察；字节超限在消费者放行前报告；恢复保留发布时内容、用量身份和修改隔离。内存和提前超限两个用例在父版本失败。
- Regression — Claude `runtime.test.ts`：致命交付压力关闭所属原生执行进程，拒绝新输入，另一执行进程仍接受输入。
- Regression — `desktopRuntime.integration.test.ts` 与 `AgentSessionRuntimeService.handoff.test.ts`：桌面在投影消费者放行前收到致命错误；排队输入不重发，会话在关闭完成前保持不可用。

原始负载下的 Windows 安装包验收仍待完成；本地内存实验不能证明所有可能的 OOM 均已消除。
