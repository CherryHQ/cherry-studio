# Agent Note: Pi 压缩上下文预算

Status: implemented

[English](2026-10-21-pi-compaction-context-budget.md) | 中文

## 问题

Pi 按字符估算历史，可能低估小上下文模型的多语言文本和工具输出，默认保留的尾部也可能使压缩请求过大。模型目录中的输出上限如果等于上下文大小，预留输出还会占满对话空间。桌面 Pi 通过原生模型请求生成摘要，因此保护措施必须保留原生请求计数和用量归属。

## 决策

Cherry 将目录输出预留限制在上下文的四分之一。小上下文提前压缩并保留更短尾部；至少 100,000 token 的上下文保留默认 20,000-token 尾部。每个模型的网关绑定提供这些设置。行为子会话可覆盖父会话的数值压缩设置，摘要执行仍由 Pi 适配器持有。

对于启用行为适配器且上下文小于 100,000 token 的 Pi 会话，原生压缩扩展限制摘要输入和输出。扩展合并准备好的历史与轮次前缀，调用会话当前的原生流，保留请求计数、会话标识和用量归属。每次获准的小上下文摘要最多发起一次模型请求。溢出、不成功响应和取消直接失败，不重试，也不回退到原生摘要器。大上下文保留 Pi 原生摘要，可能分别为历史与轮次前缀发起请求，每次请求均计数。网关路由和凭证不变，成功响应的用量用于摘要统计，网关仍是供应商计费的唯一写入方。

输入裁剪完整保留指令，并分别保留合并后对话和前次摘要的首尾。预算衡量包含转义的最终 JSON 长度，不切割组装后的 JSON，也不解析不可信文本中的分隔符。若指令和最小历史仍放不下，会在发起模型请求前失败。空响应或不成功的响应不会形成压缩检查点。

## 备选方案

- 预留完整目录输出上限可能不给对话留下空间。
- 一开始就截断所有大上下文请求会丢弃供应商本可接受的历史。
- 适配已移除的宿主摘要器接口无法保护当前的原生摘要路径。
- 摘要重试或有界请求失败后回退都会额外发起请求；小上下文压缩选择直接取消，不生成检查点。
- 切割整体提示可能丢掉原始任务锚点、最新进度或完整指令。
- 小模型子会话继承大模型父会话的预算可能溢出。

## 影响

预算是保守字符启发式，不是精确分词。裁剪可能省略历史中部。失败保持可见且不清空对话；供应商仍可能拒绝有界请求。Pi Durable 使用自己的原生压缩路径，不采用这些限制。本改动不改变独立原生会话 API 或原生分支摘要行为。

## 验证

- 回归 — `packages/agent-runtime-pi/tests/compactionSummary.test.ts` 使用原生脚本化模型调用检查有界输入/输出、来源锚点、JSON 转义、完整指令、用量、溢出、空/不成功响应和取消。
- `PiRuntimeConnection.test.ts` 走桌面手动压缩路径并检查指令传递；小上下文摘要失败不得产生无效检查点。
- `packages/agent-runtime-pi/tests/sessionEvents.test.ts` 区分失败后为阻止原生摘要回退而取消与用户中止，并清除保存的失败信息，避免后续事件继承该错误。
- `gatewayModelBinding.test.ts` 在真实回环网关路由测试中检查根/子模型各自的压缩设置。
- `piCompactionRecovery.test.ts` 检查模型各自的触发阈值；`piCompactionBudget.test.ts` 检查输出估算忽略压缩摘要之前的助手用量。
- `packages/agent-runtime-pi/tests/behaviorRuntime.test.ts` 检查行为适配器的子会话预算覆盖及有界原生摘要执行。[桌面 Pi 操作步骤](../../../../src/main/ai/runtime/pi/README.md#manual-small-context-pi-check) 描述单独的真实供应商验收；自动化回归不能证明该验收已经通过。
