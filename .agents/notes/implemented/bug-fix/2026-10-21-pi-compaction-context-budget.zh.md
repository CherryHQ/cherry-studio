# Agent Note: Pi 压缩上下文预算

Status: implemented

[English](2026-10-21-pi-compaction-context-budget.md) | 中文

## 问题

Pi 按字符估算历史，可能低估小上下文模型的多语言文本和工具输出，默认保留的尾部也可能使压缩请求过大。模型目录中的输出上限如果等于上下文大小，预留输出还会占满对话空间。桌面 Pi 现在调用宿主摘要器，因此修改 SDK 的原生摘要函数无法保护这条请求路径。

## 决策

Cherry 将目录输出预留限制在上下文的四分之一。小上下文提前压缩并保留更短尾部；至少 100,000 token 的上下文保留默认 20,000-token 尾部。每个模型的网关绑定提供这些设置。行为子会话可覆盖父会话的数值压缩设置，摘要器仍由适配器持有。

桌面宿主摘要器限制小上下文的输入和输出。大上下文保留完整输入。每次获准的摘要最多发起一次模型请求。溢出、不成功响应和取消直接失败且不重试，遵守行为适配器的请求次数上限。既有网关路由和凭证不变。成功响应的用量用于摘要统计，网关仍是供应商计费的唯一写入方。

输入裁剪完整保留指令，并分别保留对话和前次摘要的首尾。预算衡量包含转义的最终 JSON 长度，不切割组装后的 JSON，也不解析不可信文本中的分隔符。若指令和最小历史仍放不下，会在发起下一次请求前失败。空响应或不成功的响应不会形成压缩检查点。

## 备选方案

- 预留完整目录输出上限可能不给对话留下空间。
- 一开始就截断所有大上下文请求会丢弃供应商本可接受的历史。
- 保留未调用的 SDK 摘要补丁，在宿主迁移后无法保护桌面请求。
- 在只计数一次的宿主摘要内重试会绕过行为适配器的子会话请求上限，因此不将旧 SDK 重试补丁带入这条路径。
- 切割整体提示可能丢掉原始任务锚点、最新进度或完整指令。
- 小模型子会话继承大模型父会话的预算可能溢出。

## 影响

预算是保守字符启发式，不是精确分词。裁剪可能省略历史中部。失败保持可见且不清空对话；供应商仍可能拒绝有界请求。Pi Durable 也复用桌面行为宿主，因此其摘要请求使用相同限制；Durable 自身的上下文触发阈值不变。本改动不改变 SDK 单独使用时的原生分支摘要行为。

## 验证

- 回归 — `piCompactionRecovery.test.ts` 使用原生脚本化 Pi 模型调用覆盖大小上下文、来源锚点、JSON 转义、完整指令、用量、显式/静默溢出、空/不成功响应和取消。
- `PiRuntimeConnection.test.ts` 走真实桌面手动压缩路径，验证每次摘要只调用一次模型，溢出不产生无效检查点。
- `gatewayModelBinding.test.ts` 在真实回环网关路由测试中检查根/子模型各自的压缩设置。
- `packages/agent-runtime-pi/tests/behaviorRuntime.test.ts` 在实际原生会话构造时检查子会话预算覆盖。
