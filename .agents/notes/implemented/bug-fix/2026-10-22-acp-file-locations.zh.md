# Agent Note: ACP 文件位置导航

Status: implemented

[English](2026-10-22-acp-file-locations.md) | 中文

## 问题

ACP 工具卡片把报告的行号显示在文件链接之外。打开位置时行号被丢弃，重复打开同一个文件也不被视为导航。代码查看器裁剪末尾空白，还会删除本来可以定位的源码空行。

## 决策

通过共享文件打开和预览链路传递可选的、从 1 开始的源码行位置，将其与文件身份分开。ACP 位置针对文本、Markdown 和 HTML 使用只读源码预览。现有代码查看器滚动到目标行并高亮两秒。新的位置对象会再次触发定位，即使文件和行号相同。缺失或无效的位置不阻止打开文件；超出范围的行不显示高亮。

嵌入预览切换位置不会重新读取文件内容。文件页签保持仅包含路径的 URL，将目标位置保存在元数据中，因此不同行复用同一个页签。普通页签打开会清除先前的位置。没有嵌入式文件打开能力时，源码链接使用页签预览。现有文件导航代次检查会拒绝过时的元数据结果，文本加载在文件替换后忽略迟到的读取结果。

## 考虑过的替代方案

- 将行号放入文件路径或页签 URL：会混淆文件系统操作，并创建重复的文件页签。
- 创建 ACP 专用预览：会重复现有的加载、渲染和导航行为。
- 定位渲染后的 Markdown 或 HTML DOM 节点：源码行无法可靠对应渲染后的元素。

## 影响

无需数据库迁移、CLI 配置或模型推理。显式源码位置显示源码，而不是渲染后的 Markdown 或 HTML；普通打开保留已有渲染行为。高亮是临时状态，不创建文本选区。

## 验证

- Regression — 定向 renderer 测试覆盖源码行定位、重复定位、末尾空行、无效位置、文件链接激活及页签复用和重置，并运行已有预览和 Agent 面板消费者测试。

- Electron — 可控 ACP 进程在明暗主题下验证长文件和折行源码、中文路径、末尾空行、重复位置、无效和缺失行号、Markdown 源码、最后一次导航生效及空工作目录的页签回退；未记录到 renderer 错误。
