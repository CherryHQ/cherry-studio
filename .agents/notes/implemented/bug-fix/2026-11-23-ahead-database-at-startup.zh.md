# Agent Note: 数据库结构较新时停止启动

Status: implemented

[English](2026-11-23-ahead-database-at-startup.md) | 中文

## 问题

旧构建可以打开最后一条已应用迁移比随包迁移都晚的数据库。在这种情况下，Drizzle 会跳过迁移 SQL，后续业务写入可能因旧构建未知的约束而失败。Issue #22907 报告了创建知识库时因新增的必填列而失败。

## 决策

在 `DbService` 配置 WAL、执行迁移或写入种子数据之前读取最新的已应用迁移时间戳。仅当时间戳严格更新时停止启动。应用显示本地化的更新提示并退出。没有迁移记录表的数据库仍可启动初始化。

## 考虑过的方案

- 在知识库写入失败时检查会使其他写入仍然受到同一结构不匹配问题的影响。
- 在启动时采用恢复流程的完整前缀规则还会阻止同等时间戳的分叉，改变现有数据目录的启动条件。

## 影响

使用旧构建打开较新构建写过的数据目录时，用户会收到更新后重试的提示。备份恢复流程继续比较完整迁移链，且仍要求存在已应用迁移记录表。

## 验证

- Regression — 真实 SQLite 测试覆盖落后、相等和超前的迁移时间戳。超前数据库的文件字节和日志模式保持原样。
- Regression — 启动错误测试验证本地化的更新提示和退出行为。备份恢复测试覆盖既有恢复行为。
