# Agent Note: 解析已安装的 Computer Use 开发运行时

Status: implemented

[English](2026-11-07-computer-use-development-runtime.md) | 中文

## 问题

MP-140 在正常的开发安装中无法查询原生权限。中央运行时路径指向需要手工复制、实际不存在的 `.context/computer-use-runtime`，而 SDK 的平台包已包含签名运行时。

## 决策

从应用根目录解析 SDK，再从 SDK 入口解析其平台可选包。使用该包的运行时目录，并保留 macOS 应用包。仅在请求路径时解析，避免缺少可选依赖导致整个应用启动失败。打包版本保留现有的额外资源路径。

## 考虑过的替代方案

- 将二进制文件复制到 `.context` 会掩盖依赖缺陷，并给开发者增加不受管理的前置条件。
- 从打包后的主进程入口解析会丢失 pnpm 相对于 SDK 的可选依赖解析关系。

## 影响

开发环境使用随 SDK 安装的运行时。缺少原生包时，该功能的路径查询失败，不会静默使用无关的二进制文件。不引入用户数据迁移或运行时下载。

## 验证

- 回归 — 修复前，已安装运行时契约测试因旧路径中不存在可执行文件而失败。
- 回归 — 验证已安装运行时可执行、缺少可选包不会阻止注册表构建，以及打包后的 macOS、Windows 和 Linux 路径仍位于 extraResources 下。
