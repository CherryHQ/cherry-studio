# Agent Note: 为静默智能体回复提供有界失败

Status: implemented

[English](2026-11-25-agent-reply-inactivity.md) | 中文

## 问题

智能体回复可能停止产生原生事件，或因后台结果尚未返回或无法归属而保留中间成功状态。五分钟空闲资源 TTL 不覆盖执行中的任务。现有 120 分钟产品流不活动兜底不表达运行时事件进展，也不在意外 EOF 时立即报错。

## 决策

主进程使用一个 30 分钟运行时事件不活动看门狗监督当前原生执行所有者，从流打开时开始计时，覆盖连接建立阶段。符合条件的内容、用量、后台活动和原生执行转换会续期；渲染层重新连接、上下文读取和队列编辑不会续期。待处理结果非空或未知时，保留的成功状态仍受监督。意外 EOF 会立即使未完成的执行失败。

在同一连接代次上观察到并确认的人类审批会暂停期限。最后一个适用审批得到回答或中止后，重新给予完整期限，包括请求处理期间的立即拒绝。豁免仅依据注册表公开事实，不要求上下文 ID，也不推断子任务阻塞关系。现有两小时审批兜底保持不变；等待审批期间遇到 EOF 仍立即失败。

失败会向归约器注入错误，撤回排队的后续输入和所属延后放置，保留助手标识及已接收内容，同步分离连接并异步关闭。持久化确认仍然有效。条目、回复、看门狗和连接代次检查保护后继任务。恢复需要用户检查工具副作用后明确重试；不会自动重试。

## 考虑过的替代方案

- 仅对每个保留成功状态的轮次设置期限：遗漏原生完成前的静默，并无谓地监督暂停的回复。
- 渲染层看门狗：依赖窗口连接，且无法拥有原生连接退役和持久化流程。
- 驱动心跳：改变传输协议，且可能掩盖卡住的执行；运行时事件监督属于宿主。
- 不作更改：保留的回复仍缺少理解运行时进展的期限，明确 EOF 的失败也会延迟至其他兜底生效。

## 后果

真正静默的前台工具运行达到或超过 30 分钟时，即使健康也会失败。即使父任务文本和 token 计数冻结，符合条件的后台活动仍会续期。由于原生事件无法证明哪个子任务阻塞哪条回复，同一连接上的审批可能保守地豁免无关工作。五分钟资源 TTL、120 分钟流兜底、两小时审批兜底和停止/关闭期限保持不变。计时器触发要求主进程事件循环仍在运行。

## 验证

- AC1 — `AgentSessionRuntimeService.test.ts`：静默在不活动期限到达时恰好失败一次，覆盖连接建立阶段和正文为空的情况；终态持久化将同一助手待处理行改为错误。
- AC2 — `AgentSessionRuntimeService.test.ts`：未完成回复及保留成功状态遇到 EOF 时立即失败，终态交接及主动停止/关闭不受影响；关闭挂起不延迟可见失败。
- AC3 — `AgentSessionRuntimeService.test.ts`：待处理和未知结果保留状态在同一回复上失败；后台事件续期，记账不续期，已确认审批暂停期限，直至最后一个回答或中止。
- Regression — `AgentSessionRuntimeService.test.ts` 和 `agentSessionRuntimeState.test.ts`：排队后续输入被撤回，过期回调无法误伤后继任务，空闲后台占用不启动回复看门狗。
