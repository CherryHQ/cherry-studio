# Agent Note：保留提供商流内的上下文超限错误

Status: implemented

[English](2026-11-28-sse-context-overflow.md) | 中文


## 问题

上游 SSE 错误可以仅通过业务错误码标明上下文超限，无需携带 HTTP 错误状态码。普通错误对象经序列化后丢失了错误码，网关因此可能返回 HTTP 500，聊天也可能错过压缩上下文的机会。

## 决策

提供商适配层用 AI Core 的超限判定处理无状态码的流内错误和 HTTP 400，将识别到的超限作为同一种不可重试的类型传给压缩和重试。符合条件的聊天请求可以在输出前压缩上下文，然后重试失败的模型步骤。AI SDK 执行链路在重试结束后选出最终原因。序列化保留类别，网关将类别转换成客户端协议所需的错误格式。

## 考虑过的替代方案

- 在网关分类会遗漏聊天恢复，也只能使用序列化后剩余的字段。
- 给上游错误注入状态码会掩盖提供商的实际响应。

## 影响

上游错误状态码仍为可选字段。网关已经开始流式响应时，通过终止错误帧报告超限，并保留已发送的内容。

## 验证

- Regression — 本地 HTTP 上游分别在内容前后发出仅靠错误码识别的 SSE 错误。两种情况修复前失败，修复后通过。
- Regression — 429 后遇到仅靠错误码识别的 SSE 超限时，最终类别得到保留。聊天恢复只重试已完成工具调用之后失败的模型步骤。
- Regression — Electron 开发实例在输出前返回 HTTP 400，在输出后发送一次超限错误帧，每次请求只调用上游一次。
