# Agent Note：Ollama 思考行为遵循模型原生上报的控制项

Status: implemented

[English](2026-11-01-ollama-thinking-controls.md) | 中文

## 问题

Ollama 会拒绝模型不支持的命名 `think` 等级。模型具有通用思考能力，并不能说明它接受哪些
`think` 取值；本地推断出的等级——无论是已持久化在既有行上的，还是由目录或 ID 模式推断
产生的——仍可能发送 Ollama 以 HTTP 400 拒绝的值。

## 决策

沿用 #22550 的方案，以 Ollama 通过 `/api/show` 上报的控制项（`thinking.values` /
`thinking.default`）为权威来源：

- 发现流程把上报值转换为内在推理控制项：`false` 变为关闭开关，`true` 变为布尔开关，已知
  effort 名称变为对应等级，无法识别的名称被丢弃。取值全为 `false` 的模型会得到显式为空的
  控制项，使"不支持思考"成为已记录的事实，而非缺失数据。
- 创建时持久化原生控制项与思考能力标记；模型拉取流程会将其比对更新到既有行，只改动推理
  元数据，使陈旧的本地推断等级无法覆盖模型上报的控制项。对 Ollama 格式，读取与请求时解析
  优先采用已存储的控制项，而非目录或推断结果。
- 网关映射器仅在模型声明了等级时发送命名等级（序列化器会把请求映射到已声明的等级上），
  在模型声明了布尔开关时发送布尔值；对仅支持等级的模型，`auto` 使用上报的默认等级；当可
  接受取值未知时省略 `think`，由 Ollama 使用其默认值。
- 在没有原生元数据时，Ollama 的通用能力回退仍只声明开关，因此推断出的非 effort 控制项会
  通过布尔开关发送，而不会作为命名线路等级发送。

## 考虑过的替代方案

- 保留 `high` 回退值和通用推断等级：不采用，因为两者都可能发送 Ollama 拒绝的值。
- 对所有 Ollama 模型省略推理参数：不采用，因为这会禁用受支持的布尔开关与原生上报的等级。
- 等待 #22550 合并后再处理：不采用，因为该缺陷可独立修复；此处移植的子集（发现、持久化、
  读取优先）与该 PR 更广泛的端点工作兼容。

## 影响

- 仅支持布尔的 Ollama 模型收到 `think: true`/`false`，不会收到命名等级。
- 原生上报了等级的模型只会收到已声明的等级。
- 从未发现过控制项的模型退化为不发送 `think` 字段。
- 拉取提供商模型会就地刷新既有行的思考选项；名称、备注、上下文窗口等用户设置不受影响。

## 验证

- 回归 —— `listModels.test.ts`：`/api/show` 的思考取值变为精确控制项；覆盖仅布尔、仅等级、 禁用与未知取值的声明。
- 回归 —— `ModelService.test.ts`：原生控制项在创建时持久化，在自定义、已识别与预设行的重读 中保留，刷新既有行且不触碰用户设置，显式空控制项使推断等级失效。
- 回归 —— `modelSync.test.ts` 与 `useProviderModelPullReconcile.test.ts`：目录富化保留原生控制 项，创建 DTO 携带控制项，且仅当上报控制项有差异时才刷新已保存行。
- 回归 —— `providerOptionsMapper.test.ts`：仅布尔、仅等级、钳制、默认等级、禁用与未知能力的 Ollama 请求。
