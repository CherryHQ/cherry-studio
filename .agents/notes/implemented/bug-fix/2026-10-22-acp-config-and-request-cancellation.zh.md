# Agent Note: ACP 配置快照与请求取消

Status: implemented

[English](2026-10-22-acp-config-and-request-cancellation.md) | 中文

## 问题

将模式、模型和思考强度提升为专用控件时，它们在 ACP 配置数组中的位置被移除，类别信息也被丢弃。重新拼接菜单改变了原生优先级，并把模型参数与模型选择分开。Agent 取消单个 JSON-RPC 请求后，请求处理器也仍会等待用户审批。

## 决策

按原始顺序保留完整的受支持配置快照，包括类别和分组选项。派生的模式与模型视图保留现有 API；渲染进程避免重复展示控件。模型参数显示在模型选择弹窗中，仅修改原生会话。全局模型选择继续使用现有的 CLI 默认值持久化流程。完整配置更新会移除失效控件和模型目录；未知选项类型会被忽略。

将 SDK 的请求取消信号接入现有审批注册表，同时保留连接和轮次取消。取消权限请求和问答时返回各自原生取消结果。文件和终端操作在产生未经批准的副作用前，返回请求取消错误。取消终端等待不会终止终端进程。ACP 握手报告应用版本。

## 考虑过的替代方案

- 为分别存储的控件增加位置字段：重复维护原生数组已有的顺序状态。
- 实现另一套 JSON-RPC 取消分发器：重复 SDK 能力，并丢失请求归属。

## 影响

无需数据库迁移或额外的全局配置存储。取消采用协作机制，已经执行的操作无法撤销。客户端拥有的终端继续由显式释放和连接清理管理。

- Regression — 定向渲染进程测试覆盖配置顺序与去重、分组选项翻译，以及模型参数使用会话配置而非全局模型持久化。
