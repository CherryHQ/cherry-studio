# Agent Note: 在富文本编辑器插件视图重启时恢复代码高亮

Status: implemented

[English](2026-11-10-rich-editor-highlight-view-lifecycle.md) | 中文

## 问题

macOS 的 MP-74 回归中，Markdown 渲染和保存均正常，但代码块中没有语法 token。受控复现确认了一项产品生命周期缺陷：代码块高亮请求尚未完成时注册其他 ProseMirror 插件，可能导致当前文档永久失去高亮。

注册或移除插件时，ProseMirror 会保留编辑器状态并重建插件视图。高亮器的旧视图在销毁时清理代码块会话，但新视图原先依赖状态初始化来发现代码块。保留的插件不会再次执行状态初始化，因此新视图没有可供高亮的代码块。富文本编辑器也通过这一 API 动态注册插入工具栏。

## 决策

每个新建的高亮器视图在请求语法 token 前，根据当前文档重新整理代码块。销毁时仍会关闭旧会话，并忽略其迟到结果。代码文本、选区、序列化、撤销历史和 Worker 协议沿用现有契约。

## 考虑过的替代方案

延长 MP-74 的超时或接受无高亮代码，会掩盖持续存在的产品故障。保留旧视图会话会留下过期任务，并使清理职责变得不明确。复用现有文档整理逻辑即可恢复新视图，无需添加重试或另一套生命周期机制。

## 影响

插件注册和移除不再丢失尚未完成的代码高亮。新视图为当前代码块建立新会话，因此插件视图重启时，未改动的代码块也可能重新解析。普通事务仍沿用原有的增量行为。

## 验证

- Regression — 定向真实编辑器测试在高亮尚未完成时替换代码、注册其他插件、继续编辑并移除插件。该测试在修复前失败，修复后通过；富文本编辑器和高亮服务两个文件合计通过 16 项测试。
- Regression — 在已跟踪的 macOS Electron Notes 编辑器中执行同一受控操作，修复前 token span 数量为 0，修复后为 14，代码文本保持一致。这确认了生命周期缺陷，但未还原原始云端运行中的每个调度事件。
