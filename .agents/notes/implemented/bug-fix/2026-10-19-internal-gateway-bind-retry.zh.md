# Agent Note: 内部网关权限错误的有限重试

Status: implemented

[English](2026-10-19-internal-gateway-bind-retry.md) | 中文

## 问题

内部网关的 `listen` 返回 `EACCES` 时，所有等待中的调用方都会立即失败，即使操作系统分配的另一个端口可能可用。IPv4 可能先绑定成功，而同一个端口在 IPv6 上被拒绝。仅凭这一错误无法确定具体的操作系统限制。

## 决策

内部网关通过 `es-toolkit` 的有限重试函数，对 `listen` 的 `EACCES` 最多尝试启动三次。每次都创建端口为 `0` 的新服务器，由操作系统选择端口，不保证与之前尝试的端口不同。服务器启动流程在抛出错误前完成失败监听器的清理。并发调用方共用同一次待完成的启动及其重试次数上限。

达到上限后，调用方收到最后一次失败的本地化错误及其原始原因。失败的启动状态会被清除，允许后续请求再次尝试。其他错误立即向上传递。公共网关保留配置端口，通过设置页手动恢复。

## 考虑过的替代方案

- 每次内部监听被拒绝后都要求用户重新请求，会错过再次申请临时端口即可恢复的机会。
- 无限重试会在持续的回环监听限制下让调用方一直等待。
- 自动更换公共端口会使客户端端点和已配对设备的连接信息失效。

## 影响

持续的权限限制仍会在三次尝试后导致失败。重试仅作用于监听器启动，不会重放模型请求、修改公共网关偏好或启用公共网关。未引入新的延迟策略或依赖。

## 验证

- Regression — `src/main/features/apiGateway/__tests__/ApiGatewayService.test.ts`：并发调用方在共享次数上限内恢复；耗尽次数后保留诊断信息并允许后续请求；无关错误立即向上传递；公共网关仍需显式重试。
- Regression — `src/main/features/apiGateway/__tests__/server.test.ts`：受控 IPv6 拒绝覆盖真实 Node 监听器、HTTP 恢复及清理后重新绑定所有失败端口。注入的拒绝不代表已确认原 Windows 机器上的原因。
