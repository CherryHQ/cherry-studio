# Agent Note: 恢复上次打开的笔记，隔离各窗口的当前选择

Status: implemented

[English](2026-11-18-notes-selection-restore.md) | 中文

Date: 2026-11-18
Owners: Notes renderer maintainers
相关 issue：[#24843](https://github.com/CherryHQ/cherry-studio/issues/24843)

## Problem

开启收藏过滤后重启，列表恢复显示全部笔记，编辑器却丢失了选择。已有笔记但尚未选中时，编辑器还会声称没有笔记。原因是过滤开关和当前选择原本都属于会话状态，编辑器的空状态又没有区分“未选中”和“目录里没有笔记”。

直接持久化当前选择会引入并发问题：渲染进程的持久缓存写入会广播到其他窗口。选择广播绕过接收窗口的 `requestFileTransition` 及输入法组字守卫。创建或重命名时，目录镜像尚未追上文件变化，各窗口也可能互相清掉选择。

## Decision

`notes.active_file_path` 保留在窗口内存中，类型为 `AbsoluteFilePath | undefined`。渲染进程持久键 `notes.last_open_file_path` 的类型为 `AbsoluteFilePath | null`，默认值为 `null`。NotesPage 每次挂载时，只为尚未选中的页面初始化一次。后续广播不会选中笔记，清空选择后也不会再次初始化。有选中路径时写回恢复键；清理失效且无未保存修改的选择，或删除当前笔记时，清空本窗口的选择，仅在恢复键仍指向该路径时才将其清空。文件编辑恢复只修改当前窗口的内存选择，由 NotesPage 负责持久化。

存在性检查使用目录 session 的 O(1) 索引，先尝试原始绝对路径，再尝试规范化后的路径，只接受文件节点。只有根节点存在、树标识处于活动状态、加载结束且目录树无错误时，才信任当前快照。清理还需等文件会话结束加载，确定其 dirty 状态；文件会话报错时，仍可清理已缺失且无未保存修改的路径。清理选择和保留失联草稿使用同一快照，以及文件会话自身的 dirty 标志。根 session 释放、加载中或目录树报错，都不能证明文件已不存在，停止观测后保留的旧根节点也不能作为依据。重连后文件消失，仍保留可访问的未保存草稿。只有确认文件缺失且无未保存修改时，编辑器才放弃该路径，索引更新后投影尚未追上时仍保持编辑区。创建、重命名和输入法组字沿用已有过渡守卫。

收藏过滤仍只在当前会话生效。存在笔记但尚未选中时，编辑器使用 `notes.no_note_selected`，折叠文件夹里的笔记也计入；目录里没有笔记时保留原有空状态。

## Alternatives considered

- 用同一个持久键承载选择与恢复，会让广播绕过文件切换守卫。
- 持久化收藏过滤会改变它的会话语义，也无法修复选择恢复和误导性的空状态。
- 检查投影树或额外的投影 ref，会让存在性与 dirty 保留判断读取不同版本，并可能把根 session 释放误判为文件删除。

## Consequences

恢复键记录共享的打开历史，各个已打开窗口仍保留自己的选择。并发窗口可能改写恢复提示；清理时仅在它仍匹配被清理的路径时重置为 `null`，保留从其他窗口收到的新路径。清理需等活动树就绪、文件会话的 dirty 状态确定，避免已释放的索引或尚未完成的会话获取清掉选择。这是可丢弃的导航状态，不是文档存储。不为先前实验性的持久键增加兼容迁移。

跨机器恢复时更换根目录的场景仍未验证。恢复失效路径时，可信目录树清空选择之前，仍可能触发已有的“Failed to load note”提示；提示体验留待后续改进。

以下限制来自现有目录树与编辑器机制，另行跟进：`findNodeByPath` 同时匹配相对 `treePath` 与绝对路径，投影更新可能命中碰撞节点并改变编辑器 key；已确认缺失且无未保存修改时，即使输入法正在组字也可能撤掉编辑区；缺失的 dirty 会话重新读取失败会进入既有的加载失败状态，其草稿仍可从恢复界面取回。

## Verification

- Regression — `src/renderer/pages/notes/__tests__/NotesPage.test.tsx` 覆盖重启恢复、失效 clean 路径清理并写入 `null`、根 session 释放与重连、重连时保留 dirty 草稿、跨窗口持久广播、只初始化一次，以及未选中的编辑器。还覆盖文件会话从 loading 转为 ready/error、索引先于投影恢复时保持编辑区、停止观测后保留旧根节点，以及两条清理路径保留其他窗口的恢复值。新增六个用例在本轮修复前全部失败；此前的反向检查还会临时恢复旧 D2 守卫或单一持久键选择机制，验证对应回归。
- Manual — 在一次性 profile 中，用三条笔记（其中两条收藏）做真机探针：重启应用后编辑器恢复上次打开的笔记，收藏过滤归零并显示全部三条；关闭应用后删除该笔记再启动，编辑器的选择与持久恢复值都被清空；未选中时显示“请选择笔记”，不再声称没有笔记。
