# Agent Note：切换会话和标签页时聚焦输入框

Status: implemented

[English](2026-11-19-conversation-tab-input-focus.md) | 中文

## 问题

切换到已有普通聊天、Agent 会话、翻译或绘画标签页时，键盘焦点会留在导航控件上。激活时只调用一次聚焦，可能赶在输入框就绪之前。React Activity 隐藏标签页时会断开编辑器的 effect，Tiptap 可能在重新激活后才重建视图。翻译工作进行期间，原文框也可能处于禁用状态。

## 决策

为当前活动输入框保留一次待处理的聚焦请求，等已挂载且可编辑的目标能够获得焦点时执行。标签页失去激活状态或用户把焦点移到另一个控件时，丢弃请求。发送输入区直接聚焦轻量文本框或已挂载的 Tiptap 视图，并把光标移到末尾。这与[轻量输入框的焦点移交](2026-11-07-composer-deferred-intent-replay.md)互补。

普通聊天和 Agent 切换会话时已有重新挂载机制，无需在另一条聚焦路径中传递会话标识。翻译先注册语音目标，再聚焦原文框。绘画页面持有激活请求，切换历史记录时仍由页面管理，并在激活标签页时展开折叠的提示词栏。

## 考虑过的替代方案

- 固定延时或在导航处理函数中只调用一次聚焦，都无法判断编辑器是否已经挂载、输入是否已经可编辑。
- 每次创建编辑器都聚焦，会让草稿加载、绘画历史记录切换或后台渲染有机会从当前控件抢走焦点。

## 影响

选中的页面就绪后即可打字。选择绘画历史记录时，键盘焦点保留在原控件。执行新建会话操作后复用现有会话等显式聚焦请求，仍有独立的处理路径。

## 验证

- Regression — `TranslateInputPane.test.tsx` 验证输入就绪、语音目标注册及其他控件保留焦点。
- Regression — `PaintingPage.test.tsx` 验证页面激活时恢复折叠的提示词栏并聚焦。
- Regression — Electron 验证四类输入框接收首键、快速切换标签页、恢复富文本编辑器及绘画历史按钮保留焦点。
