# Agent Note：Session 消息树存储约束

Status: implemented

[English](2026-11-09-session-tree-storage-constraints.md) | 中文

## 问题

Session 消息的父节点只是无约束文本。直接写入可以保存不存在的父节点、其他 Session 的父节点，或没有父节点的普通消息。直接新增约束又会拒绝已发布 v2 数据库中的平铺历史及中间版本转换出的历史数据。

## 决策

要求 `(role = 'root') = (parent_id IS NULL)`，并建立 `(session_id, parent_id)` 到 `(session_id, id)` 的复合外键及配套唯一索引。保留已有的 root 唯一索引。父节点外键使用 NO ACTION：普通删除必须先重接子节点，整段 Session 删除仍级联清理全部历史，不沿深层消息链递归级联。

在自动生成的约束迁移之前追加自定义补数据迁移。`0039` 将没有选中节点且没有任何父边的历史按 `(created_at, id)` 重建。迁移会在关闭外键期间检查已有父边，失败时回滚迁移事务。补 root 时关闭 FTS 插入触发器，避免与显式分配的 FTS rowid 冲突；生产迁移器随后恢复触发器。在迁移事务内重建 FTS，确保生成的 root 即使没有文本也有对应的 FTS 文档。该一次性重建会扫描已有可搜索文本；仅恢复触发器会破坏外部内容一致性，并可能导致后续 Session 删除失败。

在 `0032` 和 `0039` 之间，继续旧会话可能创建根节点并追加新轮次，早期消息仍未接入树。启动和备份恢复共用的迁移入口会在执行 `0039` 前用一个事务修复这些数据库。平铺归档按 `(created_at, id)` 排序。在混合消息树里，早于根节点、没有父节点也没有已连接后代的消息成为已有分支的共同前缀。其他脱离的子树以及父节点缺失或跨会话的消息会挂到本会话根节点。修复会按需创建根节点，并清除根节点上已有的父边。

迁移 `0043` 同时修复已完成消息树回填的数据库中为空、指向缺失消息或其他会话的活动节点引用。它按 `(created_at, id)` 选择从本会话根节点可达的最新叶节点，并保留有效选择。对于仅选中了占位根节点的平铺归档，预修复会选中恢复后的末条消息。

平铺归档重构从[运行时契约](../../proposed/architecture/2026-10-17-agent-runtime-contract.md)描述的启动 Seeder 前移至表结构迁移，部分替代其回填职责。该迁移也为空 Session 建立 root 和选择状态；启动 Seeder 仅回填遗留投递回复锚点。[树操作决策](2026-11-09-agent-session-tree-operations.md)记录查询、修改及投影行为。

当前应用通过 2.2.2 中间版本完成 v1 转换，其生成的 v2 历史使用上述追加迁移。直接写 SQL 的测试夹具通过共享辅助函数创建真实 root。

## 考虑过的替代方案

- 仅约束父节点 ID 的外键允许跨 Session 连边。
- 父节点级联删除可能误删后代，长链还会触及 SQLite 触发器深度限制。
- 仅靠启动 Seeder 补树太晚，因为结构迁移先于 Seeder 执行。

## 影响

这些约束保护局部父子关系。无环和原生执行身份仍是独立的约束。兼容修复保留消息 ID、内容、时间戳，以及已有的分支选择和后代关系。修复事务先于 Drizzle 迁移事务提交。如果后续迁移失败，重试时会使用已恢复的树。

## 验证

- Regression — `agentSessionTreeConstraints.test.ts` 使用真实文件 SQLite，覆盖非法插入和更新、先重接后删除、含 2,000 个后代的整段 Session 删除、树字段引入前及约束引入前的带数据升级、分支和 FTS 结果保留、FTS 外部内容一致性以及升级后删除空 Session 和有消息的 Session，以及修复缺失或跨会话的旧父边。
- Regression — `agentSessionTreeConstraints.test.ts` 验证升级后完整保留 10,001 条平铺消息。现有数据、运行时、搜索、回收站和迁移消费者使用合法树夹具验证。
- Regression — `agentSessionTreeConstraints.test.ts` 验证恢复的 v2.2.2 历史可通过默认分页和搜索读取、其他分支得以保留、脱离子树可恢复到有根或无根的会话，并验证 v2.2.3 的无效活动节点在读取历史前得到修复。
