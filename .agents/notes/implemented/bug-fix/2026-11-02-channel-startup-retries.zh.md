# Agent Note: 连接失败后的频道启动重试

Status: implemented

[English](2026-11-02-channel-startup-retries.md) | 中文

## 问题

网络中断时，如果飞书首次连接无法解析机器人身份，`ChannelRuntime` 会报告连接失败并停止协调。协调器会有意停止重试失败的目标，除非收到新请求，因此网络恢复后频道不会自行重新启动。

## 决策

`ChannelRuntime` 会对失败的 `ChannelAdapter.connect()` 进行指数退避重试，初始间隔为一秒，最长为 60 秒。只要频道期望状态仍为已连接，重试就会持续进行。每次失败都会立即发布断开状态及错误。显式协调会取消待执行的重试并重置间隔；连接成功后也会重置间隔；运行时销毁时会取消定时器。

## 考虑过的替代方案

- 仅在飞书适配器内重试会重复生命周期管理，并且其他适配器仍会有相同的启动失败问题。
- 依赖后续协调请求意味着网络恢复后仍需要手动重连或等待无关的生命周期事件。
- 有限次数的重试可能会在设备仍离线时耗尽。

## 影响

只要频道仍处于期望连接状态，持续的连接错误（包括凭据无效）就会无限重试，频率最多为每分钟一次。等待重试期间，状态会保持断开并显示最新连接错误。定时器不会阻止进程退出，并会在运行时销毁时取消。

## 验证

- Regression — `pnpm test:main src/main/ai/channels/__tests__/ChannelRuntime.test.ts`：验证连接失败会发布断开状态、以指数退避重试、在连接成功后恢复，并在频道停用后停止重试。
