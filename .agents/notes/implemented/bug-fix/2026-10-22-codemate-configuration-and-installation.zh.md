# Agent Note: CodeMate 配置与安装所有权

Status: implemented

[English](2026-10-22-codemate-configuration-and-installation.md) | 中文

## Problem

高级设置提交完整的旧运行时快照，会覆盖其他入口修改的模型和启用状态。Windows 配置写入按大小写敏感方式读取环境变量，而 CLI 不区分大小写。二进制升级替换启动入口后，旧目录无法再通过卸载回收。启用密码保护的 OpenCode WebUI 无法通过就绪检查。

## Decision

在现有 SQLite 写事务中，将明确提交的 `localRuntime` 字段与当前 Agent 合并。更新 schema 不应用创建时的默认值。省略字段会保留其值；明确的 `undefined` 会清除可选字段。高级设置、启用开关和模型选择仅提交自己负责的字段。其他 Agent 配置嵌套对象继续整体替换。无需数据库迁移。

程序名查找使用最终有效环境。Windows 在同一来源的重复名称中遵循 Node 按字典序选择的规则；后续显式覆盖按不区分大小写的名称替换。原生配置写入使用同样的解析方式。

通过原子安装清单记录由规范启动入口证明所有权的二进制目录。升级期间保留旧版本，因为用户手动启动的 CLI 进程可能仍会读取同目录资源。明确卸载时，仅在通过目录边界、真实路径和所有权检查后回收已记录的目录。绝不只凭目录名前缀推断所有权。

OpenCode 就绪检查使用配置的 Basic 认证。浏览器认证仅为运行中的自有服务的精确 origin、非代理 Basic 认证请求以及现有 WebView 会话提供凭证。凭证不进入共享状态或 URL；认证处理器由服务生命周期管理。

## Alternatives considered

- 保存前刷新前端快照：仍存在读写竞态，并要求各调用方分别协调。
- 对全部配置执行递归合并：会改变无关对象的整体替换约定。
- 升级后立即删除旧二进制：可能破坏仍在使用其资源的外部终端。
- 删除所有前缀匹配的目录：无法证明无关用户文件的所有权。
- 将未认证的 HTTP 401 当作就绪：仍无法正常打开受保护页面。

## Consequences

清除可选字段仍须明确提交，调用方须避免再次提交自己没有编辑的字段。缺少历史所有权记录的二进制安装可能遗留无法验证来源的旧孤儿目录；这些目录有意保留。Windows 文件系统和真实安装行为仍需原生平台验收。

## Verification

- Regression — 执行生产迁移的 SQLite 与 schema 测试覆盖部分更新、模型和启用状态保留、明确清除及协议身份不可变约束。
- Regression — 二进制安装测试覆盖 Windows 命令分隔符、路径越界拒绝、升级资源保留和历史目录回收，不跟随被替换的符号链接。
- Regression — 环境与配置测试覆盖 Windows 混合大小写目录和重复名称；真实 HTTP 子进程验证受保护 WebUI 的就绪检查及认证作用范围。
