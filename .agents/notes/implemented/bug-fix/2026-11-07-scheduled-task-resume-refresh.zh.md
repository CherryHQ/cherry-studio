# Agent Note：返回会话后刷新定时任务卡片

Status: implemented

[English](2026-11-07-scheduled-task-resume-refresh.md) | 中文

## 问题

MP-145 在设置中运行周期任务，等待持久化运行记录完成后返回原会话，卡片仍可能保留运行前的状态。React Activity 暂停隐藏会话的数据变更订阅，而保留的 SWR hook 在会话恢复时不会重新执行首次挂载请求。

## 决策

任务详情 hook 的副作用再次激活时刷新数据。首次请求仍由原查询负责，保留可见期间的数据变更订阅，并继续使用共享任务详情缓存。

## 考虑过的替代方案

- 重新加载应用或在 E2E 中强制查询会掩盖产品界面的过期状态。
- 持续轮询会在已有事件订阅覆盖可见卡片的情况下增加额外工作。
- 修改所有 DataApi 消费者的恢复策略超出了本次任务卡片缺陷的范围。

## 影响

返回会话会重新获取当前任务投影，包括已完成运行和删除状态。每次恢复增加一次刷新，不改变任务执行、调度或存储结果。

## 验证

- 回归 — 使用真实 SWR 和 React Activity 的测试先隐藏卡片，再完成模拟后端运行并发布数据变更事件，最后显示会话。修复前卡片仍显示旧状态，修复后显示已完成结果。
- 回归 — 任务 hooks、Activity 恢复及定时任务卡片三个文件共 30 项测试通过。

- 回归 — MP-145 在 Electron 中通过，覆盖真实 Agent 创建任务、返回会话后的成功摘要、持久化结果历史以及删除后的卡片状态。
