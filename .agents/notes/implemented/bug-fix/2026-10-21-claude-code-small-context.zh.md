# Agent Note: Claude Code 中第三方模型的小上下文窗口

Status: implemented

[English](2026-10-21-claude-code-small-context.md) | 中文

## 问题

SDK 对 `autoCompactWindow` 的 100,000 token 下限也限制了 CLI 上下文和输出限制的传递。因此，声明 49,152 token 窗口的第三方模型没有收到这两项限制，可能在压缩前就超过后端的真实上下文上限。

## 决策

独立于 `autoCompactWindow` 传递有效的声明上下文窗口。窗口小于 100,000 token 时，不设置 SDK 不支持的该项配置，将默认压缩百分比降至 60，并将输出预留上限设为声明窗口的四分之一。四分之一上限同样适用于显式输出覆盖值；较小的有效覆盖值保持原值。显式上下文和压缩百分比覆盖值仍然优先。

## 考虑过的替代方案

- 传递更小的 `autoCompactWindow`：不采用，因为 SDK 拒绝低于下限的数值。
- 传递 100,000 token 下限或保留通用输出默认值：不采用，因为它们都不能反映较小后端的真实预算。
- 保留所有显式输出覆盖值：不采用，因为过大的输出预留会占用本修复需要保护的输入余量。

## 后果

小窗口模型会更早压缩，输出额度也可能降低，包括已配置的输出覆盖值超过四分之一上限的情况。对于 49,152 token 窗口，4,096 保持不变，而 32,768 会变为 12,288。窗口不小于 100,000 token 的模型保留原有策略。声明窗口缺失或无效时，不额外设置上下文或输出限制。

## 验证

- Regression — `pnpm test:main src/main/ai/runtime/claudeCode/__tests__/settingsBuilder.test.ts`：覆盖 49,152、64,000 和 99,999 token 窗口、100,000 token 的包含边界、无效元数据，以及安全和过大的显式输出覆盖值。
- Regression — 隔离的 CLI 2.1.284 协议探测连接本地模拟端点，报告 49,152 token 上下文，并按配置发送 `max_tokens: 4096` 或 `max_tokens: 12288`；两次运行均成功完成。

这些单元测试和模拟协议探测不能验证 Cherry Studio 连接第三方后端的真实会话。
