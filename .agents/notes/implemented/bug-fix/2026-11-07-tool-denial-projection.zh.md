# Agent Note: 在运行时结果到达后保留工具授权决定

Status: implemented

[English](2026-11-07-tool-denial-projection.md) | 中文

## 问题

回归用例 MP-51 拒绝了 Pi 的文件写入，并确认文件没有创建，但完成后的工具卡片显示普通错误，而不是用户拒绝。宿主处理授权决定后，运行时又发送了错误结果。后续 SDK 快照保留授权标识，却丢失了决定，同时覆盖实时投影和最终消息中的拒绝状态。

## 决策

对该工具的后续快照应用宿主记录的授权决定。原生根消息投影可能完全不包含授权元数据，因此根投影也保留真实的宿主授权标识，并在重新连接时从持久化片段恢复决定。拒绝保持为 `output-denied`；允许的调用保留实际执行结果，包括真实错误。尚未完成的已允许调用仍立即转为 `approval-responded`。

## 考虑过的替代方案

- 从错误文本推断拒绝，会混淆运行时故障和用户的明确决定。
- 只修改卡片标签，会让持久化消息及其他消费者继续处于不一致状态。
- 全局丢弃运行时错误，会掩盖用户允许执行后的真实故障。

## 影响

流执行对象和原生根投影分别在各自的消息边界保留决定，不引入新的存储格式或授权流程。工具完成后仍显示用户拒绝，已允许的调用仍可报告执行失败。工具执行与权限拦截行为不变。

## 验证

- Regression — `src/main/ai/streamManager/__tests__/AiStreamManager.test.ts`：真实 UI 消息流依次接收授权请求、宿主决定和后续运行时错误。最终持久化输入及订阅投影均保留拒绝；允许分支保留执行错误。拒绝分支在修复前失败。
- Regression — 受影响的流管理器测试文件中全部 165 项测试通过。

- Regression — `AgentSessionRuntimeService.projection.test.ts` 驱动注册表响应、原生结果、SQLite 持久化及重新加载的投影。原生结果缺少授权元数据时仍保留拒绝，已允许的调用仍保留真实执行错误；这两个用例在根投影修复前均失败。
