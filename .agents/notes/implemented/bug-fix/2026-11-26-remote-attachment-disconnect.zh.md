# Agent Note: 断开连接时清理尚未发送的附件选择

Status: implemented

[English](2026-11-26-remote-attachment-disconnect.md) | 中文

## Problem

手机在 Agent 对话中上传文件后，如果在发送前断开连接，桌面端会一直显示待发送卡片，直到选择记录过期或应用重启。[议题 #25303](https://github.com/CherryHQ/cherry-studio/issues/25303)

## Decision

为每条选择记录保存最近一次上报它的连接代次。连接关闭时，移除属于该连接且尚未发送的选择，并通知正在查看相应对话的渲染进程。已经关联发送命令的选择会继续保留，供界面在消息提交后切换到正式消息。

## Alternatives considered

- 按设备清空所有选择会误删客户端重新连接后已经上报的选择。
- 取消暂存的上传会影响文件传输恢复。议题中确定的行为是自动清理待发送卡片。

## Consequences

客户端重新连接后可以再次上报同一份上传文件。文件服务管理文件内容，命令回执记录与已发送消息的关联。

## Verification

- 回归验证 — 远程 Agent RPC 回归测试上报一个处于就绪状态的附件，再检查断开连接后的桌面选择列表。托管文件用例检查已发送的选择是否仍指向持久化的消息。渲染进程测试确认，已提交的消息可见后，待发送卡片会消失。
- 回归验证 — 选择服务回归测试关闭同一设备两个连接中较早的一个，检查保留下来的选择和发往相应会话的 IPC 通知。
