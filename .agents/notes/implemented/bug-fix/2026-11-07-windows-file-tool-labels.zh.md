# Agent Note: 在 Windows 文件工具卡片中显示文件名

Status: implemented

[English](2026-11-07-windows-file-tool-labels.md) | 中文

## 问题

Windows 权限 E2E 已成功创建文件，但 Write 卡片显示完整的反斜杠路径，而非文件名。Read、Edit 和 MultiEdit 同样只按正斜杠截取，存在相同缺陷。

## 决策

四类卡片统一复用渲染进程已有的跨平台文件预览文件名工具。点击目标仍保留完整路径，写入成功后才允许打开的条件保持不变。

## 考虑过的替代方案

- 放宽 E2E 的标签断言会保留 Windows 上不一致的显示。
- 新增路径解析器会重复已有工具。

## 影响

Windows 和 POSIX 的文件工具标签均显示路径末尾的文件名，文件访问和预览目标保持不变。独立的 Memory E2E 接受 Windows 的行内代码路径，因为该渲染器有意不将它们转换为链接；测试仍验证真实文件内容与新会话中的记忆回忆。

## 验证

- 回归 — 修复前四项 Windows 文件名用例全部失败，原有 50 项渲染用例通过。
- 回归 — 修复后 99 项相关渲染与文件预览测试通过；Web/E2E 类型与范围内 lint 检查通过。仍需托管 Windows E2E 验证。
