# Agent Note: 原生智能体用量归属

Status: implemented

[English](2026-10-30-agent-usage-ownership.md) | 中文

## 问题

提供商请求完成与原生助手消息发布是相互独立的。若在响应 ID 找到消息归属前将已完成的调用记录保留在内存中，进程退出会丢失用量。若把所有调用都归到当前根会话回复，则会错误归属延迟的子任务续写和原生辅助请求。

## 决策

调用完成后立即持久化，同时保留请求时的来源、价格和凭据快照。原生响应 ID 后续可补充消息关联，包括子任务消息。同一事务也重建消息用量投影。此操作不能修改金额、token、价格、凭据或来源，不能新增一笔费用，也不能替换已有的消息归属。

没有原生助手消息的调用保留费用，但不关联消息。桌面端发起的 Pi 摘要和验证请求在经过网关前捕获发起方运行时上下文；子任务摘要不借用父会话消息。捕获令牌仅限内部使用、绑定会话，并在请求结束后释放。会话 ID 用于请求校验，不作为独立计费维度存储。

## 考虑过的替代方案

- 等待原生关联后再写入记录：不采用，因为进程丢失会导致已完成的提供商用量被丢弃。
- 将辅助用量归到最后一条可见消息：不采用，因为先后顺序不能证明归属。
- 归属到达时重新计算或插入调用：不采用，因为延迟关联不能破坏请求时价格和单次计数。
- 单独持久化会话 ID 并提供带索引的会话查询 API：不采用，因为没有产品消费者需要该计费维度。立即落盘和延迟绑定消息使用现有账单 schema 即可。

## 后果

金额和请求时归因保持不可变；原生消息关联仅允许有限补充。总体用量包含未绑定消息的辅助调用，消息总量不包含这些调用。这类调用无法按会话查询。移除未合并的会话归属迁移；已发布的迁移和历史记录保持不变。此机制仍然只是尽力记录可观测用量的分析系统，不是提供商账单对账系统。

## 验证

- Regression — `AgentSessionUsageAttribution.test.ts` 覆盖立即持久化、两种关联顺序、子任务消息投影、总账中的未绑定费用、关闭、延迟完成和重复绑定不产生额外费用。
- Regression — `ApiGatewayService.test.ts` 覆盖延迟归属、子任务摘要归属、跨会话拒绝、凭据限制和捕获释放。
- Regression — 两种 Pi 桌面连接测试将首次输出和续写的原生子任务响应 ID 关联到子任务自己的产品消息。
- Regression — `pnpm db:migrations:check` 与 `pnpm db:migrations:generate` 验证现有迁移链与 schema 一致，无需用量归属迁移。
