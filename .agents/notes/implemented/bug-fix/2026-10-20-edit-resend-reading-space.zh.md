# Agent Note: 编辑重发后的阅读占位

Status: implemented

[English](2026-10-20-edit-resend-reading-space.md) | 中文

## 问题

编辑重发可能将长回复替换为较短的分支。阅读冻结逻辑保留旧内容高度，留下过多空白；首次滚轮输入时全部清除，又可能触发浏览器夹取滚动位置并造成跳动。

## 决策

在异步写入前捕获阅读位置，成功后绑定替换消息的 key。等待旧分支移除及测量稳定。有内容可见时保留阅读位置，否则将编辑后的用户消息定位到顶部。仅保留目标视口所需的占位。

替换稳定后，剩余占位只能因用户上滚、内容新增高度或到达顶部而减少。回收量受视口下方已提交布局约束，避免强制夹取滚动位置。原生滚动条拖动期间暂停回收。程序位移不计入用户消耗。新替换重新计算预算，普通折叠行为保持独立。

## 考虑过的替代方案

保留旧内容高度会留下过多空白。一次性清空会移动视口。将所有向上滚动事件计入消耗会把浏览器夹取也算进去，造成连锁收缩。整页空白时返回回复底部，会隐藏编辑后的用户消息。

## 影响

列表通过现有运行时适配器暴露两阶段替换回调，不新增持久状态、设置、依赖或迁移。新替换会取消旧测量。物理触控板及跨平台行为仍需人工验证。

## 验证

- Regression — Renderer 运行时、MessageVirtualList 和 MessageList 的 153 个测试通过，覆盖最小占位、小数位移、惯性、夹取、拖动暂停、内容增长、乐观分支替换及连续编辑。
- Regression — 使用真实 virtua 与 Chromium 输入的 Electron 组件测试：上滚 120 px 时视口移动 120 px，占位从 300 减为 180 px；整页空白定位到编辑消息并保留 88 px；PageUp 释放剩余占位。
- Regression — Renderer 类型检查、定向 lint 与格式检查通过。完整编辑请求的流式及非流式链路在最终交互调整前验证过，不作为最终版本的端到端覆盖。
