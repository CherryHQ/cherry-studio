# Agent Note: 千问平台发行版与已保存端点

Status: implemented

[English](2026-11-04-qwen-platform-editions-and-endpoints.md) | 中文

## 问题

平台更名后，已保存的官方端点覆盖值仍指向旧域名。v1 发行版豁免也会让
升级用户继续看到另一站点的供应商，即使目录元数据已将其排除在当前发行版之外。

## 决策

- 保留 `dashscope`、`qwencloud` 标识及现有凭证、模型绑定。在供应商服务边界，
  对标准预设、预设派生配置和 v1 用户统一执行目录中的发行版限制。
- 其他供应商保留 v1 豁免；没有关联预设的完全自定义供应商沿用现有规则。
- 追加迁移 `0034_qwen_endpoint_hosts`，更新已保存的旧官方 URL。v1 导入先完成
  与历史默认值的差异计算，再应用相同映射，避免导入的覆盖值重新带入旧域名。
- 更新平台名称的多语言文案及四个密钥／模型选择链接。
  本次不包含来源归因 Header 和 Token Plan 预设。
- 这两个平台上的千问系列模型复用所属供应商的新标识：`dashscope` 使用蓝色，
  `qwencloud` 使用紫色，并沿用已有深色模式资源。模型管理、发现及选择列表为
  派生配置传入预设标识；其他模型系列保留各自的图标。

## 考虑过的替代方案

- 只更新目录默认值，无法更新用户明确保存的旧官方 URL。
- 对所有供应商取消 v1 豁免，会改变无关供应商的兼容行为。
- 将旧供应商转换为另一站点的标识，会悄然改变密钥归属和模型绑定；因此保留被隐藏的记录。

## 影响

[供应商目录参考文档](../../../../docs/dev/references/provider-model/provider-registry.md)
定义可用范围和 URL 映射规则。使用受支持的发行版后，被隐藏的供应商可重新使用，
无需删除或重建数据。本次不新增公共 API、数据库列或用户设置。

迁移只替换 HTTP(S) 端点 URL 中明确匹配的官方主机名，保留其余原始写法，
包括显式默认端口和自定义完整端点末尾的 `#`。包含 ASCII 空白／控制字符、
反斜杠或无效端口的 URL 保持原样，不尝试修复。迁移具有幂等性，也不会持续改写
用户随后输入的 URL。

## 验证

- Regression — `ProviderService.edition.test.ts`：覆盖两个发行版、新用户／v1 用户、预设派生配置、供应商／模型可见性、创建、运行时拒绝，以及隐藏凭证和模型的保留。
- Regression — `qwenEndpointMigration.test.ts`：覆盖带数据升级、重复迁移、精确主机名匹配、URL 后缀保留、代理排除、凭证／模型不变，以及 v1 URL 归一化用例。
- Regression — `ProviderModelMigrator.test.ts`：验证 v1 导入更新两个官方域名，同时保留自定义代理、API Key 和模型绑定。
- Regression — 供应商配置和 DashScope 传输测试覆盖从聊天配置派生的图片域名、自定义域名、请求设置及原生图片传输。
- Regression — 供应商目录的源数据同步、端点矩阵和阿里模型目录测试验证生成的供应商元数据及已有模型契约。
- Regression — `logo.test.ts` 验证千问图标随平台切换、预设派生配置、组合 ID 和其他模型品牌的保留；模型列表及选择器测试覆盖受影响的调用方。

以上检查使用本地测试数据。真实供应商请求及桌面 UI 验收独立于这些自动化验证。
