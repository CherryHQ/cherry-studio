# Agent Note: 窗口重载后恢复聊天草稿文本

Status: implemented

[English](2026-11-27-chat-draft-reload.md) | 中文

## 问题

重载聊天窗口会清空渲染进程中的输入框缓存。重新打开时，会话和已发送消息都在，用户未发送的文本却消失了。[问题 #25530](https://github.com/CherryHQ/cherry-studio/issues/25530) 记录了已有会话中的复现过程。

## 决策

普通聊天输入框通过会话存储保留一份同窗口的草稿文本，沿用已有的会话或输入框标识和 24 小时有效期。读取时优先使用内存中的草稿，附件、标记和选项也继续由内存草稿保存。恢复时以纯文本保留粘贴的网址和已填写的提示词变量值，不保存标记元数据，并去掉其他标记贡献的提示词。清空草稿时会移除恢复副本。发送成功后，即使原输入框已经卸载，也会从会话缓存中清理与提交内容匹配的草稿；文本或标记不同的新草稿会保留。

恢复副本写入时若超出存储配额，输入框会回收自身草稿键前缀下的过期条目，并在回收空间后重试一次。其他会话存储条目和未过期的草稿不受影响。

## 考虑过的替代方案

- 共享缓存会让其他窗口访问草稿，而且输入框必须等主进程返回缓存后才能初始化。
- 把完整草稿序列化为 JSON 会把粘贴附件的 Blob 转成空对象，导致对应的文件标记引用不可用的数据。恢复附件内容需要单独的存储契约。

## 影响

文本恢复适用于同一窗口内的重载。关闭窗口会结束该窗口的存储会话。如果会话存储不可用，切换聊天会话仍可使用内存草稿。

如果用户在等待发送接受结果期间返回原会话，重新挂载的输入框仍可能保留已提交文本，并在卸载时将其写回。清理这个活动输入框需要单独的同步契约。

## 验证

- Regression — `src/renderer/components/composer/variants/__tests__/chatDraftCache.test.ts`：重建渲染进程缓存，验证按会话恢复文本、粘贴的网址、已填写的变量值、清空、过期、排除生成的提示词和标记元数据、保留新的标记选择，以及模拟配额不足后回收过期条目。
- Regression — `src/renderer/components/composer/variants/__tests__/ChatComposer.test.tsx`：在等待发送接受结果期间切换会话，再重建渲染进程缓存，验证成功发送的文本被清理、被拒绝的文本和其他会话草稿保留，并且不会删除新文本。
- Regression — macOS Electron 开发窗口：重载后两条会话分别保留各自的草稿文本，已发送消息的测试数据仍可见，清空其中一条草稿后再次重载仍为空白。
