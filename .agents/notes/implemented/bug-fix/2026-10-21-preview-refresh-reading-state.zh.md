# Agent Note: 文档刷新保留阅读状态

Status: implemented

[English](2026-10-21-preview-refresh-reading-state.md) | 中文

## 问题

文件刷新会重新挂载桌面预览和可移植格式组件，使新文档丢失缩放、页码、滚动位置、工作表和图片变换。仅删除桌面层的刷新 key，无法修复可移植宿主以及主动重置状态的格式组件。

## 决策

桌面宿主通过规范化路径和格式识别预览，可移植宿主使用来源 ID 和格式。刷新替换元数据和已打开的文档，保留兼容的格式组件。各格式拥有自己的阅读状态和资源释放逻辑。内容变短时限制位置；更换文件或格式时重置状态。

刷新开始时仍关闭上一份文档。保留的插件不得为更新的已提交请求发布选择结果或终止性错误。消费者立即清除持有的选择，格式插件取消过期的选择操作。PDF 和 PPTX 在 Activity 隐藏视口前记录位置，重建资源后恢复。

PDF 使用 PDF 坐标保存 PDF.js 的首个可见页锚点。首页就绪不代表其他页面的尺寸有效：未加载的页面使用首页尺寸。恢复前加载锚点及覆盖视口的页面，再应用 XYZ 目标；文档末尾限制视口时也加载涉及的前页。这样避免占位尺寸使浏览器限制阅读位置，同时保留阅读区域以外的按需加载。

PDF 也分别保留实际倍率和自动适应意图。在不同宽度的页面上重新应用适应预设，即使文件和视口未变，也会改变视图。恢复时保留数值倍率；响应式预览仅在容器宽度实际变化时重新适应页宽。

## 考虑过的替代方案

- 仅删除外层 React key，仍会保留可移植宿主和格式内部的显式重置。
- 共享的持久化阅读状态缓存会重复格式所有权，并引入本次修复范围外的关闭后重开历史。
- 复用旧文档或跳过重载会保留过期内容，并违反来源会话的生命周期。

## 影响

阅读状态仅在已挂载预览内保留，并由各格式检查有效性。文件访问、版本校验、大小限制、worker 清理和 HTML 沙箱策略仍归原有模块负责。HTML 成功读取后重建受限 iframe，即使文本未变，也保留源码/预览模式。失败的预览仍可重试；本次修复不承诺在会话失败或卸载后持久保留历史。

## 验证

- Regression — `Preview.test.tsx`：同源刷新延迟完成时保留页码和旧内容，接受替换文档，更换来源时重置，通过 Activity 重连，并拒绝过期的选择与错误。
- Regression — 格式与桌面预览测试覆盖内容重载、缩放/页码/工作表/图片变换保留、内容变短，以及刷新后的选择失效。
- 真实查看器回归 — `pdfFilePreviewRefresh.test.ts` 通过构建后的公共包及未 mock 的 PDF.js 和 Chromium 布局，覆盖混合/等高页面、不同页宽、页内与跨页偏移、缩放模式、Activity 恢复及短文档，包括默认和响应式预览；包内配置拥有测试服务的生命周期。旧的绝对偏移恢复实现会在混合尺寸用例中失败。
