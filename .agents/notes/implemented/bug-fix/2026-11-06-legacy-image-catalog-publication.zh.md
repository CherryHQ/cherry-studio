# Agent Note: 发布目录时保留旧版图片模型

Status: implemented

[English](2026-11-06-legacy-image-catalog-publication.md) | 中文

## 问题

新增规范图片参数可能使冻结的 v2/v3 reader 丢弃整个模型或供应商覆盖记录。目录按记录容错，因此校验器仍会成功返回。校验后直接发布原始 JSON 会掩盖模型丢失。参见 [Issue #23686](https://github.com/CherryHQ/cherry-studio/issues/23686)。

## 决策

发布器在校验前，将图片参数映射投影到冻结 v1-v3 schema 共享的词表。该历史词表属于降级契约，不能跟随当前应用枚举增长。投影覆盖模型及供应商覆盖记录中的每种现有图片模式，并保留已知参数的定义。

发生变换的文件使用与目录生成器共用的序列化器重新计算内容哈希版本，清单记录实际输出版本。未变换文件和当前 schema 流保留原始字节。既有旧流的应用最低版本与结构不兼容处理保持原样。冻结校验器不可修改。

## 考虑过的替代方案

- 冻结旧目录：违背已发布客户端继续接收兼容目录更新的承诺。
- 删除整个模型或按模型 ID 特判：丢失可用能力，或将兼容性绑定到单一厂商。
- 改写冻结校验器或使用当前枚举：改变历史 reader 契约，而非向其投影。

## 影响

发布器维护一份 v1-v3 的历史参数词表。新模式、协议及不受支持的参数定义结构不会被推断为兼容。共享序列化器是具有两个生产消费者的仓库工具，不改变包导出或内置目录。

## 验证

- Regression — `pnpm test:scripts scripts/__tests__/publishRegistryCatalog.test.ts scripts/__tests__/buildRegistrySyncRequest.test.ts`：用冻结 reader 的临时副本解码真实发布器输出，副本仅暴露既有解析结果；在 v1-v3 和全部五种图片模式下，未知参数不再导致模型或覆盖记录丢失。
- Regression — 模型保留断言在投影前失败，独立计算的内容哈希断言在重新打版本前失败。通过实际输出文件检查当前流与未变换文件的字节、清单版本、应用最低版本及无法降级的结构错误。
