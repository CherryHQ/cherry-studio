# Agent Note: 稳定的账户菜单快照

Status: implemented

[English](2026-10-29-account-menu-cache.md) | 中文

## 问题

关闭头像菜单会卸载账户面板。重新打开时，账户状态和订阅查询都会重置为加载中，短暂替换账户身份、付费套餐和可用操作。

## 决策

账户状态使用渲染进程内存中的 SWR 缓存。状态事件和完成的登录操作更新这份缓存；SWR 的变更顺序机制阻止较旧的状态读取覆盖较新的事件。后台刷新期间，已知状态保持就绪。

账户查询跟随面板的挂载生命周期，包括弹出层的退出动画。关闭菜单时，不会在内容卸载前清空查询键。

侧栏保持状态观察者挂载，并在菜单打开前准备订阅数据。面板和订阅设置复用已有的套餐缓存键，其中包含账户 ID。切换账户时，即使显示名称相同，也会选择另一条缓存记录；旧账户延迟返回的响应不能写入新记录。刷新期间保留已知套餐。没有缓存数据时的首次加载失败仍可重试。

存在有效付费套餐时，头像下方显示套餐名，菜单行显示用量和各额度周期中最低的剩余比例。重叠的限制不相加；未配置额度时显示已有的无额度提示。点击该行可查看完整用量明细。没有有效付费套餐时保留订阅操作。缓存记录只包含展示数据，不包含凭据，也不会跨渲染进程重启持久保存。

## 考虑过的替代方案

- 保持所有隐藏浮层挂载会保留无关的浮层状态，而且不能复用订阅设置数据。
- 组件局部缓存仍会在卸载时丢失快照，并需要单独处理请求顺序。
- 不区分账户的单一套餐键可能在会话切换后展示其他账户的套餐。

## 影响

刷新尚未完成或刷新失败时，界面可以继续展示缓存数据。状态事件和 SWR 的正常重新验证提供更新；刷新成功后替换快照。这属于展示缓存，不用于授权判断，也不改变计费行为。

## 验证

- Regression — `src/renderer/hooks/__tests__/useCherryAccountSession.test.ts`：重新挂载和未完成的刷新保留已知会话；较旧请求不能覆盖较新状态事件。
- Regression — `src/renderer/components/__tests__/UserAccountPanel.test.tsx`：重新打开时保留缓存的身份和套餐，直到刷新完成；切换账户会清除旧套餐，覆盖显示名称相同和响应延迟的情况；首次失败仍可重试。
- Consumers — Sidebar、SubscriptionSettings 和 OnboardingPage 的定向渲染进程测试在使用缓存会话钩子后通过。
