# Agent Note: 主窗口默认尺寸与屏幕边界

Status: implemented

[English](2026-11-14-main-window-bounds.md) | 中文

## Problem

主窗口将 960 × 600 的最小尺寸直接用作初始尺寸。历史边界虽然能缩小到较小屏幕内，但固定的原生最小尺寸以及最小尺寸重置仍可能将窗口再次撑出屏幕。

## Decision

主窗口首次使用主屏幕可用区域的 90%，上限为 1440 × 900 DIP；可用区域允许时，下限为 960 × 600。有效历史边界优先。初始矩形和原生尺寸限制均适配可用区域，包括坐标为负的显示器。

MainWindowService 将请求的最小尺寸与受屏幕限制的原生值分别保留。显示器变化和普通窗口恢复时，重新应用该最小尺寸以及当前可用区域的上限，从而在显示器变化后保留紧凑模式。屏幕监听器由服务生命周期管理，窗口监听器在创建时绑定。最大化、全屏、最小化和已销毁窗口不进行普通窗口边界修正。

## Alternatives considered

- 更大的固定默认尺寸可能超过小屏幕。
- 提高全局最小尺寸会恶化小屏幕行为，并影响无关调用方。
- 丢弃历史边界会放大用户主动调整过的窗口。

## Consequences

现有有效历史尺寸不会自动放大。屏幕小于正常最小尺寸时，优先满足屏幕边界。默认尺寸上限不阻止用户手动放大窗口至可用区域。移动完成检查使用 Electron 在 macOS/Windows 上的 `moved` 事件；Linux 的窗口位置由窗口管理器控制。

## Verification

- Regression — `mainWindowBounds.test.ts`：初始尺寸、可用区域偏移、超宽屏和竖屏、负坐标、显示器移除、无效记录及最小尺寸扩展，均保证最终矩形处于可用区域内。
- Regression — `MainWindowService.test.ts`：最小尺寸重置适配宽高两个维度，请求的紧凑模式最小尺寸在屏幕变化后保留，屏幕事件修正实际窗口，全屏恢复时适配普通边界且不改变特殊窗口状态。
- Regression — macOS Electron 45.2.2 实机：在 1728 × 1024 可用区域内，初始边界为 1440 × 900；重启恢复 1200 × 760；紧凑模式、最小尺寸重置、屏幕外窗口修正及退出全屏均保留可用的普通窗口边界。Windows/Linux 和物理显示器热插拔尚未实机验证。
