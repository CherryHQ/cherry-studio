# Agent Note: 代码查看器的原点随布局变化更新

Status: implemented

[English](2026-10-31-code-viewer-layout-origin.md) | 中文

## Problem

展开的 `CodeViewer` 使用外层滚动容器。`scrollMargin` 表示代码列表在可滚动内容中的原点，普通滚动不会改变这个值。但 PR #22469 引入的滚动监听器会在每次滚动事件中读取列表和容器的矩形，并提交这个原点。即使提交的状态值相同，与虚拟列表的同步更新交错时仍可能导致组件重复执行。

仅删除该监听器会留下位置跟踪缺口。固定高度的祖先内部，前置兄弟元素可能改变尺寸；Virtua 也可能只修改消息包装元素的 `top`，不改变其尺寸。这两种情况都会移动代码块，却不会触发原先观察的祖先元素的尺寸通知。

## Decision

在初始化和布局失效通知时测量原点，并在更新状态前保留相等值去重。通过 `ResizeObserver` 观察查看器根元素、直到滚动容器的祖先，以及这些元素的前置兄弟元素。通过 `MutationObserver` 观察祖先的 `style`／`class` 属性和直接子节点列表变化，以及前置兄弟元素的 `style`／`class` 属性。子节点列表变化后刷新观察目标，让新增兄弟元素参与观察，并释放已移除节点。

不观察查看器内部的虚拟代码行或语法标记子树，避免将它们的滚动和高亮更新转化为布局原点失效通知。在 effect 清理时断开两个观察器。保留用于选区记录的既有滚动监听器，以及虚拟列表自身的滚动订阅。

## Alternatives considered

- 仅对相等值去重可以减少重复状态提交，但每次滚动回调仍读取矩形。
- 仅观察祖先尺寸会漏掉固定高度容器内兄弟元素的增长，以及虚拟列表项仅改变位置的情况。
- 观察整个消息子树会将代码行虚拟化和语法高亮转化为重复的几何测量。
- 短代码块渲染阈值和更换虚拟列表属于独立优化，不在本次修复范围内。

## Consequences

普通滚动事件派发期间不再测量代码列表原点。布局通知仍需要读取几何信息；属性观察是保守的，也可能响应不影响几何的变化，例如 Virtua 在滚动开始和结束时切换 `pointer-events`。不引入轮询或逐帧位置观察器。既有代码行尺寸、滚动锚定、选区、截图和高亮行为保持不变。

## Verification

- Regression — `pnpm test:renderer src/renderer/components/__tests__/CodeViewer.test.tsx`：滚动会推进虚拟代码行，但不读取列表原点；前置兄弟元素尺寸变化、祖先重新定位以及兄弟节点插入／删除，无需滚动事件即可更新显示的代码行。
- Regression — `tests/e2e/ondemand/specs/code-block-scroll.ts`：真实消息列表滚轮滚动期间，滚动事件派发过程不读取代码列表矩形，完整保留可见代码块的源代码行，并在反向滚动后恢复第一个代码块。
