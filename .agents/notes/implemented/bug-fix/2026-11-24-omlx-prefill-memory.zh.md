# Agent Note：归类 oMLX 预填充阶段的内存拒绝

Status: implemented

[English](2026-11-24-omlx-prefill-memory.md) | 中文

## 问题

[#25181](https://github.com/CherryHQ/cherry-studio/issues/25181) 的 oMLX 错误包含用于计算内存的安全余量。共享分类逻辑把 “safety” 当作内容策略信号，导致 Work 提示用户修改输入。

## 决策

共享分类逻辑识别这条错误文案和明确的服务商错误码，将它归为预填充内存不足。沿用原有错误卡片，提示用户缩短对话或使用更小的模型。详情保留原始错误。

## 考虑过的替代方案

- 通用 HTTP 400 提示缺少可操作的恢复信息。
- 即使请求仍在模型的上下文窗口内，上下文超限分类也可能把用户引向自动上下文恢复。oMLX 有单独的内存预算。

## 影响

桌面端可单独识别这类资源不足。远程协议沿用通用回退，并带上服务商文案和 HTTP 状态。显式内容策略信号保持原优先级。

## 验证

- 回归 — Windows Electron 的 Work 会话对原始 HTTP 400、旧版错误文案和仅含专用码的响应显示内存不足提示。内容拦截和普通 400 保持原提示。
- 回归 — 共享分类测试覆盖结构化状态的优先级，以及普通校验错误在正文提到专用码的情形。
