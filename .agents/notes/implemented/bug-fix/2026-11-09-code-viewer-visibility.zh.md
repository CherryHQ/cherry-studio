# Agent Note: 代码查看器在视口可见性变化时通知渲染

Status: implemented

[English](2026-11-09-code-viewer-visibility.md) | 中文

## 问题

展开的代码查看器位于视口外时不渲染代码行。短代码块在滚出视口后再滚回来时，TanStack 的行范围可能始终为 `[0, 0]`。滚动持续期间，虚拟列表会更新偏移量，但范围不变时不会通知 React。消息列表的滚动补偿将代码块带回视口后，标题已经可见，正文却要等到 150 ms 后的滚动结束通知才恢复。已就绪的高亮随代码行一起出现，看起来像是高亮延迟。

## 决策

包装元素和窗口的偏移量观察器，使用缓存的几何信息比较虚拟列表更新前后的视口可见性。跨越可见性边界时通知其 React 适配器。保留现有的代码行虚拟化和屏外省略行为。首次进入可见区域的查看器还会在发起首次高亮请求前，给纯文本一次绘制机会。

## 考虑过的替代方案

- 仅延后高亮：即使高亮或纯文本已经可用，代码行仍可能缺失。
- 渲染全部屏外代码行：移除了可见性优化，没有修正其通知契约。
- 滚动时读取矩形：缓存的偏移量、视口高度、原点和总高度已经足以确定可见性；[布局原点决策](2026-10-31-code-viewer-layout-origin.md) 将几何读取保留在布局失效时。

## 后果

短代码块在持续滚动中返回视口时立即恢复可读。即使行范围不变，跨越可见性边界也能通知 React。普通偏移量更新仍使用 TanStack 按行范围触发的通知；没有新增定时器、逐帧观察器或滚动期间的矩形读取。

## 验证

- Regression — `CodeViewer.test.tsx` 在真实 TanStack 视口中，将单行代码块滚出再滚回，整个过程保持滚动：正文必须在滚动结束前立即恢复。旧实现会留下空白。
- Regression — `CodeViewer.firstPaint.test.tsx` 让高亮立即完成：首次高亮请求前完整纯文本仍然可用，高亮就绪后文本内容保持一致。
- Electron — 在已有会话中发送消息并滚动查看代码块，修复前能复现约 150 ms 的可见正文空白。修复后同场景录像没有采样到可见正文空白；新代码先显示纯文本，再显示高亮。
