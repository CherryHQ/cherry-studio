# Agent Note: 移除 v1 数据迁移

Status: proposed

[English](2026-11-09-retire-v1-data-migration.md) | 中文

## 问题

应用进入 v2 后仍携带完整的 v1 到 v2 转换引擎、迁移窗口、IPC、preload 和渲染器。移除转换能力不能让从 1.9.x 升级的用户进入空白数据目录。

## 提议

用一个在应用 bootstrap 之前运行的小型 preboot 兼容性检查替换转换入口。保留最小的只读旧数据和迁移状态检测，包括旧版自定义数据目录。尚未迁移或迁移未完成的数据阻止启动；检查不能仅为判断状态而创建数据库或标记迁移完成。已完成的 v2 迁移状态优先于残留的 v1 文件。全新数据目录和已建立的 v2 数据目录正常启动。

提供本地化的原生对话框，允许下载含迁移能力的版本或退出。下载操作在系统浏览器打开 https://github.com/CherryHQ/cherry-studio/releases/tag/v2.1.10 后退出。说明用户必须安装并启动 v2.1.10、完成迁移，再重新安装新版。关闭对话框也退出。该固定版本包含迁移引擎，是准备方案时核实的最新已发布版本；实现发布前再次核实截止版本。

旧版自定义数据目录不可访问或迁移状态无法读取时，显示可操作的错误并停止启动，不能将其视为空目录。保留开发环境数据隔离。被拦截的启动不能修改旧数据、持久化更改数据位置，或初始化空的 v2 数据库。

删除 v1 转换引擎和迁移器、迁移 UI 及通信层，以及仅供迁移使用的导出、构建入口、依赖、测试和已无其他消费者的生成映射。先修改生成器的源，再重新生成相关产物。保留仍被迁移之外的模块使用的共享工具、现行 Preference 和 BootConfig 生成、备份恢复，以及所有已发布的 SQLite schema migration。更新受影响的现行参考文档，保留历史 Agent Notes。

## 考虑过的替代方案

无限期保留转换会持续产生运行和维护成本。静默进入新数据目录会让用户误以为数据丢失。链接到最新版本不稳定，因为未来的最新版本将不再包含转换能力。固定含迁移能力的版本可以提供可重复的升级路径。

## 验收标准

- AC1 — 未迁移的 1.9.x 数据在 bootstrap 前被拦截，并收到固定下载链接及升级说明；下载、退出和关闭对话框均不能启动应用。 (verification: unit and Electron)
- AC2 — 全新数据目录及已完成迁移的 v2 数据目录正常启动且不执行转换，包括残留旧文件的情况。 (verification: unit and Electron)
- AC3 — 旧版自定义目录、不可访问目录、不可读状态及未完成迁移不能被静默视为全新数据；被拦截的检测不修改业务数据和迁移状态。开发环境隔离仍有效。 (verification: unit with filesystem and database fixtures)
- AC4 — 生产产物不再包含 v1 转换系统或迁移窗口；保留的消费者编译通过，已发布的 SQLite migration 不变。 (verification: scoped typecheck, build inspection, and diff review)
- AC5 — 原生提示完成本地化，受影响的双语文档说明固定的中转升级路径。 (verification: locale checks and docs gate)

## 风险

过期的迁移标记或旧目录检测规则可能误判数据。测试必须使用真实持久化数据覆盖迁移完成但有旧文件残留及转换中断的情况。中转版本必须保持可下载且支持用户的平台。检查 tag 源码只能确认转换能力存在，发布前仍需验证打包版本的升级行为。安装中转版本时用户必须保留原有数据。
