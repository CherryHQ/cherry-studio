# Agent Note: 恢复 Chat 上下文超限

Status: proposed

[English](2026-11-13-chat-context-overflow.md) | 中文

## Problem

持久化 Chat 在请求前估算上下文，并在达到配置的阈值时压缩。提供商的 token 计数、工具 schema、多模态内容和工具结果可能导致实际输入超限，即使估算结果仍在范围内。AI SDK 的常规重试不会改变输入，而且上下文超限 HTTP 400 通常不可重试。Cherry 的循环错误钩子目前也没有实现重试。

摘要本身也是一次模型请求。目前摘要预算依赖估算，会用简短占位替换过大的工具结果，必要时还会丢弃中间消息并加入省略标记。首条消息和指令仍可能超过预算。摘要失败后，Chat 会使用原有上下文，后续模型请求也可能失败。

## Proposal

保留现有的预先压缩和用户设置。对启用压缩的持久化 Chat，根据提供商状态码与结构化错误信息识别真实的上下文超限，必要时兼容提供商的错误文本。普通 HTTP 400、鉴权、配额、工具、取消及其他无关错误保持现有结果。无法恢复时保留提供商原始错误。

识别到超限后，压缩失败模型请求所用的模型上下文，再以更小的上下文重试该请求。恢复必须发生在该请求的任何输出被提交之前，且不得重放已完成的工具调用、之前的输出或整个轮次。保留工具调用与结果的配对、系统指令、当前用户输入、取消操作，以及现有重试和后备行为。限制恢复次数，压缩没有取得进展时停止。遵守关闭压缩的设置，以及现有对临时聊天、调用方持有上下文和 Agent 会话的排除规则。

摘要使用压缩模型自身的输入和输出预算。按顺序将过长历史拆成有界的分块并滚动合并摘要；估算不准导致压缩模型拒绝某个分块时，缩小分块并在有限次数内重试。单条文本过大时，在可行的情况下拆分。不得为了适配窗口而静默遗漏输入后宣称摘要完整：非文本项、指令或最小分块无法安全容纳时，明确失败并保留原有上下文。现有对附件和工具结果的有意缩减仍须可识别。空摘要或失败摘要不得推进持久化边界，也不得显示为压缩成功。

原始对话记录保持不变；只有成功完成的持久化摘要才能更新现有边界。循环内压缩仍限定于当前请求。可观测信息必须区分尝试、成功、跳过和失败，不得提前宣称恢复成功。

## Alternatives considered

- 在 400 后重试整个 Chat 轮次：这可能重复执行已经完成的工具并重复显示输出。
- 重试所有 HTTP 400 或原样重发输入：这会误判无关错误，或重复发送无法容纳的请求。
- 丢弃旧历史直到摘要请求可以容纳：这可能推进持久化边界，同时生成不完整的摘要。

## Acceptance criteria

- AC1 — 持久化 Chat 请求因估算偏低收到可识别的上下文超限 HTTP 400 后，会压缩并重试失败的模型请求，然后使用压缩后的上下文继续。 (verification: AI SDK runtime integration — implementation owner)
- AC2 — 工具循环超限后保留之前的可见输出和已完成工具结果，不重复执行已完成的工具；恢复次数有界，取消操作能终止恢复。 (verification: AI SDK runtime integration — implementation owner)
- AC3 — 无关的 400、鉴权和配额失败、关闭压缩及不支持的 Chat 范围不会触发超限恢复；无法恢复时保留原始错误。 (verification: AI SDK runtime integration — implementation owner)
- AC4 — 摘要按顺序处理多分块历史，通过有界缩小处理估算偏低的分块，且不静默遗漏覆盖的消息；最小分块无法容纳或摘要失败时，持久化边界保持不变。 (verification: ai-core and real SQLite Chat context — implementation owner)
- AC5 — 压缩生命周期报告和保留历史能区分成功、失败及无操作，包括重新打开对话后。 (verification: Main consumers and real SQLite — implementation owner)

## Risks

提供商错误格式各异，匹配不准确可能触发不安全的重试，也可能漏掉真实超限。多模态载荷和工具 schema 可能占据无法通过压缩历史释放的大部分空间。多次摘要调用会增加延迟和费用，而且即使每个分块都被处理，摘要仍不可避免地有损。配置的压缩模型可能无法容纳最小可用提示，因此无法保证恢复成功或任务不中断。
