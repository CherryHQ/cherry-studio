# Agent Note: Sentry 应用稳定性上报

Status: proposed

[English](2026-10-27-sentry-stability-reporting.md) | 中文

## 问题

自动上传错误日志会把共享的 Sentry 额度消耗在可恢复的网络和业务失败上。同一次 DataApi 失败还可能在多个边界被记录。这些上报挤占了应用故障和移动端事件的额度。现有本地日志和用户主动发起的应用内反馈已经承担运行问题排查。

## 提案

分离日志与遥测。包括 `logger.error` 在内的普通日志保留在本地，供反馈使用。Sentry 接收非预期的未处理异常、已捕获的 DataApi 内部故障、显式上报的渲染失败、致命启动失败，以及 Electron 进程崩溃摘要。应用故障被捕获不代表它符合预期；网络失败未被处理也不代表它值得上报。

以主进程 SDK 的发送前回调作为主进程和界面事件共用的策略边界。过滤自动捕获的非致命事件中已知的取消和网络传输失败。显式启动或渲染失败、致命异常即使原因类似暂时性错误，仍可上报。不统一屏蔽所有 `NOT_FOUND`：移除日志桥接后，正常处理的请求不再上传，非预期的未处理失败仍然可见。

DataApi 捕获到 `INTERNAL_SERVER_ERROR` 或 `DATA_INCONSISTENT` 时，仅发送一次包含原始错误的事件。遥测服务在 DataApi 初始化完成后订阅，数据层不依赖 Sentry。这些显式上报保留堆栈和底层异常链，共用意外异常的额度与运行噪声过滤；其他已处理的请求错误留在本地。通用错误边界和文件预览错误边界都上报捕获的渲染故障，并保留现有降级界面。

对规范化的错误特征跨窗口去重，窗口为十分钟。每个运行中的应用分别保留每小时十条应用致命故障、渲染或启动事件，以及十条其他意外异常的额度。仅保留容量受限的内存状态，保留首次接收的样本，不改变本地日志。不进行随机采样。

复用 Electron SDK 的进程退出检测，不启用操作轨迹、子进程命令参数或原生内存附件。通过现有生命周期事件观察采用 fail-fast（失败即中止）策略的服务初始化失败，以及主窗口初始化失败，不改变主窗口当前允许启动流程继续的错误策略；逃逸到启动最外层的意外错误在退出前进行有时限的发送等待。保留用户授权、隐私政策版本检查、脱敏和开发模式禁用。在能够读取授权之前，失败只保留在本地；主进程原生崩溃转储也保留在本地供诊断使用。不引入新的授权缓存或离线上传队列。

## 考虑过的替代方案

- 服务端限流：当前套餐不支持，也不能明确哪些应用事件值得上报。
- 保留日志桥接并扩大排除列表：新增业务错误仍会默认进入上报。
- 只做随机采样：既保留低价值噪声，又可能丢失新故障的首个有效样本。
- 全局忽略 `NOT_FOUND` 或所有类似网络错误的事件：会掩盖状态缺陷和启动失败。
- 上传原生内存或持久化授权前的事件：扩大现有授权和诊断边界之外的数据收集。

## 验收标准

- AC1 — 普通主进程和界面错误日志保持可用，不产生 Sentry 事件。（验证：unit；负责人：维护者）
- AC2 — 非预期的未处理异常、已捕获的 DataApi 内部故障、通用及文件预览边界内的渲染失败、主窗口和 fail-fast 服务初始化失败，以及受支持的 Electron 进程崩溃摘要可进入上报。（验证：unit 和 Electron；负责人：维护者）
- AC3 — 自动捕获的取消和网络传输噪声被丢弃，显式应用故障和未知错误不会因此被丢弃。（验证：unit；负责人：维护者）
- AC4 — 交错出现的重复错误和变化的 UUID 不能绕过十分钟去重窗口，一类事件不能耗尽另一类事件的每小时额度。（验证：unit；负责人：维护者）
- AC5 — 开发模式、缺失或撤回或过期的授权、脱敏以及不上传原生内存的现有保证保持有效。（验证：unit 和 Electron；负责人：维护者）

## 风险

改动只对已升级的客户端生效。每个安装实例的额度不能保证组织级总额度。仅保留在本次进程中的去重状态会在应用重启后重置。在现有授权模型下，偏好不可读时发生的启动失败无法自动上传。原生主进程崩溃通过本地诊断转储保留，不自动上传内存。负责人已在当前对话中要求实现这一边界；此处不声称已获得 GitHub Spec 审批或已执行运行时验证。测试和构建仍由用户决定。
