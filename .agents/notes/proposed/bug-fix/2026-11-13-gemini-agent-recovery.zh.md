# Agent Note: Gemini 智能体工具校验与 Pi 原生恢复

Status: proposed

[English](2026-11-13-gemini-agent-recovery.md) | 中文

## 问题

Gemini 可能以 `MALFORMED_FUNCTION_CALL` 终止生成。将该结果报告为成功会掩盖失败；仅保留失败状态也不能减少发生次数或恢复中断的智能体步骤。调整默认策略前，必须先保证显式 Gemini 函数调用策略经过 SDK 转换后仍然有效。

Cherry 的 Pi runtime 目前强制设置 `retry.enabled: false`。已安装的 Pi 1.5.2 会话已经拥有重试预算、可取消退避、失败尝试历史省略和继续执行机制。其分类器可以识别临时状态码文本，但不能识别 `Provider stopped with: MALFORMED_FUNCTION_CALL` 或 PR #24442 中通用的 `error`/`other` 结束文本。因此仅打开重试并不能证明能够恢复本次故障。

现有[网关 SDK 转发决策](../../implemented/architecture/2026-11-09-gateway-sdk-forwarding.md)继续有效：网关只执行一次 SDK 调用，不拥有智能体循环或生成重试。

## 提案

### 默认策略

对于 Cherry 管理的 Pi 智能体请求，当目标为 Google Gemini 生成端点且包含函数工具时，仅在调用方未指定模式或提供 `MODE_UNSPECIFIED` 时选择 `VALIDATED`。保留显式 `AUTO`、`NONE`、`ANY`、`VALIDATED` 和允许函数范围。外部网关调用方、普通聊天、其他提供商、Claude、ACP 和 Pi Durable 保持现有默认值。

策略放在受管理的 Pi 请求所有者处，通过网关复用现有 SDK 工具选择和严格 schema 能力。不覆盖原始 HTTP 请求体、不为收紧约束而重写 schema、不从历史校验中删除工具，也不在提供商拒绝校验模式时静默回退到 `AUTO`。初始范围不增加用户设置。

### 原生运行时恢复

使用 Pi 原生 AgentSession 重试机制，不在 Cherry 中增加第二套 prompt 循环或 HTTP 重试包装。网关和提供商 HTTP 重试保持为零。每次失败的生成最多重试一次，等待一秒且可以取消。模型步骤成功后重置预算；连续失败的生成不能重置预算。

为使用 Gemini 的受管理 Pi 会话启用原生临时错误恢复。保留 Pi 现有的配额和计费错误排除规则，以及上下文溢出的压缩路径。其他模型和 runtime 保持现有重试设置。

在原生 SDK 分类边界补齐范围明确的畸形函数调用恢复。提供商原始终止原因经过提供商归一化、网关错误帧和 Pi 错误表示后仍须保留。优先使用上游支持的分类钩子；若不存在，在该所有者处维护带测试的局部依赖补丁。不修改 AgentSession 私有方法，不把所有 `other` 归为临时失败，也不为了匹配重试正则而伪造状态码。输出的提供商错误必须仍可与鉴权、schema、配额、安全拒绝和未分类终止失败区分。

已检查的 Pi 底层循环会先判断 `error`/`aborted`，再执行该响应的工具调用。使用锁定的 SDK 验证这一顺序：失败响应中的调用绝不能执行，先前成功步骤已完成的工具则保留在原生历史中且不重放。即使失败尝试从后续模型输入中省略，也保留其诊断与用量。用户取消、关闭和 detach 所有权处理不能发起新的尝试。恢复结束后仅发布一次最终运行结果，不能让临时失败尝试提前结束整个运行。

### 交付与证据

先落地显式工具策略透传，再依据本 Spec 将受管理默认策略和原生恢复作为独立可审查变更实现。修改依赖前检查已有 SDK 补丁。针对锁定的包验证每个依赖补丁，并覆盖流式和非流式网关错误转换。这些检查证明恢复契约，不代表畸形生成已经被消除。

真实提供商 A/B 使用相同失败请求、模型、工具和历史，对比默认生成与 `VALIDATED`；分别报告尝试次数、失败次数、token 用量和延迟，与确定性夹具证据分开。若缺少原始请求或提供商访问条件，应记录缺口，不宣称已复现事故或测得可靠性提升。

## 考虑过的替代方案

- 不修复分类而直接启用重试：通用终止错误和原生畸形函数错误目前不会命中重试分类器。
- 在网关重试：网关无法安全拥有工具执行和调用方历史，且违反现有转发决策。
- 实现第二套 Cherry 重试循环：重复 Pi 的取消、历史和最终结算所有权。
- 对所有 Gemini 调用方强制 `VALIDATED`：改变外部 API 默认行为并覆盖显式调用意图。
- 重试所有 `other` 或所有校验失败：混淆未知或正常的提供商状态、确定性无效请求和临时生成失败。

## 验收标准

- AC1 — 受管理 Pi Gemini 请求包含函数工具且模式缺失或未指定时才使用 `VALIDATED`；显式模式和函数范围保留到提供商请求，外部及非 Gemini 请求保持默认行为。 (verification: unit)
- AC2 — 首次生成畸形、随后生成有效时，在一次原生 Pi 运行中恰好请求模型两次，仅发布一次最终成功结果，并保留两次尝试的用量。 (verification: unit)
- AC3 — 连续两次畸形生成恰好产生两次请求和一次最终失败结果；无关终止原因及确定性、鉴权、配额错误不会新增重试。 (verification: unit)
- AC4 — 退避期间或下一请求发起前取消，阻止恢复派发且仅保留一次取消结果。 (verification: unit)
- AC5 — 失败响应中的调用绝不执行；后续生成失败前已完成的工具只执行一次，其结果在重试和会话重新加载后仍保留。 (verification: unit)
- AC6 — 原生 Pi 历史、投影、排队输入和关闭在重试期间保留其所有权，不引入网关或 HTTP 重试及新的 prompt 重放。 (verification: unit)
- AC7 — 实现报告区分确定性的请求和运行时测试与真实提供商 A/B 证据，并明确标注未完成的事故复现。 (verification: docs gate)

## 风险

`VALIDATED` 可能拒绝 schema 或不受兼容网关支持，该失败保持显式。重试增加计费生成和延迟。锁定版本的原生 Pi 根据消息文本分类错误，因此准确传递原因并测试提供商错误封装是前提。SDK 补丁更新可能改变重试、历史和最终结算行为；测试必须覆盖锁定的原生 runtime，而非模拟重试回调。Pi Durable 需要独立的日志与计量设计，不在本次变更范围内。
