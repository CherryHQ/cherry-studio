# Agent Note: 创建远程对话时选择桌面模型

Status: proposed

[English](2026-11-24-remote-session-model-selection.md) | 中文

## Problem

桌面端支持为每个交互会话单独选择模型。配对的手机能看到智能体的默认模型，但无法查询这台电脑上可选的模型，也无法在创建会话时指定模型。

## Proposal

桌面端声明是否支持为新远程会话选模型。手机通过已有的智能体授权，分页读取所选智能体在这台电脑上可选的模型。由桌面端判断提供商可用性、运行时兼容性及 Cherry Cloud 访问权限，返回提供商和模型的标识与显示名称。手机从草稿输入框打开模型选择器，按提供商分组，并提供跟随智能体默认模型的选项。

用户明确选择的模型随 `agent.sessions.create` 提交。桌面端在创建时按当前目录校验，并在已有事务中随会话保存。省略模型时，会话跟随智能体默认值。手机将选择随待处理的创建命令一同记录，供重连恢复。执行时沿用[会话模型归属决策](../../implemented/bug-fix/2026-11-14-agent-session-model-ownership.md)。

## Alternatives considered

导出提供商配置需要另一项授权，也会要求手机负责桌面端的筛选规则。每条消息都携带模型，会让两端对同一个会话的模型选择产生分歧。

## Acceptance criteria

- AC1 — 配对手机可按提供商浏览所选智能体在桌面端可选的模型，并能区分来自不同提供商的同名模型 (verification: unit and mobile)
- AC2 — 新对话从第一轮起使用选定模型，之后在任一端继续对话都沿用该选择；其他会话和定时任务各自的模型规则不受影响 (verification: unit)
- AC3 — 跟随智能体默认模型时，会话模型覆盖值为空。连接旧版桌面端时，手机仍可照常创建远程对话，且不显示模型选择器 (verification: unit and mobile)
- AC4 — 创建前模型已不可用时，桌面端拒绝创建，手机可恢复草稿。携带待处理创建命令重连时，模型选择与命令标识均保留 (verification: unit and mobile)

## Risks

从浏览到发送期间，电脑账号或权益等变化可能影响目录可见性。桌面端需要在写入会话前校验当前选择。移动端依赖共享的协议定义，更新时需要与协议包发版协调。
