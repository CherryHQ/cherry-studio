# Agent Note: 原生消息外观控制

Status: proposed

[English](2026-11-22-message-appearance-controls.md) | 中文

## Problem

Issue #12917 请求为消息头像、服务商名称、不同角色的背景和时间戳，以及思考／搜索间距提供原生控制。自定义 CSS 使这些选择依赖内部标记结构。应由共享消息设置和渲染配置负责这些偏好。

## Proposal

分别添加用户与助手／模型头像、时间戳开关，服务商名称开关，用户与助手背景开关，以及思考和内置／服务商搜索组件上下间距的四个数字控件。在设置 > 外观及共享对话偏好面板中提供相同控件，并配备可搜索的设置锚点和翻译后的无障碍标签。

通过现有 Preference 服务持久化，定义来源为 `scripts/data-classify/data/target-key-definitions.json`，由工具生成类型与默认值。头像、时间戳默认显示；服务商名称、助手背景默认隐藏。用户背景覆盖值可为空，未明确修改前跟随简洁／气泡样式，以保留原有默认效果。修改后，明确选择独立于布局生效。不改写消息数据或历史快照。

共享渲染配置 hook 解析布局相关默认值，并向现有和重新挂载的列表分发已保存的选择。消息头和右对齐用户布局均遵守头像设置，不留下空头像列或偏移的页脚。隐藏时间戳不得隐藏 token 用量、选择控件、投递来源或消息操作。服务商标签使用生成消息的模型身份，通过当前名称解析器显示；配置删除后回退为服务商标识符。

背景使用现有语义 muted 表面。编辑、附件、多模型横向滚动、用户气泡布局不依赖背景是否绘制。头像开关也控制次级模型身份图标。

间距接受 0 至 32 的整数像素。导入值限制在该范围，非法数字使用默认值；兼容默认值为思考上方零、下方二，搜索上下各一。搜索间距覆盖进行中、失败、空结果、不透明服务商输出和成功结果。嵌套过程的 CSS 不得覆盖已保存的思考间距。纯内容的思考／搜索展示也应获得相同有效间距，且折叠组件内部不得重复应用。

不包含自定义颜色、逐条消息覆盖、服务商改名、导出样式、通用 MCP 工具间距或尚未明确的未来控件。它们可另行提议。

## Alternatives considered

- 保留自定义 CSS：没有原生发现和持久化契约，选择器仍不稳定。
- 永久将背景绑定到简洁／气泡样式：无法满足独立选择要求。
- 为两种布局使用同一用户背景布尔默认值：会静默改变原有简洁或气泡效果。初始可空覆盖值可避免此变化。
- 将外观选择存入消息：重复全局偏好，并在内容未变时改写历史数据。
- 支持任意间距或颜色字符串：验证、主题和支持范围超出所请求控件。

## Acceptance criteria

- AC1 — 两处设置提供可访问、已翻译、可搜索的控件；保存选择在重新挂载／重启后保留，并传播到其他消息列表，不改变无关偏好。 (verification: renderer and Electron)
- AC2 — 独立用户／模型头像选择覆盖简洁与气泡布局及次级模型图标，在窄宽度下不留下空头像列、裁剪内容或错误页脚偏移。 (verification: renderer and Electron)
- AC3 — 服务商标签对应生成消息的模型，解析配置名称，配置删除后回退；用户消息或关闭选项时不显示。 (verification: renderer)
- AC4 — 两种布局中的用户与助手背景可独立切换，保留既有默认值、附件、编辑和多模型滚动。 (verification: renderer and Electron)
- AC5 — 用户／模型时间戳选择互相独立，不移除 token 用量、投递来源、选择或消息操作。 (verification: renderer and Electron)
- AC6 — 思考／搜索上下间距在折叠、纯内容、不同搜索状态及嵌套过程中使用有界的已保存像素值，并适用于深浅色与窄布局。 (verification: unit, renderer and Electron)
- AC7 — 生成偏好、全部语言目录、双语用户文档和现有受影响消费者通过定向检查；最终实现分别报告原生验收，在原生条件验证前保持 proposed。 (verification: docs gate and scoped checks)

## Risks

两种用户布局和嵌套过程样式可能使设置虽已保存却不生效。应检查实际渲染像素和交互，而不是仅检查偏好写入或 CSS 类存在。同时验证保留默认值的升级和切换布局后的明确覆盖值。

模型快照保留时，服务商配置可能已经消失。不得用当前默认服务商替代历史身份。名称解析仅用于展示。

渲染器夹具可验证真实组件组合和偏好传播，但不能证明 Electron 预加载、数据库持久化或操作系统运行时。原生库缺失是明确的验证边界，不能据此绕过保护或宣称完成。
