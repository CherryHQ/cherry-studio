# Agent Note: 智能体会话的 MCP Skills 客户端

Status: proposed

[English](2026-10-21-mcp-skills-client.md) | 中文

## Problem

Cherry 可以连接 MCP 服务，但连接边界没有 Skills 扩展操作。内置 `skills` 服务用于搜索市场和安装本地技能，不消费远端技能清单。Claude Code 通过白名单发现本地技能目录，Pi 接收本地 `additionalSkillPaths`。把远端内容复制到这些目录会丢失来源信息，并在实际需要之前加载文件。

本提案为两个已注册的智能体运行时 Claude Code 和 Pi 增加 `io.modelcontextprotocol/skills` 客户端支持。向外部客户端提供 Cherry 技能、修改市场安装流程，以及助手聊天接入不在本提案范围内。

## Proposal

### 协议边界

采用[上游稳定规范](https://github.com/modelcontextprotocol/ext-skills/blob/c1aa87e4c381c82b99aa37471d0eae4ab50f9985/specification/stable/skills.mdx)，以基础协议 `2026-07-28` 为目标。发送扩展方法前检查服务声明的能力；旧协议服务或未声明扩展的服务保持现有工具、提示词和资源行为。

已安装的 `@modelcontextprotocol/client@2.3.0` 和已检查的 npm `2.3.1` 导出均没有文档中的 Skills 专用入口。已安装的 SDK 提供了用于扩展方法的 `request(request, resultSchema, options)`。在 `ClientMcpConnection` 内使用此公开 API，仅为 `skills/list` 和 `skills/get` 添加必要的 schema。传输、元数据、取消、鉴权和协议代际协商继续由现有 SDK 路径负责。不修改 SDK 内部实现，也不另建连接。可安装版本提供等价的上游专用 API 后优先采用；该替换不是本提案的前置条件。

完整遍历分页，但不假定结果枚举了服务提供的全部技能。支持在已选服务上按 URI 直接查询，包括服务 instructions 中的 URI。保留未知 frontmatter 字段。条目进入目录前校验清单、根路径与名称关系、重复资源和资源归属。支持规范规定的每个技能 512 个文件、16 MiB 边界。本次实现拒绝 `resources: "dynamic"`，并提供可见的原因说明。

### 职责与用户流程

`McpRuntimeService` 负责连接访问与失效处理。`McpCatalogService` 提供远端技能元数据投影。`src/main/ai/skills/` 下由生命周期管理的模块负责校验读取、会话级来源信息和当前持有的清单。SDK 对象保持在 `connections/` 内部；渲染进程命令通过 IpcApi。本版本不新增 SQLite 表或持久化的远端技能安装记录。返回已验证的指令前，将来源与清单事实存入现有消息 JSON 的私有 `data.mcpSkills` 字段；公共读写不能暴露、伪造或删除这些事实。原生分叉保留这些事实，而批准仅适用于当次调用，文件内容缓存仅存于内存。

仅从智能体已选择且处于启用状态的 MCP 服务发现元数据。在现有智能体技能选择界面展示远端技能，标注 Cherry 分配的服务标签和可区分条目的 URI 路径。身份始终是 `(serverId, skillUri)`，不能仅使用名称。本地技能与同名远端条目保持独立选项。选择表示请求在当前会话使用，不代表安装技能或授权执行。

模型通过宿主统一的工具接口发现名称、描述和来源标签，然后按需加载技能与读取附件。Claude Code 和 Pi 适配该接口，不把远端目录加入其原生本地技能加载器。目录与内容错误均携带来源服务反馈给用户和模型；列举失败不能视为成功返回空目录。

### 加载、工具审批与读取

通过现有内置 skills 服务提供 `list_mcp_skills`、`load_mcp_skill` 和 `read_mcp_skill_file`。初始模型上下文只需这些工具定义；发现工具按需返回名称、描述、服务身份和 URI。加载一次返回条目与已验证的 `SKILL.md`，包括完整文件清单，不提前获取附件。已知服务和 URI 时可以跳过列举。

使用现有 Tool Approval 注册表、运行时事件和输入框审批卡片。列举和同来源读取是只读工具；加载遵循常规必需审批工具策略，包括 Full Access。删除独立 elicitation/consent 流程及可复用执行授权。远端指令生效时，宿主代码执行调用需要逐次明确批准，Full Access 除外。嵌套激活与跨来源资源读取同样需要逐次明确工具批准，Full Access 除外。Full Access 默认放行这些操作，完整性和来源校验仍然生效。这有意放宽了该模式下规范关于明确批准的要求。这些决定不会持久化或授权后续调用。忽略远端 frontmatter 中授予权限或安装 hooks 的字段。

通过 `resources/read` 获取 `SKILL.md`，校验原始字节长度和 SHA-256，并将解析出的 YAML frontmatter 与清单对比。校验通过后，以普通模型上下文返回带来源的内容。仅预览或普通资源读取不激活技能。格式错误或无法验证的内容不得进入加载路径。

只要已加载的指令可能仍在上下文中，就持有对应清单；保守地按会话整个生命周期处理。仅在读取时获取附件，并使用同一清单校验。相对路径从已加载技能自身的根目录解析，拒绝越界。即使资源 URI 看起来是 HTTPS 或文件地址，也通过来源服务读取，不直接抓取这些 URI。加载结果返回完整文件清单，不需要连接层的目录读取方法，也不需要单独面向模型的目录工具。

初期使用会话级内存缓存，每个技能受清单限制约束。不在任何文件系统技能发现路径中创建文件。远端技能生效期间触发的普通资源读取也必须遵守来源边界；Full Access 以外的跨来源读取需要逐次工具批准，并标明两个服务。单一来源的加载不能通过通用工具授权另一来源。

文件或刷新后的清单变化时，使持有的条目失效，取消待决审批，停止基于旧条目的后续读取或执行。展示变化后的技能，要求在新会话中加载替换版本。不将替换内容混入仍在使用旧条目的上下文：加载替换版本前建立新的运行时上下文。禁用或删除服务、修改其连接或鉴权配置、取消选择服务时，取消待完成操作，防止迟到结果重新填充目录或授予权限。会话恢复或分叉保留来源与清单事实，但不复用批准。恢复普通对话不会弹窗；后续代码执行遵循当前权限模式。需要批准的操作在没有交互响应者时会被拒绝。

### 交付与验证

用户已明确要求本次实现跳过 Spec 批准门槛。先交付协议与宿主层，再交付运行时及 UI 接入。两层全部满足验收条件后功能才算完成。可控制的 MCP 测试服务放在 `tests/helpers/`，由定向集成测试和 Electron 测试共享。使用真实客户端与服务端交互，以及脚本化模型轮次验证用户可见行为，不依赖提供商输出。本地仅运行显式指定的受影响测试文件，更广范围的验证由 CI 承担。

## Alternatives considered

- 将远端技能视为普通资源：保留读取能力，但缺少激活、清单校验和绑定来源的授权。
- 下载到本地技能库：违背按需读取要求，且使远端指令与可信的本地发现无法区分。
- 实现可选的 `resources/directory/read`：该连接方法没有生产调用者，只有协议测试使用。静态清单已经提供完整文件列表。删除未使用的方法及其专属 fixture 分支；只有产品流程需要时，再考虑目录浏览。
- 等待 SDK 专用导出：可以避免本地协议 schema，但会阻塞 SDK 公开请求 API 已能承载的扩展。保持适配器范围小且可替换。
- 立即持久化授权和技能内容：增加存储、迁移和重启信任契约，而这些并非初次使用所必需。先采用会话级状态，并明确恢复行为。

## Acceptance criteria

- AC1 — 声明扩展的服务通过现有连接支持分页发现和按 URI 直接查询；未声明扩展及旧协议服务不收到扩展调用，并保持原有功能。(verification: unit)
- AC2 — 发现和授权阶段不获取技能文件；授权后的加载只获取 `SKILL.md`，附件仅在请求时获取，无 `directoryRead` 时也能获取完整文件清单。(verification: unit)
- AC3 — 两个服务的相同 URI、一个服务内的重名技能，以及同名本地技能均可独立寻址且来源可见；不会静默遮蔽其他选项。(verification: renderer)
- AC4 — 无效清单、根路径越界、未列出文件、字节长度或摘要不匹配、frontmatter 不匹配均不能成为已加载内容；有效的 512 文件和 16 MiB 边界清单正常工作，动态条目说明无法加载的原因。(verification: unit)
- AC5 — 工具审批替代独立 consent；嵌套激活和每次宿主代码执行都需要明确批准，Full Access 除外，远端权限字段不能扩大权限。(verification: unit)
- AC6 — 附件和普通资源读取均执行来源约束；Full Access 以外的跨来源访问需要明确的逐次授权，直接 HTTP 或文件系统抓取不能绕过来源 MCP 连接。(verification: unit)
- AC7 — 清单替换、取消、服务禁用或删除或重配置、会话关闭均拒绝迟到结果与过期授权；恢复或分叉保留逐次执行审批约束，不会仅因恢复而弹窗，替换加载使用新上下文。(verification: unit)
- AC8 — Claude Code 和 Pi 均通过真实 MCP 测试服务与脚本化模型完成发现、授权、技能加载、附件读取，以及结果依赖技能内容的任务；拒绝授权阻止加载，Full Access 无需审批即可完成加载和执行。(verification: Electron)
- AC9 — 现有本地技能激活和 MCP 工具或资源使用保持正常；不可用的远端技能有明确提示且不阻塞无关服务，无人值守操作遵循现有工具策略，Full Access 默认放行审批。(verification: Electron)
- AC10 — 双语 Spec、受影响的参考文档及本地化 UI 文案与实际交付行为一致；定向检查结果与 CI、提供商验收分别记录。(verification: docs gate)

## Risks

如果原生工具没有经过相同的授权边界，运行时适配器可能绕过宿主策略。实现必须验证 Claude Code 和 Pi 的真实工具执行，而不只是协议辅助函数。如果任一运行时无法通过其支持的 API 执行边界约束，必须先改进该运行时接入，再为其启用远端技能，不能静默降低契约。

按会话持有清单会有意高估指令在上下文中的存留时间。逐次执行审批、替换时新建上下文会增加操作成本，但避免假定已注入的指令已经被移除。动态技能与助手聊天是明确的能力缺口，不宣称普遍支持。
