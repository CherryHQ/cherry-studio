# Agent Note: Agent 会话的 MCP Skills 客户端

Status: proposed

[English](2026-10-21-mcp-skills-client.md) | 中文

## 问题

Cherry 可以连接 MCP 服务，但无法发现和读取 Skills 扩展提供的工作流。把远端文件复制到本地技能目录会丢失来源，也会提前获取附件。把一次读取视为持续激活，则会引入与获取指令无关的会话状态和审批策略。

本提案通过现有内置 skills 服务，在 Claude Code 和 Pi 中消费 `io.modelcontextprotocol/skills`。向外部客户端提供本地技能、修改市场安装流程，以及 Assistant 聊天均不在范围内。

## 提案

### 协议边界

采用[稳定版上游规范](https://github.com/modelcontextprotocol/ext-skills/blob/c1aa87e4c381c82b99aa37471d0eae4ab50f9985/specification/stable/skills.mdx)，目标协议为 `2026-07-28`。复用官方 SDK `SkillsClient` 的能力检测与直接查询，以及 core 的 Schema 和限制。保留宿主分页，因为 SDK 的完整列表方法遇到循环游标会静默返回部分结果。旧版和未声明能力的服务保持原有行为，不发送扩展请求。

验证清单、名称、URI 根目录、资源范围和唯一性，支持规范规定的 512 个文件与 16 MiB 边界。保留未知 frontmatter 字段。对 `resources: "dynamic"` 给出可见的不支持说明。列表不必穷举全部技能，已知 URI 仍可直接寻址。

### 职责与使用流程

现有 `McpRuntimeService` 负责连接、取消、超时和配置校验；`McpCatalogService` 提供元数据。内置 skills 服务负责单次请求内的加载和文件校验。不再保留独立 Skill 服务、会话激活表、版本固定、已验证内容缓存、审批凭据、来源记录或历史消息扫描。会话标识只作为普通工具调用上下文，供现有 MCP 交互宿主使用。

输入框只列出 Agent 已选且启用的服务所提供的元数据，并标明服务和 URI。身份为 `(serverId, skillUri)`；本地技能、重复名称和不同服务的相同 URI 保持独立。选择条目只插入使用请求，不读取文件或执行安装。

暴露 `list_mcp_skills`、`load_mcp_skill` 和 `read_mcp_skill_file`。初始提示无需列出技能。加载时一起获取当前清单和已验证的 `SKILL.md`，包含完整文件目录。附件仅在需要时获取。文件读取接受服务、技能和资源 URI，获取当前清单，无需预先加载。重复调用读取当前远端数据，不使用会话固定版本。

### 完整性与普通工具策略

所有文件都通过其来源 MCP 连接获取，不直接访问 HTTP 或文件系统。在请求字节前验证资源范围和清单成员身份。只接受请求的单个资源，校验字节长度和 SHA-256；入口文件 YAML 必须与所有声明的 frontmatter 字段一致。每次调用都按本次获取的清单校验。无需拦截通用资源读取，也无需跨调用失效管理。

复用现有工具策略和审批卡片。加载保持 required 工具策略，包括 Full Access 自动放行。列表和文件读取保持只读策略。远端 frontmatter 不能安装 hooks 或授予权限。加载指令不会改变后续执行、cron、委派、本地技能或跨来源资源的策略。嵌套 `SKILL.md` 是普通 Markdown。Claude Code 和 Pi 中不增加 Skill 专属审批或失效监听。

本范围明确不实现扩展的 acting-window 激活及特殊执行、跨来源审批模型。它通过普通工具提供动态且经过校验的文本和附件读取，不声称完整符合宿主策略。历史工具结果仍是普通对话历史；重新读取不会重写先前模型上下文。并发调用可以返回不同的有效版本，某次调用发现变化也不会撤销其他调用的结果或审批。

### 交付与验证

用户明确授权删除激活模型，并豁免 Spec 批准门禁。更新已有提案，不新增另一份职责记录。使用共享真实 MCP fixture 验证协议和宿主；本地仅运行明确受影响的测试文件。Electron 和真实提供商验收与单元测试、构建和 CI 结果分开记录。

## 考虑过的替代方案

- 通过会话激活固定清单并缓存已验证内容：给动态文本读取引入状态、失效管理、跨工具执行分类和审批凭据。直接删除，不把同一套机制移到另一个模块。
- 持久化激活或从消息历史重建：增加存储与恢复信任约定；历史工具结果继续作为普通历史。
- 下载到本地技能目录：破坏按需读取并丢失远端来源。
- 用 SDK 方法替换全部宿主检查：复用官方查询与 Schema，但保留失败即拒绝的分页和工具边界现有的字节、frontmatter 校验。SDK 读取自行发起请求，不能验证已有资源响应。
- 增加 `resources/directory/read`：完整静态清单已经包含文件目录，当前没有产品流程需要额外目录 API。

## 验收标准

- AC1 — 声明能力的服务支持分页发现与直接查询；旧版和未声明能力的服务不收到扩展请求。（验证：unit）
- AC2 — 发现和加载审批不读取文件；加载只读取 `SKILL.md`，附件仅在请求时获取。（验证：unit）
- AC3 — 重复名称、不同服务的相同 URI 和同名本地技能保持独立寻址，并显示来源。（验证：renderer）
- AC4 — 无效清单、根目录逃逸、未列出文件、错误资源响应、摘要或大小及 frontmatter 不匹配均返回错误；有效边界清单可用，动态条目解释限制。（验证：unit）
- AC5 — 加载使用普通工具审批，包括 Full Access；加载和读取不会授予权限，也不会给后续工具增加 Skill 专属审批。（验证：unit）
- AC6 — 每次文件读取均使用明确选中的来源服务，通过现有 MCP 连接校验当前清单，无需提前加载。（验证：unit）
- AC7 — 重复调用无需重新打开会话或重新加载，即可获取更新后的清单和内容；普通请求取消和服务选择检查继续拒绝无效调用，不保留跨调用激活状态。（验证：unit）
- AC8 — 真实 MCP fixture 与脚本模型在两个运行时完成发现、加载审批和附件按需读取；拒绝加载不读取文件，Full Access 跳过加载提示。（验证：Electron）
- AC9 — 现有本地技能和 MCP 工具、资源保持可用；不可用来源与成功的空目录分开报告。（验证：Electron）
- AC10 — 双语提案与相关参考文档准确描述所选的请求级行为及其限制，并如实记录验证边界。（验证：docs gate）
- AC11 — 宿主和运行时适配器不再保留 Skill 专属会话生命周期、激活缓存、执行工具分类、审批凭据或通用资源拦截器。（验证：unit）

## 风险

远端指令属于不可信工具结果上下文。普通工具策略是唯一执行审批边界，本范围不实现扩展特殊的 acting-window 保证。调用方可能在不同读取间混用版本；后续读取不会撤回先前指令。动态清单和 Assistant 聊天仍不受支持。
