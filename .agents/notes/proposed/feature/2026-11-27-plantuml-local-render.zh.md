# Agent Note: PlantUML 离线预览

Status: proposed

[English](2026-11-27-plantuml-local-render.md) | 中文

## 问题

Markdown 的 PlantUML 预览在用户确认后会把图表源码发送到 `www.plantuml.com`。用户无法离线渲染私有图表，预览也受该服务器可用性影响。

## 方案

- PlantUML 代码块默认在本地渲染，沿用源码和预览切换。代码块结束流式输出后开始渲染。移除公共服务器请求、确认界面及远程回退。
- 随应用打包 PlantUML 官方 TeaVM 无界面引擎，沿用 Viz.js 支持依赖 Graphviz 的布局。在 Web Worker 中按需加载引擎。限制渲染时间，并在源码或预览发生变化时取消旧任务。
- 预处理在离线环境中进行。图表可以内联定义宏。外部 URL、本地文件、未打包的标准库引用会显示渲染错误。沿用 SVG 净化，以及缩放、复制和下载操作。

## 考虑过的替代方案

- 保留手动远程回退。该方案保留仅服务器支持的功能，但仍会传输图表源码。选定的方案终止这类传输。
- 调用本地 PlantUML Java 进程。各桌面平台都需要安装或打包 JVM，并管理子进程。
- 在渲染进程的主线程上使用官方浏览器版本。该版本的字符串渲染接口依赖 DOM API，同步布局可能延迟交互。无界面版本可在 worker 中运行。

## 验收标准

- AC1 — 阻断外网访问时，已完成的 Markdown PlantUML 代码块默认展示图表，用户仍可切换到源码。验证中文时序图和依赖 Graphviz 的类图。（验证方式：Electron，负责人：实现者）
- AC2 — 无效源码和不可用的外部引用会显示本地渲染错误。所有 PlantUML 预览入口均不通过网络发送图表源码，生成的 SVG 不会自动加载外部资源。（验证方式：renderer 和 Electron，负责人：实现者）
- AC3 — 渲染期间编辑、清空或关闭预览时，丢弃过期结果。超时后释放 worker，后续图表仍能渲染。（验证方式：renderer，负责人：实现者）

## 风险

- 使用公共服务器资源、自定义字体或完整 Java 渲染功能的部分图表，在无界面版本中可能呈现不同或渲染失败。
- 引擎会增加打包后的渲染资源体积。按需加载避免在启动时或处理不含 PlantUML 代码块的 Markdown 时加载该引擎。
