# Agent Note: 在 preboot 安装迁移桥接版本

Status: proposed

[English](2026-11-11-preboot-bridge-install.md) | 中文

## Problem

现有升级拦截能正确阻止未迁移数据进入正常启动流程，但仍需要用户打开浏览器，手动下载并安装 2.1.0。期望体验是在 Cherry Studio 内点击一次，完成迁移版本的下载、校验、安装和启动。

本方案部分替代[移除 v1 数据迁移](../../implemented/simplification/2026-11-09-retire-v1-data-migration.md)中的浏览器下载交互。只读检测、固定 2.1.0 桥接版本、历史状态消费者以及移除转换代码的决定均保持不变。实现正在 PR #23998 中进行；安装包验收完成前，本记录保持 proposed。

## Proposal

### 用户体验与范围

保留紧凑的无标题栏窗口、统一内容边距和固定底部操作区。主操作为“安装迁移版本”；说明明确标注 2.1.0，并告知 Cherry Studio 将重启进入该版本。点击一次即授权下载和安装，下载完成后不再重复确认。操作系统仍可能要求权限确认。

窗口只展示当前阶段：准备中、下载中（总大小已知时显示百分比）、校验中或正在重启至 2.1.0。总大小未知时使用不定进度。安装交接之前，取消会停止本次操作，保留当前安装；退出会先取消再退出。失败时保留窗口，提供重试和手动下载。技术错误记录在主进程日志中；窗口提供简短恢复提示，不突出显示文件系统路径。交接期间禁用重复操作；不能显示“迁移完成”或“升级完成”。

第一阶段仅在能明确确认旧数据来源与桥接版本兼容时自动安装 2.1.0。现有 `legacy` 分类本身不足以证明这一点。根据历史版本记录新增只读的前置条件分类，使用真实历史格式和经过测试的版本排序。记录缺失、格式错误、相互冲突或不受支持时，不能启用自动安装。已知 1.9.11 及更早版本或版本不确定时，主操作改为现有的 1.9.12 下载和启动指引，不能猜测或静默跳过前置条件。自动编排 1.9.12 不在本次范围内。

启动后，迁移及其恢复界面由 2.1.0 负责。迁移完成后，用户通过该版本正常的更新流程获取最新版。自动返回最初运行的精确版本不在本次范围内：已发布的旧程序不支持新的交接协议。不保留后台辅助进程、定时任务或宣称整个往返升级已经完成的标记。

### 平台约定

| 当前安装形式 | 第一阶段拟采用的方式 | 必须具备的安装包验证证据 |
| --- | --- | --- |
| 正常安装且已签名的 macOS 应用 | `MacUpdater`，使用对应 ZIP 而非 DMG | 原生 x64/arm64、Rosetta、签名身份兼容性、替换和启动 |
| Windows NSIS 安装版 | `NsisUpdater`，保留安装目录和发行版 | x64/arm64、转译运行的 x64、取消提权、安装和启动 |
| Linux AppImage | `AppImageUpdater`，仅针对实际运行且可写的 AppImage | x64/arm64、可执行文件替换和启动 |
| Linux deb/rpm | 根据打包的 `package-type` 标记选择 `DebUpdater` / `RpmUpdater`，使用包管理器的降级能力 | 包数据库确认 2.1.0、提权失败可恢复、启动与迁移 |
| Windows 便携版 | 补丁中的 `PortableUpdater` 校验暂存文件后在原路径替换启动器 | 双架构、签名连续性、文件锁、恢复及启动 |
| Linux 未知形式、未打包开发环境 | 保留手动下载指引 | 版本、发行版和架构正确；不自动替换 |

Global 和 CN 必须保持当前发行版。架构选择沿用原生架构规则，包含转译运行场景；不能回退到资源列表第一项。跨架构替换只有在安装包验收证明安装和数据目录兼容后才能启用，否则提供对应的手动安装包。资源缺失、原生更新器不可用或数据目录连续性未经验证时，转入手动流程并简短解释原因。

Linux 包格式扩展已在实现会话中获授权。手动下载也应匹配检测到的安装格式，包括 1.9.12 的历史文件名。扩展现有 updater 补丁，让 RPM 安装区分降级和升级，不在应用代码里自行实现包管理器命令。

### 所有权和依赖边界

保留 `src/main/core/preboot/legacyUpgradeGate.ts` 中现有的只读拦截。在 `src/main/data/migration/` 的现有升级模块旁新增会话级桥接安装器。它拥有一个更新器实例、取消令牌、状态和事件订阅，随 preboot 窗口一起释放。由于整个生命周期发生在 bootstrap 之前并随本次拦截结束，不注册为正常生命周期服务。

直接实例化已安装的 `electron-updater` 平台更新器，不初始化 `AppUpdaterService`，不修改其单例，也不为这一个流程抽取全应用更新框架。现有服务读取 Preference，并依赖 WindowManager、SchedulerService 和 NotificationService；下载本身不需要这些服务。使用 `loggerService` 和路径注册表；最小化的 `AppAdapter` 提供缓存、配置路径及现有应用退出集成，不另建应用生命周期。

更新器缓存必须与正常更新下载及旧数据目录分离，通过应用拥有的缓存位置下专用路径注册键解析。适配器还应将 `.updaterId` 等更新器自有记录重定向到该隔离位置，不能写入旧数据目录。不允许写入 SQLite、Preference、迁移状态、Chromium 存储或旧配置。必须对比检测到的数据目录与 2.1.0 实际重新打开的目录：自定义路径和安装形式的连续性是启用条件，不能直接假定。不能通过重写旧配置让桥接版本打开另一个目录。

### 固定资源与校验

从官方 2.1.0 发布元数据生成小型、随代码提交的目标清单：精确版本、发行版、操作系统、架构、安装形式、URL 和 SHA-512。对每个符合条件的目标，通过库支持的自定义 provider 扩展只暴露一个固定资源。复用库的下载器、校验和验证、缓存验证、签名检查与安装器。不在应用业务代码中解压 ZIP 或替换应用，不修改更新器私有字段，不增加本地元数据服务器。

首先考虑了固定 tag 的 generic feed。它可以提供现成元数据，但本身不能约束唯一的发行版和架构资源，也不能固定不可变的预期校验和。当前安装的更新器根据 `process.arch` 选文件，而产品在转译运行时选择原生架构。显式的固定资源 provider 能表达产品约定，无需修改依赖的选择行为。复用库的元数据类型；目标缺失或不匹配时拒绝，不能改选其他版本。

设置 `autoDownload = false`、`autoInstallOnAppQuit = false`，并仅在此实例设置 `allowDowngrade = true`，因为当前运行版本高于桥接版本。这次一次性切换使用完整下载。只有用户明确操作后才开始下载。保留 Windows 发布者验证与 macOS 签名要求；校验和不匹配、签名失败或缺少信任信息时不得安装。固定 HTTPS URL 和内置哈希约束所选资源，但不代表 Linux 发布元数据具有数字签名。

### 状态、IPC 和退出

主进程拥有 `idle → preparing → downloading → verifying → installing` 状态。交接前失败进入 `failed`，取消返回 `idle`，重试创建新一轮尝试。一次只运行一个尝试。串行执行尝试，每次使用独立取消令牌，重试前移除上一次监听器，防止迟到进度或完成事件影响下一次操作。限制进度事件频率，renderer 重载时可读取当前快照。

扩展现有隔离的 preboot IPC，增加开始、取消、快照和状态事件。renderer 只发送意图，不传 URL、路径、版本或更新器设置。保留 sender、主 frame 和来源校验。交接前关闭窗口应取消并退出，不安装；整个过程中保持 `autoInstallOnAppQuit` 关闭。失败或取消的终态移除本次订阅，退出时移除全部 IPC 和窗口监听器。

安装交接与普通窗口结束必须区分。调整 gate 当前无条件执行的 `application.quit()`，避免它与 `quitAndInstall()` 竞争或提前关闭 macOS 原生更新器的暂存服务器。成功安装时由更新器控制退出。真正提交交接前保留错误监听和窗口；可观测的安装器启动失败恢复重试及手动操作。进程退出后的安装器错误或断电无法由此窗口报告，下次启动重新执行只读检测。不自动回滚，不破坏性清理用户数据。

### 证据与实现顺序

2026-11-11 的仓库检查确认了 `electron-updater` 6.7.0、直接实例化平台更新器、自定义 provider 扩展、取消与下载事件，以及正常更新服务的生命周期依赖。官方 2.1.0 发布包含两种发行版、两种架构、macOS ZIP 和更新元数据；macOS 与 Windows 元数据包含 SHA-512。资源存在不代表安装、签名兼容性或数据目录连续性已经验证。

首先在可丢弃的真实安装环境中，使用合成旧数据验证固定 provider 和降级交接。根据结果决定启用哪些平台和安装形式。然后连接现有界面、增加明确限定文件的契约测试，并在发布入口启用前完成安装包验收。开发验证不替换真实用户安装和数据。仅在本方案实际改变已交付行为后更新已有的迁移移除记录。

### Implementation evidence and remaining release gate

用户已批准扩展现有 electron-updater 6.7.0 补丁。自定义 AppAdapter 现在保留 Electron 下载传输，MacUpdater 提供 `dispose()`，用于下载结束后移除自身原生监听器并关闭暂存服务器。应用只使用这些公开能力，不访问更新器私有字段。

实现包含 24 项固定资源清单（Global/CN、x64/arm64、macOS/Windows/Linux）、隔离缓存与记账文件、串行取消和重试、界面进度以及更新器控制的退出。清单来自官方 `v2.1.0` 元数据，以及通过发布资产 SHA-256 验证的便携包内容。自动安装排除未打包构建、转译进程和缺少发布者验证元数据的非便携 Windows 安装。自定义目录及便携版/deb/rpm 均在范围内；便携版在退出前验证签名。版本记录不明或低于 1.9.12 时，主操作为先安装 1.9.12。

限定范围测试覆盖会话取消、校验失败、重试、迟到事件、原生监听器清理、自定义适配器下载传输、IPC 校验和安装交接退出保护。这些测试不能证明真实签名应用替换成功。三个操作系统的安装包安装、签名兼容、重启至 2.1.0 和迁移仍是发布前必须完成的验收；AC5 尚未完成。不能仅凭单元测试和界面测试把该实现分支视为可发布。

### 自定义目录与便携版安装扩展

用户已批准将一键安装扩展到自定义数据目录和 Windows 便携版。本节取代前面的排除范围及禁止应用替换的笼统限制：便携版替换由现有 electron-updater 依赖补丁负责，不放在应用业务代码中。

安装交接前，将选中的数据目录按规范化可执行文件键持久化到 BootConfig。已发布的 2.1.0 读取相同映射。不复制用户数据、不改写旧版配置。下载和取消不写映射；持久化失败阻止安装，可观察的交接失败恢复原映射。保持可执行文件位置及版本渠道不变。

PortableUpdater 复用固定目标下载和校验流程。隐藏窗口的 PowerShell 进程在原文件旁暂存便携 EXE，校验 SHA-512，以及有效且主体相同的 Authenticode 发布者签名，再发出准备就绪信号让应用退出。等待应用退出及启动器文件锁释放后，将旧 EXE 改名为备份，替换并从原位置启动。替换或启动失败时恢复并启动备份；退出后的错误记录在缓存下载文件旁。整个过程不触碰相邻 data 目录。缺失或无效签名会停止安装并保留重试和手动恢复。隐藏窗口的命令宿主通过重定向管道启动 PowerShell，工作进程可在更新器的 Windows 作业退出后继续运行。工作进程发出就绪信号后，更新器先通过标准输入确认交接，再退出应用。标准输入在确认前关闭会取消替换。仍须完成 Windows 原生替换验收，不能用模拟测试代替。


## Alternatives considered

- 仅保留浏览器下载：实现最少，但把用户要求自动完成的安装留给用户；保留为兜底。
- 启动或复用 `AppUpdaterService`：把正常生命周期及设置带入必须先于它们运行的拦截流程，并可能改变常规更新配置。
- 不筛选目标的固定 tag generic feed：更简单，但单独使用无法表达固定原生架构资源的约定。
- 自行编写下载和替换脚本：重复实现库已负责的安装、签名、权限、重启及平台失败处理。
- 恢复当前版本转换代码或自动编排整条历史版本链：前者推翻迁移移除决定，后者需要已发布版本并不具备的协议。

## Acceptance criteria

- AC1 — 只有前置条件兼容的数据和验证过的安装形式展示自动桥接安装；不受支持或不确定的情况保留可执行的手动指引。(verification: unit; owner: legacy profile/platform tests)
- AC2 — 用户操作只选择精确的 2.1.0，发行版、原生架构、安装形式及固定校验和均匹配；错误或缺失的目标不能回退为其他资源。(verification: unit; owner: bridge provider tests)
- AC3 — 下载、校验失败、取消、重试、重复点击、迟到事件和 renderer 重载产生一致的可见状态，底部操作可达且不重复安装。(verification: renderer and unit; owner: preboot window/session tests)
- AC4 — 检查、下载、取消及交接前失败均保持旧数据目录字节不变，不启动正常服务或创建数据库。(verification: Electron; owner: isolated preboot fixture checks)
- AC5 — 每个启用的平台和安装形式均安装并启动 2.1.0，重新打开预期的默认或自定义数据目录，并允许完成迁移；具有发行版、架构和签名连续性证据。(verification: packaged artifact; owner: desktop release validation)
- AC6 — 退出不会意外触发安装，成功的更新器交接不会被 gate 清理打断，可观测的安装器启动失败仍可恢复。(verification: unit and packaged artifact; owner: preboot lifecycle tests and desktop release validation)
- AC7 — 紧凑窗口在进度、错误、长翻译及深浅主题下仍对齐且可操作；文案区分安装与迁移，并解释后续常规更新。(verification: renderer and Electron; owner: legacy upgrade UI validation)
- AC8 — 双语 Spec、受影响的参考文档和本地化文案与交付范围一致，明确记录未支持的平台和未验证的路径。(verification: docs gate and i18n; owner: implementation author)

## Risks

历史 macOS 签名身份、Windows 发布者变更、转译进程替换、自定义目录和文件权限可能导致元数据有效但无法原地安装。未获证据的组合必须保留手动流程。下载失败会保留当前安装，但安装交接后断电可能需要手动修复应用；不承诺跨平台原子回滚。旧版本迁移和后续更新仍是用户可见的独立阶段。发布资源可能不可用；固定哈希防止静默接受被改动的程序，但无法保证资源始终可下载。
