# Agent Note: 共享记忆

Status: proposed

[English](2026-10-29-shared-memory.md) | 中文

## 问题

当前智能体（Agent）文件记忆把长期事实保存在各自的 `memory/FACT.md`，把事件保存在 `memory/JOURNAL.jsonl`。它不能直接让其他智能体和已开启共享功能的助手（Assistant）复用长期用户偏好。事实增多后，还需要保持入口简短，避免每条事实都变成一个小文件。

去掉专用记忆 MCP 工具，不会自动让原生文件编辑变得安全。并发会话可能覆盖未读到的修改，多文件整理失败也可能留下不完整的内容或链接。除模型选择内容外，还需要程序强制执行读取、保存、备份、恢复和后台调度。

现有[记忆概述](../../../../docs/references/memory/overview.md)、[智能体提示词构建器](../../../../src/main/ai/agents/prompt.ts)和[智能体记忆 MCP 实现](../../../../src/main/ai/mcp/servers/agentMemory.ts)说明了当前接入方式。本提案定义文件记忆的后续方案；知识库和独立的 `@cherry/memory` 知识图谱 MCP 继续作为独立能力。

## 提案

### 1. 范围与职责

提供共享用户偏好和各智能体的私有知识。项目、客户知识保留在所属智能体的私有范围中。私有范围跨会话、跨工作目录归属于同一个智能体，不自动按项目隔离。

首版包括入口注入、受控文件访问、记忆编辑器、修改前备份、最近一次操作恢复，以及整理已有记忆的 Dreaming。具备受控写入能力的对话模型，可在检查已有内容后，在当前轮次保存明确的长期偏好或用户要求记住的内容。临时任务、普通问答、无依据推断和凭据不属于长期记忆。

后台从对话提炼记忆放到后续。首版 Dreaming 不读取聊天记录，也不开启对话提炼开关或会话数量触发。未来提炼需要明确的来源授权、消息版本、删除检查，以及首次启用和清空后的处理起点；开启共享记忆不能授予全部聊天的读取权。跨智能体私有资料向共享层提炼、多设备同步、完整历史版本、召回模型和重复的候选正文库也放到后续。

模型选择事实、措辞、归属和组织方式。主进程的记忆模块检查访问并提交修改；运行时适配层把原生工具调用关联到该模块；Dreaming 负责复核与调度；编辑器通过 IpcApi 调用同一模块。不新增记忆 MCP 协议、记忆正文数据库或检索索引。

### 2. 文件与主题粒度

通过集中路径注册管理共享目录和备份目录。`{userData}` 表示应用实际使用的数据目录。私有文件使用当前智能体已注册的数据目录。

```text
{userData}/Data/Memory/
  MEMORY.md
  .memories/
    preferences.md
    development.md

{agentData}/
  MEMORY.md
  .memories/
    project-payments.md
    troubleshooting.md
  memory/
    FACT.md
    JOURNAL.jsonl

{userData}/Data/MemoryBackups/
```

活动内容仅包括 `MEMORY.md` 和 `.memories/` 中的主题 Markdown 文件。旧 `memory/` 文件、备份、临时文件和未知文件不进入正常注入、搜索、Dreaming 或写入范围。Windows 设置目录隐藏属性；macOS 和 Linux 使用点目录约定。应用列表、搜索、导出和备份仍须包含受管理主题。隐藏状态不提供访问保护。

入口保存少量完整的常用事实和有用的主题链接，不是全部文件清单，也不是全部事实摘要。只有一句“通常用中文回答”的偏好，可以直接留在入口，不另建文件。低频细节需要独立查阅，或逐渐出现条件与例外时，移入相关主题。正文只维护一个位置，入口随后仅保留定位说明。

一个主题按使用场景包含多条相关事实和小节。新建前先搜索已有主题。出现不同使用场景或容量不足时再拆分，不按关键词、日期或列表项逐一建文件。文件大小和数量只是整理线索，不是删除依据；用途独立的小文件可以保留。

事实使用普通列表项。可选的 `[source: reference; added: YYYY-MM-DD]` 记录真实、已知的来源，不编造来源，也不授予来源读取权。`[[path]]` 相对于当前记忆根目录，可省略 `.md`。适用条件与事实保存在一起。未列入入口的主题仍可通过受控列表和搜索发现。入口中的事实是原始内容，不能从主题文件自动重建。

### 3. 资格与请求加载

| 调用方 | 共享记忆 | 私有记忆 |
|---|---|---|
| 桌面智能体 | 默认开启，可关闭 | 仅当前智能体 |
| 普通持久会话中的助手 | 默认关闭，可开启；工具需完成受控接入 | 无 |
| 临时、辅助或普通 headless 助手 | 无 | 无 |
| 关联外部渠道的智能体 | 无 | 仅所属智能体的既有权限范围 |
| Dreaming | 明确绑定的共享维护范围 | 明确绑定的单个智能体范围 |

调用身份来自主进程可信的会话或任务上下文。模型提供的 ID 或路径不是授权。Dreaming 使用独立维护身份。每次操作复查身份、归属、开关和资源是否存在。解析真实目标，拒绝目录穿越、越界路径，以及逃出受管理范围的符号链接、junction 和其他重解析路径。链接不授予另一作用域的访问权。

每个新轮次、恢复请求和压缩后的请求，重新加载符合资格的共享入口和当前智能体私有入口。已有系统提示词、`SOUL.md` 和 `USER.md` 保持各自职责，不重复复制到共享记忆。注入明确标记的参考资料和稳定的使用说明，替换旧记忆区块，不另存为普通聊天消息。当前用户的明确要求优先于记忆。

压缩保留任务进度和有用路径，不据此认定旧记忆仍然最新。主题正文不再可用，或新编辑需要新基准时，重新读取主题。先使用链接，再搜索获准范围内的文件名和正文。报告截断、不完整或分页的搜索结果。没有受控文件能力的请求，只能使用已注入的完整事实，不能声称已展开链接或保存内容。

| 限制 | 规则 |
|---|---|
| 每层入口 | 200 行或 25,000 UTF-8 字节，以先达到者为准 |
| 每个主题 | 25,000 UTF-8 字节 |
| 入口预警 | 160 行或 20,000 UTF-8 字节 |
| 主题预警 | 20,000 UTF-8 字节 |
| 一批 Dreaming | 包括入口在内最多 10 个输入文件，总计 50,000 UTF-8 字节，一次整理模型调用 |

入口注入在完整行处停止，并明确说明有内容未展示。受控入口保存同时检查两项限制，主题保存检查字节限制。不静默截断保存的文件，不把搜索片段当成完整正文。外部产生的超限原文保留并提示需要整理。编辑必须通过具备完整读取能力的适配层，否则拒绝操作。不增加自动展开全部主题或跨请求正文缓存。

### 4. 受控工具与模块接口

复用已有的文件列表、搜索、读取、写入、编辑、删除和重命名能力。执行层将受管理目标交给记忆模块，普通文件保持原有行为。迁移切换时停止旧智能体 FACT/JOURNAL 工具路径。不移除独立的[图谱记忆服务](../../../../src/main/ai/mcp/servers/memory.ts)或无关 MCP 工具。

| 调用边界 | 输入与职责 | 结果与拒绝条件 |
|---|---|---|
| 运行时或编辑器读取记忆 | 可信调用方、作用域、目标；检查访问并完整读取 | 正文及绑定调用方的读取凭据；不可访问或读取不完整时，不允许据此编辑 |
| 运行时或编辑器修改记忆 | 已批准的准确操作与内容，以及读取凭据；新建明确使用目标不存在的基准 | 实际结果、最终哈希和恢复批次引用；拒绝陈旧、不明确、未授权或超限请求 |
| Dreaming 提交记忆 | 单个作用域、任务代次、全部输入基准、目标内容和有序操作 | 逐文件返回已完成、未完成或冲突；模型不直接写磁盘 |
| 编辑器发起恢复 | 选定的最近批次、已展示文件集与当前基准、用户确认 | 逐文件恢复结果；冲突时保留后续修改及双方版本 |
| 记忆模块通知调度 | 已确认的变更路径、哈希和可信修改来源 | 由所属模块管理复核标记；不接受模型自行声明修改来源 |

读取凭据把模型实际所见字节的哈希绑定到调用方、目标和编辑依据，保存在模型无法修改的内容之外。不能在保存前临时取得最新哈希，冒充模型原先的读取基准。不能用其他会话或较新读取的凭据替代旧编辑的凭据。关联缺失或不明确时，须重新完整读取并重新生成编辑。审批绑定作用域、目标、操作、拟保存内容和预期版本，修改这些内容须重新审批。既有权限策略决定何时授予审批，但已获准操作仍执行保存保护。

Pi 和 Claude Code 分别适配。Pi 在 [PiRuntimeConnection](../../../../src/main/ai/runtime/pi/PiRuntimeConnection.ts) 装配 SDK 工具，在 [approvalExtension](../../../../src/main/ai/runtime/pi/approvalExtension.ts) 应用策略。Claude Code 在 [PreToolUse 钩子](../../../../src/main/ai/runtime/claudeCode/hooks.ts)检查规则，因为自动批准路径可能跳过 `canUseTool`。这些是接入位置，不是已有的事务保存服务。仅有工具执行前权限检查，不能让保存锁一直覆盖后续写入。

各运行时须列明并验证实际经过记忆模块的操作，包括删除和重命名。不能满足接口约定的操作，不作为受保护记忆编辑交付。助手文件编辑也须完成同等能力和审批接入，否则只使用入口。

具有直接磁盘权限的 Shell、脚本、子进程、其他工具和外部编辑器可以绕过文件适配层。首版备份与版本保证覆盖受控操作。更强的保证需要有效的文件系统隔离，包含子进程和路径别名，并逐平台验证。提示词、命令文本匹配、普通审批和事后文件监听均不能建立这种保证。

### 5. 提交、内容检查与计数

沿用应用对数据目录的单实例管理，同一作用域的受控修改串行提交。设置保存、运行时编辑和 Dreaming 共用以下流程：

```text
authorize operation and bind read baseline
-> acquire scope write lock
-> recheck permissions, task generation, and actual file hashes
-> persist pre-change backup and recovery manifest
-> write complete temporary file and safely replace target
-> inspect actual result and record completed operations
-> release lock and return result
```

使用完整文件字节的 SHA-256 做乐观并发检查。新建检查目标不存在，重命名同时检查源与目标条件。目标意外消失、目标位置出现新文件或哈希不符均为冲突。备份失败则停止修改。作用域锁约束遵守流程的写入方，不能排除外部文件系统写入，也不能单独保证崩溃持久性。

SHA-256 是内容指纹，不是次数或按时间递增的版本。`A -> B -> A` 可能发生两次编辑，但最终哈希与起点相同。首版不增加 YAML 展示版本。仅程序元数据变化不算内容修改；冲突检查仍覆盖全部字节。

只统计文件自上次成功整理或检查后，程序观察到的成功受控内容修改。失败写入、相同内容保存、Dreaming 自身修改、恢复和仅元数据变化不增加计数。修改来源由可信执行上下文提供。外部变化和崩溃间隙标记待复核，不编造次数。恢复或清空还须使旧任务代次失效，即使内容回到以前的哈希。

保存失败或结果不确定时，重新读取目标，区分旧内容未变、预期新内容已生效和出现其他版本。重试前先报告实际结果；不盲目重放编辑、创建重复主题或覆盖其他写入方的内容。

### 6. 备份与最近一次操作恢复

注册的备份根目录为 `{userData}/Data/MemoryBackups/`，位于活动内容之外。按作用域和操作批次隔离，普通记忆工具不暴露该目录。替换或删除前备份原始字节，新建记录原先不存在。一次多文件整理使用一份批次清单，记录修改前状态、预期修改后哈希，以及实际完成或未完成的步骤。恢复清单不充当另一份 Dreaming 状态库或记忆事件日志。

每个作用域最多保留五批备份，备份正文与清单合计最多 20 MiB。接受修改前，计算该操作需要的备份，优先清理最旧且可清理的已完成批次，使两项限制都满足。不清理执行中、恢复中的批次或最近可恢复批次。若受保护资料与必要的新备份无法同时容纳，则拒绝写入并说明限制。备份保留策略不删除活动记忆。

提供最近一次可恢复修改或整理批次的恢复入口。预览受影响文件，确认权限与当前版本，恢复前先备份当前状态。仅在文件仍符合记录的操作结果时恢复。撤销新建要求该文件内容仍未变化；撤销删除要求路径仍不存在。后续出现的同名文件属于冲突。恢复本身也是新的受控修改。

更新使用同目录完整临时文件和安全替换。临时文件不进入搜索或注入。在 Windows、macOS 和 Linux 验证替换与失败行为，不把安全替换等同于已验证的断电保证。多文件保存和恢复报告部分成功、未完成步骤与冲突，保留剩余恢复资料。

### 7. Dreaming 整理与触发

受管理范围的自动整理默认开启，使用应用默认模型。不增加独立的 Dreaming 模型选择器。没有可用默认模型时暂停并显示原因。仅在应用运行且空闲时执行，全应用最多一个 Dreaming 任务，向前台对话让出资源。自动整理关闭时，用户仍可手动请求，但必须满足作用域授权和相同的资源限制。

| 触发条件 | 资格 |
|---|---|
| 手动请求 | 明确选择的已授权作用域 |
| 受控修改 | 单文件自上次成功检查后达到 10 次成功的受控内容修改 |
| 变化与等待 | 内容不同于已处理哈希，且最早待处理变化已达到 7 天；后续变化不重置起点 |
| 容量预警 | 已变化或未处理的入口、主题达到上述预警限制 |

仅扫描绑定的作用域。复核作用域时发现外部变化，从首次观察到变化开始等待，不推断应用关闭期间编辑了多少次。重开应用后检查当前条件，不补跑每个错过的时间点。已检查且内容不变的文件，不因仍然较大或上次未提出修改而反复触发。

完整读取入口和相关主题，包括入口未链接的相关文件。优先选择已变化文件，并在批次间轮转剩余工作；未处理文件不标记完成。上述输入与单次调用限制覆盖全部选中文件的正文。遵守所选模型的上下文和输出限制，必要时减少批次文件；拒绝不完整输出，不应用截断内容。

模型提出去重、精简、合并或拆分建议，并保留事实、条件和真实来源引用。用途独立的小文件保留。矛盾或未核实的陈述保留其不确定性，不能只凭时间或重复次数判定真假。Dreaming 不清空作用域，不修改 `SOUL.md`/`USER.md`，不读取旧 JOURNAL 或聊天记录，不访问其他作用域或网络，也不执行记忆中的命令。

推理期间不持有写入锁。提交时，在作用域锁内检查全部相关源文件和目标文件的基准、任务代次与授权，拒绝陈旧建议。合并时先保存承接内容，再更新受管理链接，最后移除已完整承接的旧内容。前置步骤失败，停止依赖它的操作。无法确认已完整转移时，保留源文件。程序检查版本和保存结果，不证明语义等价。

检查成功且无需修改时，记录该输入已处理。发生修改后记录实际最终哈希，避免 Dreaming 再把自身输出当成新变化。只有完成的文件推进进度。失败采用有界重试并显示原因；持续失败不能导致无限模型调用。新输入或明确的手动请求可提供新的检查机会。

### 8. 持久状态、取消与重启

现有数据库为 `{userData}/Data/cherrystudio.sqlite`，通过 `application.getPath('app.database.file')` 获取。复用已有存储：

| 信息 | 所属模块与存储 | 边界 |
|---|---|---|
| 已处理哈希与时间、最早待处理变化、受控计数、复核代次 | Dreaming 拥有的 `app_state` 键 | 按作用域和文件区分；无正文；仅通过所属模块访问 |
| 执行状态、时间、错误、简短结果 | 由 `JobManager` 管理的 `job` | 执行历史不作为永久已处理文件清单 |
| 持久调度与下次运行时间 | 通过已有调度 API 使用 `job_schedule` | 调度回调不独立保存进度 |
| 全局自动整理偏好与已有默认模型 | `PreferenceService` | 不在偏好设置中保存逐文件进度 |
| 各智能体、助手的共享访问选择 | 已有实体配置 | 预设携带开关，不携带记忆正文 |

遵循 [app_state 归属规则](../../../../docs/references/data/app-state-overview.md)，实现时登记所属模块的新键。不增加记忆表、独立数据库或调度状态 JSON 文件。[JobManager](../../../../src/main/core/job/JobManager.ts) 会清理已结束任务，因此完成复核的标记须独立保留。在所属模块生命周期初始化时注册 Dreaming 处理器，并使用启动恢复策略 `abandon`。定时唤醒重新判断资格，不重放旧模型结果。

文件替换与 SQLite 进度不属于同一事务。先确认文件结果，再更新标记。失败或重启后，结合备份清单与哈希复核实际文件。任务行显示成功不足以证明未知文件已完成；无法确认的状态继续待处理，不重建虚假的精确修改次数。

取消、相关权限撤销、关闭整理、清空、恢复或删除作用域时，使受影响的待执行任务与未提交输出失效。关闭某个调用方的共享访问，使该调用方的读取凭据和审批失效，不改变其他调用方的访问权。重启丢弃未完成整理的输出。已提交修改保留到显式恢复为止。设置展示上次运行时间和需要处理的失败；无改动检查不新增聊天消息或记忆内容。

### 9. 编辑器、清空、初始化与迁移

复用设置界面、受管理文件列表、Markdown 编辑器和 IpcApi。将调用方共享访问开关与按作用域自动整理分开。智能体共享访问默认开，助手默认关。展示和编辑完整入口、主题；冲突时保留草稿；删除、共享清空和恢复前预览并确认。隐藏页面不改变权限；关闭访问停止后续注入与受控访问，但不能撤回已发送的上下文。

共享清空列出并绑定准确的受管理文件集与版本，取得作用域锁，复核后再重置入口或移除主题。出现新增或变化的文件时重新预览，不删除未展示或未知文件。私有记忆和旧历史保持不变。清空使用独立可恢复批次，并使旧任务、读取凭据和审批失效。部分失败须报告剩余内容。说明可恢复备份仍然存在；永久删除备份需要另行明确范围并授权。

初始化缺失目录和入口，不覆盖已有文件。完整数据备份和搬迁在协调应用内写入后，包含活动文件、恢复批次和匹配的数据库状态。完整恢复使旧任务与读取凭据失效，从恢复后的文件建立新基准，不信任不匹配的旧标记。

迁移前检查并备份旧 FACT。完整常用事实进入入口，细节、条件和来源进入私有主题；不自动把私有事实提升到共享层。核对保留完整后，一起切换提示词加载、原生工具目标、初始化与内置模板。不完整迁移保留可恢复原文，不启用半迁移的作用域。旧 FACT 作为历史保留并退出正常读写；JOURNAL 原文不变并停止追加事件。未知文件不覆盖、不移除。不承诺双写或新旧版本交替使用兼容。

## 考虑过的替代方案

- 新增专用记忆 MCP：不采用，以保留已有文件工具交互；程序强制保护仍需要适配运行时。
- 仅用提示词要求备份与版本检查，或使用文件监听：不采用，两者都不能保证修改前备份或受控编辑的原子准入。
- 用哈希或 YAML 版本充当修改计数：不采用，内容相等不能还原编辑历史，模型可编辑的元数据不能强制并发控制。
- 每条事实建文件，或入口列出全部主题：不采用，简短完整事实可留在入口，相关知识应放在一起；仍允许独立的小主题。
- 新建正文数据库、事件日志或永久任务历史索引：不采用，Markdown 保存正文，已有模块私有状态和执行能力覆盖本期需要。
- 首版同时提供完整历史界面和对话提炼：放到后续，先交付基本恢复，并避免在来源授权建立前读取聊天。

## 验收标准

- AC1 — 共享和私有入口、主题采用指定布局；各支持平台的隐藏主题仍可列出、搜索、导出和备份，历史、备份、临时文件及未知文件不进入活动内容。 (verification: unit + Electron; owner: memory storage)
- AC2 — 各调用方只获得符合资格的范围；关闭共享、其他智能体、临时或 headless 请求、外部渠道共享访问被拒绝，目录穿越和重解析路径也不能泄露名称或片段。 (verification: unit + runtime integration; owner: runtime adapters)
- AC3 — 新轮次、恢复与压缩后重新加载符合资格的入口，不重复身份或上下文区块；仅入口请求不能读取或声称保存主题，截断明确且不会覆盖完整正文。 (verification: runtime integration + representative model tasks; owner: prompt integration)
- AC4 — 每项受支持原生修改使用真实的调用方完整读取基准和已批准内容；陈旧、缺失、跨会话、不明确或已撤权的基准被拒绝，覆盖新建、删除、重命名和自动批准模式。 (verification: unit + runtime integration; owner: runtime adapters and memory storage)
- AC5 — 备份失败或容量不足时原文件不变；不确定保存结果在重试前被核实，成功的受控更新返回实际最终哈希和恢复批次。 (verification: filesystem fault injection + Windows/macOS/Linux native checks; owner: memory storage)
- AC6 — 各作用域同时遵守 5 批和 20 MiB 限制，不清理受保护恢复资料；最近操作恢复正确处理新建、删除及部分完成批次，不覆盖后续内容或后续同名文件。 (verification: unit + filesystem fault injection + Electron; owner: memory storage and memory editor)
- AC7 — 入口和主题保存执行规定的行数、字节限制，保留外部超限原文和未保存草稿，绝不以不完整读取作为替换依据。 (verification: unit + renderer; owner: memory storage and memory editor)
- AC8 — 自动整理默认开启并使用应用默认模型；10 次修改、7 天等待、容量和手动触发遵守授权、空闲执行、全局单任务并发及规定批次预算。 (verification: unit with controlled time + runtime integration; owner: Dreaming)
- AC9 — 相同内容、失败、仅元数据、Dreaming 和恢复保存不增加受控修改计数；外部变化与崩溃间隙待复核且不虚构次数，已检查的未变文件不会反复调用模型。 (verification: unit with controlled time and restart scenarios; owner: Dreaming)
- AC10 — 相关主题仅在承接内容与受管理链接保存成功后合并清理；代表性整理任务保留无关小主题、事实条件和真实来源，部分失败时未转移的源内容仍可恢复。 (verification: fault injection + representative model tasks; owner: Dreaming and memory storage)
- AC11 — 成功或无修改的检查只为已完成文件持久化标记，且不依赖任务历史保留；崩溃复核不重放陈旧输出，不把不匹配的文件和数据库状态当成已完成。 (verification: real SQLite integration + filesystem fault injection; owner: Dreaming)
- AC12 — 取消、关闭、相关撤权、清空、恢复、删除和重启阻止受影响的未提交结果生效；已提交内容和其他调用方权限保留，反馈出现在普通聊天之外。 (verification: unit + runtime integration + Electron; owner: Dreaming and memory editor)
- AC13 — 编辑器确认准确的共享清空文件集，保留草稿、未知文件、私有文件和历史文件，报告部分结果并说明保留的备份；完整备份和恢复包含活动记忆、恢复批次及一致状态。 (verification: renderer + Electron + restore scenarios; owner: memory editor and backup integration)
- AC14 — FACT 迁移在协调切换前保留事实、条件和来源；JOURNAL 不变，旧事实不双写，部分迁移不启用，独立图谱记忆与知识库行为不变。 (verification: migration fixtures + affected runtime integration; owner: migration integration)
- AC15 — 首版 Dreaming 从不读取聊天记录、旧 JOURNAL、其他作用域、身份文件或网络来源；普通受控对话保存仍可使用，无需开启后台对话提炼。 (verification: runtime integration + representative model tasks; owner: Dreaming and runtime adapters)

## 风险

- 原生钩子和审批 API 不等于文件系统隔离。在逐平台证明限制有效前，直接磁盘访问不在受控保证之内；不能把未支持操作宣传为受保护写入。
- 外部编辑可能与应用锁竞争，文件和 SQLite 提交也可能在失败后不一致。复核与识别冲突的恢复可降低丢失风险，但不承诺多文件事务或断电持久性。
- 自动整理消耗模型额度，也可能误判事实或丢失条件。复用默认模型、限制批次、无改动时保持安静、保留可恢复原文和代表性任务验证可限制影响；备份不证明语义正确。
- 五批和 20 MiB 限制恢复存储，但受保护资料占满预算时可能阻止写入。编辑器须解释失败，不能删除受保护历史或静默省略备份。
- FACT 迁移和停止 JOURNAL 追加改变持久化约定。须保留原文并协调所有使用方；保留历史文件不意味着新旧应用版本可以交替使用。
