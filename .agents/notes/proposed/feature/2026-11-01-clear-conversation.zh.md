# Agent Note: 按用户明确要求清除对话上下文

Status: proposed

[English](2026-11-01-clear-conversation.md) | 中文

## 问题

每一轮都会重新发送直到最后一个 `data-clear` 分隔线为止的全部历史，旧话题会持续消耗 token 并渗入新回答，直到用户找到 Ctrl+K 分隔线为止。模型无法响应"清空上面的内容，然后……"这种用户最自然的说法。Agent 会话完全没有分隔线。Ctrl+L 会在不停止正在生成的回复的情况下直接删除，而排队的后续消息在中止后从不自动发送，因此在生成过程中清除会让队列卡住。

## 提案

- 新增内置工具 `clear_conversation`，在 Chat（AI-SDK 注册表）和 Agent（`cherry-tools`）各注册一次，共用同一个主进程核心。工具描述承载触发规则：仅当用户当前消息明确要求清除、重置、忘记或重新开始时调用；绝不用于随口提及、关于该功能的提问、引用文本或含糊请求；绝不由模型自行发起。输入为 `reason`（用户原话）和可选的 `mode`。
- 分隔线模式为默认，并复用现有的 `data-clear` part。Chat：在发起请求的用户消息正上方插入分隔线，并把该消息重新挂到分隔线下，这样发起请求的这一轮得以保留，现有的分隔线切换即为撤销。Agent：追加一行分隔线；运行时恢复查询忽略最新分隔线之前的行，会话空闲后丢弃热连接，下一轮从全新的原生记录开始。工具结果告知模型在当前轮忽略更早的上下文。
- 删除模式绝不在一轮内部执行。工具广播 `ai.conversation.clear_requested`；渲染进程显示现有的清除确认对话框并附上模型给出的理由，只有确认后才执行清除。
- 单一 IPC 路由 `ai.conversation.clear` 同时服务于 Chat 与 Agent 会话主题的 Ctrl+L 和已确认的删除：先 `abortAndDrain`，再插入分隔线或删除。之后由渲染进程主动触发队列头部，因为 `aborted` 状态从不自动发送。分隔线模式不弹对话框；删除总是先询问。
- 回复生成期间按 Ctrl+K 或橡皮擦，会向后续消息队列加入一个 `clear` 动作项。它按顺序执行且不消耗本次完成信号，因此排在它后面的消息会在同一轮完成时发送。Agent 获得行为相同的 Ctrl+K 与橡皮擦工具栏按钮。
- 非用户点击产生的分隔线（模型清除、Agent 分隔线）提供 10 秒撤销提示，由 `ai.conversation.undo_clear` 支持。
- 两个偏好设置：`chat.clear_context.default_mode`（`divider` | `delete`，默认 `divider`）和 `chat.clear_context.model_tool_enabled`（默认 `true`），显示在上下文管理设置中。

## 考虑过的替代方案

- 不改应用、仅用外部 skill 或 MCP 服务器：否决，因为没有任何网关或远程路由能触及消息行，且 Agent 的上下文位于只有应用才能停止恢复的运行时记录中。
- 用客户端短语匹配代替模型工具：否决，因为"算了，继续吧"和"清空我的日程"会被误清除；由模型判断，而分隔线让误判可逆。
- 把 Chat 分隔线插在正在生成的回复之后而非发起消息之上：否决，因为历史切片会丢掉刚被回答的问题。
- 让工具直接删除：否决，因为删除不可逆，且轮内删除会与终态持久化竞争；由渲染进程对话框把关。
- 每次中止都自动发送队列：否决，因为停止回复往往是有意暂停；只有 Ctrl+L 会触发队列。
- 在同一请求内以干净上下文重启本轮：推迟为单独提案；下一轮已是干净的，当前轮由工具结果指示模型。

## 验收标准

- AC1 — 在 Chat 中，"清空上面的内容，然后 X"会在该消息正上方生成分隔线，下一轮历史从此开始，点击分隔线可恢复之前的历史。（verification: unit + Electron）
- AC2 — 在 Agent 会话中，模型清除后，下一次连接不携带分隔线之前的恢复令牌或原生会话 id，删除分隔线行可恢复它们。（verification: unit）
- AC3 — 随口或含糊的说法（"说清楚一点"、"算了"、"怎么清除上下文？"）不会调用工具。（verification: Electron）
- AC4 — 模型请求的删除在用户确认引用了模型理由的对话框之前不改变任何内容；取消则对话保持原样。（verification: renderer）
- AC5 — 回复生成期间按 Ctrl+L 会先停止回复再清除，仅在删除模式下询问，之后下一条排队消息会被发送。（verification: renderer + unit）
- AC6 — 回复生成期间按 Ctrl+K 或橡皮擦会加入一个按顺序执行、不可编辑、且不阻塞其后消息的排队清除项。（verification: renderer）
- AC7 — 关闭 `chat.clear_context.model_tool_enabled` 后，工具从 Chat 请求和 `cherry-tools` 服务器中移除；Ctrl+L 与 Ctrl+K 继续可用。（verification: unit）
- AC8 — 在 Agent 会话中连按两次清除只产生一条分隔线，撤销提示可将其移除。（verification: unit + renderer）
- AC9 — 所有用户可见字符串在每种语言中都存在，i18n 门禁通过。（verification: docs gate）

## 风险

- 在发起清除的那一轮，模型仍能看到清除前的历史；只有工具结果中的指示阻止它使用。缓解方式是分隔线可见且可逆。
- 已排在清除轮之后的 Agent 后续消息仍会在旧记录上运行，因为重置在会话空闲时才生效。
- Agent 重置依赖每会话的待处理标记加上限定范围的数据库查询；关闭屏障带入新条目的令牌必须在连接时清除，实现中已显式处理。
- 直接的 DataApi 调用方看不到 `ai.conversation.cleared`；只有主窗口的输入框提供撤销。
