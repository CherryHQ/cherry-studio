# Agent Note: 为网站上传添加名称并可选抓取同源链接

Status: proposed

[English](2026-11-12-website-upload-naming-auto-link-crawling.md) | 中文

## Problem

知识库的 URL 条目只记录 URL。上传后列表中显示的是抓取到的页面标题或主机与路径生成的 slug，用户很难将其与想要整理的文章对应起来。上传目录页或索引页时，也只会索引该单个页面，页面中链接的文章需要逐一手动添加。

Issue [#19063](https://github.com/CherryHQ/cherry-studio/issues/19063) 提出两项需求：为网站上传指定用户自定义的名称，以及自动抓取上传页面中的内部链接。

## Proposal

**命名。** 在 `UrlItemDataSchema`（`src/shared/data/types/knowledge.ts`）中新增可选的 `name` 字段。添加对话框为 URL 来源提供名称输入框。设置了 `name` 时，它作为快照 frontmatter 中的标题和文件名主干；为空时，沿用 `urlSnapshot.ts` 中现有的标题推导逻辑。该字段存储在条目的 JSON `data` 中，因此无需迁移。

**抓取。** 抓取需要按次上传手动开启：添加对话框提供"同时添加此站点上的链接页面"复选框，默认关闭。开启后，扫描上传页面的 Markdown 中的链接，每个满足以下全部条件的链接都会在上传条目的分组下成为子条目：

- 与上传 URL 同源（协议、主机和端口必须一致）；
- 解析后为绝对 HTTP 或 HTTPS 地址；
- 不是指向同一页面的纯片段链接；
- 本次上传中尚未安排过。

抓取深度为 1：只跟随上传页面上的链接。每次上传最多创建 20 个条目（含上传页面本身），超出上限的链接会在发起抓取前被丢弃。子条目与手动 URL 条目使用相同的抓取、快照和索引路径，并获得推导出的标题；自定义名称只作用于上传的条目。

提议扩展 `groupId` 的所有权模型，让开启抓取的 URL 条目拥有抓取所得的子条目。当前 `KnowledgeItemService.validateGroupOwnerTx()` 只接受目录所有者，因此这需要上游所有权与状态协调契约变更，并非复用已支持 URL 所有者的 API。实现必须验证所有者与子条目属于同一知识库，拒绝向删除中的所有者添加子条目，在创建或删除子条目后协调抓取所有者状态，并在删除所有者时取消待处理的子任务和删除子条目。普通 URL 上传仍保持为单个条目。此契约仅供人工评审，本文未实现运行时扩展。

## Alternatives considered

- **仅标题覆盖，不存储字段。** 无需修改 schema，但重新抓取时名称会丢失，也无法与页面标题区分显示。因用户需要自行控制名称而否决。
- **默认抓取。** 会在用户未同意的情况下将一次上传扩展为最多 20 次抓取。否决；由用户按次选择开启。
- **包含子域名的同域抓取。** 对按子域名拆分的文档站点覆盖更广，但扩大了抓取范围。第一版否决，之后可作为单独选项添加。
- **解析 HTML 链接而非 Markdown 链接。** 抓取路径只返回 Markdown，因此从 Markdown 链接语法中读取链接。仅在非 Markdown 输出中存在的链接不被覆盖。
- **为每次抓取创建目录容器。** 这样可以保留现有的仅目录所有者校验，但删除上传的 URL 本身不会删除同一容器中的其他页面。本提案未选择此模型，因为 AC7 要求上传的 URL 是删除所有者；评审者仍可在实现前改选目录容器模型。
- **递归抓取。** 覆盖更深，但增长无界且更难取消。否决；深度为 1。

## Acceptance criteria

- AC1 — 填写非空名称的 URL 上传会保存该名称，快照标题和文件名主干使用它；名称为空时回退到现有的推导标题。（verification：unit + renderer）
- AC2 — 未保存 `name` 的 URL 条目仍可解析并以不变的标题索引。（verification：unit）
- AC3 — 抓取选项关闭时，URL 上传只创建一个条目。（verification：renderer + unit）
- AC4 — 抓取选项开启时，上传页面上的同源绝对 HTTP(S) 链接成为分组子条目；跨源链接、非 HTTP 链接、纯片段链接和重复链接不创建条目。（verification：unit）
- AC5 — 单次上传最多创建 20 个条目（含上传页面），超出上限的链接不触发任何抓取。（verification：unit）
- AC6 — 子页面抓取失败只将该子条目标记为失败；上传条目和其他子条目继续处理。（verification：unit）
- AC7 — 删除开启抓取的 URL 所有者时，会取消待处理的子任务并删除其抓取的子条目；跨知识库所有权和向删除中的所有者添加子条目均被拒绝，创建或删除子条目会协调所有者状态。（verification：service + unit）

## Risks

- 同源站点仍可能很大；20 条上限只约束单次上传的成本，不约束多次上传的总量。
- Markdown 链接提取依赖阅读器的输出；仅由 JavaScript 渲染链接的页面不会产生子条目。
- 子页面可能与知识库中已有的页面重复；与现有条目的去重不在本 Spec 范围内。
