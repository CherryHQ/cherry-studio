# Agent Note: Chat 与 Agent 的音视频预处理

Status: proposed

[English](2026-10-19-audio-video-preprocessing.md) | 中文

## 问题

纯文本模型无法使用附加的音频或视频，而能够接收这些模态的模型和端点仍应保留原生传递路径。Issue #20749 最初提出仅通过处理器回退。当前交付还涉及有界的本地 FFmpeg 运行时、帧选择、设置和 Agent 读取路径；这些新增选择需要在整组 PR 合并前获得明确审查。

## 提案

- 为支持的桌面平台打包经过校验和验证的 FFmpeg 与 FFprobe。Linux 的 LGPL 库及许可和源码资料随运行时提供，定位打包文件时不依赖用户可变的工具安装。
- 由一个主进程媒体服务探测文件、提取有界音频分块和代表性视频帧，使用已经可用的转录资源及调用方选定的视觉模型，保留源时间戳、缓存可复用分析并传递取消信号。分析过程不得安装语音资源。
- 持久化可选的 Video Vision 模型；媒体服务应用自身的有界分析预算。Chat 保留原附件显示：仅当模型和实际端点接受文件的真实 MIME 时原生传递音视频，否则内联有长度上限的分析文本。必需的分析失败时以指向设置的错误终止本轮；有效的静音结果仍作为提示继续。
- 通过按附件授权的 `read_file` 提供完整的带时间戳分析。Pi 保留文件系统 `read` 工具和轮次身份，对媒体分析分页并遵守 Stop。普通 Claude Code Agent 只挂载只读的 `assistant-files` 操作并使用不透明句柄；保存和移入废纸篓不可用，实时禁用工具规则会撤销当前连接后续的工具调用。

## 考虑过的替代方案

- 只依赖原生多模态服务商：纯文本模型仍无法回答音视频内容问题。
- 在 Chat 和各 Agent 运行时分别预处理：会重复资源上限、取消、缓存归属和失败行为。
- 给普通 Agent 原始附件路径或完整可写文件服务：暴露了超出附件读取所需的文件系统权限。
- 在分析时下载转录资源：会让用户请求触发意外安装，并掩盖处理器不可用的事实。

## 验收标准

- AC1 — 支持的 macOS、Windows 和 Linux 安装包中的 FFmpeg 与 FFprobe 能探测并提取媒体；Linux 携带 LGPL 运行依赖及许可和源码资料，不加载用户可变的二进制文件。 (verification: unit + packaged artifact)
- AC2 — 视频分析选择数量有上限、感知场景且不重复的帧，并在帧或音频流稀疏时保留源时间。 (verification: unit + packaged artifact)
- AC3 — 单一媒体服务返回有界且带时间戳的转录和可选视觉分析，复用有效缓存，准确报告分析不可用，并在完成、失败或取消时清理资源。 (verification: unit + Electron)
- AC4 — 用户可以选择并持久化 Video Vision 模型，后续分析使用所选模型。 (verification: renderer + Electron)
- AC5 — Chat 接受音视频附件，对模型和端点确实支持的 MIME 保留原生传递，否则内联有界分析；WebM 与 Ogg 按实际媒体类型路由，必需的分析失败时在调用服务商前终止，原附件仍可见。 (verification: unit + renderer + Electron)
- AC6 — Agent `read_file` 仅分页读取获准附件，Pi `read` 在不改变工具身份的前提下分页读取媒体，已停止或被取代的轮次不能发布迟到的分析结果。 (verification: unit + Electron)
- AC7 — 普通 Claude Code Agent 可通过不透明句柄读取当前附件分析，但不能经该挂载保存或移入废纸篓；精确、服务器、通配符和全部 MCP 禁用规则可撤销当前连接后续的工具调用。 (verification: unit + Electron)

## 风险

- 打包行为、Linux LGPL 产物来源及平台库加载需要在产物层验证；单元测试无法单独证明。
- 转录质量取决于已安装的本地资源，视频描述取决于选定的视觉模型。能力缺失必须明确呈现，不能悄悄编造内容。
- 大型媒体可能耗尽时间或上下文预算；发布前需要验证取消、截断和真实数据下的 UI 行为。
