# Agent Note: 商城发现与安装契约

Status: proposed

[English](2026-11-07-skill-marketplace.md) | 中文

## 问题

用户需要在一个入口发现技能、智能体模板和 MCP 资源。目录条目只是远端元数据，不代表已安装资源，也不授予执行权限。来源显示名不能改变持久化标识或安装目标。

本文补充 #20978 现有实现的契约，供审查使用。不表示功能已发布，也不表示此 Spec 已获批准。上层个人资源库草稿 #21834 保持独立范围。

## 提案

### 发现流程与来源标识

从启动台和侧栏进入商城。资源导航包含全部、技能、智能体和 MCP。总览展示各类资源的预览。智能体目录合并智能体与助手预设；创建时使用现有对话框和本地选项。

| 来源 | 显示名 | 标识与浏览 |
|---|---|---|
| CherryIN | 精选 | 选中来源为 `null`。每页加载 100 个热门技能，校验分页并按 ID 去重。搜索筛选已加载的目录。详情可包含多个技能目录组成的集合。 |
| skills.sh | skills.sh | 来源 ID 为 `skills.sh`。按页浏览累计排名。查询非空时使用该来源的搜索适配器。 |
| claude-plugins.dev | claude-plugins | 保留来源 ID `claude-plugins.dev` 和 `/api/skills` 接口。偏移量按原始响应条目数推进，不按过滤后的数量推进。 |
| 用户订阅 | 用户提供的名称 | 独立保存来源 ID 和规范化 URL。添加来源不会安装其中的条目。 |

外部目录共用卡片、详情和安装状态。缓存键包含来源标识。切换来源时重新挂载目录，避免旧结果和已打开的详情混入新来源。搜索与浏览使用不同请求路径；清空搜索后恢复浏览。加载更多使用目录游标和 ScrollArea 的实际视口。

claude-plugins 安装使用 `claude-plugins:owner/repo/directoryPath`；目录取自元数据，不能由技能显示名推断。skills.sh 使用已校验的来源句柄。不支持的来源卡片不能安装。显示名不改写存储的 ID、URL 或句柄。

### 安装与订阅边界

复用现有技能命令和安装校验。读取目录或打开详情不授予执行技能指令的权限。安装技能不会授予智能体新的工具权限。智能体级启用仍由现有技能管理流程负责。

CherryIN JSON 读取拒绝超过 16 MiB 的响应。主进程负责下载包、解压、目录校验和安装。保留归档大小、路径检查及回滚行为，不另建安装器。集合操作保留各成员的成功和失败，不能把失败成员标为已安装。

订阅 URL 接受不含内嵌凭据的 HTTP 或 HTTPS 地址。GitHub URL 会规范化。刷新替换目录数据，不替换已安装文件。移除订阅只移除来源，不会悄悄卸载本地技能。目录数据不可信。URL 可访问不代表发布者或内容安全。

### MCP 管理与布局

MCP 目录保留现有添加和配置流程。“管理 MCP”通过 `mcpStandalone` 打开设置。保留设置一级导航和内容出口，只隐藏 MCP 二级菜单。该模式仅在当前设置页实例内有效，包括离开 MCP 后再返回。新开的普通设置页显示正常二级菜单。

MCP 工具栏第一行放标题、搜索和添加，第二行放筛选和环境状态。保留创建、导入和 JSON 导出操作。列表在内容区域内伸展，不依赖固定窗口高度。

保留 Store 图标的原有形状和尺寸。选中时反转前景与背景的表现。列表和横向来源导航使用共享 ScrollArea。虚拟列表、分页观察器和滚动复位都指向其视口。保留键盘焦点、可访问的操作名称及关闭详情后的焦点恢复。窄窗口、深色主题和实际滚动仍需单独验收。

### 失败与恢复

加载中、空结果和错误是不同状态。请求失败显示重试，不能伪装为空结果成功。外部目录失败时记录来源、游标和原始错误。保留来源的失败语义；没有证据时不延长超时，也不吞掉错误。

安装操作显示忙碌和已安装状态，并阻止重复提交。安装失败显示错误，允许再次尝试。目录重试不代表重新安装本地内容。尝试刷新时，可以继续显示已有订阅快照。

## 考虑过的替代方案

- 把发现入口留在各个设置页：不采用，因为用户浏览前就得先知道来源。
- 为匹配短显示名而修改来源 ID：不采用，因为缓存身份和精确安装目标必须稳定。
- 另建安装器或全局持久化 MCP 布局模式：不采用，因为安装保护和普通设置行为已有负责模块。
- 将“我的资源”放入本层：不采用，因为其隐藏导航和编辑行为属于独立草稿 #21834。

## 验收标准

- AC1 — 用户可以浏览 CherryIN、skills.sh 和 claude-plugins，搜索、打开详情并加载后续页面，不混淆来源身份。 (verification: unit and renderer; owner: Frontend)
- AC2 — 安装使用已校验的精确目录；阻止重复提交，并显示集合成员的失败。读取目录不执行技能。 (verification: unit and main-process integration; owner: Backend)
- AC3 — 添加、刷新或移除订阅不会悄悄安装、更新或卸载本地技能。 (verification: unit and renderer; owner: Backend and Frontend)
- AC4 — 商城 MCP 管理仅在当前设置实例隐藏二级菜单；普通设置保留二级菜单以及创建、导入和导出操作。 (verification: renderer and Electron; owner: Frontend)
- AC5 — Store 图标形状、键盘操作、详情焦点恢复和视口分页在浅色、深色和窄窗口中工作正常。 (verification: renderer and Electron; owner: Frontend and QA)
- AC6 — 加载中、空目录和失败目录可以区分；重试和安装恢复保留原始失败信息。 (verification: unit, renderer and controlled network failure; owner: Frontend and QA)
- AC7 — 文档层只包含此双语契约和一致性记录；实现与个人资源库改动保持分层。 (verification: docs gate and parent-relative Git diffs; owner: Maintainer)

## 风险

远端服务可能改变结构、响应变慢或不可用。之前的偶发目录错误未能复现；请求成功不能证明当时的原因，也不能证明已修复。

本地依赖安装不完整。已安装的 Claude SDK 与清单不一致，标准测试可能在收集用例前失败。隔离检查不代表标准套件、打包应用或真实技能安装通过。当前提交的 Electron、深色和窄窗口、真实安装验收仍未完成。验收证据完整前，不把此文档改为 implemented。

回滚沿用现有安装恢复行为。撤销目录界面修改时，必须保留用户已安装的技能和订阅。本契约不引入数据库迁移。
