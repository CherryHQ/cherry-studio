# Agent Note: 明确 Home 重试与重新生成操作

Status: proposed

[English](2026-11-22-chat-regeneration-operations.md) | 中文

## Problem

[Issue #18616](https://github.com/CherryHQ/cherry-studio/issues/18616) 要求清晰的失败重试、重新生成及编辑重发链路。[聚焦替换或分支的后续 issue](https://github.com/CherryHQ/cherry-studio/issues/19038) 增加了明确保留结果及显示有效请求的要求。部分报告描述早于当前源码。再加一层重试循环，或假设保留的每个同级回复都会污染上下文，都会破坏已有保障。

本提案负责普通的持久化 Home 话题聊天，不替代[消息树约定](../../../../docs/dev/references/chat/message-tree.md)、[模型重试所有者](../../../../docs/dev/references/ai/model-retry.md)或 [Agent 历史提案](../architecture/2026-11-08-agent-history-operation-boundaries.md)。原生 Agent 会话、仅追加临时聊天、工作区回退、整个对话的树形扁平化及把分支复制到新对话不在本次交付内。更广的按助手覆盖重试设置及用户指定重试间隔仍明确留待后续；完成本 Spec 不能单独关闭整个 #18616 或 #19038。

### Source-checked baseline

基线：`253bd3d400e40a9cb9afdd7a4f97ecd5bc5f9d63`。以下是源码观察，不是新的 Electron 验收。

| 范围 | 当前所有者与行为 |
|---|---|
| Home 重新生成 | `useChatWriteActions.ts` 对非 pending 目标采用显式模型覆盖或当前输入框选择；推理强度、服务层级和快速模式可继承源轮次 |
| 失败助手回复重试 | `PersistentChatContextProvider.prepareAssistantRetry` 校验话题/用户消息/模型，从父节点重建历史，在重置准确行前再次准入，并保留活动节点指针 |
| 编辑重发 | `handleForkAndResend` 创建用户同级消息，可保留直接多模型回复 ID 和继承的轮次控制；不是统一采用当前输入框设置的约定 |
| 上下文 | `resolveCompactedHistory` 从 `getPathToNode(anchorMessageId)` 开始；仅保留同级消息不证明上下文污染 |
| 重试入口 | `MessageGroupMenuBar` 已为失败/暂停/空且非 pending 回复提供重试，并按模型去重分组重试；单消息入口的可发现性仍需交互验证 |
| 自动重试 | `createRetryableWrap` 和全局 `chat.retry.*` 偏好已负责有界模型调用重试、退避、密钥故障转移及配置的模型回退；输出内容开始后不再重试，取消不重试 |

源码所有者为 [Home 操作](../../../../src/renderer/pages/home/hooks/useChatWriteActions.ts)、[消息动作](../../../../src/renderer/components/chat/messages/frame/messageMenuBarActions.tsx)、[分组重试](../../../../src/renderer/components/chat/messages/list/MessageGroupMenuBar.tsx)、[Main 上下文准备](../../../../src/main/ai/streamManager/context/PersistentChatContextProvider.ts)、[消息持久化](../../../../src/main/data/services/MessageService.ts)及[模型调用重试](../../../../src/main/ai/runtime/aiSdk/retry/createRetryableWrap.ts)。

## Proposal

### 1. Give each operation a distinct meaning

| 操作 | 有效请求 | 历史结果 |
|---|---|---|
| 重试失败回复 | 同一失败回复的模型及已保存且受支持的轮次控制；预览无法重建而采用的当前默认值 | 复用合格失败助手消息的身份；保留分支选择和附件 |
| 重新生成，保留分支 | 显示当前选中的模型及有效且受支持的控制；允许显式选择源设置 | 创建可导航同级消息；下一次上下文只包含选中的路径 |
| 重新生成，替换 | 相同请求预览，并明确警告替换 | 生成成功后只替换确认过且合格的叶回复；保留无关同级分支 |
| 保存并发送编辑后的用户输入 | 显示编辑后的 parts、当前模型选择、有效控制及保留的附件 | 创建编辑后的用户同级消息，并从该准确节点重新生成；保留原输入分支 |

换模型属于重新生成，不是原位重试。暂停输出及非空的部分/工具输出需要明确的重新开始警告，不能称为安全透明重试。缺失的历史控制应显示为继承当前默认值，不能宣称准确重放。多模型请求显示每个模型，不得默默缩成单模型，也不能用分页加载的同级列表推断意图。

### 2. Resolve once in Main and review before dispatch

扩展现有类型化流准入/请求边界，提供只读操作预览。Main 解析话题/来源所有权、父锚点、模型身份、有效且受支持的控制、附件引用、重试策略摘要、资格及受影响回复身份。渲染进程通过 Home 适配器显示该投影；共享消息 UI 接收能力，而不是 Home 专属状态或页面模式标志。

预览不得调用 `prepareDispatch`、预留消息、重置失败回复、压缩上下文、同步 MCP 工具、联系服务商或产生模型费用。需要时抽出无副作用解析，不得为获取预览而执行请求。不得暴露凭据、不透明服务商请求头或隐藏提示词内容。适用时显示受支持的采样控制及现有推理/服务层级/快速模式控制；如实标明默认值和省略的不受支持值。

确认操作绑定预览中的话题、来源、父节点、所选模型、相关配置版本及操作模式。Main 在预留/重置前重新验证它们及实时流资格。树、模型/配置、附件可用性或资格变化时，拒绝并提供可刷新预览，不能默默发送另一个请求。成功派发把有效控制记录到结果回复。已配置的服务商回退仍由重试所有者管理，提交前显示模型可能变化，结束后显示实际模型。

### 3. Keep replacement narrow and failure-safe

初始默认保持现有保留分支行为。在重新生成审阅中提供 `Keep old reply as a branch` 和 `Replace current reply`。显式保存的默认值使用 Preference，迁移不改变已有话题，也不得跳过请求审阅或破坏性警告。

初期替换仅适用于成功、位于活动路径、没有活动后代、待处理工具/审批工作或竞争执行的助手叶回复。多模型替换针对一个显式选中的回复，不是整组。已有后续内容的旧回复仅允许分支，并给出原因；不得默默重挂后代或级联删除对话。执行及最终发布时都重新检查资格。

生成成功前保留原回复及选择。替换意图归 Main 执行所有者，不属于渲染定时器或乐观删除。成功时经持久化所有者原子删除确认过的旧叶节点并选中新回复，保留其他分支及文件引用所有权。发布前错误/取消保留原回复；新的部分输出如实保留为失败同级消息。若成功与新分支/配置变化竞争，或最终替换持久化失败，则把成功的新答案保留为同级消息，同时保留旧回复，并说明未应用替换。不得为隐藏发布失败而丢弃已生成答案。重启不自动继续破坏性替换；既有中断执行恢复仍具权威。

### 4. Make retry visible without multiplying attempts

失败回复有支持键盘且不依赖悬停的 Retry 动作，并与重新生成明确区分。该回复有活动尝试时，禁用重复提交并提供取消。重试非活动路径回复不得激活它。保留现有分组去重、源文件引用、请求所有权及尝试身份，使旧尝试的迟到事件不能覆盖当前结果。

失败审阅提供现有全局自动重试设置的入口，不增加渲染进程整轮重试定时器。当前有界次数、退避、Retry-After 处理、显式退出、配置的回退及密钥故障转移语义仍由现有所有者负责。不得默默启用重试、重放已完成工具、在部分内容输出后重启、刷新后重发，或把未知投递结果当作新的自动发送。可配置精确间隔或按助手覆盖须在同一所有者处另行修改，不得在外面再包一层循环。

### 5. Preserve source files and explicit edit choices

Home 编辑/保存并发送审阅在确认时捕获当前模型选择及有效控制，不用已加载历史回复顺序代替选择。允许显式采用源设置并标明。保留未更改的文件 parts 及受管引用，只有用户编辑时才移除。Main 在修改树前解析引用及目标模型媒体/工具能力。文件缺失、无法访问或能力不支持时给出具体可操作错误，不删除源分支或默默替换模型。

第一条用户输入与后续编辑输入一样使用话题虚拟根。保留现有分支感知上下文及保留附件规则。本提案不宣称压缩过的对话能逐字节复现早先的服务商请求。

### Delivery order

| 层 | 范围 | 所需证据 |
|---|---|---|
| A | Main 所有的无副作用预览/解析及类型化准入绑定 | 所有权、过期预览及无网络/无写入回归 |
| B | 保留/替换预留及仅成功后原子发布 | 真实迁移 SQLite、同级/附件完整性、失败与重启场景 |
| C | Home 动作审阅、显式重试及编辑发送选择 | 渲染交互、全部语言目录、响应式/键盘检查 |
| D | 既有自动重试集成、当前指南及原生验收 | 重试所有者调用方测试及打包 Electron 端到端检查 |

中间层保持此说明为 proposed。实现以所需堆叠流程发布在 Spec 上方。存储层、模拟对话框或文档门禁通过均不等于功能完成。

### 部分实现边界

首个重试源守卫在异步准备前捕获失败回复的已存祖先路径。最终重置在写事务内比较消息身份、话题、父节点、角色、状态、同级组、模型及已存 data。回复内容/控制变化、历史编辑或祖先删除/重挂会在清空回复或后代上下文锚点前被拒绝。压缩摘要、用量/计时投影及无关同级编辑不会使此内容路径检查失效。每次显式重试会增加两次完整路径读取和一次比较。

此守卫仅覆盖 AC1/AC2 的一部分，不是只读有效请求预览、配置/文件可用性绑定或新的重试界面。现有上下文准备仍可能在拒绝过期源之前写入追踪/压缩状态或调用压缩模型；此守卫不作相反承诺。替换、编辑重发及原生验收仍未完成。

## Alternatives considered

- 请求替换前删除旧答案：服务商失败或取消时可能丢失可用回复。
- 把重新生成当作原位重试：隐藏模型/设置变化，并抹去重试身份约定。
- 增加渲染自动重试或刷新后重发：放大既有次数，可能重放工具或创建重复计费请求。
- 从每个可见分组回复重建上下文：违反分支所有权，误把显示分组当作活动上下文。
- 现在加入全局线性/树形转换模式：需要独立破坏性转换约定，明确单次操作选择不需要它。

## Acceptance criteria

- AC1 — Home 失败提供可见且支持键盘的 Retry 动作；阻止重复活动尝试；对合格非活动路径失败重试时保留模型、受支持的已存控制、文件引用及活动选择。 (verification: renderer + Main integration + Electron)
- AC2 — 重新生成或编辑重发前，审阅显示操作、实际选中模型、受支持控制/默认值来源、保留文件及回退可能；预览不写消息、不调模型、不压缩、不同步工具。过期确认不改变任何状态，要求新预览。 (verification: renderer + Main integration)
- AC3 — 保留分支的重新生成保留可导航同级消息，下一次服务商输入仅包含选中的祖先路径，覆盖虚拟根首轮及多模型场景。 (verification: real SQLite + scripted provider payload + Electron)
- AC4 — 替换仅在生成成功并原子发布后移除确认过且合格的旧叶节点；无关分支和引用不受影响。错误、取消、资格过期、发布失败及重启保留旧内容，并如实显示新同级消息。 (verification: real SQLite + stream failure injection + Electron)
- AC5 — 编辑重发遵守确认过的当前模型/控制选择或显式源设置，保留未改附件，并在不丢失原分支的前提下拒绝缺失/不受支持文件。 (verification: renderer + Main integration + Electron)
- AC6 — 现有全局自动重试次数、退避、退出、故障转移/回退及瞬时状态维持单一所有者；取消、部分已输出内容及未知投递绝不触发新的整轮自动提交。 (verification: retry-owner unit + stream integration)
- AC7 — 中英文用户指南及全部变更语言键描述受支持 Home 模式、替换资格、重试限制和 Agent/临时聊天边界；验证键盘、窄布局及明暗原生交互。更广的间隔/覆盖/扁平化请求仍明确未完成。 (verification: docs gate + i18n + renderer + Electron)

## Risks

成功的远程请求与 SQLite 替换不是同一事务。发布含糊时保留两个答案，不承诺服务商只执行一次。现有消息删除可重挂后代；替换不得在缺少更严格叶节点守卫时复用该行为。审阅和派发可能与配置变化、文件清理、分支编辑及另一窗口竞争。多模型分组与服务商回退要求区分请求身份和实际结果身份。更显眼的操作可能产生额外计费请求，因此保留明确确认及当前可选重试上限。仍需原生 Windows/Electron 验收；源码检查与文档检查不是功能验证。
