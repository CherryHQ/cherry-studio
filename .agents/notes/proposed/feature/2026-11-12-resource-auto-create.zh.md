# Agent Note: 以用途为起点的智能体与助手创建流程

Status: proposed

[English](2026-11-12-resource-auto-create.md) | 中文

## 问题

创建智能体或助手目前只能走分步的 `ResourceCreateWizard`（`src/renderer/components/resourceCatalog/dialogs/create/ResourceCreateWizard.tsx`）。助手有三步（基础信息 → 系统提示词 → 知识库），智能体最多四步（基础信息 → 系统提示词 → 技能 → 知识库）。用户要自己选头像、起名、写或生成提示词，再手动勾选技能和知识库。唯一的生成辅助是 `PromptPolishActions`，它只能根据名称生成系统提示词。没有任何能力能把一句用途变成一整套配置。创建时也完全无法选择 MCP 服务：`buildCreateAgentCommand` 和 `buildCreateAssistantDto`（`src/renderer/utils/resourceCatalog/resourceCreate.ts`）从不发送 MCP。

智能体向导也没覆盖智能体需要的配置。内置工具、MCP 服务、IM 频道、回复语言、心跳和环境变量，都只能在创建之后去编辑弹框或全局设置里改。系统提示词步骤只显示用户自己写的指令，用户看不到智能体实际收到的内容。创建结束时也没有任何反馈：视调用方不同，弹框要么直接关闭，要么选中新项，要么打开对话，用户始终看不到配了什么。

设计原型（`bot-profile-cherry`）定下了一个入口页：头像、名称、用途、模型，然后选择 **自动创建** 或 **手动创建**。原型还定义了完整的智能体向导、结果页和头像选择器的改进。原型的其余部分由[分页式编辑弹框](2026-11-12-resource-edit-pages.md)和[对话页资料面板](2026-11-12-chat-profile-pane.md)负责。

## 提案

### 在现有向导前加一个入口页

`ResourceCreateWizard` 打开时先显示新的入口页，助手和智能体共用。入口页包含：

- 居中的大号 emoji 头像，使用 `EmojiAvatarPicker`；
- 名称，自动创建时可以不填；
- 用途文本框，绑定到现有的 `description` 字段；
- 模型选择器，过滤规则与基础信息步骤相同。

底部按钮是：取消、**手动创建**、**自动创建**。

- **手动创建** 切到步骤页的第 1 步。头像、名称、模型和用途（作为描述）共用同一个表单，所以会自动带入。如果智能体的系统提示词还是空的，用途也会预填进系统提示词。
- 填好用途并选好模型后，**自动创建** 才可点。它会生成一套配置，合并进提交的值（不改写表单），再调用调用方现有的 `onSubmit`。
- 如果调用方预置了 `initialValues.prompt`（例如已经配好的模板），向导直接打开步骤页。

### creator skill：一次生成并校验

`src/renderer/utils/resourceCatalog/autoConfigure.ts` 负责三部分。

- **creator 系统提示词。** 要求模型只返回一个 JSON 对象，包含这些字段：
  - `name`、`emoji`、`description`、`prompt`、`knowledgeBaseIds`、`mcpServerIds`；
  - 智能体另加 `skillIds` 和 `permissionMode`；
  - 助手另加 `enableWebSearch`。
- **输入构造。** 发送用途、可选的名称，以及用户实际已安装内容的精简目录：
  - 非内置技能（仅智能体）；
  - 知识库；
  - MCP 服务；
  - 该运行时允许的权限模式。
- **校验解析。** 依次做这些事：
  - 去掉代码围栏，截取出 JSON 对象；
  - 用 zod 校验；
  - 丢掉不在所给目录里的 ID；
  - emoji 只有是单个 RGI emoji，且不是旗帜、单独的修饰符或纯符号时才采用，否则用该类型的默认头像；
  - 权限模式只有在运行时允许且不是 `bypassPermissions` 时才采用，否则用该运行时的创建默认值；
  - 名称或提示词为空时不返回结果。

生成通过 `fetchGenerate` 调用默认模型，和 `PromptPolishActions` 用的是同一个。用户选的模型只分配给新建的资源。没有设置默认模型时，自动创建直接提示这一点，不调用模型。超时时间为 60 秒，关闭弹框即取消。用户自己选的头像或输入的名称优先于生成值。失败时，弹框显示错误，不创建任何资源，手动创建仍然可用。

### 头像

- 默认头像：助手是 💬，智能体是 ✨。creator 提示词仍然禁止使用 🤖。
- `EmojiAvatarPicker` 弹层加一个标题栏，带 🎲 按钮，点一下随机换一个 emoji。
- 共用的 emoji 选择器（`src/renderer/components/EmojiPicker`）调整样式：搜索框改为无边框浅灰底；当前分类和高亮用前景色而不是主题色；分类图标 16 px、灰色，悬停和选中时加浅底；emoji 24 px，一行 8 个；分类标题 12 px 灰色。键盘焦点仍然可见。
- 该选择器中隐藏 🇹🇼 旗帜（`1f1f9-1f1fc`），浏览和搜索都看不到。
- 判断用户是否选过头像改为读表单的 dirty 状态，不再和默认值比较。

创建流程里头像仍然只用 emoji。编辑弹框里依然可以上传图片。

### 步骤

助手的步骤保持 基础信息 → 系统提示词 → 知识库。智能体的步骤改为 基础信息 → 工具 → 技能 → 知识库 → MCP → 频道 → 高级。只有智能体的运行时支持的步骤才会显示。智能体仍按现状在 Pi Durable 运行时上创建，不提供运行时选择。

- **基础信息。** 头像和名称，智能体接着是权限模式，然后是一个模型。这一步去掉描述字段；入口页填的用途仍作为描述。
- **工具（智能体）。** 浏览器控制、电脑操作两行，全局未开启时各显示「未启用」标记，并带一个跳转到其设置的链接。下面是该运行时的内置工具，按分类分组，每个一个开关。关掉一个工具，就把它加进 `disabledTools`。
- **技能、知识库和 MCP。** 三者共用一个列表组件，编辑弹框也用它。它有搜索框、「添加 …」菜单、「全部开启」，每项一行，显示图标、名称、描述和开关。添加菜单分别是：技能——在线搜索、本地导入、系统搜索；知识库——新建知识库、导入文件；MCP——从市场添加、手动添加、导入 JSON。内置技能锁定为开启。添加操作在弹框内打开，复用设置页现有的对话框。
- **频道（智能体）。** 列出这个智能体将拥有的频道，「添加频道」菜单包含所有支持的平台，每个频道有一个配置对话框：名称、凭据、允许的会话 ID、平台支持时的「仅 @ 消息」，以及继承智能体或单独指定的权限模式。频道随创建命令一起发送，在主进程中与智能体在同一个事务里创建。扫码登录的平台（微信，以及飞书扫码注册）创建时已绑定但未启用，扫码登录在结果页或编辑弹框里进行。
- **高级（智能体）。** 完整系统提示词、回复语言、心跳和环境变量：
  - **完整系统提示词。** 主进程新增一个 IpcApi 路由，根据草稿（指令、语言、技能、禁用的工具、知识库），用运行时自己的构建函数组装出 Pi Durable 运行时实际会发送的提示词。渲染进程以只读分段显示，中间只有一块可编辑，即智能体自己的指令，并显示大致 token 数。技能或语言变化时会刷新。指令为空时，依赖指令的段落不出现，与运行时现有行为一致。
  - **回复语言。** 一个下拉框：跟随全局设置（显示其当前值）、不限制、预设语言之一，或「其他语言…」，选它时出现输入框。写入现有的 `languageMode` / `languageCustom` 映射。
  - **心跳。** 一张卡片，含标题、说明和开关。打开后显示间隔和最长执行时间（分钟），沿用现有的上下限和默认值。心跳任务在创建后再编辑。
  - **环境变量。** 一个文本框，每行一个 `KEY=VALUE`。

### 结果页

每条创建路径，无论自动还是手动，最后都在同一个弹框里进入结果页。自动创建生成期间，弹框显示一个进行中的视图，展示头像和正在配置的内容，不伪造逐步进度。结果页显示头像、名称、描述，以及已配置内容的摘要：系统提示词是否已填写、模型、权限模式、已启用工具（`X / Y`）、技能、知识库、MCP 服务、频道（含待扫码登录的）和心跳。它有两个操作：

- **调整设置**：打开新资源的编辑弹框。
- **开始对话**：执行调用方的开始操作。资源库、智能体页和会话选择器打开对话；选择器选中新建项；市场模板打开对话。

`onSubmit` 返回新建资源的 ID，以便向导显示它。向导的每个调用方都提供自己的开始操作。

### 创建数据

创建值新增 `mcpServerIds`，助手另加 `enableWebSearch`。智能体还新增 `disabledTools`、回复语言、心跳设置、环境变量和频道。默认都为空或关闭。

- 运行时支持 MCP 时，智能体发送 `mcps`，以及现有的 `disabledTools` 和 `configuration` 字段。
- 助手发送 `mcpServerIds`。选了 MCP 服务或网络搜索时，同时发送对应的 `settings`。

## 备选方案

- **智能体在运行时自行配置。** 做法是内置一份 `SKILL.md`，给 `mcp__cherry-tools__config` 扩展头像、提示词、技能等操作，然后开第一个会话让智能体自己配置。没有采用：助手没有智能体运行时，同一流程要做两套机制；而且更慢，还会扩大一个无需授权就能运行的工具。
- **Cherry Assistant 的 `create_agent`。** 这个工具只接受 `name`、`description`、`instructions` 和 `model`，只属于内置的 Cherry Assistant，也不能创建助手。
- **通过 `ai.text.generate` 使用结构化输出。** 这比从文本里解析 JSON 更可靠。但该 IPC 路由没有输出 schema 选项，属于上游改动，留给单独决定。文本 JSON 加 zod 校验对所有服务商都可用。
- **用用户选的模型生成。** 只给智能体用的模型可能不支持 `ai.text.generate`，所以和提示词润色一样改用默认模型。
- **启用全部已安装技能，知识库和 MCP 留给用户选。** 这是原型最初的画法。让模型从已安装目录中挑选，得到的配置更贴合用途，而且之后都能改。
- **向导使用 Claude Agent 运行时。** 原型的工具页列的是 Claude Agent 的 17 个工具，提示词页却展示 Pi 的提示词。Pi Durable 是产品的创建运行时，它的提示词能组装成文本；Claude Agent 的基础提示词是 SDK 预设，无法展示。
- **在渲染进程里组装完整提示词。** 原型把组装逻辑复制到了渲染进程。副本会与运行时逐渐不一致；主进程路由复用运行时自己的构建函数。
- **先建草稿频道，提交时再绑定。** 取消时会留下无主的频道和扫码会话。和智能体在一个事务里创建可以避免。
- **频道推迟到创建之后配置。** 更简单，但原型把频道作为配置智能体的一部分，而且只有扫码登录需要智能体先存在。

## 验收标准

- AC1 — 为智能体或助手打开新建弹框时显示入口页，包含头像、名称、用途、模型、手动创建和自动创建，且在填好用途并选好模型之前自动创建不可点 (verification: renderer; owner: implementer)
- AC2 — 点手动创建会打开现有的第一步，已填的头像、名称、模型以及作为描述的用途都已带入 (verification: renderer; owner: implementer)
- AC3 — 模型返回有效结果时，自动创建只调用一次 `onSubmit`，带上生成的名称、emoji、描述和提示词；用户自己输入的名称或选的头像会保留，不被生成结果覆盖 (verification: renderer; owner: implementer)
- AC4 — 生成的技能、知识库、MCP ID 如果不在已安装目录里，不会进入创建数据；生成的权限模式永远不是 `bypassPermissions` (verification: unit; owner: implementer)
- AC5 — 旗帜、多字符或非 emoji 的头像值会回退为该类型的默认 emoji (verification: unit; owner: implementer)
- AC6 — 输出无法解析、名称或提示词为空、生成出错或超时时，显示错误、不创建任何资源，手动创建仍可用 (verification: renderer; owner: implementer)
- AC7 — 运行时支持 MCP 时，选中的 MCP 服务以 `mcps` 写入新建的智能体；对新建的助手，以 `mcpServerIds` 写入并带上使用这些服务的设置；选中的网络搜索写入助手设置 (verification: unit; owner: implementer)
- AC8 — 在运行中的应用里，根据用途自动创建一个智能体和一个助手后，它们的编辑弹框显示生成的 emoji、名称、提示词和选中的能力 (verification: Electron; owner: implementer)
- AC9 — 所有新增界面文案在全部渲染进程语言包中都有翻译，没有占位符 (verification: docs gate; owner: implementer)
- AC10 — 新建智能体的默认头像是 ✨，头像选择器的 🎲 按钮会把头像换成另一个 emoji，在 emoji 选择器里浏览或搜索都找不到 🇹🇼 旗帜 (verification: renderer; owner: implementer)
- AC11 — 系统提示词为空的智能体走手动创建时，系统提示词预填为用途，基础信息步骤不再显示描述字段 (verification: renderer; owner: implementer)
- AC12 — 自动或手动创建完成后，弹框显示列出已配置内容的结果页，它的两个操作分别打开新资源的编辑弹框、执行调用方的开始操作 (verification: renderer; owner: implementer)
- AC13 — 智能体向导显示基础信息、工具、技能、知识库、MCP、频道和高级七个步骤，每一步选的值都进入创建命令 (verification: renderer; owner: implementer)
- AC14 — 在工具步骤关掉一个内置工具后，新建的智能体的 `disabledTools` 里包含该工具；全局未开启时，浏览器控制和电脑操作两行显示「未启用」标记 (verification: renderer; owner: implementer)
- AC15 — 技能、知识库和 MCP 列表可按搜索过滤，「全部开启」会开启每一项，并提供本 Spec 列出的添加操作 (verification: renderer; owner: implementer)
- AC16 — 向导中配置的频道在同一次操作中创建并绑定到新智能体，智能体创建失败时不留下任何频道 (verification: main service test; owner: implementer)
- AC17 — 高级步骤显示组装好的 Pi Durable 系统提示词，只有智能体自己的指令可编辑；技能或回复语言变化时预览随之更新 (verification: main service test and renderer; owner: implementer)
- AC18 — 高级步骤中设置的回复语言、心跳和环境变量写入新建智能体的配置 (verification: renderer; owner: implementer)
- AC19 — 在运行中的应用里，手动创建一个带频道、禁用了一个工具并开启心跳的智能体后，从结果页点调整设置，编辑弹框中三者都能看到 (verification: Electron; owner: implementer)

## 风险

- 模型质量参差不齐。较弱的模型可能返回散文或不合格的 JSON。解析器会拒绝，手动创建只差一次点击。
- 生成时会读取已安装的技能、知识库和 MCP 服务的名称与描述，并发给默认模型的服务商。这和任何列出这些资源的对话暴露程度相同，只是现在发生在创建时。
- 自动创建可能启用用户没检查过的 MCP 服务和技能。它们仅限于用户已经安装的资源，而且之后都可以修改。
- 每次自动创建多一次模型调用，会增加几秒延迟和 token 成本。
- emoji 选择器的样式调整和隐藏旗帜，会作用于所有使用该共享选择器的地方，包括用户资料。
- 对原本直接打开对话的调用方，结果页让用户多点一次。
- 频道和智能体一起创建，会扩大创建命令及其事务。一个频道校验失败会让整次创建失败，所以向导在提交前先校验频道表单。
- 提示词预览读取的文件与运行时相同（工作区 `system.md`、记忆、首次引导状态）。新智能体使用默认工作区，因此用户之后为某个会话选择其他工作区时，实际提示词可能和预览不同。
