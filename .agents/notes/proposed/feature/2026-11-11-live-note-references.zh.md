# Agent Note: 实时笔记引用的源路径与当前内容交付

Status: proposed

[English](2026-11-11-live-note-references.md) | 中文

## Problem

笔记引用目前交付托管快照，后续修改和文件系统智能体使用的路径可能与用户的源笔记不一致。

## Proposal

在对话中传递明确的笔记来源标记和绝对源路径。每次请求解析当前笔记根目录、检查路径包含关系，并交付源文件当前内容或明确的不可用状态。文件系统智能体在现有权限下获得源路径。

## Alternatives considered

- 新增需要审批的内置笔记写入工具暂缓：它会引入写入权限、路径包含和审批范围。
- 复用文件系统 MCP 或将工作区指向笔记目录需要额外配置，且不携带明确的引用身份。
- 渲染器提供将回复应用到笔记的操作需要单独的用户流程，也不会向智能体提供源路径。
- 按 `.md` 扩展名推断来源被否决：普通 Markdown 附件并非笔记引用。

## Acceptance criteria

- AC1 — 从启动器或 `@` 提及选择的笔记在发送、持久化、编辑往返及重新发送过程中携带 `noteReference` 和绝对源路径；文件选择器中的普通 Markdown 附件不携带。 (verification: 编辑器测试)
- AC2 — 每次聊天请求包含保留对话中每个引用笔记的源路径及磁盘当前内容，包括文件修改和压缩之后；正文受既有附件预算限制，源不可读时给出明确的不可用状态而不是过期内容。 (verification: 聊天和保留上下文测试)
- AC3 — `read_file` 返回引用笔记的当前内容并沿用现有分页。 (verification: 工具测试)
- AC4 — Claude Code、Pi 和 Pi Durable 公布源路径而非托管副本路径。 (verification: 运行时测试)
- AC5 — 缺失、不可读或根目录之外的源文件产生明确的不可用状态，绝不静默使用快照、按文件名搜索或转向其他根目录。 (verification: 源读取器及消费者测试)
- AC6 — 外部写入后，笔记通过现有监听链刷新打开的干净笔记，并保留脏草稿的冲突对话框，不需要新增代码。 (verification: 笔记回归测试)

## Risks

本层不增加写入能力；普通聊天仍不能编辑笔记。原位编辑使用智能体运行时现有权限策略：默认提示和 `acceptEdits`/Full Access 保持不变。此处尚未验证 Windows 路径及 junction 行为。
