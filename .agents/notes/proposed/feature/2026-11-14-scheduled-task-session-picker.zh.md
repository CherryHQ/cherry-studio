# Agent Note：定时任务会话选择器

Status: proposed

[English](2026-11-14-scheduled-task-session-picker.md) | 中文

## 问题

定时任务只能复用第一次执行时恰好创建的会话。任务表单只提供一个 `reuseSession` 开关（`src/renderer/components/ScheduledTask/TaskFormDialog.tsx:401-416`），实体的 `reuseSessionId` 注释为"上一次执行绑定的会话，首次执行前为 null"（`src/shared/data/api/schemas/agents.ts:184-186`）。绑定由 `AgentJobsService` 在执行后写入（`src/main/ai/agents/AgentJobsService.ts:272`、`:313-314`），因此用户无法选择任务要延续哪个会话。

目前唯一记录的重新绑定方式是先关闭、保存、开启、再保存（`src/renderer/i18n/locales/en-us.json:506`）。这种方式不易发现，而且仍然只会生成新会话，无法接续已有会话。智能体侧的 `reuse_session` 工具参数也只是布尔值（`src/main/ai/mcp/servers/cherryAutonomyTools.ts:137`）。希望每个项目保留一个长期会话、或希望原地自动化已有对话的用户无法做到这一点（#21190）。

## 方案

将表单中的布尔开关替换为三选一的会话选项：

- **每次执行新建会话** —— 即当前的 `reuseSession: false`。
- **延续已绑定会话** —— 即当前的 `reuseSession: true`；会话由第一次执行绑定。
- **延续已有会话** —— 用户从所选智能体的会话中挑选一个。所选会话 id 立即保存为 `reuseSessionId`，因此第一次执行会接续该会话，而不是再创建一个。

### 数据

- 不新增列。`reuseSession` 与 `reuseSessionId` 的含义保持不变。保存"延续已有会话"时，设置 `reuseSession: true`，并将 `reuseSessionId` 设为所选会话 id。
- `2026-10-31-scheduled-tasks-page.md` 中提出的归属模型（`agent_session.taskId`、`isTaskReuseTarget`、未发布的迁移 `0035`）是所选会话的存储基础。若该 Spec 在实施前变更，本 Spec 需随之修订。
- 升级后，已有任务保持当前的 `reuseSession` 与 `reuseSessionId` 值及行为。本 Spec 自身不带迁移或回填。

### 选择规则

- 选择器只列出所选智能体拥有的会话。`AgentJobsService` 在创建和更新时拒绝属于其他智能体的会话。
- 选中已有会话时，工作区字段禁用，并显示任务将在该会话的工作区中运行。否则修改工作区会静默丢弃已绑定的指针（`AgentJobsService.ts:313-314`）。
- 选中已有会话时，在选择的当下即显示上下文增长警告（`agent.tasks.reuseSession.warning`），而不只是静态文案。

### 编辑

- 编辑提示词、计划、超时或渠道时，永远不改变 `reuseSessionId`。
- 只有在表单中明确更改会话选项时才会改变绑定会话。切换为"每次执行新建会话"会清除绑定。

### 会话缺失

- 若绑定会话在执行前已被删除，本次执行以专用错误码失败，不创建新会话，运行日志记录该失败。
- 任务详情显示会话缺失状态。用户可选择其他会话或切换模式来解决，不存在静默回退。
- `resolveTaskConversation`（`src/renderer/services/taskConversation.ts:59-61`）目前在绑定会话缺失时会回退。对于启用复用的任务，这部分取代了 `2026-10-31-scheduled-tasks-page.md` 中解析顺序的第 3 步：改为显示会话缺失状态，而不是最近一次执行。该 Spec 保持有效，其余解析步骤不变。

### 范围

- 智能体侧的 `reuse_session` 保持布尔行为，本次变更不为其增加会话选择器。
- 远程任务 API 的输出（`src/main/services/remoteAccess/agentTaskQueries.ts:120`）读取相同字段，无需修改。

## 考虑过的替代方案

- **在任务详情行上提供重新绑定操作。** 改动更小，但无法在创建时选择会话，仍保留三步式的心智负担。本 Spec 未采用；日后可在选择器之上添加。
- **从会话入口发起"在此运行任务"。** 对原地自动化的可发现性最好，但跨越会话界面与任务创建。暂缓；它复用此处定义的同一套服务规则。
- **绑定会话缺失时回退为新会话。** 在新位置重现当前的困惑（#21190）。拒绝。
- **让工作区跟随所选会话并保留指针。** 可行，但会改变表单显示的工作区，并需要独立的迁移方案。目前拒绝；改为禁用工作区。

## 验收标准

- AC1 — 任务表单提供"每次执行新建会话"、"延续已绑定会话"、"延续已有会话"三个选项；重新打开后保存的选择保持不变。（验证：渲染进程测试；Electron）
- AC2 — 保存"延续已有会话"时，在第一次执行前即绑定该会话，第一次执行接续它且不创建新会话。（验证：主进程服务测试）
- AC3 — 选择器只列出所选智能体的会话；服务在创建和更新时拒绝属于其他智能体的会话。（验证：主进程服务测试；渲染进程测试）
- AC4 — 选中已有会话时，在选择的当下显示上下文增长警告。（验证：渲染进程测试）
- AC5 — 编辑提示词、计划、超时或渠道永远不改变 `reuseSessionId`；只有明确更改会话选项才会改变。（验证：主进程服务测试）
- AC6 — 绑定会话已被删除时，执行以专用错误失败，不创建会话；任务显示会话缺失状态，直到用户选择会话或切换模式。（验证：主进程服务测试；渲染进程测试）
- AC7 — 变更前已存在的任务保持当前的 `reuseSession` 与 `reuseSessionId` 值及行为，无需迁移。（验证：主进程服务回归测试）
- AC8 — 选中已有会话时，工作区禁用，且表单说明原因。（验证：渲染进程测试）
- AC9 — 新增或变更的文案在所有已发布语言中均已翻译，并通过 i18n 检查。（验证：文档门禁；语义审查）

## 风险

- 所选会话可能很长，已超出模型的上下文窗口。警告与失败即报机制可限制损害，但无法阻止。
- 删除所选会话会使任务进入需要手动处理的会话缺失状态。这是有意设计，但对依赖旧静默回退的用户来说可能像是回归。
- 选择器依赖所选智能体的会话列表。会话很多的智能体需要分页或搜索；首个实现可能限制列表数量，且必须明确说明。
- 会话与对话的双重身份（CherryHQ/cherry-studio#20635）仍未理清。若该工作改变了会话 id 的含义，本 Spec 必须在实施前修订。
