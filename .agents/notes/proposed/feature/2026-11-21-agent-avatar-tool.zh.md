# Agent Note: 在对话中生成和恢复智能体头像

Status: proposed

[English](2026-11-21-agent-avatar-tool.md) | 中文

## 问题

智能体可以用 `generate_image` 调用已配置的绘画模型，用户也可以在智能体编辑器中上传图片。这两个入口目前都无法让用户要求智能体为已有智能体生成并应用新头像。现有的头像写入会替换受管理的文件引用。旧图失去最后一个引用后，可能被文件清理机制回收。

智能体创建和头像裁剪已有各自的手动操作流程。[图片上传 PR](https://github.com/CherryHQ/cherry-studio/pull/23788) 提供现有的头像绑定能力，[头像裁剪 Spec](https://github.com/CherryHQ/cherry-studio/pull/24618) 涵盖手动上传，[历史头像修复](https://github.com/CherryHQ/cherry-studio/pull/24478) 使历史消息显示智能体的当前头像。

## 方案

在 `cherry-tools` 中新增一个内置智能体工具，暂命名为 `agent_avatar`。支持根据文字描述生成头像和恢复头像两个操作。默认目标是当前智能体，由可信的会话上下文提供。修改其他智能体时，使用通过 `agent_list` 查到的稳定 ID。用户提供的名称存在歧义时，先请用户明确目标，再调用工具。目标须为智能体库中的有效智能体。目标 ID 不存在、在回收站中或仅供内部使用时，拒绝操作，提交头像时再次核对。

Claude Code 和 Pi 共用现有的智能体工具可见性与审批机制。生成或恢复前，审批绑定具体操作和目标。该工具会修改智能体的持久身份，因此完全访问模式也需要交互审批。审批被拒、工具被禁用，或会话无法收集审批时，均不会写入头像或开始生图。工具处理函数负责检查目标资格，运行时权限策略负责审批。

通过现有生图链路，用已配置的绘画模型根据描述生成一张头像。复用模型能力检查、取消处理、头像转码和受管理文件绑定。仅作为中间输入的生成文件可按现有机制清理。恢复无需配置绘画模型。头像描述与目标分别传入，生图请求只需要图片描述。

每个目标跨重启保留一份旧头像。备份涵盖带备用表情的受管理图片、表情及默认头像。备份中的图片使用持久文件引用，让现有的文件清理和备份机制能够识别。头像服务在同一写事务内保存旧头像并切换新头像。生图在事务外完成，备份以提交时实际使用的头像为准。再次生成成功时更新备份，恢复成功时消耗备份。此后用户手动修改头像会使备份失效，避免恢复旧的工具操作时覆盖用户手动选择的头像。备份图片缺失或无法读取时，返回失败并保留当前头像。

事务提交后，复用现有的智能体读模型刷新机制。以已提交的结果报告实际操作和目标。生图失败、提交前取消、解码失败或绑定失败时，当前头像和已有备份均保留。新增的临时文件遵循现有补偿和清理规则。数据库改动限于智能体头像数据，复用现有事务、文件引用和清理基础设施。

## 考虑过的方案

- 给现有的 `generate_image` 增加头像写入选项。这会扩大普通对话生图工具的权限，并改变它的持久化语义。
- 让智能体把生图工具返回的文件 ID 交给另一个写入工具。这需要验证文件确实来自本次生图，并处理跳过第二次调用或第二次调用失败时的文件保留。
- 把旧图 ID 写进工具输出或普通配置。文件清理系统需要有效引用，才能保证清理和重启后仍可恢复。

## 验收标准

- AC1 — 在智能体对话中说“给你自己生成一个水彩狐狸头像”，使用已配置的绘画模型生成图像，智能体编辑器、侧边栏、打开的标签页和历史消息标题都显示新头像。 (verification: Electron)
- AC2 — 用 `agent_list` 找到具名智能体且用户批准后，只修改该智能体。遇到同名歧义时先澄清，目标 ID 不存在、在回收站中或仅供内部使用时均不写入。 (verification: unit | Electron)
- AC3 — 在 Claude Code 和 Pi 中，禁用、拒绝审批或无界面的调用均无法生成或写入头像。完全访问模式仍显示具体目标和操作并要求审批。 (verification: unit | Electron)
- AC4 — “恢复上一个头像”能在文件清理和重启后恢复受管理的图片，也能恢复原来的表情或默认头像。再次恢复会提示没有备份，且恢复无需配置绘画模型。 (verification: unit | Electron)
- AC5 — 生图失败、提交前取消、解码失败或绑定失败均保留当前头像及已有备份。后续替换以提交时的头像为备份。此后用户手动修改头像会使工具备份失效。 (verification: unit)
- AC6 — 现有智能体头像上传、选择表情和重置的行为保持一致。永久删除智能体时释放备份头像引用，已有数据库升级后保留所有当前头像。 (verification: unit | Electron)

## 风险

文件创建和提供商调用是异步的。事务须覆盖备份与当前头像引用的切换。文件生命周期须处理新建的临时文件、被覆盖的备份和智能体的永久删除。审批目标的稳定 ID 须与实际写入目标一致。并发修改和可用运行时都需要通过智能体的实际入口验证。
