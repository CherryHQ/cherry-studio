# Agent Note: 可复用的上下文交接说明

Status: proposed

[English](2026-11-19-context-handoff-note.md) | 中文

## Problem

长对话最终会丢失早期的约束与决策。自动压缩会保留当前对话，但它是破坏性的，且不产生可携带的产物。用户若想在新对话中继续工作，只能手动重建状态。Issue [#19820](https://github.com/CherryHQ/cherry-studio/issues/19820) 要求在截断前生成一份可审阅的 Markdown 交接说明，使新对话无需原始记录即可使用。

本提案与 [原生压缩提案](../simplification/2026-11-12-native-agent-compaction.md) 及 [聊天上下文溢出缺陷说明](../bug-fix/2026-11-13-chat-context-overflow.md) 互补。它不改变压缩如何总结历史，也不拥有上下文用量报告，后者仍由 [运行时持有的上下文用量提案](../architecture/2026-10-30-agent-context-usage.md) 负责。

## Proposal

用户可以在任何至少有一条消息的对话中随时请求交接。当已用上下文达到完整上下文窗口的 80% 时，产品还会提供一次交接提示。该提示仅为建议：它本身不会生成说明、保存文件或开启新对话。

生成过程读取未修改的记录，产出一份 Markdown 草稿，章节依次为：目标、已确认决策、约束、待定问题、相关文件、下一步。已确认的决策与待办事项分属不同章节，便于读者区分既定事实与未决事项。

用户在可编辑的预览中审阅草稿。取消则不写入任何内容。确认则保存 Markdown，并在同一助手下创建一个新话题，将该文件作为附件带入。新对话的第一次请求携带该文件，而不携带原始记录。

交接提示未处理期间，该对话的自动压缩不会启动。提示在用户完成、关闭或取消，或生成失败时结束。这样可以保证草稿生成之前，源记录保持完整。

未经用户明确确认，交接内容不会写入磁盘、附加到对话或导出。本提案不包含自动保存设置。

## Alternatives considered

- 每次跨过阈值时自动生成交接：会产生模型请求成本，并在用户无意的情况下存储敏感内容。
- 压缩之后再生成摘要：破坏性截断已经移除了说明所需的源细节。
- 提示未处理时仍允许压缩继续：草稿可能基于已截断的记录生成，违反"交接先于截断"的要求。代价是用户决定期间压缩会被延迟，因此提示必须不阻塞、可关闭。
- 将交接存为新的数据库实体：Markdown 附件复用现有的文件与话题路径，无需新增 schema。

## Acceptance criteria

- AC1 — 在任何至少有一条消息的对话中，均可使用手动"创建交接"操作，且不改变记录。 (verification: renderer)
- AC2 — 已用上下文达到完整窗口的 80% 时，每个对话出现一次不阻塞的提示，直到被关闭；未经用户操作，不会生成或保存说明。 (verification: renderer)
- AC3 — 交接提示未处理期间，该对话的自动压缩不会启动，且生成读取的是未修改的记录。 (verification: unit)
- AC4 — 生成的 Markdown 依次包含"目标""已确认决策""约束""待定问题""相关文件""下一步"章节，既定事实与待办事项分属不同章节。 (verification: unit)
- AC5 — 用户可在保存前编辑预览中的草稿；取消则不写入任何文件。 (verification: renderer)
- AC6 — 确认后，在同一助手下创建新话题并附带该 Markdown，该话题的首次请求包含该文件且不含原始记录。 (verification: Electron)
- AC7 — 未经用户明确确认，交接内容不会写入磁盘、附加或导出。 (verification: unit)
- AC8 — 生成失败时，源对话及其压缩状态保持不变，用户会看到可重试的错误。 (verification: unit)
- AC9 — 功能的参考文档以中英文描述提示阈值、审阅步骤与附件行为。 (verification: docs gate)

## Risks

本提案中 80% 阈值为固定默认值；上下文窗口很大的用户可能比预期更早看到提示。提示打开期间压缩被延迟，如果用户忽略提示，对话可能继续增长，因此提示不得阻塞发送。交接的完整性取决于模型的提取能力；审阅步骤是遗漏或错误项的控制手段，本提案不声称草稿是详尽的。
