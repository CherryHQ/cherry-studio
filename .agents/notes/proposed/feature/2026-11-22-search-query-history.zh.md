# Agent Note: 全局搜索中的查询历史

Status: proposed

[English](2026-11-22-search-query-history.md) | 中文

## Problem

Issue #19537 希望能找回此前的搜索词，而不只是最近打开的任务。截图展示的是全局搜索弹窗。目前 `GlobalSearchPanel` 读取 `ui.global_search.recent_items`，其中的 route/topic/session 条目是导航历史，而非搜索词。面板已经通过保护逻辑防止 Enter 误处理输入法确认或过时的防抖、延迟查询结果。查询历史不能绕过这些保护，也不应保存每次按键产生的中间文本。

## Proposal

### 记录主动执行的搜索

全局搜索输入为空时，在现有最近打开分组上方增加独立的查询历史分组。导航历史及其现有限制和行为保持不变。查询历史不包括浏览器历史、设置搜索、知识库召回历史或网络搜索服务的搜索历史。

用户激活与当前查询一致的搜索结果，或从该查询进入完整消息搜索时，记录去除首尾空白后的非空查询。同时在非空输入旁提供可访问的 Search 操作，让用户可以主动记录并执行没有可打开结果的查询。此操作复用现有搜索流程，停留在面板内，不打开对话。不改变 Enter 激活当前选中结果的行为。Search 操作必须等待输入法组合输入结束，并确认输入、防抖值和延迟值一致；结果加载中或失败时不能提交过时文本。成功但没有结果的搜索也是有效查询。仅输入、切换筛选条件、关闭弹窗或后台自动刷新都不记录查询。

最多保存 20 个查询，按最近使用时间排序，仅包含查询文本和最后使用时间。去除首尾空白，保留内部空白、Unicode 和大小写。按处理后的完整文本精确去重，再次使用时移到最前。不保存结果摘要、对话内容、实体 ID、凭据或筛选条件快照。历史查询沿用当前面板的筛选条件，且这些条件保持可见、不被修改。查询只是本地搜索的字面输入，绝不是 URL、命令、工具请求或发给模型的指令。

### 调用与删除

输入为空时展示最近六个查询，有更多记录时提供本地化的 Show all 操作。通过鼠标或键盘选择查询后，填入输入框、聚焦并执行普通搜索，不打开结果。用户可以先修改查询再选择结果。输入和历史都为空时，保留现有最近打开或空状态，不展示空的历史标题。

为每个查询提供可访问的删除操作，并提供 Clear search history 清空整个查询列表。删除不能激活所在行、导航、清空导航历史或删除对话。删除后保持合理的键盘焦点，包括删除最后一行。请求进行中清空历史后，迟到的响应不能恢复历史；只有后续主动搜索操作可以再次添加。使用普通文本渲染、带完整可访问值的截断显示以及稳定 ID，不将查询文本注入为标记。

### 存储与职责

按数据层对可丢弃搜索历史的指导，使用新的类型化 `usePersistCache` 键。现有 recent-items 键和结构保持不变，不将标题或路径迁移为查询。渲染层 CacheService 负责 localStorage 持久化；Main 仅转发已有的跨窗口 persist-sync 消息，不存储此历史。渲染层模块负责分组、规范化、调用历史和键盘交互。跨进程缓存类型仅定义存储数据契约。复用现有 UI 原语和缓存同步，不新增数据库表、偏好设置、IPC 协议或服务。

在读取边界校验持久化值：只接受预期的文本和时间结构，丢弃空值或无效项，并在展示前去重、限制数量。沿用现有缓存归属与重置行为。历史是本地便利状态，不保证永久保存，也不是同步到账户的档案。查询可能包含敏感文本，不新增日志、分析上报或模型、服务商请求。删除更新应用缓存，不承诺从备份或存储介质中进行取证级抹除。

## Alternatives considered

- 用查询替换最近打开条目：移除现有导航能力，而查询调用并不需要这样做。
- 每次防抖后保存：没有主动搜索动作就记录未完成或输入法组合文本。
- 仅记录打开结果的操作：遗漏有价值的零结果查询，因此还需要显式 Search 操作。
- 保存筛选条件、结果或消息摘要：增加请求之外的隐私与过时状态成本。
- 将历史放在偏好设置或新数据库表中：违背现有可丢弃缓存的归属，并在没有用户数据需求的情况下增加迁移工作。

## Acceptance criteria

- AC1 — 主动激活与当前查询一致的结果、进入完整消息搜索及显式 Search 都记录正确的非空查询，包括成功的零结果搜索；仅输入、输入法确认、过时或失败、加载中的结果以及关闭弹窗都不记录。保留现有 Enter 行为。 (verification: renderer)
- AC2 — 重启或重新打开后，最多恢复 20 个精确去除首尾空白、去重、按最近使用排序的查询，与导航历史独立；安全丢弃损坏缓存条目，现有最近打开记录不变。 (verification: unit, renderer and Electron)
- AC3 — 空输入展示六个查询，需要时提供 Show all；鼠标或键盘调用历史会填入查询并在可见的当前筛选条件下搜索，不打开结果；历史为空时不显示空分组。 (verification: renderer and Electron)
- AC4 — 单条删除和 Clear 仅影响查询历史，不激活所在行，保持可访问焦点，且不会因迟到的搜索响应而恢复。 (verification: renderer and Electron)
- AC5 — 中英文标签、窄屏、明暗主题及辅助技术语义通过定向检查；现有输入法、过时 Enter、消息预览、导航历史和筛选流程保持正常，原生验证边界明确说明而非假定通过。不新增查询日志或外部、模型调用。 (verification: renderer, docs gate and Electron)

## Risks

以主动搜索为记录边界不如记录每次后端调用自动，但可以避免堆积输入片段。Search 操作必须与选中第一个结果区分，并保留现有异步保护。

查询可能包含私密文本。历史应有数量上限、可删除、不新增遥测，并如实说明存储限制。重置缓存时历史可能丢失，它不是用户编写的对话数据。

新增历史行会改变列表框的键盘顺序。删除控件不能错误嵌套交互元素或抢占行操作。复用面板的选项 ID 和 active-descendant 模型，并在宣称实现完成前验证真实键盘行为。
