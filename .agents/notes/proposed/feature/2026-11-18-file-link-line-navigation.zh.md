# Agent Note: 文件链接行级定位

Status: proposed

[English](2026-11-18-file-link-line-navigation.md) | 中文

## 问题

聊天中的文件引用可以包含源码位置，但 `ClickableFilePath` 会移除冒号后缀中的行列号，Markdown 文件链接解析也会丢弃片段。文件打开动作和预览插件收到的只有路径，没有位置信息。因此，指向第 42 行的链接只会打开文件，不会显示该行。智能体文件打开流程还会在源码预览之前将 HTML 路由到浏览器面板。

## 提案

将文件引用解析为文件系统路径和可选的渲染进程源码位置。在可点击的内联路径和本地 Markdown 链接中支持 `path:42`、`path:42:5`、`path#L42` 和 `path#L42-L48`。行号从一开始，范围包含两端。位置中保留输入的列号，但首版仅承诺行级定位和行高亮。在解码 Markdown 路径之前识别位置语法，使经过编码的文件名标点保持字面含义。保留 Windows 盘符、主目录展开、工作区相对路径解析和现有链接安全机制。普通片段不属于源码位置，沿用现有处理方式。

Markdown 文件打开、`ClickableFilePath`、消息动作和文件预览导航使用统一的位置契约。仅传路径的调用方继续有效。文件系统元数据、目录检查、复制路径、保存和外部应用打开操作仅接收文件系统路径。外部编辑器行级定位不在本版范围内。

右侧面板的导航所有者将位置与已接受的文件选择请求一起传递。每次点击都是一次导航意图，包括再次点击同一个文件的同一行。匹配文件加载完成且视口就绪后，仅应用最新接受的意图；过期异步任务不得移动新文件的位置。保留未保存编辑确认和草稿。取消文件切换时不得改变当前可见位置。打开普通文件或切换会话时清除待处理位置。

通过 `ArtifactPane` 和 `FilePreview` 将位置传给源码查看器。文本文件显示并高亮目标行或包含两端的范围。带位置的 Markdown 和 HTML 文件使用源码视图；带位置的 HTML 绕过浏览器路由。不带位置的链接保持当前预览或浏览器行为。目录和二进制预览保留现有打开行为，不显示源码高亮；没有应用内预览的界面保留现有回退行为。

`FileEditor` 使用 Pierre 支持的 API 和虚拟化能力，负责显示和高亮逻辑行。实现前检查已安装库的公开 API；如果无法可靠定位虚拟化逻辑行，应改进上游能力，而不是增加 DOM 查询或像素估算。超出范围的正数位置收敛到已加载文档边界；逆序范围以及零、不安全或格式错误的数字不得产生定位请求或引发崩溃。导航不得修改文件内容，也不得在显式导航动作之外丢弃用户选区。

## 考虑过的替代方案

- 将带后缀的原始字符串传给文件 API：否决，因为元数据和读取操作需要真实文件系统路径。
- 为 Markdown 和可点击路径分别添加解析器：否决，因为路径解码、Windows 盘符和行号语法会产生分歧。
- 查找行元素并调用 `scrollIntoView`：否决，因为屏幕外的虚拟化行可能没有 DOM 节点。
- 将所有带位置的链接交给外部编辑器：否决，因为本版面向现有应用内预览，不涉及编辑器专用协议。

## 验收条件

- AC1 — 内联引用和本地 Markdown 链接保留支持的行号及范围语法、Windows 和工作区路径，以及经过编码的文件名标点；错误位置不产生定位请求 (verification: 路径与 href 解析单元测试)
- AC2 — 点击带位置的文本文件后打开预览，并在加载完成后显示及高亮指定行或范围；普通链接、目录打开和回退界面保留现有行为 (verification: 渲染进程集成测试与 Electron 交互)
- AC3 — 同文件重复点击有效，最新接受的导航优先于延迟完成的旧请求，取消未保存文件切换时保留草稿和可见位置 (verification: 渲染进程导航测试)
- AC4 — 带位置的 Markdown 和 HTML 链接在指定行打开源码视图，不带位置的链接保留当前渲染预览或浏览器路由 (verification: 渲染进程路由测试与 Electron 交互)
- AC5 — 大文件中初始渲染区域之外的目标在导航后可见并高亮，包括自动换行场景；越界目标收敛且不修改内容 (verification: 使用大型源码样本进行 Electron 交互)
- AC6 — 变更文件格式检查、受影响消费者的定向测试、渲染进程类型检查、文档影响审查及双语文档检查通过；明确报告未验证的运行时范围 (verification: 定向本地检查与文档门禁)

## 风险

当前 `FileEditor` 使用 Pierre `File` 和共享虚拟化器，因此另一个 Pierre 组件提供滚动 API，并不能证明当前界面能定位逻辑行。选择实现前必须确认库的兼容能力。源码模式切换必须配合宿主编辑状态，不能通过重新挂载丢弃未保存内容。以冒号数字语法结尾的字面文件名在内联引用中仍然存在歧义；显式 Markdown 目标中编码后的标点提供转义方式。源码行号指向当前加载的文件，不是消息引用的历史版本。
