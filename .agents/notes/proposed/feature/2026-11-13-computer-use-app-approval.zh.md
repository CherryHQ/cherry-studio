# Agent Note: 默认开启 Computer Use 并记住应用授权

Status: proposed

[English](2026-11-13-computer-use-app-approval.md) | 中文

## 问题

Computer Use 目前默认关闭。`ComputerUseService` 负责应用解析、原生会话和停止控制，但没有按应用请求并记住授权。批准一个 Automation REPL cell，无法代表用户同意访问其中动态选择的每个应用。

## 提案

通过偏好设置生成器的源文件，将 `app.computer_use.agent_control.enabled` 改为默认开启。保留已明确保存的关闭设置。该设置控制能力是否可用；普通权限模式下，访问应用仍需授权。

在主进程解析实际应用身份，并在启动应用、打开原生控制会话、读取应用内容或发送输入之前询问。应用发现和身份解析可以在授权之前执行。展示应用名称和身份，提供恰好三个选项：

- **Always**：在本机安装中持久保存该应用的允许授权，跨会话共享，重启后保留。
- **Approve for session**：仅允许发起请求的当前对话访问该应用。授权跨轮次和 REPL 重置保留；对话结束或 Cherry Studio 退出后清除。不继承到其他对话或子会话。
- **Reject**：拒绝当前请求，不授予权限，也不写入永久拒绝规则。后续请求可以再次询问。

使用原生稳定应用身份作为授权键，不使用显示名称、进程 ID 或 guest 提供的目标字符串。无法确定稳定身份时，不为未验证目标提供可复用授权。在不启动应用的情况下解析身份；批准后，要求实际启动的目标与已批准身份一致。

发起请求的执行使用 `bypassPermissions` 时，跳过应用授权并直接执行，不弹出批准提示。Bypass 不创建记忆授权。返回普通权限模式后，恢复应用授权检查。现有操作系统权限、Computer Use 显式关闭开关、用户停止控制和应用所有权约束继续生效。

`ComputerUseService` 在公共原生边界执行权限检查，包括对已打开句柄的操作。运行时适配器提供可信的对话身份、当前权限模式及现有批准请求/响应桥接；REPL 代码不能提供这些值。持久授权归 Preference 所有；对话授权是主进程运行时状态。复用现有批准注册表和展示流程，明确携带应用身份和决策范围，不从通用工具批准推导应用授权。覆盖所有内置 Computer Use 入口，包括智能体运行时和助手话题；交互执行若没有可用的批准响应通道，则在访问原生目标之前失败。

同一对话和应用的并发请求共享一个待批准项。取消或销毁对话时撤销待批准项；迟到的回答不能恢复已取消操作，也不能创建授权。一个 cell 访问另一个应用时，必须在访问前单独获得该应用的授权。在 Computer Use 设置中增加已保存应用列表，允许用户移除 Always 授权；之后的访问，包括通过已有句柄访问，都必须重新检查权限。

这是与现有[应用身份展示](../../implemented/feature/2026-11-10-computer-use-app-icons.md)并行的新授权决策；原有说明继续负责图标和调用元数据。

## 考虑过的替代方案

- 保持默认关闭：保留额外设置步骤，无法提供所需的按应用授权流程。
- 仅批准外层 REPL 工具：无法约束 cell 内稍后选择的应用。
- 按显示名称或原生进程 ID 记住授权：会混淆不同应用，或在重新启动后丢失授权。
- 将 Reject 视为永久拒绝：增加用户未明确选择的持久封禁。

## 验收标准

- AC1 — 未设置 Computer Use 偏好时启用能力；已明确关闭的偏好保持关闭。(verification: unit)
- AC2 — 首次访问未授权应用时，在启动、观察或输入之前展示其已解析身份及 Always、Approve for session、Reject；Reject 不产生目标侧副作用。(verification: unit and Electron)
- AC3 — Always 跨重启和对话保留，且仅匹配已批准身份；从设置中移除后，即使已有句柄也需要重新授权。(verification: unit and renderer)
- AC4 — 会话授权跨轮次和 REPL 重置保留，不授权其他对话或子会话，并在对话销毁或应用退出时失效。(verification: unit)
- AC5 — Bypass 不弹出应用批准提示、不保存授权；离开 bypass 后恢复授权检查，同时保留原生权限、显式关闭、停止控制和所有权的现有约定。(verification: unit and Electron)
- AC6 — 多应用 cell 分别询问；并发重复请求共享提示；取消和迟到响应不能执行操作或保存授权。(verification: unit)
- AC7 — 所有内置 Computer Use 适配器执行相同的应用策略；批准界面和设置使用翻译字符串及现有 UI 组件。(verification: unit, renderer and Electron)

## 风险

需要在每个受支持平台上核验已安装 SDK 的稳定身份能力。缺少启动前身份解析能力时，应改进上游 SDK，而不是先启动应用再发现用户批准的对象。现有安装可能已将旧默认值保存为 false；本提案明确不推断已保存的 false 是误设。

批准可能挂起正在执行的 REPL cell 内部的宿主调用。取消、执行超时和运行时批准投影需要集成验证，保证等待人工响应既不会丢失请求，也不会在取消后执行。Always 的广泛授权是有意设计，必须能在设置中查看和移除。
