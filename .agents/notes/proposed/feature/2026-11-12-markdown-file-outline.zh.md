# Agent Note: Markdown 文件预览大纲

Status: proposed

[English](2026-11-12-markdown-file-outline.md) | 中文

## 问题

Issue #22705 请求为从代理工作区打开的 Markdown 文档提供标题导航。现有 PR 没有实现。当前 main 已在 `src/renderer/components/FilePreview/plugins/markdown/MarkdownFilePreview.tsx` 管理 Markdown 文件渲染，因此大纲应属于该预览，而非新建平行文档渲染器或会话大纲。

## 提案

- 为渲染后的 Markdown 文件预览添加可折叠大纲，包括代理从工作区打开的文件。手动打开复用同一预览，不增加代理专用解析器。
- 按文档顺序缩进显示 H1-H3。ID 和标签来自实际 Markdown 渲染流程；重复标题拥有稳定且不同的目标，围栏代码不能产生标题。
- 点击或键盘激活条目时，将所属预览视口滚动到对应标题。滚动更新当前条目。明确焦点行为，仅打开或关闭大纲不能改变阅读位置。
- 窄面板默认折叠；提供可访问的大纲开关和本地化空状态。不占用可编辑源码面板，也不改变文件内容。源码和编辑模式保留现有控件。
- 文件或内容变更时重建条目，切换或卸载时断开观察器；锚点按预览实例隔离，避免同一文件的两个预览互相跳转。

## 已考虑的替代方案

- 浮动跳转菜单：更省空间，但隐藏文档结构；若面板宽度验收失败，可作为后续替代。
- 原样复用 PDF 大纲组件：其 PDF 页码导航不能提供 Markdown 锚点；仅在所有权明确时共享展示层。
- 在共享预览包新增 Markdown 插件：与渲染器现有 Markdown 预览和文件导航生命周期重复。

## 验收标准

- AC1 — 代理和手动打开的 Markdown 预览显示相同的 H1-H3 顺序、缩进和标签；代码围栏与非标题语法不产生条目（验证：渲染器）。
- AC2 — 重复、Unicode 和带格式标题在两个同时存在的预览中分别跳转到正确目标（验证：渲染器）。
- AC3 — 激活条目滚动所属视口；滚动更新当前条目而不移动键盘焦点；开关大纲保留阅读位置（验证：渲染器和 Electron）。
- AC4 — 文件刷新或切换更新大纲，无旧条目或观察器泄漏；编辑、源码模式和保存行为不变（验证：渲染器）。
- AC5 — 在实际应用检查窄宽布局、明暗主题、键盘和读屏标签；长文档保持响应，观察器工作量受标题数量约束（验证：Electron）。

## 风险

- 独立解析标题文本可能与渲染器 ID 不一致。导航必须以渲染器的实际标题输出为源。
- 观察器或全局 ID 可能跨预览实例；必须明确视口所有权及清理。
- 面板位置和共享预览范围均是提议中的决策。未声称实现或批准；实现等待针对当前 Spec 提交的明确人工批准。
