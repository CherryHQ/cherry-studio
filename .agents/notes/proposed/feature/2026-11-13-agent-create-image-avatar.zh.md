# Agent Note: 新建智能体时使用图片头像

Status: proposed

[English](2026-11-13-agent-create-image-avatar.md) | 中文

## 问题

共享创建向导只收集表情字符串，现有智能体编辑器则通过 `agent.set_avatar` 支持图片上传。编辑器需要已经存在的智能体 ID，并立即持久化，因此将它挂载到创建草稿中会要求在用户提交之前创建智能体。

本次检查基线为 `9952477297bea3deba0122ab496b0060c6909f47`，已包含 `b1d344c50e1fdf3caed717e512820a59d8789448`（#24474），用于防止 portal 内文件输入的点击通过 React 冒泡而聚焦名称字段。必须保留这一修复；包含此修复并不证明新流程中的原生选图正常。

## 方案

在智能体创建向导中同时提供图片上传与表情选择，覆盖该向导的全部现有调用入口。提交前，选定图片仅保存在内存草稿中。复用 `prepareAvatarImage` 的原文件 10 MB 限制、解码及 128 乘 128 WebP 规范化能力，以本地预览显示处理后的图片。选择表情或重置头像时清除草稿图片。关闭后重新打开会开始新草稿；离开基础信息步骤再返回则保留草稿。替换或丢弃时释放预览资源。

仅扩展现有 `ai.agent.create` 命令，增加由 `ImageBytesSchema` 校验的可选图片字节。不接受渲染进程提供的文件 ID，不将字节放入 DataApi DTO 或持久化配置。保留表情配置作为图片的回退值。不带图片的调用方维持现有行为；助手创建不在本次范围内。

在同步智能体创建事务之前，复用 `withCreatedImageEntry` 并采用 `delete_when_unreferenced`。为现有 `AgentService.createAgentWithId` 原语增加可选的主进程持有的头像文件 ID，在插入智能体及关联的同一事务内通过 `setAvatarSlotTx` 绑定头像。返回实体和创建事件包含头像。仅在该事务提交后发布创建通知，心跳初始化仍作为提交后的非致命操作。现有 `agent.set_avatar` 编辑路由继续使用当前服务及绑定代码。

图片预处理或文件创建失败不得创建智能体。数据库或绑定失败时回滚智能体事务，触发现有图片条目补偿清理，并通过现有创建回滚移除预留的智能体目录。清理失败需要记录日志并明确报告限制，不得隐藏。头像上传失败时，不采用先创建智能体再删除以修补状态的方式。

在所有创建入口使用同步提交防护，拒绝请求进行中的重复激活。提交全程保留关闭保护。报告失败后，保留名称、设置及处理后的图片以便重试。丢弃来自已关闭或已被替换草稿的图片处理结果。不引入通用幂等协议；进程崩溃或传输结果不确定时的恢复不属于本次有限范围。

## 已考虑的替代方案

- 先创建智能体，再调用 `agent.set_avatar`：可以复用公开编辑命令，但上传失败会留下已创建的智能体，直接重试则会创建重复对象。选择复用其底层图片及事务原语，放弃此方案。
- 选图时持久化临时托管图片：需要在持久化存储中管理草稿所有权及取消清理。改为将草稿保存在内存中。
- 在 `configuration.avatar` 中存放 data URL：绕过托管文件引用，并改变表情合同。放弃。
- 强制挂载或延迟卸载现有编辑选择器：既无法提供合法智能体 ID，也会掩盖已经修复的 portal 焦点根因。放弃。

## 验收标准

- AC1 — 所有智能体创建入口提供选图和可见草稿预览；成功提交仅返回一个智能体，其托管头像可在列表及重新打开的编辑器中加载。 (verification: renderer | Electron)
- AC2 — Windows 原生选图与取消操作不会导致名称字段抢焦点或已选图片丢失；取消时保留原草稿头像。CDP 输入注入单独记录。 (verification: Electron)
- AC3 — 无效、无法解码和超限文件显示错误、保留原头像，并允许改用有效图片重试；较早的异步结果不能替换较新或重开的草稿。 (verification: renderer | Electron)
- AC4 — 图片创建及头像绑定失败均不产生智能体或头像引用；成功重试仅创建一个智能体，并在真实迁移后的测试数据库中验证图片文件补偿清理。 (verification: unit | Electron)
- AC5 — 提交中重复激活创建只产生一个请求；完成前禁止关闭；失败保留全部草稿字段并允许重试，关闭后重开则丢弃草稿。 (verification: renderer | Electron)
- AC6 — 离开基础信息步骤再返回仍保留图片；选择表情或重置会移除图片；现有智能体图片上传、表情选择及重置仍然正常。 (verification: renderer | Electron)
- AC7 — 定向测试覆盖修改代码及受影响创建调用方；报告变更文件 lint、格式检查、适用类型检查及文档检查，区分基线失败与本次引入的失败。完成前进行单独的对抗式审核，覆盖生命周期、原子性、重试及重复创建。 (verification: unit | renderer | docs gate)

## 风险

SQLite 事务不能包含异步图片处理，因此文件创建先于事务，失败时依靠补偿清理。补偿本身也可能失败，必须保持可观测。现有创建事件不得在头像绑定提交之前公布智能体。预览与处理状态需要在步骤卸载后保留，同时不得泄漏到其他对话框会话。原生对话框时序与输入注入不同，需要独立证据。本提案不声称已经实现成功、运行验证通过或获得批准。
