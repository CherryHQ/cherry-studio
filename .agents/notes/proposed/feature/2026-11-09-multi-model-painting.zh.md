# Agent Note: 绘画页多模型并行生图

Status: proposed

[English](2026-11-09-multi-model-painting.md) | 中文

## Problem

绘画页每次只能把一个提示词发送给一个供应商和一个模型。绘画记录只保存单个 `providerId` 和 `modelId`，参数只存在于草稿中，因此发送后或重启后都无法保留比较多个模型所需的状态。目前要比较 FLUX、gpt-image-1、Imagen，只能重复输入提示词、逐个切换模型，再手动对比结果。需求见 [Issue #15014](https://github.com/CherryHQ/cherry-studio/issues/15014)。它依赖的 v2 绘画重构 [Issue #14207](https://github.com/CherryHQ/cherry-studio/issues/14207) 已关闭。

## Proposal

绘画草稿包含一个或多个**目标**。每个目标由 `providerId`、`modelId` 以及可选的单目标参数覆盖组成。只有一个目标的草稿沿用现有路径。

提交一个包含 N 个目标的草稿时，同时发起 N 个相互独立的生成请求。每个目标创建自己的 `painting` 记录，保存自己的供应商、模型、参数、输出文件和生成状态，失败只影响该记录。N 条记录通过新增迁移中可为空的 `batch_id` 共享同一批次。共享的提示词保存在每条记录上，因此不需要单独的批次表。

界面为每个目标一列，放在可横向滚动的网格中。每列显示模型名称、图片、状态（等待、生成中、完成或失败）以及所用参数。列上的已有操作（保存、再创作、复制提示词、仅重新生成该目标、删除）只作用于该条记录。目标选择复用现有模型选择器的多选。聊天端的 `@` 提及不在本 Spec 范围内。

参考图只发送给支持图片输入的目标。其他目标仅依据提示词生成，并在其列中显示参考图不受支持的提示。单目标路径的参考图行为保持不变。

历史记录侧栏把每个 `batch_id` 分组显示为一个条目，并展示输出缩略图。打开条目时，从已保存的记录还原网格。

## Alternatives considered

- **单条记录内保存 `results` 数组。** 不采用：单列重新生成、删除以及文件引用归属都需要在一条记录内重新实现。
- **单独的 `painting_batch` 表。** 暂不采用：批次层面的数据只有共享提示词和分组 ID，记录上的一列即可承载。
- **仅在客户端分组、不持久化。** 不采用：重启后批次会消失，违背历史记录需求。
- **把扇出逻辑移到主进程生成服务。** 暂缓：这样可以修复 `paintingAbortControllerStore.ts` 中提到的渲染进程中止控制器问题，但那项重构范围更大，应单独立 Spec。

## Acceptance criteria

- AC1 — 单目标草稿只提交一条记录，不带 `batch_id`，不显示网格相关界面（verification: renderer）
- AC2 — N 个目标同时发起 N 个请求，每个请求携带共享提示词及该目标自己的供应商、模型和参数，并共享同一 `batch_id`（verification: unit）
- AC3 — 某个目标失败时，其列显示错误和重试操作，其他目标继续运行直至完成（verification: renderer）
- AC4 — 单目标参数覆盖只作用于该目标的请求；未修改的参数使用该目标的默认值（verification: unit）
- AC5 — 重新生成某一列只替换该记录的输出，其他列保持不变（verification: renderer）
- AC6 — 参考图发送给支持图片输入的目标；其他目标仅依据提示词生成，并在其列中显示提示（verification: unit, renderer）
- AC7 — 从历史记录打开批次时，还原为一个分组条目和相同网格，每列显示其保存的参数（verification: renderer, Electron）
- AC8 — 新增迁移添加可为空的 `batch_id` 列，并能在已有数据的数据库上向前迁移（verification: unit）
- AC9 — 在标准桌面宽度下四列无需横向滚动即可完整显示；窗口变窄时改为横向滚动而非换行（verification: renderer, Electron）
- AC10 — 本 Spec 及其中文配对文件通过文档门禁（verification: docs gate）

## Risks

- **成本。** 一次发送变为 N 个付费请求。提交前草稿应显示目标数量。
- **渲染进程持有的中止控制器。** 批次因刷新中断后，记录会停留在 `running`。现有恢复路径必须覆盖批次中的每条记录，而不仅是当前可见草稿。
- **供应商速率限制**可能同时导致多个目标失败。按 AC3，每个失败只影响其列。
- **与待处理的参考图守卫冲突。** [PR #22541](https://github.com/CherryHQ/cherry-studio/pull/22541) 会拒绝在不支持图片输入的模型上使用参考图。AC6 要求改为列内提示，两者需取舍其一。

## Decisions

维护者已于 2026-11-09 批准。

- **D1 — 分期。** 分两层交付。第一层覆盖 AC1–AC6、AC8、AC9 以及 AC8 中的数据结构：扇出、各列状态、网格和共享迁移。第二层覆盖 AC7（分组历史条目与还原），并将本 Spec 转为 implemented。
- **D2 — 参数持久化。** `painting` 记录在与 `batch_id` 相同的迁移中新增参数快照列。重新打开批次时，每列显示其保存的参数。
- **D3 — 参考图。** 在多目标草稿中，不支持图片输入的目标仅依据提示词生成，并在其列中显示提示。这仅在多目标草稿中取代 PR #22541 的拒绝行为；单目标路径保持不变。
- **D4 — 目标数量上限。** 不设上限。超过四列时横向滚动。
