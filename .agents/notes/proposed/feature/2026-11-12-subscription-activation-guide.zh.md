# Agent Note: 订阅开通引导

Status: proposed

[English](2026-11-12-subscription-activation-guide.md) | 中文

## 问题

用户在外部浏览器订阅 Cherry Cloud 套餐后回到应用，唯一的反馈是一条短暂的「{{plan}} 已生效」toast；国内版在通知中心在线时连这条 toast 也不显示。套餐模型其实已经同步到对话顶部的模型选择器，但没有任何地方告诉用户模型在哪里，也无法直接开始使用。

## 提案

- 现有提醒逻辑检测到「新变为有效的付费套餐」时，主窗口弹出开通弹窗，取代原 toast。弹窗与套餐无关：不显示套餐名，头图是中性的模型菜单插画，正文列出该套餐已在本地可用的对话模型（最多三行，其余折叠为数量），权益带到期时间时一并显示。
- 默认选中第一个模型。「开始对话」记录所选模型并打开对话标签页；可选的「同时设为默认模型」通过 `useDefaultModel` 写入 `chat.default_model_id`。关闭弹窗只记录新模型，不记录选择。
- 当前活动的对话标签页只消费一次所记录的选择，并通过对话顶部已有的模型选择处理函数应用，助手设置的联动逻辑仍只在一处。
- 随后该对话标签页显示一次性引导：除顶部模型按钮外压暗页面，锚定的浮层预览新模型并说明在此切换。点击按钮、打开模型菜单或按 Escape 关闭后清除记录，不再出现。
- 若套餐模型在本地都不可用，保留原 toast。国内版通知中心在线时，与现状一致由通知中心单独宣布开通，弹窗和 toast 都不显示。埋点与套餐检测逻辑不变。

## 备选方案

- 保留 toast 只加引导浮层：toast 在用户操作前就消失，且无法选择模型。
- 在主窗口弹窗中直接切换模型：没有全局的「当前对话」归属方，会重复对话顶部已有的助手设置联动逻辑。
- 头图使用套餐专属插画或模型 logo：套餐和模型会变化，且不同套餐面向不同用户，不能互相看到对方的名字。

## 验收标准

- AC1 — 新变为有效的付费套餐会弹出开通弹窗，列出该套餐在本地可用的对话模型且不出现任何套餐名，同时不显示开通 toast。(verification: renderer)
- AC2 — 套餐模型在本地都不可用时，显示原开通 toast 而不是弹窗；国内版通知中心在线时两者都不显示。(verification: renderer)
- AC3 — 「开始对话」通过顶部选择处理函数把当前活动对话切换为所选模型，勾选复选框时同时设置默认助手模型。(verification: renderer)
- AC4 — 弹窗关闭后，下一个活动的对话标签页在顶部模型按钮上显示一次聚光引导；通过按钮、模型按钮或 Escape 关闭后不再出现。(verification: renderer)
- AC5 — 弹窗与引导使用共享 UI 组件，浅色与深色主题下清晰可读，所有可见文案在全部渲染进程语言中完成本地化。(verification: Electron + i18n gate)

## 风险

- 国内版通知中心在线的用户不会看到弹窗和对话页引导，只能依赖通知中心的条目。
- 模型列表依赖 `plan.models` 或权益的额度池；若服务端两者都不返回，用户会回落到 toast。
