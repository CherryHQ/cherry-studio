# Agent Note: Agent 快速创建与 Profile

Status: proposed

[English](2026-10-30-agent-quick-create-and-profile.md) | 中文

## Problem

现在创建 Agent 要走四步向导：在 Agent 还不存在之前，用户就得选运行模式、权限模式和模型，写系统提示词（或点「生成」），再挑技能和知识库。多数用户只知道想让 Agent 做什么，于是要么卡在向导里，要么建出一个缺少所需技能的 Agent。打开已有的 Agent 时直接进入带标签页的表单：它的身份和定时任务都不是第一眼看到的内容，左侧导航把配置分散在八个页面里。

2026-10-29 社区版需求同步会决定：Agent 只靠名称和用途就应该能用；大多数用户的配置应自动完成，其他用户仍能找到配置入口；Pi 已是默认运行时，去掉运行模式选择；打开 Agent 时先看到 Profile，再看设置。会后 `main` 新增了 Pi 的持久化版本 Pi Durable，新 Agent 改为使用 Pi Durable（2026-11-04 决定）。

## Proposal

- **快速创建。** 创建 Agent 时打开一个单页：头像、名称输入框、用途输入框。主按钮「Agent 创建」和次按钮「手动创建」在填写名称且模型已确定后可用。可用的默认模型会被静默预选；只有没有默认模型时，页面才出现模型选择器并提示用户先选一个。助手的创建流程不变。
- **手动创建。** 「手动创建」打开现有的引导式向导，预填头像、名称、描述（取自用途）和系统提示词（取自用途），并提供「返回快速创建」，已填写的内容不丢。向导不再提供运行模式和权限模式选择：新 Agent 一律使用 Pi Durable 和该运行模式的默认权限模式，权限模式仍可在更多设置中修改。已有的 Pi 和 Claude Agent SDK Agent 继续可用，运行模式只读显示。
- **Agent 创建。** 「Agent 创建」在同一个弹框内执行，并显示进度：
  1. 用选定的模型，根据名称和用途生成系统提示词。生成失败时，用途（或名称）作为提示词。
  2. 启用全部已安装的技能；内置工具保持全部启用（`disabledTools` 为空）。
  3. 让选定的模型给出资源市场搜索词，在现有技能源中搜索，由模型从结果里最多挑选两个相关技能，安装后为新 Agent 启用。搜索、挑选或安装失败会显示在进度中，但不阻塞创建。
  之后通过现有的 `ai.agent.create` 命令创建 Agent。
- **创建之后。** 无论从资源库还是 Agent 页创建，完成后都进入新 Agent 的 Profile 卡片；Agent 页仍会在卡片下方打开新 Agent 的对话。自动配置有部分兜底（提示词生成或技能安装失败）时，卡片会说明，并引导用户去更多设置。
- **Profile 卡片。** 打开 Agent（资源库、全局搜索、输入框上的 Agent 名称）时显示 Profile 卡片：头像、名称、主模型、已启用的技能和工具数量、描述，以及来自 `GET /agents/:id/tasks` 的定时任务：每条显示上次执行结果（「上次成功 / 失败」），尚未执行、已暂停或已错过时显示状态（没有时显示空状态；新 Agent 永远没有任务）。该接口的条目增加与全局任务列表相同的 `runSummary`，Agent 自己的「列出任务」工具也能看到。卡片提供「更多设置」和「去对话」；「去对话」通过现有的 `/app/agents?agentId=` 路由打开该 Agent。明确的「编辑」操作（右键菜单、选择器里的编辑按钮）和深链跳过卡片，直接打开设置。
- **更多设置。** 设置改为一个可滚动的单页，不再有左侧导航，由「左标签、右控件」的紧凑行组成，分为五组（基础信息、模型、能力、行为、其他）。头像和名称、描述、模型、只读的运行模式、权限模式、回复语言、心跳原地修改。内置工具、技能、MCP 服务、知识库显示为带已启用数量的行，点击后原地弹出可搜索的开关列表；每个列表保留原页面上的链接（浏览器和 Computer Use 设置、「添加更多技能」、MCP 设置、移除旧版限制）。系统提示词、提示词绑定、环境变量仍在子页面里使用原有的编辑组件，心跳任务仍用原有的编辑弹框。现有深链打开对应的列表（`tools.skills`、`tools.mcp` 等）或子页面。原编辑弹框的所有设置都保留；返回 Profile 卡片前会先保存未完成的修改。
- 本次头像仍使用 emoji；图片头像另行处理。

## Alternatives considered

- 保留向导，加一个「自动填写」按钮：否决，运行模式、模型、提示词这些决定仍然摆在不想做决定的用户面前。
- 创建后在后台补全配置：否决，用户会和配置不完整的 Agent 对话，也看不到补了什么。
- 创建后直接回到对话、不展示 Profile 卡片：否决；用户要在卡片上确认「Agent 创建」配置了什么，也要知道哪些步骤兜底了。
- 只自动安装官方精选技能：长期更合适，但 `main` 上还没有精选技能源；自动安装使用现有技能源，限制最多两个，并明确列出安装了哪些。
- 只重新设计现有的左侧导航，不改成分组单页：否决，左侧导航本身就是要去掉的复杂度。
- 每个多选编辑组件（技能目录、MCP 列表、知识库选择）各占一个子页面：否决；每个列表一个子页面，会把「启用了什么」藏在导航后面，而原地的开关列表写入同样的表单字段，复用弹框已有的保存逻辑。提示词绑定不只是开关，因此保留子页面。
- 让明确的「编辑」操作也先经过 Profile 卡片：否决，这会给一个意图已经很明确的操作多加一步。

## Acceptance criteria

- AC1 — 创建 Agent 时打开包含头像、名称、用途的页面；在填写名称且模型确定之前，「Agent 创建」和「手动创建」均不可用；只有没有可用默认模型时，才出现带提示的模型选择器。（verification: renderer）
- AC2 — 「手动创建」打开引导式向导，预填快速创建页的头像、名称、描述和系统提示词，不提供运行模式和权限模式选择，可以返回快速创建，并创建 Pi Durable Agent。（verification: renderer）
- AC3 — 「Agent 创建」显示进度，创建 Pi Durable Agent：系统提示词根据名称和用途生成，全部已安装技能被启用，内置工具全部保持启用；生成失败时仍以用户输入创建 Agent。（verification: unit + renderer）
- AC4 — 「Agent 创建」最多安装并启用两个按用途挑选的市场技能，并在进度中列出；搜索、挑选或安装失败会显示出来，但不阻塞创建。（verification: unit + renderer）
- AC5 — 打开 Agent 时显示 Profile 卡片，包含头像、名称、模型、描述，以及带上次执行结果或状态的定时任务（或空状态）；「去对话」打开该 Agent，「更多设置」打开其设置；明确的编辑操作和深链直接打开设置。无论从哪条路径创建，完成后都进入新 Agent 的 Profile 卡片，自动配置有兜底时卡片会提示。（verification: unit + renderer + Electron）
- AC6 — 更多设置是没有左侧导航的分组单页，包含原编辑弹框的全部设置；内置工具、技能、MCP 服务、知识库原地弹出带搜索的开关列表，`tools.skills` / `tools.mcp` 深链打开对应列表，返回 Profile 卡片前会保存未完成的修改。（verification: renderer + Electron）
- AC7 — 已有的 Pi 和 Claude Agent SDK Agent 可以打开，运行模式只读显示，其余设置均可编辑。（verification: renderer）

## Risks

- 自动安装会在没有逐个确认的情况下运行来自社区技能源的第三方技能。最多两个的限制、可见的安装清单以及在更多设置中可移除，限定了风险范围；有精选技能源后应替换开放技能源。
- 模型调用会增加「Agent 创建」的耗时；每一步都有超时和兜底，保证创建总能完成。
- 分组设置页重新承载了所有现有字段；漏掉任何一个字段都是静默回归，因此 AC6 需要对照原有标签页清单验证。
