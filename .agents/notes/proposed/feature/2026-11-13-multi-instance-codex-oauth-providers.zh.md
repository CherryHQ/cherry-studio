# Agent Note: 多实例 Codex OAuth 服务商

Status: proposed

[English](2026-11-13-multi-instance-codex-oauth-providers.md) | 中文

## Problem

单个 Codex 服务商会话无法区分多个 ChatGPT 账号。用户需要独立的服务商实例，以便同时使用多个账号并识别其模型。

## Proposal

使用现有存储按服务商实例保存 OAuth 凭据和账号身份。将请求和会话失效操作路由到所属实例。由于 OAuth 重定向使用固定回调端口，在预设范围内排斥并发浏览器登录。账号 ID 可用时，在选择器分组、置顶行和详情卡片中将其显示在服务商名称旁。

## Alternatives considered

- 在一个服务商行中存储多个账号的凭据：不采用，因为维护者已推迟此方案，且它需要独立的选择器和账号管理契约。
- 为每个实例运行一个回环传输：不采用，因为固定的 1455 重定向端口会使并发监听器冲突，且相比预设范围内的互斥没有收益。

## Acceptance criteria

- AC1 — 两个 openai-codex 预设的服务商实例各自持有 ChatGPT OAuth 会话；登录第二个实例绝不改变第一个实例的令牌或账号 ID。（验证：单元测试）
- AC2 — 两个实例无需重启即可在同一应用会话中使用：每个请求携带发送该请求的实例的 bearer 令牌和 chatgpt-account-id。（验证：单元测试）
- AC3 — 退出登录或一个实例的会话失效时，仅清除并禁用该实例；另一个实例的凭据和启用状态不受影响。（验证：单元测试）
- AC4 — 模型选择器在服务商分组、置顶行和详情卡片中标识 Codex 模型所属的账号。（验证：渲染器测试）
- AC5 — 无需数据库模式变更或凭据迁移，单实例安装保持原有行为。（验证：单元测试）

## Risks

固定回调端口使浏览器登录串行化。账号 ID 在选择器标签中较长。仍需要一位拥有两个 ChatGPT 订阅的维护者验证上游接受情况。
