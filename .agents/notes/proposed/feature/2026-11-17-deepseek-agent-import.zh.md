# Agent Note: 将 DeepSeek 导出数据导入智能体会话

Status: proposed

[English](2026-11-17-deepseek-agent-import.md) | 中文

## 问题

用户需要将 DeepSeek 账号导出数据导入智能体页面，并在后续对话中让模型使用历史上下文。现有渲染进程 `ImportService` 创建的是助手和话题，仅在那里添加解析器无法满足需求。智能体消息是展示投影，Pi Durable 在独立的原生存储中持有模型上下文。

用户提供的 11 月 17 日导出包使用 `export_format_version: 3`、`chat_session_index.json` 和 `chat_sessions/<id>.json`。本地检查发现 106 个会话、500 条消息，其中 14 个会话包含分支。消息使用 `parent_id`，会话通过 `current_message_id` 选择当前消息。五个文件引用包含四张有实际文件的图片和一个缺失内容的文件（`export_path: null`）。消息状态包括 `FINISHED`、`TIMEOUT`、`INCOMPLETE` 和 `CONTENT_FILTER`。这些是样本观察结果，不代表所有 DeepSeek 导出都采用这一结构。私有账号数据和会话内容不得进入仓库测试样本或 PR 附件。

## 提案

### 入口与范围

在智能体页面为选中的 Pi Durable 智能体增加导入操作。用户选择原始 ZIP，查看会话数、消息数和警告，再导入为该智能体下的新会话。每个源会话对应一个新会话；导入不向已有会话追加内容。目标智能体提供后续对话使用的模型、工作区策略和权限。导入过程不运行模型或工具。不支持的智能体运行时显示原因，不静默创建普通聊天话题，也不更改智能体类型。

首版支持已观察到的 DeepSeek v3 ZIP 格式和 Pi Durable。不增加 ChatGPT/Claude 智能体导入，不同步 DeepSeek 账号，不恢复 DeepSeek 身份验证，也不重建导出包中不存在的文件。现有助手导入保持独立。

### 压缩包与内容映射

主进程使用现有压缩包依赖，负责有资源限制的 ZIP 读取与校验。发布前校验 manifest、会话索引、唯一 ID、父子图、选中消息和引用的压缩包条目。拒绝不支持的版本、非法图、规范化后重名路径、绝对路径或路径穿越、链接，以及超过明确条目大小、数量、解压后总大小限制的压缩包。不任意解压路径，不获取远程 URL。逐条读取，不通过 IPC 传送整个压缩包或全部消息正文。

保留标题、原始时间戳、角色、源 ID、父子关系和选中分支。生成新的产品 ID。保留空消息或未成功的源消息作为历史记录，不静默丢弃。它们不得变为待处理输入、可恢复的失败任务或伪造的成功回答。存储原始源状态，并明确映射终态展示状态。将导入回答归属为 DeepSeek，不编造模型版本，不将源 token 计数导入为 Cherry 计费。

将 `REQUEST`、`RESPONSE` 和 `TEMPLATE_RESPONSE` 映射为文本。将 `THINK` 映射为已完成的推理内容，保留可用的耗时。将 `CONTENT_RISK` 保留为可见的历史文本。将 `TOOL_SEARCH`、`TOOL_OPEN` 和 `TOOL_IMAGE_SEARCH` 展示为历史搜索或打开记录，保留查询、URL、标题、摘要和可用结果。它们不是可执行工具调用。未知片段类型导致校验失败，并指出受影响的会话，不静默丢弃。

通过受管理的文件存储导入可用的 `FILE` 内容，保留稳定的消息引用，使重新打开不依赖原始 ZIP。保留缺失文件的元数据，显示警告，并在模型上下文中加入附件不可用的标记。可用图片以图片形式进入原生上下文，遵循目标模型现有的能力和大小限制。非图片附件使用现有智能体附件表示；不支持的内容明确报校验错误，不虚报成功。

### 原生历史与分支

在 Pi Durable 集成的原生历史边界扩展能力。使用公开原生事务 API（`createConversation`、`appendEntry`、`forkConversation`），写入不会触发执行的应用自有导入条目以及面向模型的消息。不为 `AssistantEntry` 伪造生成任务 ID，不修改原生 SQLite 表，也不通过 `submit` 重放历史用户输入。

分歧路径使用原生会话，分支选择使用现有产品消息树和上下文绑定。初始选择遵循 `current_message_id`，即使导出包中另一个分支出现得更晚也不改变。切换分支后发送新消息必须选取该分支的原生历史前缀。已完成的助手回答边界获得有效的原生检查点；不可用的历史操作继续使用现有明确的资格判定原因。导入的推理和搜索记录是可阅读的历史，不具备原生任务、目标、审批或工具权限。模型上下文保留用户和助手角色；推理及搜索内容使用标记清楚的历史文本，不伪造提供商专属的推理签名或工具结果。

产品会话可见前，必须完成原生准备并验证其上下文。重新打开及后续投影更新必须保留导入的展示记录，不产生重复。现有 [Pi Durable Fork 所有权](../../implemented/feature/2026-11-09-pi-durable-desktop-fork.md)和后端身份规则继续生效；本提案增加外部历史构造能力，不增加第二个运行时所有者。

### 发布与失败恢复

通过 IpcApi 访问由主进程持有、具有持久身份和进度的导入操作。渲染进程负责审阅和观察；对话框是否可见不决定操作生命周期。原生存储和文件准备前先持久化操作身份。以目标智能体、压缩包摘要和源会话 ID 标识每个源会话。重试同一压缩包时恢复未完成工作，并报告已导入的会话，不创建重复项。不同压缩包摘要视为独立导入；首版不合并已变化的导出数据。

在一次同步产品数据库事务中发布每个会话的会话记录、消息树、文件引用、上下文绑定和完成标记。原生存储与产品 SQLite 分别提交：中断后核对已准备的原生身份，不宣称存在跨存储事务。取消在会话之间或发布前停止，保留已发布会话。准确报告已导入、已存在、失败和剩余数量。保留可识别且不会执行的准备结果，直到恢复或能够证明只清理该操作自有资源；不得删除共享原生祖先或无关文件。如果操作身份需要新的产品结构，使用追加迁移。

### 实现与验证归属

主进程智能体会话域负责编排和发布；Pi Durable 适配器负责原生条目与检查点；共享 IPC schema 负责命令和进度；现有智能体 UI 负责选择、预览和结果导航。使用现有 UI 组件、本地化、文件所有权、集中路径和生命周期规则。适度分离解析逻辑，以便使用合成样本测试，不将本功能扩展为通用导入框架。

先实现原生导入与真实文件数据库上的发布，再实现 UI 和端到端验证。此 Spec 当前提交获得批准前不开始实现层。如果公开原生 API 无法满足某项契约，应先修订此 Spec，提出上游解决方案，再实施替代做法。

## 考虑过的替代方案

- 仅在助手导入中增加 `DeepSeekImporter` 会进入错误的产品入口，也无法提供智能体上下文。
- 仅写产品消息行会让历史可见，却不会让下一次模型请求获得历史。
- 展平所有分支会混合互斥历史；仅导入选中路径则会静默丢失源消息。
- 重放历史输入会运行模型和工具并改变回答。将整个对话作为一条巨大用户消息导入会丢失角色、分支和附件语义。
- 一次支持全部运行时需要分别制定原生历史契约，会将功能范围扩展到已验证的 Pi Durable 基础能力之外。

## 验收标准

- AC1 — 从 Pi Durable 智能体选择有效 v3 ZIP 后可预览数量与警告，并创建新智能体会话；启动前取消不创建任何数据，不支持的运行时有明确说明，普通助手导入仍正常工作。(verification: renderer and Electron; owner: UI implementer)
- AC2 — 合成样本保留所有源消息、角色、标题、时间戳、父子边和选中消息；非法 ID、图、索引以及不支持的版本或片段明确报错。(verification: unit; owner: parser implementer)
- AC3 — 文本、推理耗时、拒答或风险文本、搜索记录以及失败或空消息保持可见且终态真实；导入不调用模型或工具，不记录 Cherry 费用。(verification: unit and real runtime; owner: native import implementer)
- AC4 — 导入后及关闭重开后，脚本模型的首次请求包含选中分支的历史角色和内容，不包含兄弟分支尾部；切换分支后的新一轮使用对应原生历史前缀，不重复展示历史。(verification: real runtime and file-backed integration; owner: native import implementer)
- AC5 — 删除源 ZIP 后，可用图片仍可查看，并可进入兼容模型请求；缺失内容保留元数据和明确警告或标记；不安全路径、链接、重复条目和超过资源限制的压缩包在发布前被拒绝。(verification: unit, file-backed integration, and Electron; owner: archive implementer)
- AC6 — 在原生准备和产品提交前后注入故障，以及取消、进程重启时，均不暴露部分发布的会话或删除无关数据；重试同一压缩包时每个源会话仅产生一个产品会话，进度数量真实。(verification: file-backed integration and process restart; owner: import coordinator implementer)
- AC7 — 导入的已完成助手检查点以正确上下文支持现有 Fork/Edit 资格判定，失败边界仍不可用；历史工具或任务元数据在重开时不会变为可执行工作。(verification: real runtime and affected history-action tests; owner: native import implementer)
- AC8 — 使用用户提供的压缩包进行本地验收时，完整核对 106 个会话和 500 条消息，保留 14 个有分支的会话及四张图片，报告一个缺失文件，并在 Electron 中成功继续一个选中会话。只发布合成样本与汇总结果。(verification: Electron and local archive inspection; owner: integrating implementer)

## 风险

样本不是公开 schema 保证；不支持的格式必须明确报错。保留全部分支和图片会增加存储量，并可能超过目标模型上下文限制；遵循现有模型限制和压缩机制，导入器不静默截断。跨存储恢复和投影核对需要真实运行时证据，不能只依赖解析器测试。原生 SDK 没有通用的公开会话删除 API，因此失败的准备结果可能保留为可识别且不会执行的记录。无法从此 ZIP 恢复缺失文件。首版仅支持 Pi Durable 是实现前需要审阅的明确兼容性限制。
