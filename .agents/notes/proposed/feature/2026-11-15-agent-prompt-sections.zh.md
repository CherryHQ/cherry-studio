# Agent Note: 可编辑 Pi Durable 智能体系统提示词的每个部分

Status: proposed

[English](2026-11-15-agent-prompt-sections.md) | 中文

## 问题

Pi Durable 智能体的系统提示词页面（`PiPromptField`）展示组装后的完整提示词，但只有智能体自己的指令可以编辑。Cherry 在其周围写入的指引（指令优先级、汇报产物、创建智能体与修改设置、引导设置、记忆、引用）都是只读的，用户想换个写法也无从修改。Cherry 助手这类内置智能体的指令框是空的，但运行时实际使用的是它的内置提示词，而且编辑之后也无法恢复到内置提示词。与其他运行时的提示词页面不同，这个页面没有 AI 优化。

## 提案

- 页面以智能体系统提示词开头，下面按运行时发送的顺序列出其他段落的名称，并注明各自如何产生（自动生成、已修改或自动更新）。每个段落在自己的页面中打开，对话框标题显示段落名，在那里编辑或查看。
- **指引段落**（指令优先级、汇报产物、创建智能体与修改设置、引导设置、记忆、引用）可以编辑。编辑内容作为该智能体的覆盖文本保存在 `configuration.prompt_overrides` 中，以段落为键。被修改过的段落带有"已修改"标记，并提供"恢复自动生成"，它会删除覆盖文本。
- 覆盖文本只替换运行时在当前设置下会生成的段落。某个设置让该段落不再生成时（例如没有启用任何检索工具时的引用段落），覆盖文本会保留，但不会发送。
- **智能体系统提示词段落**承载智能体的指令。没有自定义指令的内置智能体，在这里显示其内置提示词；编辑后保存为自定义指令，"恢复内置提示词"会清除它们，让内置提示词重新生效。
- 每个可编辑段落都提供 **AI 优化**，用默认模型只改写这一段；与现有的提示词润色一样，结果可以撤销。
- **身份段落**打开智能体的记忆编辑器（与记忆页相同），直接编辑 SOUL.md、USER.md 和 FACT.md。该段落仍随这些文件更新；文件有未保存的修改时，点返回会先询问。
- **其他实时段落**保持只读，并注明由什么保持更新：技能列表、工作区指令和 MCP 服务说明，分别随技能、工作区和 MCP 服务变化。回复语言段落随回复语言设置变化。
- 覆盖文本只对 Pi Durable 智能体生效，它是唯一有完整提示词预览的运行时。Claude Code 和 Pi 智能体仍只能编辑自己的指令。
- 预览接口改为返回每个段落的键、类型和生成文本，而不是指令前后的两段文本，这样页面可以按段落显示生成文本、覆盖文本和恢复操作。

## 备选方案

- 把实时段落的编辑副本保存为覆盖文本（否决：副本会冻结记忆、技能和工作区指令，它们之后不再更新；身份段落改为直接编辑文件本身）。
- 回复语言段落可编辑（否决：它会与生成它的回复语言设置不一致）。
- 覆盖文本对所有运行时生效（否决：只有 Pi Durable 显示完整提示词，在其他运行时用户看不到改动后的效果）。
- 对整个提示词做一次 AI 优化（否决：整体改写难以审阅，还会改到用户不想改的段落）。

## 验收标准

- AC1 — Pi Durable 智能体的系统提示词页面以智能体系统提示词开头，按运行时顺序列出其他段落的名称；每个段落在自己的页面中打开，指引段落可编辑，除身份外的实时段落只读并注明由什么保持更新 (verification: renderer; owner: implementer)
- AC2 — 编辑指引段落会为该智能体保存覆盖文本并标记为已修改，运行时下次组装的提示词在该段落位置使用编辑后的文本 (verification: unit; owner: implementer)
- AC3 — "恢复自动生成"会删除覆盖文本，该段落和下次组装的提示词重新显示生成的文本 (verification: unit; owner: implementer)
- AC4 — 当前设置不会生成的段落，其覆盖文本不会发送 (verification: unit; owner: implementer)
- AC5 — 没有自定义指令的内置智能体，其智能体系统提示词段落显示内置提示词，"恢复内置提示词"会清除编辑过的指令 (verification: renderer; owner: implementer)
- AC6 — 对可编辑段落使用 AI 优化只替换这一段，且可以撤销 (verification: renderer; owner: implementer)
- AC7 — Claude Code 和 Pi 智能体忽略已保存的覆盖文本，提示词页面仍只编辑指令 (verification: unit; owner: implementer)
- AC8 — 新增的段落标题、说明和操作在所有语言中都有对应文案 (verification: renderer; owner: implementer)
- AC9 — 在应用中，Pi Durable 智能体编辑过的指引段落出现在其提示词中，"恢复自动生成"会带回生成的文本 (verification: Electron; owner: implementer)
- AC10 — 身份段落通过记忆编辑器编辑 SOUL.md、USER.md 和 FACT.md，文件有未保存的修改时点返回会先询问 (verification: renderer, Electron; owner: implementer)

## 风险

- 覆盖文本不会跟随生成文本之后的变化（例如新的工具名）；"已修改"标记和"恢复自动生成"让这一点可见且可恢复。
- 用户可能删掉智能体依赖的指引，例如如何汇报产物；这是用户明确的选择，该段落可以恢复。
