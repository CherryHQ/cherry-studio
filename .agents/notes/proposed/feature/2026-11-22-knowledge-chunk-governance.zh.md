# Agent Note: 受治理的知识块变更

Status: proposed

[English](2026-11-22-knowledge-chunk-governance.md) | 中文

## Problem

Issue #19001 要求可恢复的检索排除、批量标签/元数据，以及保留来源的知识块文本修正。目前知识块是派生索引数据。`KnowledgeIndexStore.rebuildMaterial` 会替换单元和搜索文本，单元身份包含材料 ID、内容哈希、类型、序号及偏移量。直接覆盖这些行会在重建时丢失用户意图，并破坏原始块文本是源内容切片的不变量。

主数据库拥有知识业务数据，每个知识库的 `index.sqlite` 可以重建。用户决策不能只存放在可丢弃索引中。现有源删除/重建守卫、后台作业、可见性检查和来源/引用所有权仍然有效。

## Proposal

### 持久治理与派生有效索引

将块治理保存在 Main 拥有的业务数据中，通过已验证的 DataApi 读写和现有知识工作流编排访问。记录绑定知识库/条目身份、源内容哈希、单元身份/偏移量、原始文本快照/哈希、用户标签、可选文本覆盖、排除状态和修订号。原始文本及来源与修正后的检索文本分开保存。只存放这些变化和变更历史，不复制源凭据或无关文档。迁移不会为未修改的块创建记录。

每库索引仍然是派生数据。它为一个已提交治理修订生成有效检索文本和排除状态，不改写源内容或原始偏移量。覆盖文本使用独立的有效文本/嵌入身份。保留现有规范化源切片作为原始证据；覆盖不表示原文件本来包含这些修正字符。备份/恢复必须随所属知识库/条目保留持久决策，重建可丢弃索引必须能重新生成其效果。

### 用户操作与状态

现有知识块检查器显示原始文本、有效文本、来源身份、标签，以及生效/等待/需审阅状态。用户可排除/恢复检索而不删除源、编辑/移除覆盖文本，并为明确选中的块增删标签。排除影响检索，不改变来源所有权或检查原内容的能力。标签属于组织元数据；添加标签不改变内容，也不会静默加入模型提示词或查询。

批量操作前预览选择数量和影响。Main 验证所有选择属于指定且可访问的知识库/条目和预期来源/修订。无效或过期选择应原子失败，而非部分编辑其他修订。恢复块仅移除排除，不移除文本修正或标签。移除覆盖通过相同索引更新路径恢复原文。现有材料/库删除仍是独立操作，按现有删除/恢复生命周期处理其治理记录。

### 安全应用变化

通过现有每库知识变更所有者串行化治理修改与重建/删除。先接受持久修订，再用可恢复的 JobManager 作业准备有效词法文本，以及向量库中变化文本的嵌入。显示等待/失败状态和可恢复原因。排除必须立即在检索权威层生效，无需等待新嵌入；恢复/修正则只有完整有效修订准备好后才能称为已索引。

主数据库与每库索引不能共享事务。将派生结果绑定到持久修订，原子发布材料的有效词法/向量视图。修订不一致或准备失败时，从所有检索路径抑制受影响单元，不将旧文本或过期嵌入当作当前内容返回。其他块继续可搜索。重试、重启和取消不能让旧修订覆盖新编辑。移除覆盖也遵循相同规则，包括必要的原文嵌入准备。仅打开检查器不会发起未批准模型调用；应用/确认需说明向量修正何时会使用现有配置嵌入工作及其潜在服务商费用。

在 BM25/向量/混合检索的有界候选选择前执行排除，不能只隐藏最终界面行。否则被排除的高排名单元仍会占满有限候选预算，挤掉有效低排名块。重排前和返回结果前重新验证已接受治理修订，防止过期的进行中搜索将排除文本传给重排器或模型。保留现有条目/库可见性检查、排名语义及限制。

### 重建协调与引用

只有源内容和准确的单元身份/偏移量仍匹配时才自动重新应用记录。同内容、同分块的重建会重现身份，可安全复用决策。源/分块变化后不能仅靠序号、相似子串或标题匹配。身份不再匹配时保留记录及原始证据，标为需审阅并显示原因和受影响来源。不能静默丢弃修正或复活排除内容。用户明确审阅、重绑或放弃未匹配记录前，暂停该材料的检索，其他材料仍可用。重绑预览新旧原文，并创建有可追溯链接的新修订。

有效搜索命中标明覆盖及治理修订，引用区分原始来源证据和用户修正文本。打开引用可查看原文和有效修正，不因覆盖长度不同而移动原始来源偏移量。历史引用保留其记录修订，或明确说明已不可用，不能静默解析成今天不同的文本。源读取/grep 继续暴露来源本身，不能误标为修正后的检索视图。

## Alternatives considered

- 直接编辑/删除派生索引行：重建会抹除决策，无法保留可恢复性或来源。
- 仅在 `index.sqlite` 保存决策：可丢弃投影会变成用户工作的唯一所有者。
- 改写原内容来适配修正：破坏源切片/引用契约，使修正看起来像原始证据。
- 重建后模糊重新关联：源/分块变化后可能把排除或修正转移到无关文本。
- 仅在 top-K 后或渲染器中隐藏排除：可能将文本泄露到重排器/模型，并挤掉有效候选。
- 假装两个数据库提交是原子的：失败或重启后会混用词法/向量/治理修订。

## Acceptance criteria

- AC1 — 治理记录、原始证据、标签、修订和历史在重启、索引重建及支持的知识库备份/恢复后保留；源字节/偏移量保持原始值，所有权遵循库/条目生命周期，迁移后未修改库不存在虚构变更。(verification: database, main and restore integration)
- AC2 — 排除/恢复及批量标签只影响明确选择且可访问的块，可逆，并在来源/修订过期时安全冲突；排除不删除源或无关标签/修正。(verification: database, main, renderer and Electron)
- AC3 — 检索使用词法/向量文本匹配的完整有效修订；排除在候选上限前及重排/模型使用前生效，其他块可搜索，失败/取消/重启作业不能泄露旧文本或覆盖后续编辑。(verification: main retrieval and job integration)
- AC4 — 同身份重建保留生效决策；变化/歧义身份保留证据及可见需审阅状态，明确审阅前暂停受影响材料检索；确认重绑/放弃不能静默将意图应用于其他块。(verification: database, reindex integration and renderer)
- AC5 — 原始/修正文本及引用修订清晰，历史引用不静默解析成不同修正，移除修正可恢复原文检索而不虚构源偏移量。(verification: main, citation integration and renderer)
- AC6 — 无障碍双语检查器、批量预览、等待/错误/审阅状态及费用提示在窄屏/明暗布局工作；用户指南和范围检查通过，部分实现保持 proposed，不宣称完整解决。(verification: renderer, visual inspection, docs gate and Electron)

## Risks

跨数据库恢复和有界检索属于正确性边界，不是界面细节。首个仅存储或仅排除实现不能覆盖整个问题。将持久记录/协调、检索/索引发布、检查器/引用体验分层，每层明确 AC 覆盖。

保守协调可能在不相关编辑改变内容哈希后暂停整个来源。这是有意且可见的，宁可审阅，也不静默重新引入排除内容或错用修正。审阅应可逆且不能抹除原始证据。

修正和原始片段可能包含敏感信息。保持所属知识库访问/备份边界，常规日志不记录完整文本，并说明检索排除不是安全删除，也不限制明确源读取。
