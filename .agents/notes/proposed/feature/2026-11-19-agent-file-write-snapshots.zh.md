# Agent Note: 智能体文件写入快照

Status: proposed

[English](2026-11-19-agent-file-write-snapshots.md) | 中文

## Problem

智能体写入文件可能覆盖用户尚未提交的改动，或创建不需要的文件。没有写前基线时，用户无法通过会话恢复被覆盖的工作。撤销还必须避免破坏智能体写入之后的修改，并区分完整恢复与部分失败。

## Proposal

对受支持的智能体写入，在写入前保存文件基线，并将其关联到已接纳轮次的 replyId。同一轮多次写入同一文件时只保留首次基线；后续轮次拥有各自的基线。不存在的文件记录为缺失，以便撤销该轮创建的文件。记录写入结果，并对危险或无法判断的写入使用现有审批流程；拒绝会阻止写入。

会话操作提供按轮撤销，列出受影响文件并请求确认。主进程持有路径并校验回复、修订号和文件状态；渲染进程不能选择路径。安全时恢复基线或删除新建文件，保留冲突文件，报告部分失败并允许安全重试。快照保留至会话永久删除，包括会话仍被保留或可恢复的期间。

## Key mechanisms

- 写前基线保存原始字节、完整权限位和父目录身份。写后状态是"工具入参推算出的内容"的哈希，不从磁盘采样，因此在 Agent 写入与结算之间发生的用户保存会被报为冲突，而不是被覆盖或删除。
- 撤销要求轮次已结束、修订号匹配、逐文件状态校验，并且当前轮由运行时实时背书；重启后磁盘上的轮次指针本身不被信任。
- 一直未结算的 pending 尝试只在超过 120 秒且目标仍与基线一致时才被取消，否则继续阻断撤销。
- 快照根若会落在任一已登记工作区内则拒绝写入；危险写确认不能被权限模式、headless 或超时绕过。

此保护不覆盖 `bash`、shell 或子进程、CLI、automation、外部 MCP 和内置 filesystem MCP 的写入。它不是通用备份。

## Alternatives considered

- 仅依赖 Git 不适用于无版本控制的工作区，也可能影响无关更改；快照保留受支持写入前看到的状态。
- 盲目恢复可能覆盖用户后续工作；冲突检查优先保留文件，而不是自动完成撤销。
- 完整历史和差异浏览会增加范围及复杂度；本提案只提供按轮撤销。
- TTL 或容量淘汰可能在用户需要前悄然删除唯一恢复基线；按会话生命周期保留以磁盘空间换取可预期的可用性。

## Acceptance criteria

- AC1 — 同一轮对文件的多次受支持写入可撤销到首次写入前的状态，包括删除新建文件；后续轮次恢复各自的基线。(verification: unit — 运行时和快照负责人)
- AC2 — 危险或无法判断的受支持写入请求确认，拒绝后文件保持不变。(verification: unit — 运行时负责人)
- AC3 — 撤销保留智能体写入后被修改的文件，报告冲突或部分失败，并允许安全重试。(verification: unit — 快照负责人)
- AC4 — 会话列出受影响文件，并在撤销所选轮次前请求确认；结果区分成功与部分失败。(verification: Electron — 桌面端负责人)
- AC5 — 会话被保留期间快照仍可用，永久删除会话时快照被移除。(verification: unit — 快照负责人)
- AC6 — 可从会话撤销受支持的交互式智能体写入，恢复文件原有内容。(verification: Electron — 桌面端负责人)

## Risks

快照在会话永久删除前持续占用磁盘。文件系统校验仍存在检查时与使用时之间的 TOCTOU 窗口；待处理写入期间的同内容替换可能无法区分。外部并发写入或持久化中断可能导致结果不明确。不受支持的写入路径仍无保护。后续可考虑历史或差异视图及明确的存储策略，但不能悄然破坏保留期限承诺。
