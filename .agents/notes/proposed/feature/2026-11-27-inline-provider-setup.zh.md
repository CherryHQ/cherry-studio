# Agent Note: 在聊天中配置模型提供商

Status: proposed

[English](2026-11-27-inline-provider-setup.md) | 中文

## 问题

[Issue #15646](https://github.com/CherryHQ/cherry-studio/issues/15646) 记录了所选模型需要提供商凭据时聊天流程中断的问题。[PR #21675](https://github.com/CherryHQ/cherry-studio/pull/21675) 将聊天内配置和配置状态标记留给该 Issue。

## 提案

对符合条件且没有已启用 API Key 的模型显示标记。用户可在模型选择器中打开简洁的配置界面，也可在向这类模型发送消息时打开。首版覆盖已可选择且只需配置 API Key 的模型。需要额外字段的提供商、已禁用的提供商、选择器中没有的模型、已吊销的密钥以及从完整设置返回后自动恢复发送，留待后续处理。其他配置路径可进入完整的提供商设置。保留现有模型可见性规则以及 OAuth 和免密钥提供商的现有行为。

复用现有凭据保存与所选模型连通性检查，并保持提供商启用状态。只有明确验证成功才可恢复发送。现有同步钩子会跳过已有本地模型的提供商，因此自动发现模型留待后续处理。保存和必需验证成功后，可恢复一次被拦截的发送。在编辑器清空草稿前拦截普通的直接发送。将待发送请求绑定到原始会话和分支、所选模型及包含附件的草稿版本。排队的后续消息和编辑后重发沿用现有行为。用户关闭配置界面或更改上述任何一项时，取消自动发送。仅从模型选择器打开配置界面时，没有待发送请求。

## 考虑过的替代方案

直接跳转到设置可使用完整的提供商表单，但会打断消息编辑。保存后立即发送可以缩短流程，但在已有连通性检查可用时，草稿可能遇到本可提前发现的认证失败。

## 验收标准

- AC1 — 符合条件且没有已启用 API Key 的模型在选择器中显示配置入口。已配置、使用 OAuth 和免密钥的模型保留现有选择与发送行为。 (verification: renderer)
- AC2 — 向符合条件的未配置模型发送消息时打开配置界面，并保留原始草稿。完成配置及验证后，如果原始会话、分支、所选模型和草稿版本仍处于活动状态，即使点击两次保存，也只自动发送一次原始草稿及附件。 (verification: Electron)
- AC3 — 缺少必填字段或连通性检查失败时，用户可在配置界面中更正，草稿继续保留。关闭界面或更改会话、模型或草稿时，取消自动发送。 (verification: Electron)
- AC4 — 配置界面提供进入完整提供商设置的入口。打开或关闭配置界面时，提供商的启用状态保持不变。 (verification: Electron)

## 风险

提供商的凭据和可用性取决于认证方式。实现期间需要验证提供商支持范围和认证探测。提供商验证和模型发现可能在用户离开后才完成，异步结果必须遵守原始发送上下文。
