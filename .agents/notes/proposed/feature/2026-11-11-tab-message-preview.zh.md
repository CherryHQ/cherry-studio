# Agent Note: 水平会话标签状态与消息预览

Status: proposed

[English](2026-11-11-tab-message-preview.md) | 中文

## Problem

水平会话标签展示标题和头像，却没有呈现会话侧边栏已有的活动状态。用户在多个并行会话间切换时，不打开会话就无法判断哪个正在运行、需要处理、执行失败或已经完成。只有标题的提示也无法说明会话进行到了哪里。

## Proposal

### 范围与状态归属

为水平智能体会话和普通聊天话题标签增加状态标记与只读消息预览，包括固定标签。侧边栏的悬浮内容保持不变。网页、小程序、设置及其他非会话标签保留现有行为。尚未解析出会话身份的标签不能沿用此前访问的会话状态。

复用侧边栏的状态语义、文案、颜色和完成已读确认。当前智能体侧边栏依次判断待审批、执行中、错误、完成未读。不另建标签专属的优先级或未读标记。必要时共享状态推导，但不改变侧边栏行为。无论流仍在运行还是已经结束，审批锚点都保持权威；提问请求使用真实的未解决交互记录，不能根据消息文本或加载标记猜测。如果缺少问题状态能力，应先在所属交互边界补齐，不能先在界面推断。

保持头像、标题、选中背景和关闭控件稳定。普通标签预留一个状态位置，固定标签使用紧凑角标。根据可用空间调整侧边栏状态的呈现，不引入不同含义。选中标签保留正在活动及需要处理的标记。空闲、完成已读和用户主动停止无需持续标记。仅悬浮或聚焦不会确认完成已读；进入会话使用现有已读确认路径。

### 预览内容

沿用现有消息展示语言，不生成单独摘要。卡片包含最多两行的标题、简短当前状态、有尺寸限制的消息片段和低强调的打开会话提示。视觉验证从约 400 px 宽、最大 360 px 高开始；限制在窗口内，短内容允许自然收缩。这些是功能布局目标，不是新的设计系统令牌。

普通活动展示最新消息中的连续片段，优先保留最新回复末尾，空间允许时保留前一条用户消息。卡片打开时，流式文本和工具活动持续更新。需要用户交互时，展示未解决请求而非最新末尾。多个请求待处理时，按会话顺序展示最早的一条及剩余数量。请求解决后，选择下一条未解决请求或恢复最新消息。错误展示真实失败及相邻上下文；已停止轮次展示最新片段并注明已停止。区分加载中、空会话和预览不可用。

使用只读消息渲染：保留角色标识、Markdown 和可辨认的工具展示；不提供编辑、复制、重试、分支、审批、回答及输入框控件。问题选项使用纯文本，而非看似禁用的按钮。工具详情保持折叠；过大的代码和媒体裁切或限制尺寸，不出现内部滚动或自动播放。卡片本身也不滚动。标明被省略的内容，不能让裁切后的消息看起来完整。不在卡片内增加模型、token 或目录清单。

### 交互

鼠标在非当前会话标签上停留约 500 ms 后展开预览。移入卡片保持打开；离开标签与卡片后，短暂延迟关闭。同一时间仅打开一张卡片。键盘聚焦可展示相同信息，Escape 关闭。拖动、关闭标签、打开标签上下文菜单、切换其会话身份或激活标签时关闭预览。不预览当前选中标签，也不叠加原生标题提示。

点击卡片激活该已有标签，不创建另一个会话标签。如果预览的是未解决请求，在激活后使用现有消息定位流程定位其锚点。如果请求在点击前已经解决，正常打开会话，不处理陈旧内容。预览内不执行审批、回答、登录、重试或其他业务动作。普通标签选择、关闭、固定、快捷键和拖动行为保持不变。

### 实现边界

标签壳层负责位置与悬浮生命周期；会话身份、状态和消息仍由既有领域负责。轻量状态订阅独立于标签页面是否挂载或被 LRU 保留。仅为已打开的预览读取有限消息数据，使用现有历史查询和实时投影。关闭后取消订阅，并拒绝属于旧身份的结果。不能为获取预览挂载完整聊天页面、启动运行时任务、确认消息已读或持久化复制的流状态。

复用共享消息展示边界，必要时增加明确的只读能力。仅用 CSS 隐藏交互控件不够。使用 `@cherrystudio/ui` 基础组件、语义设计令牌、本地化文案、无障碍名称及减少动画行为。当前侧边栏悬浮卡片与新的水平标签布局保持独立。

### 交付与验证

先发布本双语 Spec。当前提交获得明确的人工 Approval 后，以一个依赖实现层覆盖全部验收标准。所有标准都有实际证据前，文档保持 proposed。先针对状态映射、预览内容选择、交互安全、导航及受影响的侧边栏和标签调用方运行明确的 Renderer 测试，再在真实 Electron 中验证明暗主题下的悬浮与流式行为。默认不运行全量本地测试。

## Alternatives considered

- 单独设计标签状态分类会与侧边栏产生偏差，因此复用其语义。
- 复用侧边栏的元数据悬浮卡片无法展示消息进展，因此水平标签预览保持独立。
- 可滚动的迷你会话或直接审批控件会把快速查看变成第二个交互界面，因此阅读和决策进入真实会话完成。
- AI 生成摘要或挂载完整聊天页面会增加成本或副作用，却无助于所需预览，因此复用有限的消息展示与数据。

## Acceptance criteria

- AC1 — 普通和固定会话标签与侧边栏的状态语义和完成已读确认一致，覆盖流中的审批锚点及后台标签；非会话标签与侧边栏悬浮内容保持原有行为。 (verification: renderer)
- AC2 — 预览展示最新消息片段或最早的未解决交互，并准确显示剩余数量；实时更新、请求解决、错误、已停止、加载、空会话及数据不可用均不会显示其他会话的内容。 (verification: renderer)
- AC3 — 卡片及所有嵌套消息内容保持尺寸受限且不可滚动，不提供业务控件或自动播放；打开或聚焦预览既不确认完成已读，也不启动执行。 (verification: renderer)
- AC4 — 激活预览选择已有标签并定位仍待处理的请求；已解决请求退回正常激活，同时标签关闭、固定、快捷键及拖动保持现有契约。 (verification: renderer)
- AC5 — 真实 Electron 交互验证明暗主题下的悬浮延迟、鼠标移入、关闭行为、键盘访问、减少动画、窗口边界、固定标签及后台实时更新。 (verification: Electron)
- AC6 — 双语 Spec、受影响的参考文档和本地化界面文案与交付行为一致，在文档迁移到 implemented 前记录限定范围的检查及实际证据。 (verification: docs gate)

## Risks

侧边栏状态组件目前混合了状态含义与列表行专属的位置和悬浮操作行为；复用时不能将这些布局规则带入标签栏，也不能改变侧边栏。消息组件可能包含可操作的工具控件、媒体及昂贵的渲染器；必须在所属模块落实只读能力和有限加载。LRU 淘汰、延迟的历史查询和交互解决可能与悬浮或导航竞争；会话身份及请求锚点必须保持权威。长内容裁切可能损失有用上下文，这是只供快速查看的预览所接受的代价；完整内容仍可在会话中查看。
