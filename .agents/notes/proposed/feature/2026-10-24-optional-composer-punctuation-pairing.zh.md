# Agent Note: 输入框可选标点配对

Status: proposed

[English](2026-10-24-optional-composer-punctuation-pairing.md) | 中文

## 问题

[Issue #22583](https://github.com/CherryHQ/cherry-studio/issues/22583) 反馈 Windows v2.1.7 的聊天输入框需要手动补全另一半标点。[作者澄清](https://github.com/CherryHQ/cherry-studio/issues/22583#issuecomment-6379229105)明确希望按一次左侧符号就插入整对符号，并将光标放在中间；原始反馈还希望提供开关。视频对比与澄清均不能证明 Cherry Studio 丢弃了输入法已经输出的字符。

所检查的 v2.1.7 输入框预设没有标点配对扩展。本提案增加可选的编辑行为，不把缺少便利功能认定为已证实的文本丢失，也不声称已经实现修复。

## 提案

为聊天输入框增加一个持久化、需主动开启的标点配对偏好。现有安装与新安装默认均保持原样输入。开关位于聊天输入设置中，使用仓库现有的偏好系统和翻译文案，不改变其他文本字段或已存消息。

首批支持的配对为 `()`、`[]`、`{}`、`""`、`（）`、`【】`、`「」`、`『』`、`“”` 和 `‘’`。ASCII 单引号和反引号保持原样，避免改变英文撇号和代码分隔符。这是标点辅助功能，不是识别编程语言的代码补全。

开启后，在输入法未处于组字状态时，输入一个受支持的左侧字符会补齐右侧字符，并将光标留在中间。仅在文本块末尾、空白字符之前或受支持的右侧字符之前配对；在其他文字之前输入时保持原样。ASCII 双引号紧跟字母或数字时保持原样。同一个文本块内非空的纯文本选区会被包裹，并保持选中；跨文本块或包含 token 的选区沿用编辑器正常行为。

仅跟踪当前编辑器会话中由配对功能生成的右侧字符。在跟踪位置输入对应的右侧字符时，光标越过该字符而不再添加一个。在未改动的空生成配对中间按退格，会将两侧作为一次编辑一起删除。内容移动或修改时必须映射或使关联失效，绝不能跳过或删除无关的现有标点。撤销和重做将配对、包裹以及成对删除分别作为正常的单次编辑。

绝不拦截正在进行的组字、粘贴、拖放、程序化内容插入或模型输出。输入事件提供整对或多个字符时，保留原文而不添加标点。输入法输出的中文标点保持原生顺序和光标行为；仅非组字期间插入单个左侧字符时才可触发配对。不改写组字结果来强行配对。若确认存在输入法文本丢失，须单独调查对应输入路径。

沿用输入框现有扩展边界和偏好归属。在引入自定义输入处理前，检查 Tiptap/ProseMirror 的现成能力。不替换编辑器，不增加语言解析器，不改变发送快捷键、提示词变量 token 或建议菜单导航。实现层必须说明所选扩展机制，并验证受影响的输入框消费者。

本提案仅为 Spec。只有当前 Spec PR head 获得明确的人类 `APPROVED` review 后，才按 [Agent Note 规则](../../README.md#spec-first-stack)开始实现。行为规则或验收条件发生实质变化时，需要重新批准。

## 考虑过的替代方案

- 始终开启配对：不采用，因为普通对话、代码片段和现有工作流仍然需要原样标点。
- 仅依赖操作系统输入设置：不采用，因为它无法提供要求的应用内开关，且行为因输入法而异。
- 将反馈当作已证实的字符丢失：不采用，因为尚未确认实际输出内容；据此修改组字处理可能损坏有效文本。
- 在所有场景配对所有引号和分隔符：不采用，因为英文撇号、代码分隔符、组字和现有文本需要明确的行为边界。
- 替换输入框或引入语言解析：不采用，因为对于可选的标点辅助功能而言，改动过大。

## 验收条件

- AC1 — 关闭配对时，键入文本保持原样，现有安装保留当前输入行为；偏好在重启后保留，界面文案完成翻译（验证：偏好测试和 Electron 设置检查；负责人：实现作者）。
- AC2 — 开启配对时，每个受支持的左侧字符在符合条件的位置恰好插入对应整对符号，光标位于中间；排除的符号和不符合条件的位置保持原样（验证：明确的输入框 renderer 测试用例；负责人：实现作者）。
- AC3 — 单块纯文本选区被包裹后不丢文字且保持选中；跨块和包含 token 的选区保留编辑器正常行为（验证：输入框 renderer 测试；负责人：实现作者）。
- AC4 — 仅跟踪的自动生成右侧字符可被跳过，仅未改动的空生成配对可一起删除；中间发生编辑后仍保留无关标点（验证：输入框 renderer 测试；负责人：实现作者）。
- AC5 — 组字、多字符输入、粘贴和程序化插入完整保留提供的文本，不产生额外标点；Windows 实际输入法检查覆盖单左侧符号和已配对输出，并记录输入法及模式（验证：renderer 测试和 Windows 功能证据；负责人：实现作者）。
- AC6 — 配对、包裹和成对删除可连贯撤销及重做，发送快捷键、提示词变量 token 和建议菜单导航仍然可用（验证：受影响的现有输入框消费者测试和 Electron 功能检查；负责人：实现作者）。
- AC7 — 实现 PR 为每项验收条件提供实际证据，说明未执行的场景，并与本次仅包含 Spec 的提案分开（验证：PR 证据审阅；负责人：实现作者和维护者审阅者）。

## 风险

Windows 各输入法的行为不同。模拟编辑器测试不能单独证明原生组字正确；缺少真实输入法验证时，必须如实记录，不能称为通过。即使启用配对，多字符输入也有意保持原样。

选区编辑、撤销或 token transaction 可能使生成配对跟踪状态过期。状态只属于当前编辑器会话，须随 transaction 映射或失效，绝不单凭相邻标点推断归属。引号规则在歧义场景有意优先原样输入，牺牲部分便利以保护现有文本。

开关和符号集合是拟议的产品选择，尚未获维护者批准。本 Spec 不包含实现、发布说明或已完成的功能验证。未发现已有活跃 note 负责输入框标点配对；文档治理和其他输入框决定保持不变。
