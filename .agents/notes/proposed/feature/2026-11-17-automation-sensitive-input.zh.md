# Agent Note: 为 Browser 和 Computer Use 请求敏感输入

Status: proposed

[English](2026-11-17-automation-sensitive-input.md) | 中文

## 问题

Browser 和 Computer Use 可能遇到只有用户能够提供的密码、验证码或其他秘密。要求用户发送普通聊天消息或回答 `AskUserQuestion`，会让值进入模型可见的对话或工具数据。仅将输入框显示为遮挡样式，并不会改变这些传递和持久化路径。

当前 Automation REPL 已支持临时应用授权请求，并将其等待时间排除在执行预算之外。Browser 输入绑定页面和元素，但普通的失效引用恢复可能选中替代元素。Computer Use 提供按元素填写的 `setValue` 和按键盘输入的 `typeText`；后者没有绑定具体的焦点控件。已安装 SDK 固定为 `@cherrystudio/computer-use` 0.1.11，其公开协议没有敏感输入目标或观察保护契约。不能把上游较新的源码当作已安装能力。

本决策独立于[应用授权](2026-11-13-computer-use-app-approval.md)和[对话浏览器所有权](2026-11-14-session-browser-tabs.md)，原有说明继续负责各自的决策。可复用授权只允许访问应用，绝不提供秘密，也不代表用户同意将秘密填入另一个目标。

## 提案

在 Cherry Studio 中提供一套临时敏感输入请求生命周期，首先供绑定目标的 Browser 和 Computer Use 操作使用。Bash 后续也应使用同一请求生命周期，但 shell、stdin 和 PTY 传递不属于本 Spec 的验收范围。不增加秘密保险库、记忆值、剪贴板传递或供模型读取秘密的通用 API。

### 请求与传递

1. 模型指定已观察到的可编辑控件并说明用途。主进程在请求值之前解析真实目标并准备目标绑定；目标不可用或有歧义时不创建输入请求。
2. 在请求所属对话的输入区显示遮挡输入卡，展示已验证的网站来源或应用身份、窗口和字段说明、用途，以及提交、取消按钮。目标身份由宿主提供。模型编写的用途和页面提供的标签只是展示数据，不构成授权。需要应用授权时，先完成现有授权，再发起敏感输入请求。
3. 值通过独立且绑定发送方的 IpcApi 响应，直接交给主进程中的待处理操作。操作再次验证原始目标，只填写一次，并仅向模型返回固定结果。值和原生目标令牌都不进入 REPL、模型工具参数/结果或普通批准的 `updatedInput`。
4. 提交、取消或过期后，主进程撤销请求并释放值引用。即使输入失败，提交也会消耗请求；结果不确定的操作绝不重试。新请求必须先重新观察目标，并由用户再次提交。不修剪、不规范化用户提供的值，也不将其解释为代码或组合键；派发前拒绝换行输入，防止其提交表单。填写操作不会自动在目标中按 Enter 或点击提交。

复用现有临时输入区模式，不走普通提问、草稿缓存和持久化批准响应路径。生命周期服务拥有待处理请求；共享 schema 描述请求元数据和响应。渲染进程仅在已挂载输入框中保存值，变更事件不携带值，并在提交、卸载或取消时清空。切换对话后不恢复输入草稿。这表示移除保留的引用，不承诺物理清零 JavaScript 或操作系统内存。

### 目标保证与上游责任

Browser 的准备操作绑定现有对话所有者、guest/页面绑定、文档、来源和确切 DOM 元素。提交时重新校验这些身份及控件可编辑性。导航、guest 替换或元素替换都会让请求失效，即使新元素具有相同角色和名称。敏感输入不得使用自动 `recoverRef` 重新选定目标。基于焦点的页面输入还必须在派发时验证焦点属于原始元素；无法保证时，必须在发送值之前失败。

在 [Cherry Computer Use](https://github.com/CherryHQ/cherry-computer-use) 上游补齐缺失契约，包括生成式 SDK 协议和原生实现。准备操作生成不透明的原生目标令牌，绑定私有运行时、应用会话、进程、窗口、确切控件及选定输入通道。准备操作及时返回，不会在用户于 Cherry 输入期间一直挂起原生输入请求。提交一次性消耗令牌，并在原生输入边界重新校验绑定。同一窗口内发生焦点控件变化时，不得向新控件发送键盘输入。原生实现能够保证确切控件身份时，继续支持无需焦点的元素写入。取消、停止、目标销毁和运行时退出会使令牌失效。不按无障碍名称重新选定目标，不回退到其他通道，不使用全局键盘输入，也不重放结果不确定的写入。

原生准备操作还必须为目标建立观察保护。读取密码控件的值之前先进行分类；即使选定的秘密/验证码控件是普通文本框，也对其施加相同保护。SDK 按平台报告这项能力。无法保证契约的后端，在收集秘密之前返回明确的不可用/不支持结果。检查补丁和兼容性后，Cherry 仅升级到已发布且 SDK/原生版本匹配的版本；不保留仅在宿主侧模拟的实现，也不提交本地运行时符号链接。

### 观察与保密边界

支持的保证涵盖输入卡、宿主传输、确切目标控件，以及 Cherry 交付的该目标观察。原始值不写入消息、历史、草稿、工具回执、追踪、诊断或日志。错误只暴露固定错误码和目标元数据，不返回可能回显输入的原生/页面原始错误文本。原生服务和页面服务为执行用户请求的输入，必然需要接收该值。

模型可见的受保护控件观察不包含值、选中文本或可编辑后代内容。保护在输入请求结束及后续轮次中继续保留，直到后端确认控件已清空、移除，或其文档/窗口已销毁。取消尚未填写的请求，不会抹除目标中已有的值。失败或结果不确定的输入继续保持保护。

目标仍受保护时，不向模型输出该页面/窗口的截图，不依赖可能失效的遮挡矩形。阻止可能绕过字段保护的 Browser 无限制 `evaluate`、页面内容提取、WebMCP 调用和检查缓冲区读取；继续允许符合策略的操作及过滤后的 AX 观察。Computer 的观察抑制和字段过滤属于上游原生契约。本地用户仍可查看和操作目标。模型提供的标志、REPL 重置、新句柄或运行时适配器都不能移除保护。解除保护需要后端证据，不能相信模型声明。解除后，先丢弃保护期间收集的检查记录，再恢复这些读取。

这不承诺任意网站或应用无法将秘密复制或转换为无关内容、将其持久保存，或通过自身网络发送。目标侧任意回显和外传不在保证范围内；精确字符串脱敏无法实现更广泛的承诺。不得宣传通用的端到端保密保证。

### 等待、取消与可用性

敏感输入是由模型显式请求的操作，不宣称能够自动识别每一个密码或验证码提示。两类界面复用 REPL 暂停人工等待计时的机制，并验证各受支持运行时的取消与超时传播。Browser 命令和原生提交的期限从用户提交之后开始计算。每个输入请求独立于执行时间，在五分钟后过期。用户停止、能力撤销、对话/窗口/目标关闭、运行时完成和退出都会撤销请求；迟到或重复提交不能填写任何目标。响应绑定请求所属窗口、对话和操作。其他对话的请求彼此独立，绝不继承值。

应用授权、`bypassPermissions` 和自动工具批准都不能跳过用户输入或目标校验。没有授权响应方的非交互执行和已连接 Channel 的执行，在收集秘密之前失败。保留受保护目标之外的普通 Browser/Computer 行为。文案使用翻译和 `@cherrystudio/ui` 组件。

### 交付与验证责任

当前 Spec head 获得批准后，先实现并验证上游目标/观察能力，再将已发布 SDK 接入 Cherry 的请求生命周期、Browser/Computer 适配器和输入区。上游负责原生身份、输入通道保证、密码分类和 Computer 观察。Cherry 负责对话/窗口授权、请求、Browser 目标/观察、模型可见结果和生命周期集成。实现 PR 链接上游修复及发布证据。Bash 后续适配需要自己的传递契约和验收证据；本 stack 不宣称交付 Bash 适配。

## 考虑过的替代方案

- 普通聊天或带密码输入框的 `AskUserQuestion`：遮挡了展示，但仍保留模型可见回答及草稿/历史存储。
- 向 REPL 返回明文或通用秘密查询句柄：允许模型编写的代码在已验证目标之外打印、重定向或保留值。
- 用户回复后，向当时拥有焦点的控件输入：应用/窗口校验不能证明控件身份。
- 在 Cherry 中通过先点击再输入或依赖补丁模拟缺失的原生保证：竞态仍发生在原生边界，并绕过上游责任方。
- 遮挡截图矩形并到处替换匹配字符串：过期的几何信息，以及经过转换或复制的内容，都无法建立通用保密保证；应抑制有风险的观察。

## 验收标准

- AC1 — 交互式 Browser 或 Computer 请求展示已验证目标和遮挡、可取消的输入区；普通聊天/提问缓存、已保存授权及 bypass 模式都不能提供或暴露值。(verification: renderer and Electron)
- AC2 — 合成秘密原样且仅一次到达选定目标，只产生固定的模型可见结果，成功和失败时都不会出现在 REPL 代码/状态、模型请求/结果、消息/历史/草稿存储、日志、追踪和诊断中。(verification: unit and Electron)
- AC3 — Browser 导航、guest 或元素替换、来源变化及错误输入焦点都会在发送秘密之前拒绝待处理写入，包括无障碍名称和角色相同的替代元素。(verification: unit and Electron)
- AC4 — 上游原生准备/提交拒绝跨会话令牌、变化的进程/窗口/控件/通道、同窗口焦点变化、重复提交及取消或停止后的提交；支持的确切控件写入只填写一次，不重新选定目标或回退。(verification: upstream unit and native fixture)
- AC5 — 在读取值之前，所有受支持的 Computer 观察路径都省略密码及显式受保护验证码/文本控件的值、选中文本和可编辑后代；不支持的平台在请求输入之前报告能力缺失。(verification: upstream unit and native fixture)
- AC6 — 受保护的 Browser/Computer 目标不输出模型可见截图；过滤后的 AX 仍可用，Browser 绕过读取被阻止，重置/新句柄不移除保护，解除保护需要后端证据并丢弃受保护检查缓冲区。(verification: unit and Electron)
- AC7 — 等待至少 90 秒仍保留有效请求和剩余执行预算；五分钟过期、取消、撤权、目标/对话/窗口关闭及退出都能阻止迟到或重复提交发送输入。(verification: unit and Electron)
- AC8 — 请求和响应始终绑定窗口、对话和操作；其他对话无法回答或消费请求，没有授权交互响应方的执行不收集值。(verification: unit and Electron)
- AC9 — Claude、Pi、Pi Durable 和助手话题适配器共享同一输入/保护策略，保留现有停止与应用授权行为，并通过现有 UI 组件展示翻译文案。(verification: unit, renderer and Electron)
- AC10 — Cherry 使用已发布且版本匹配的 SDK/原生制品，不依赖本地链接或宿主模拟；每个宣称可用的平台都有原生 fixture 证据，并明确记录尚未验证的 GUI/平台范围。(verification: packaged artifact and native fixture)

## 风险

原生控件和浏览器框架在能否无焦点竞态地向确切元素输入方面存在差异。后端可能需要对某些控件报告不支持；必须将该结果与输入成功区分。五分钟等待需要超出仅测试内核时钟的集成证据。临时卡片不得意外进入普通批准持久化或错误上报载荷。

秘密仍存在时，观察保护会有意限制自动化。过滤后的 AX 可以支持下一步操作，但需要无限制脚本或仅靠截图交互的页面/应用可能继续受阻。目标可能把秘密复制到受保护控件之外；这是明确的保密限制，不代表可以削弱传递路径。移除引用不保证内存清零。真实桌面和打包制品证据必须与 mock、fixture 和 CI 结果区分。
