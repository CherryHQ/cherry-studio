# Agent Note: 本地 Agent 统一用量分析

Status: proposed

[English](2026-11-02-local-agent-usage-analysis.md) | 中文

## Problem

ACP `session/prompt.usage` 描述一轮提示的汇总，而 `ai_usage_record` 描述可观测的服务商调用。一轮可以包含多次服务商请求。改动前，`AcpConnection` 将所有路径固定交给 `agent-sdk` 采集，并为每轮上报生成新的调用身份。CLI 使用 Cherry 网关时，网关也可能记录底层请求。叠加两种观测会重复统计同一工作量，并把轮数误当成请求数。

保存到 CLI 的网关配置由终端和聊天启动共享，不能可靠证明某个 HTTP 请求属于哪条 Cherry 回复。智能体选中的来源模型，也不足以证明实际服务请求的模型或凭证。

原生会话费用又属于另一种范围：金额是累计值，可能下降，币种也可能超出 Cherry 调用账本的支持范围。现有 [ACP 会话费用决策](../../implemented/feature/2026-10-22-acp-session-cost.md) 明确将其独立保存。

## Proposal

### 三种观测范围

| 范围 | 事实来源 | 计数规则 |
|---|---|---|
| 服务商请求 | 现有 `ai_usage_record` | 每次可观测调用只计一次，保留真实服务商、模型、凭证和价格快照 |
| 智能体轮次 | 现有消息 JSON 中由 Main 管理的有类型本地用量汇总 | 每轮上报只计一次，不描述为服务商请求次数 |
| 原生会话 | 现有 `localSessionCost` 快照 | 每个原生会话只取最新金额，不累加历次快照 |

调用计费和消息统计继续归现有模块所有。首期不新增数据库表或字段。有类型的本地轮次汇总可以在消息 JSON 中保留原生会话身份、原生模型身份、上报 Token 和上报时间，不能覆盖调用记录派生的 `MessageStats`，也不能虚构服务商价格。

新的 ACP 轮次汇总不再生成伪造的逐调用记录。现有不可变记录保持原样；历史 CLI 汇总应在读取模型中单独标识，不能静默当成新的请求级证据。缺乏可靠归属时，不自动修复历史重复数据。

### 采集与归属

网关请求继续由服务商调用链路采集。对支持连接级临时覆盖的 CLI，复用内部网关和受限凭证，将连接绑定到智能体会话和模型，并在连接关闭时撤销凭证。不向 CLI 全局配置写入会话 ID 或临时凭证，不新增代理或安装管理器。

连接级覆盖必须保留用户选择的全局模型，以及 CLI 原生配置的所有权。适配器无法可靠应用覆盖时，仍保留服务商请求记录，不伪造消息归属，并将关联状态标为未知。已配置的来源模型、接近的时间或相似的 Token 数都不能证明关联。

存在服务商调用采集时，仍可单独展示原生轮次汇总以便诊断，但不能将它加入请求总量。未上报用量的情况保持未知，上下文窗口占用也不等于已消耗 Token。

### 分析界面

复用现有用量设置页和聊天用量详情，明确区分服务商请求与 CLI 轮次汇总两种观测类型。捕获到智能体身份时展示它，允许用户查看原生用量，不把外部 CLI 冒充成 Cherry 模型服务商。

服务商请求总量仍基于调用账本。原生 Token 汇总与原生会话费用分别标注、单独展示，不提供叠加重叠观测的总计。协议没有上报时，不把原生累计费用分配到单个请求或日期。保留原币种，区分未知值和明确的零，不换算币种，也不根据选中模型的目录价格推断费用。

持久化保留内部模型身份，协议和遥测消费者使用 API 模型身份。当前智能体或服务商设置的修改，不得重写历史归属快照。

## Delivery

1. 增加有类型的原生轮次读取模型、持久化保护和计数规则；新轮次停止生成伪造的 ACP 调用记录。
2. 为支持连接级临时覆盖的适配器建立可靠网关关联；不支持的关联明确保持未知。
3. 复用分析页和消息详情组件展示不同范围，补齐翻译，并完成 Electron 验收。

本批不导入 CLI 历史，不修改原生凭证，不重算旧账单，也不扩展到非 ACP 协议。

## Alternatives considered

- 将原生用量加到网关用量：重复统计 Token，并让一轮看起来产生了额外请求。
- 将原生会话累计费用转换为调用差额：无法处理原生历史恢复、金额下调及上报缺失。
- 让 `ai_usage_record` 同时表示轮次或会话：扩大既有不可变调用契约，需要另行决定数据库结构。
- 根据 CLI 全局配置或时间关联请求：并发会话和终端启动会让关联失去可靠性。

## Acceptance criteria

- AC1 — 一轮网关对话产生多次服务商请求，并收到 ACP 用量汇总时，服务商请求与 Token 只计一次；原生汇总仍可单独查看（验证：协议测试进程和生产迁移后的数据库测试）
- AC2 — 仅使用原生模型的轮次准确保留上报用量，计数标为观测轮次，不虚构服务商请求次数；未上报时保持未知（验证：协议和数据库测试）
- AC3 — 重复、下调、零值及币种变化的会话费用上报只替换快照，不改变逐调用计费，不虚构每轮费用（验证：现有费用测试及新增受影响消费者）
- AC4 — 并发聊天会话不会交换归属；关闭连接会撤销受限凭证，终端和全局配置保持不变（验证：网关生命周期和已支持适配器测试）
- AC5 — 用量设置和聊天详情在中文、英文下区分服务商请求、原生轮次、上下文占用及累计费用，不静默合并币种（验证：前端测试、多语言检查和 Electron）
- AC6 — 不重写现有记录或用户历史；有类型的 JSON 数据重启后仍可读取，并阻止前端消息写入覆盖（验证：生产迁移后的数据库测试和 Electron）
- AC7 — 不支持的关联显示为未知，不静默丢弃服务商记录，也不声称消息级统计完整（验证：适配器失败及不支持场景测试和 Electron）

## Risks

不同第三方智能体的 Token 语义及连接级配置能力存在差异。首轮实现必须记录哪些适配器已验证关联，不能将所有预设当成已验证。基于 JSON 的大量汇总还需要有日期范围和分页的读取路径，避免打开用量页面时扫描或返回全部消息。

本提案会改变参与用量总计的观测口径，须先评审计数契约再实施。本文不表示该能力已经交付。

## 工作区验证

用户已在实施对话中批准此契约。代码已在本地实现；此提案仍等待 PR 评审生命周期确认。

- 生产迁移数据库测试验证三次服务商调用加一份原生汇总不会重复计数，并覆盖旧版数据分离、游标分页、受保护 JSON 写入、分支排除，以及累计费用的零值、未知值和币种快照。
- 协议与运行时测试覆盖轮次汇总、缺失用量、轮次重置、持久化和既有调用记录消费者。限定凭证测试覆盖并发会话、伪造请求头、撤销及不支持的覆盖配置。
- OpenCode 2.0.29 和 Kilo 7.8.8 通过进程临时配置，在受控回环后端完成真实 ACP 对话。OpenCode 发出两次 HTTP 请求并报告一份轮次汇总；Kilo 发出一次请求。探测未修改 CLI 全局配置或 Cherry 对话历史。
- 渲染测试覆盖中英文口径切换、分页、原币种、极小正数费用与未知值。Electron 通过 DataApi 读取既有旧版观测和费用快照，未创建用户记录。新汇总的消息详情使用受控渲染与协议测试验证。

首个完成真实适配器验收的路径是 OpenAI 兼容聊天补全。其他 SDK 端点映射已由限定网关契约覆盖，但尚无逐端点真实 CLI 验收证据。不支持或被用户覆盖的路径保持未关联状态。
