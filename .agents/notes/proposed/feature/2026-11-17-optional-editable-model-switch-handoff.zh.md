# Agent Note：切换 Agent 模型时的可选可编辑交接

Status: proposed

[English](2026-11-17-optional-editable-model-switch-handoff.md) | 中文

## Problem

在非空 Agent 会话中切换模型会保留对话历史，但新模型可能难以理解较长或只完成了一部分的任务。Issue #18978 要求在切换时提供一份可选的、用户可编辑的任务交接。会话拥有自己的模型选择，见 [会话所有的模型选择](../../implemented/bug-fix/2026-11-14-agent-session-model-ownership.md)。目前 `AgentChat.tsx` 中的模型切换对话框只有"本次应用运行中跳过"复选框；确认后只更新会话模型，没有其他动作。想为新模型提供任务简报的用户没有办法创建，切换来源也不会被记录。

## Proposal

- 在现有模型切换确认对话框中新增选项"为新模型创建交接"，默认不勾选。
- 勾选后，由当前模型生成交接内容：目标、决策、已完成工作、待办步骤、相关文件、未解决风险。
- 生成的交接显示在对话框内的可编辑字段中。用户确认或编辑后，切换才完成。
- 确认时，将编辑后的交接作为系统消息持久化到同一会话，并关联一条记录先后模型身份的切换记录。原始消息不被修改或删除。
- 未勾选时，切换行为与现在一致，对话历史仍是上下文来源。
- 切换后的下一轮，新模型通过会话上下文接收编辑后的交接。

## Alternatives considered

- 每次切换都提示交接：被 Issue 否决（"不要为每次切换强制使用"）。
- 不调用 LLM 的确定性摘要：成本低且可离线，但无法可靠提取决策和待办步骤。可作为生成失败时的备选，不在本 Spec 范围内。
- 用交接内容新建会话：保持旧会话干净，但会把对话和文件拆到两个会话中。本轮不采用。
- 仅存为输入框草稿：会丢失来源记录，且不在新模型的上下文中。不采用。

## Acceptance criteria

- AC1 — 切换对话框提供交接选项，默认不勾选；未勾选时，切换不调用 LLM，也不持久化任何新内容（verification: renderer）
- AC2 — 勾选时，生成的交接区分已完成与待办工作，并列出相关文件和风险（verification: unit）
- AC3 — 用户确认前可编辑生成的交接；持久化的系统消息包含编辑后的文本，而非生成的原文（verification: renderer）
- AC4 — 持久化的交接记录先后两个模型身份；原始消息保持不变（verification: unit）
- AC5 — 交接后的下一轮会把编辑后的交接发送给新模型作为上下文（verification: unit）
- AC6 — 不交接直接切换、或取消对话框，都不改变会话（verification: renderer）
- AC7 — 交接生成失败时，对话框显示错误，用户仍可不带交接直接切换（verification: renderer）

## Risks

- 原生运行时恢复：会话带有运行时恢复 token 和上下文投影。会话中途插入的系统消息不能使原生恢复失效，也不能被投影丢弃。在验证 AC5 前，需要在 Pi 与 Claude Code 运行时上检查实现。
- 跨运行时切换：切换运行时类型可能改变系统消息的投递方式。交接必须作为上下文送达模型，而不能成为用户轮次。
- 生成成本与延迟：交接调用在切换完成前使用当前模型。生成期间取消，不得切换模型。
- 摘要准确性：可编辑字段是缓解手段；本 Spec 不声称生成的摘要完整。
