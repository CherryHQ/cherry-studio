# Agent Note: 通知中心抽屉与任务结果展示

Status: proposed

[English](2026-10-29-notification-center-redesign.md) | 中文

## 问题

通知入口应与 [#23043](https://github.com/CherryHQ/cherry-studio/pull/23043) 的账号区域保持一致。已关闭的 [#21772](https://github.com/CherryHQ/cherry-studio/pull/21772) 和 [#21884](https://github.com/CherryHQ/cherry-studio/pull/21884) 包含可复用的通知存储、公告拉取和任务结果逻辑。但它们的顶部弹出框、数字角标、分类标签和详细任务条目不符合目标界面。旧 PR 保持关闭，新实现 PR 复用其中相关改动。

用户需要一个安静的收件箱、容易找到的未读提示，以及“谁完成了、谁失败了”的简短信息。详情应在原对话或任务页面查看。用户回到应用时，也应刷新官方公告，并避免并发请求。

## 方案

### 交付与职责

依赖链为 `#23043 → Spec → notification center → task results`。本设计 PR 只改文档。两层实现均需先获得当前设计稿版本的批准。中间层保持文档为 proposed；最终层为全部 AC 记录实际证据后，再将中英文和配对记录一起移到 implemented。

| 层级 | 职责 | 验收条件 |
|---|---|---|
| 通知中心 | 入口、未读圆点、抽屉、统一列表、已有通知存储和官方公告 | AC1–AC10 |
| 任务结果 | 紧凑任务展示、运行结果、送达规则和结果跳转 | AC11–AC14 |

账号菜单行为仍由[账号菜单缓存与交互](../../implemented/bug-fix/2026-10-29-account-menu-cache.md)说明。本方案在该体验旁增加通知入口，不重新设计账号操作。

### 入口与未读提示

- 侧栏完整显示或仅显示图标时，铃铛放在用户头像正上方。复用侧栏底部的操作插槽。移除原先常驻标签栏的铃铛。
- 侧栏隐藏时，铃铛放在顶部头像旁边。临时浮出的侧栏不能再挂载一个抽屉，也不能重复订阅通知。
- 存在未读通知时，只显示一个小圆点。铃铛、抽屉标题和单条通知都不显示数字或 `99+`。未读条目也使用圆点。保留通知入口和未读状态的无障碍标签。
- 保留现有未读数量 API。界面只判断数量是否大于零。不建立第二套未读状态或独立角标计数。

### 左侧抽屉

复用现有 [Drawer 基础组件](../../../../packages/ui/src/components/primitives/drawer.tsx)。增加可选的遮罩控制，默认保持现有行为。通知抽屉使用非模态模式，不显示暗色蒙版；其他使用方保持原样。

抽屉从左侧滑出，覆盖内容，不改变聊天布局宽度。侧栏可见时，抽屉左边界跟随侧栏右边缘。侧栏隐藏时，从窗口左边缘展开。窗口顶部操作按钮保持可用。默认宽度为 384px，不能超过可用内容宽度。列表独立滚动，头部和底部保持可见。

头部显示通知标题、全部已读和关闭按钮。底部保留保存 30 天的提示。再次点击铃铛、点击外部、按 Esc 或点击关闭按钮，均关闭抽屉。外部点击可以继续作用于下方控件，不设置透明的模态阻挡层。打开时将焦点移入抽屉。通过键盘关闭后，焦点返回当前可见的铃铛；侧栏布局变化后也遵守该规则。遵守系统的减少动态效果偏好。

每个主窗口只拥有一个抽屉，以及一份打开状态和指定通知状态。侧栏与顶部入口共用这份状态。`notification.open` 事件打开同一个抽屉，并显示指定记录，不重复插入记录，也不打乱时间顺序。抽屉打开期间切换布局时，只调整位置，不重置列表。打开账号菜单通过正常的外部交互关闭抽屉。

### 统一通知列表

删除全部、系统、用量和官方标签，以及对应筛选状态。请求现有分页列表时不传分类参数，继续按创建时间倒序显示。不增加替代性的分组标题或分类标签。内部分类和分类设置开关仍用于送达规则。

保留分页、加载更多、全部已读、单条关闭、加载状态、空列表、加载失败重试和目标不可用提示。仅打开抽屉不标记已读。沿用当前激活规则：内容型通知展开时标记已读；任务通知通过激活操作标记已读并跳转。关闭单条通知不能同时触发激活或展开。关闭按钮与信息放在同一区域，不单独占用贯穿条目高度的一列。

官方公告继续按原文显示为纯文本，并保留换行。折叠时显示渐隐预览，展开时在原条目显示全文，不添加第二份正文。已有的可选 HTTPS 原文链接仅在展开后显示。API 公告不拼造原文地址。版本说明继续使用 Markdown，并保留已有更新操作。备份和用量通知保留有意义的内容。

### 紧凑任务条目

智能体、助手和定时任务统一使用紧凑布局，覆盖成功批次，以及失败、取消或中断结果。此改动只作用于抽屉。应用内即时提示、操作系统通知及其送达设置保持现有展示方式。

| 条目 | 图标 | 主名称 | 结果 |
|---|---|---|---|
| 智能体 | 智能体头像 | 智能体名称 | 已完成、失败、已取消或已中断 |
| 助手 | 助手头像 | 助手名称 | 已完成、失败、已取消或已中断 |
| 定时任务 | 任务图标 | 定时任务名称 | 已完成、失败、已取消或已中断 |

只显示图标、主名称、结果和时间。每条只显示一个身份图标，不再附加通用分类图标。通过现有实体 API 读取身份；读取不到时，先使用有效的已有身份或名称快照，再回退到默认来源名称和图标。来源被删除时，条目仍需显示。不能解析展示文案来还原身份。

隐藏会话标题、回复片段、错误详情、耗时和成功批次数量。存储中的这些值保持不变，供目标页面和其他通知展示使用。长名称截断，悬停或聚焦时可查看全文。当天记录显示本地时间，较早记录显示简短本地日期和时间；悬停或聚焦时可查看完整时间戳。始终显示状态文字，不能只靠颜色区分结果。失败和中断可以使用已有错误色，但不将整张卡片染色。

点击任务条目沿用已有跳转规则：消息锚点定位到对应消息，明确的末尾目标打开末尾，锚点不存在时等待历史加载后回退到末尾。定时任务结果打开详情，并展示已保存的错误摘要。目标不存在或已删除时，提示不可用，不创建替代会话。

### 官方公告刷新

保留所有服务就绪后等待五秒的启动检查，以及每轮结束后三十分钟的检查间隔，失败轮次也遵守该间隔。应用在后台时继续检查。应用从后台切回前台时，立即检查一次。启动时首次获得焦点不算额外切换；在 Cherry Studio 内部切换窗口、标签、账号菜单或通知抽屉，也不算应用切回前台。

在主进程观察焦点，并按整个应用汇总状态。只有从没有 Cherry Studio 应用窗口获得焦点，变为某个窗口获得焦点时，才请求检查。合并内部窗口交接期间短暂的失焦和聚焦事件。不能让每个渲染窗口各自拥有轮询计时器或网络请求。

定时和前台触发共用一个请求入口。已有一轮拉取时，由该轮满足新触发，不并发，也不排队追加一轮。前台检查开始时替换待执行的定时检查。每轮结束后，重新安排三十分钟后的检查。空闲时，每次真实的后台到前台切换都可以触发检查；不增加会静默忽略切换的额外冷却时间。

关闭公告开关或停止服务时，移除焦点订阅，取消请求和计时器，并使旧会话失效。旧结果不能写入通知，也不能重新安排计时器。重新开启时，沿用已有启动调度和最近历史补入规则。

保留公开接口 `https://api.cherry-ai.com/api/announcements`、Electron `net.fetch`、`platform=desktop` 和 `getAppEdition()` 到 `global/cn` 的映射。不发送登录、签名或管理端凭证。每轮从 offset 零开始，每页 100 条，每次请求超时 15 秒，只接收最近 30 天的公告；恰好处于保留期边界的记录按过期处理。遇到已有记录不能停止分页。遇到过期记录、到达总数或返回空页时停止。事件键 `announcement:api:${JSON.stringify([id, published_at])}` 保留 `published_at` 原始字符串和小数秒；转换后的时间只用于排序和保留期。失败结束本轮，保留已保存的历史。后续轮次重试未保存记录。服务端下线不擦除本地历史。

### 复用与兼容

复用已关闭实现中的单一通知表、列表／详情／已读 API、偏好设置、SQLite 去重、调度器和导航。本方案不在该通知表之外增加数据表，不新增 DataApi 路由、依赖或企业版识别。内部通知分类和设置保留。迁移旧代码时，所需通知表迁移必须接在已核对的底座迁移之后生成，不能恢复已失效的草稿迁移编号。

保留已有任务结果契约：终态监听器执行完毕或任务最终状态提交后，才发布持久结果；保留稳定结果标识，并将消费标记与可选通知一起持久化。定时任务拥有发布权，避免流事件和任务事件重复通知。等待审批不算失败；确认的用户停止按取消处理，其他中断不能误报为成功。前台成功保持静默；已有已读状态、后台通知和声音规则保持不变。不恢复上下文容量提醒，不增加任务看板耦合、终态事件重放或崩溃恢复。

### 验证方式

设计 PR 只运行文档、翻译配对和定向格式检查。这些检查不代表产品行为已实现或已验收。每层实现运行明确指定文件的已有测试，以及覆盖本层 AC 的回归测试；再执行受影响的类型、lint、翻译检查，并在 Windows 开发窗口检查浅色和深色主题。持久化使用真实 SQLite 夹具，拉取使用可控焦点事件，抽屉内容使用本地夹具。不创建线上公告。如实报告原生平台和真实提供商验证的限制。

## 考虑过的替代方案

- 保留顶部弹出框和数字角标：仍会保留分离的入口和本设计要减少的视觉干扰。
- 使用右侧抽屉、暗色模态蒙版或挤压布局的面板：与已选择的左侧、非模态交互不符。
- 保留分类标签或改成分组：仍要求用户先选择类别，而非浏览一个有序收件箱。
- 每条保留任务摘要、错误和耗时：削弱来源与结果的重点；详情仍可在目标页面查看。
- 同时精简即时提示和系统通知：超出了仅调整抽屉的范围。
- 每个渲染窗口聚焦都拉取，或增加第二套公告缓存：造成重复管理，并削弱取消和去重保证。
- 将全部实现合成一个 PR：不符合通知中心与任务结果接线分成两层的要求。

## 验收条件

- AC1 — 完整侧栏和图标侧栏的铃铛位于头像正上方；侧栏隐藏时位于顶部头像旁边，原顶部常驻入口不再重复出现。 (verification: renderer and Windows; owner: notification center)
- AC2 — 任意正数未读量只显示圆点，零未读不显示；未读条目显示圆点和无障碍未读标签，不显示数字角标。 (verification: renderer; owner: notification center)
- AC3 — 左侧抽屉没有暗色或阻挡操作的遮罩，覆盖而非挤压聊天区域，遵守侧栏和顶部按钮边界，并在两种主题下适配窄窗口。 (verification: Windows; owner: notification center)
- AC4 — 再次点击铃铛、外部交互、关闭按钮和 Esc 均可关闭抽屉；键盘焦点返回可见入口，布局变化或 IPC 打开不会产生重复抽屉或记录。 (verification: renderer and Windows; owner: notification center)
- AC5 — 混合通知共用一个按时间倒序的列表，没有分类请求、标签或分组；分页、重试、空状态和指定记录展示保持该顺序。 (verification: renderer; owner: notification center)
- AC6 — 打开抽屉不改变已读状态；激活、全部已读和关闭保持各自独立行为，重启后仍有效，且不重复生成记录。 (verification: renderer and real SQLite; owner: notification center)
- AC7 — 公告中的 HTML／Markdown 按原文显示，保留换行和原位展开；重复展开已读记录不重复写入已读状态，版本说明保留更新行为。 (verification: renderer and Windows; owner: notification center)
- AC8 — 启动五秒后检查，每轮结束三十分钟后再检查，后台也继续；真实前台切换立即请求一次检查，内部窗口和标签切换不触发。 (verification: main with controlled scheduler/focus events; owner: notification center)
- AC9 — 重叠的定时和焦点触发共用一轮拉取；禁用、停止、重新开启和请求失败不会产生旧结果写入、重复计时器或排队的重复拉取。 (verification: main with controlled in-flight requests; owner: notification center)
- AC10 — 产品映射、分页、30 天保留期、超时、原始发布时间小数秒去重、部分写入重试和本地历史保留继续符合已有契约。 (verification: main and real SQLite; owner: notification center)
- AC11 — 智能体、助手和定时任务的抽屉条目仅显示来源图标／名称、结果和时间；长名称、缺失或删除的来源仍可使用，即时提示和系统通知展示保持不变。 (verification: renderer and Windows; owner: task results)
- AC12 — 任务激活保留消息和末尾跳转，等待历史加载，锚点缺失时回退，并提示已删除目标；定时任务详情能显示紧凑条目省略的已存错误。 (verification: renderer and main navigation tests; owner: task results)
- AC13 — 运行失败、取消和中断只根据权威最终结果发布一次；定时任务的流／任务归属避免重复，审批等待或暂停输出不能误报为成功完成。 (verification: main and real SQLite; owner: task results)
- AC14 — 已有前台静默、初始已读状态、后台送达和声音偏好继续有效；已消费的结果不会在关闭、过期或重启后重新出现。 (verification: main and real SQLite; owner: task results)

## 风险

- 修改共享 Drawer 可能影响其他界面。新的遮罩选项必须保留原有默认值；通知抽屉不仅外观无蒙版，行为上也必须是非模态。
- 侧栏悬停、布局变化和多窗口可能产生重复界面实例或误判前台切换。必须明确验证这些切换；`RuntimeActivityService` 管理阻止休眠的持有状态，不代表应用是否在前台。
- 紧凑条目减少了上下文，多个会话使用同一个智能体时尤其明显。这是明确接受的取舍；保留目标跳转和可访问的完整名称，不恢复已隐藏的摘要。
- 已关闭 PR 的测试和旧开发资料只代表历史证据。需要重新核对底座和迁移链，保留旧资料并使用隔离夹具；文档检查通过不代表实现验证通过。
