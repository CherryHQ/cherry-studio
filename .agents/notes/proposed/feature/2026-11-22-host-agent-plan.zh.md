# Agent Note: 宿主拥有的可编辑 Agent 计划

Status: proposed

[English](2026-11-22-host-agent-plan.md) | 中文

## Problem

Issue #18961 要求 Cherry 拥有可跨轮次、兼容运行时切换和重启保留的任务计划，并支持编辑待办步骤。目前已经存在计划能力：`ExitPlanModeTool` 显示原生计划文本，`TodoWriteTool` 显示列表，`agentRightPaneProjection` 从任务台账和待办快照中推导根 Agent 计划，并将派生进程单独展示。这些是有用的运行时投影，但不是统一、可编辑且带修订号的宿主计划。

持久化的可编辑副本不能静默替换原生历史，也不能承诺运行时尚未接受的执行顺序。自由格式的 ExitPlanMode 文本也不一定包含结构化步骤或依赖。

## Proposal

### 会话拥有一个计划

通过 Main 的 DataApi、服务和数据库，为每个持久化 Agent 会话保存一个活动宿主计划。内容包括目标、稳定步骤 ID、标题、依赖 ID、顺序、待办/进行中/完成/错误状态、修订号，以及仅追加的已接受变更历史。普通待办编辑不能修改已完成步骤的文本、状态和历史。更正应新增历史记录，而不是改写旧的完成证据。

在现有 Agent 状态界面展示宿主计划，并明确来源和最近更新时间。保留原生工具卡片和独立的派生任务/运行列表。宿主步骤不是后台进程、工具批准，也不能证明工作已经执行。删除会话时删除计划和历史；迁移初始为空，不虚构旧执行记录。历史只保存计划变化和来源，不复制凭据、工具输出或完整对话。

### 不靠猜测导入运行时观察

Main 适配器将已识别、校验通过的根 Agent 计划事件投影到会话计划。保留运行时种类、来源轮次/消息/工具调用身份及来源事件顺序，使重放幂等，并防止子 Agent 计划替换根计划。原始产物继续由现有对话记录保存，计划通过链接引用，不在计划表中复制。

成功的结构化 TodoWrite/任务台账事件可以提供步骤和状态。通过稳定的运行时到宿主 ID 映射匹配更新，不能靠标题或数组位置。如果运行时只提供没有稳定 ID 的整表快照，在已有宿主计划时将其作为需要审阅的替换提案；不猜测它替换哪些已完成或用户编辑过的步骤。失败、部分、取消、重复或较旧事件不能标记完成或回滚较新状态。

ExitPlanMode 文本以带来源链接的计划提案/目标展示，不从自然语言中虚构步骤或依赖。用户可明确采纳并添加待办步骤。采纳不等于批准 ExitPlanMode，不处理其批准卡片，也不启动执行。现有批准和模型交接行为，包括 PR #21080 跟踪的工作，仍然独立。

### 安全编辑待办工作

会话空闲时，允许用户修改目标、编辑/添加/删除待办步骤，并通过指针和键盘调整顺序。展示依赖阻塞，拒绝缺失引用、自依赖、环，以及将步骤放在前置条件之前的顺序。编辑器不能删除或改写已完成/进行中步骤。不从自然语言推断依赖，也不静默调整顺序。

变更携带预期修订号。Main 在同一串行变更路径内检查会话访问权和空闲状态、校验依赖图、记录变化并发布新修订。并发窗口发生冲突后需重新加载并重做意图。到达的原生提案不能覆盖用户编辑；移除或取代步骤的迟到完成事件保持可追溯，但不能复活该步骤。编辑期间开始运行应安全拒绝变更，而不是中途修改计划。

### 在轮次边界交付已接受修订

兼容适配器必须明确支持在下一次现有的用户发起轮次/恢复边界接收宿主计划。轮次准备时捕获已接受修订，通过支持的运行时输入路径交付目标及有序的可执行步骤，并记录已交付修订号。保留依赖和完成历史。不得改写运行时私有文件或伪造工具事件强制接收计划。

显示修改已保存、等待交付、已交付到指定轮次，或所选运行时不支持。交付不证明执行：只有实际关联的运行时观察才更新进度，模型轮次结束不能自动完成所有步骤。切换运行时保留宿主记录；不兼容时显示只读状态和原因，而不是丢弃记录或声称已经应用。

调整顺序意味着下一次兼容执行收到修改后的就绪步骤顺序，而不是 Cherry 可以抢占正在运行的工具或保证语言模型行为。功能完成前，集成场景必须证明兼容适配器消费了顺序，并将进度关联到正确步骤 ID。此前只能描述为存储/编辑层，不能宣称支持执行。编辑或恢复计划不会自动启动轮次、调用模型、批准工具、修改文件或购买。

## Alternatives considered

- 仅保留对话投影：保留原生历史，但无法独立编辑待办步骤或维持跨运行时身份。
- 将渲染器当前列表作为持久真相：位置型待办 ID 和最后写入者投影可能覆盖用户变更，或混淆子 Agent 与根步骤。
- 将所有计划 Markdown 解析成可执行步骤：虚构运行时未提供的依赖、身份和完成语义。
- 编辑运行时原生文件，或采纳时标记批准：绕过运行时/批准所有权，可能触发用户未启动的工作。
- 向活动轮次注入修订：与启动时冻结的输入及运行中工具产生竞争；应使用下一个支持的边界。

## Acceptance criteria

- AC1 — 带稳定步骤、依赖、状态、修订和来源历史的会话计划在重启及兼容运行时切换后保留；迁移初始为空，删除会话会清除其记录；原生对话卡片和派生任务跟踪保持完整。(verification: database, main and Electron)
- AC2 — 已识别的根 Agent 结构化事件通过稳定身份安全重放；歧义快照/自然语言成为可审阅提案，不虚构步骤、不批准工具、不替换用户/完成历史；子任务、失败、部分和过期事件不能破坏根计划。(verification: unit, main and renderer)
- AC3 — 空闲时编辑待办及指针/键盘排序可以持久化，拒绝无效图并保护进行中/完成工作；多窗口、原生更新和启动竞争安全冲突，不丢失编辑或复活步骤。(verification: database, renderer and Electron)
- AC4 — 兼容适配器在下一次用户发起边界捕获并交付已接受修订，证明遵循修改后的就绪步骤顺序并正确关联进度；不兼容切换保留计划并显示不支持交付，恢复/编辑不启动工作或处理批准。(verification: main, runtime integration and Electron)
- AC5 — 已保存/等待/已交付/不支持状态及来源可见，具备双语、无障碍键盘/焦点行为以及窄屏/明暗布局；原生工具卡片和现有进度保持正确，部分层仍保留 proposed 并声明未验证边界。(verification: renderer, docs gate and Electron)

## Risks

稳定运行时身份及宿主编辑协调是主要边界。现有投影 ID 不一定适合作为数据库身份。允许编辑导入快照前，必须证明映射和重放行为。

若将已保存与已交付、已完成混淆，宿主计划会误导用户。需明确区分，不可用仅提示词夹具宣称顺序执行。没有支持的消费契约的运行时，在执行方面必须保持只读。

计划内容属于私有会话数据。遵守现有会话访问和备份规则保存及暴露内容，保留来源，不记录完整计划文本日志。历史在会话生命周期内仅追加，但仍随会话删除。
