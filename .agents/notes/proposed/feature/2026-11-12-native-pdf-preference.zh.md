# Agent Note: 原生 PDF 路由偏好

Status: proposed

[English](2026-11-12-native-pdf-preference.md) | 中文

## 问题

Issue #22833 希望控制原生 PDF 输入与本地文本提取。现有 PR 没有实现。当前 main 在 `src/main/ai/runtime/aiSdk/params/nativeFileSupport.ts` 判断原生文件支持；能力与转换器检查仍是最终边界。本提案不声称任何供应商接受未经验证的网络载荷。

## 提案

- 供应商默认值提供三个选项：自动（现有路由）、优先原生 PDF、提取文本。单模型覆盖额外提供“继承供应商默认值”。未保存字段表示自动或继承，保持现有行为。
- 有效优先级为模型覆盖、供应商默认值、自动。通过现有供应商和模型配置所有者保存，不另建以显示名称为键的偏好存储。
- 仅当解析后的供应商、模型和转换器支持原生 PDF 时，优先原生才发送原始 PDF 字节。不支持时使用现有本地提取路径。提取文本对本次请求关闭原生 PDF。两者均不能绕过文件访问、大小限制或能力拒绝。
- 对每个实际目标（包括回退模型）分别解析有效设置，而非只检查最初选择的模型。不修改附件、不丢弃原始文件，也不把此偏好用于图像、音频或视频。
- 在模型编辑器和供应商设置中用受支持的语言展示有效选项及不支持原生时的回退说明。网络、认证和模型错误沿用正常处理；原生请求失败后不自动增加第二次计费请求。

## 已考虑的替代方案

- 仅保留自动：无需迁移和界面，但用户无法对支持原生的模型选择文本提取。
- 对所有看似兼容的端点强制原生：不采用，因为偏好不是网络支持的证据。
- 全局开关：更简单，但无法表达不同供应商和模型的要求。

## 验收标准

- AC1 — 缺省设置保持现有路由；模型覆盖优先于供应商默认值，重置恢复继承（验证：单元测试）。
- AC2 — 支持的优先原生发送原始 PDF 字节；提取文本使用本地提取；不支持的优先原生安全回退且不绕过能力或文件检查（验证：单元测试）。
- AC3 — 回退目标使用自己的有效偏好与能力；原生 API 失败不增加网络尝试（验证：集成测试）。
- AC4 — 供应商和模型控件在重启后保留，显示有效继承与回退，支持各语言的键盘和读屏操作（验证：渲染器和 Electron）。
- AC5 — 使用含布局、表格和扫描页的 PDF，在一个已验证原生目标及一个仅文本目标上测试，记录目标、端点与实际载荷，不声称普遍支持（验证：Electron）。

## 风险

- 能力元数据可能过期。优先原生仍受当前转换器支持约束，并非无限制兼容性覆盖。
- 文本提取可能丢失布局。界面应区分主动选择文本与不支持原生导致的回退。
- 这是提议中的 Spec，不是已批准行为或已完成实现。实现等待针对当前 Spec 提交的明确人工批准。
