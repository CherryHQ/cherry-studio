# Agent Note: Agent 工作目录恢复

Status: proposed

[English](2026-11-08-agent-workspace-recovery.md) | 中文

## Problem

Agent 保存了一个工作目录。当该目录在当前机器上不存在时，例如备份恢复或设备迁移后、文件夹被重命名或删除、外接硬盘断开连接时，Agent 没有原地恢复的途径：

- 技能加载可能一直停留在加载状态，且不说明工作目录缺失。
- 唯一的提示是工具提示式的警告。没有任何说明解释技能和文件工具为何无法加载，也没有让用户选择新文件夹的入口。
- 已有消息的会话无法更改工作区。数据层在发出第一条消息后锁定绑定，因此即使文件夹已经不存在，有历史记录的 Agent 也无法继续使用。

## Proposal

当 Agent 保存的工作目录不可访问时，Cherry Studio 显示恢复状态，而不是无限期加载，并允许用户将会话重新绑定到有效文件夹。

### 检测

- 打开 Agent 或加载其技能时，先检查保存的工作目录是否为可访问的目录，然后才继续常规技能加载。
- 不可访问的目录会结束加载状态，并被视为可恢复的情况，而不是无限重试的失败。

### 恢复状态

- 输入框上方的提示说明工作目录不可用，解释技能和文件工具无法加载，并显示缺失的路径。
- 提示只提供一个主要操作“选择工作目录”，用于打开文件夹选择器。
- 取消选择器会保留提示和操作入口。Agent 仍可用于其他操作，并且不会回到无限加载指示。

### 重新绑定

- 所选文件夹会注册为工作区，会话重新绑定到该工作区，即使会话已有消息。
- 只有在这种情况下才放宽消息锁定：当前用户工作区文件夹缺失，且目标是另一个用户工作区。文件夹仍存在的会话保持锁定。
- 重新绑定后，技能加载会针对新文件夹重试，提示随之消失。
- 之后重新打开该 Agent 时，使用新路径，且不再显示提示。

### 覆盖的场景

设备迁移或备份恢复、应用关闭期间文件夹被重命名或删除、外接硬盘断开。所有情况使用同一路径，因为唯一的输入是保存的路径不是可访问的目录。

## Alternatives considered

- **保留消息锁定并要求新建会话。** 已否决。这会让有历史记录的迁移 Agent 无法继续，正是所报告的问题。
- **对所有已有消息的会话放宽锁定。** 已否决。正常进行中的对话可能悄悄切换目录，并改变其工具可读取的内容。
- **只启用顶部的工作区选择器并保留工具提示。** 已否决。它不解释技能为何缺失，也没有主要操作。
- **自动回退到系统工作区等文件夹。** 已否决。它对用户隐藏了变更，并可能让工具指向无关的文件。

## Acceptance criteria

- AC1 — 当 Agent 保存的工作目录缺失或不是目录时，打开 Agent 或加载其技能会结束加载状态，并显示一条提示，其中包含不可用目录的缺失路径。（验证：renderer；负责人：Agent 聊天负责人）
- AC2 — 不可用提示提供一个主要操作，用于选择工作目录。取消文件夹选择器会保留提示、操作入口以及 Agent 的其余部分可用，且不会出现无限加载指示。（验证：renderer；负责人：Agent 聊天负责人）
- AC3 — 选择一个可访问的本地文件夹会将其注册为工作区，并将会话重新绑定到该工作区，包括已有消息的会话。（验证：main 数据服务与 renderer；负责人：Agent 会话数据负责人）
- AC4 — 只有当会话当前的用户工作区文件夹不可访问时，已有消息的会话才允许重新绑定。文件夹仍存在的会话保持消息锁定，尝试重新绑定时返回无效操作错误。（验证：main 数据服务；负责人：Agent 会话数据负责人）
- AC5 — 重新绑定后，技能加载针对新文件夹运行，并显示可用技能。（验证：renderer；负责人：技能加载负责人）
- AC6 — 重新绑定后重新打开 Agent，使用新路径且不显示不可用提示。（验证：renderer 与 Electron；负责人：Agent 聊天负责人）
- AC7 — 设备迁移、备份恢复、文件夹重命名或删除以及外接硬盘断开后，同样的提示和恢复路径都适用。（验证：Electron；负责人：Agent 聊天负责人）

## Risks

- 文件夹检查在主进程的写入事务中运行。网络或外接硬盘缓慢或挂起可能延迟重新绑定，因此检查必须保持为单次同步 stat 调用。
- 重新绑定会改变 Agent 工具可访问的范围。提示必须让新文件夹可见，且必须由用户明确选择。
- 技能加载挂起问题尚未在运行中的应用里复现。在找到原因之前，AC1 和 AC5 无法验证。
- 新字符串的翻译尚未经过审校。
