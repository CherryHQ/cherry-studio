# Agent Note: 紧凑的智能体会话详情卡片

Status: proposed

[English](2026-11-08-agent-session-details-card.md) | 中文

## 问题

智能体会话状态被注册为全高右侧面板能力。即使上下文读数不可用，也会占据整列检查面板。工具栏入口还提供独立的悬停预览，因此少量信息有两套展示，点击时又会不必要地改变会话布局。

用户指定的参考是 T3 Code 按内容高度布局的线程详情卡片：紧凑行、弱化的分组分隔线、空间充足时内嵌显示，否则使用工具栏锚定浮层。本次仅改智能体会话详情。文件、浏览器、Trace、资源和任务执行视图保留现有大面板。

这是一项新的展示决策。它保留[Harness 拥有的上下文用量](../architecture/2026-10-30-agent-context-usage.md)的数据语义，以及[将右侧面板展示状态绑定到实例](../../implemented/bug-fix/2026-10-31-right-panel-presentation-identity.md)的工作面板身份规则，不宣称完成相关提案尚未通过的验收工作。

## 提案

### 卡片与布局

用一个“会话详情”开关和一个内容归属替换“状态”入口及其悬停预览。使用 `@cherrystudio/ui` 的共享 Button、Tooltip、Popover、ScrollArea 和展开组件。遵循 `DESIGN.md` 的语义表面、排版、焦点及明暗主题规则，不复制 T3 的颜色字面量或引入第二套设计系统。

卡片目标宽度为 280 CSS 像素，外侧留出 12 像素间距，使用轻边框和容器圆角。高度随内容增长，最多占用可用高度。不保留全高背景、拖拽调宽手柄、“状态”大标题或卡片套卡片。分组使用紧凑行和分隔线；行操作保留可用的指针点击目标与键盘焦点。长标签截断后仍可查看全文。超出高度的内容在卡片内部滚动。

根据侧栏和工作面板占用后剩余的实际会话区域选择布局。当该区域能同时容纳可读的聊天列、卡片及间距时，将卡片放在工具栏下方的右边缘，并在会话布局中为其预留横向空间。消息列与输入框一起向左让位，仅在必要时缩小宽度；两者保持对齐且不与卡片重叠。关闭内嵌卡片时释放这部分空间。卡片保持内容高度，下方是空白画布，不形成全高侧栏表面。保留用户的窄版/全宽偏好，作为剩余空间内聊天列的尺寸策略；全宽聊天本身不强制切换浮层模式。

如果剩余区域无法同时容纳可读的聊天列和卡片，详情入口改用锚定开关下方、右侧对齐的非模态浮层。打开浮层时覆盖聊天，不预留横向空间，也不改变消息/输入框几何布局。两种展示均限制在可用视口高度内，超出内容内部滚动。内嵌卡片可以延伸到输入框旁边，因为两者横向边界不相交。应用窗口更宽并不代表内嵌布局一定放得下：已打开的文件或浏览器面板会减少可用会话区域。现有外壳插槽足够时直接复用，仅补充该行为需要的聊天列空间集成，保留现有工作面板尺寸规则。

### 显隐、焦点与身份

分别维护会话级的内嵌显隐意图和临时浮层显隐意图。内嵌默认显示，浮层默认关闭。展示模式由可用空间决定，不增加独立的“固定”开关。点击工具栏开关改变当前展示模式的显隐；悬停只展示提示。开关提供无障碍名称和当前展开状态。内嵌显示不抢占输入框焦点，点击其他区域也不关闭。浮层焦点、点击外部关闭及 Escape 行为使用共享 Popover 契约；键盘关闭后焦点返回开关。内嵌卡片仅在焦点位于卡片内时响应 Escape 关闭，不拦截输入框或其他面板的快捷键。

布局变窄时暂停内嵌展示，但保留其显隐意图，不自动打开浮层。下次点击开关可以明确打开浮层。空间恢复时清除临时浮层显隐状态，并恢复记住的内嵌显隐选择。如果用户曾明确隐藏内嵌详情，即使期间打开过浮层，恢复宽布局后仍保持隐藏。关闭浮层不会禁用后续的内嵌显示。切换时保留有效焦点目标，不得为了不同布局同时挂载两份实时内容。详情的开关或尺寸变化不得启动模型轮次、压缩上下文或引入新的轮询。

内嵌显隐和分组展开状态归会话身份所有。切换会话或离开智能体会话时关闭临时浮层，并清空已展开分组。返回时恢复该会话自己的内嵌选择；新会话采用默认内嵌显示，不能继承另一会话的选择或内容。通过现有渲染层会话 UI 状态在当前窗口生命周期内保留该选择；跨重启持久化不属于本次范围。缺失或等待中的会话沿用现有就绪状态契约。旧会话的延迟更新不得出现在新卡片中。不新增持久化偏好或数据库迁移。

文件和浏览器仍是独立控制的工作面板。打开或关闭这些面板时重新计算剩余会话布局，不改变其身份、状态或自动打开策略。剩余空间足够时，内嵌详情与工作面板并存；否则详情开关在缩小后的聊天区上方打开浮层。工作面板最大化时，随现有工具栏控件一起暂停内嵌详情并关闭浮层。恢复面板后，仅在空间足够且该会话内嵌选择为显示时恢复内嵌详情，绝不自动恢复浮层。

### 内容与操作

按以下顺序展示：工作目录、任务计划、Subagent（子智能体）、工作流、后台 Shell 任务、产物、现有上下文用量区域。省略空任务/产物分组及其分隔线。不为模仿截图而凭空增加设备、编辑器、Git、项目脚本或周配额行。

- 工作目录：展示当前工作区名称和截断路径，并可查看完整路径。路径可用时复用 `OpenTargetButton` 的现有目录打开操作。工作区/模型选择保留在当前归属位置，详情行不引入第二个选择器。系统工作区使用现有产品术语，路径不可用时不显示目录操作。
- 任务计划：从 `AgentRightPaneStatus.tasks` 展示当前进行中的步骤和已完成/总数，展开后显示现有有序计划。没有进行中步骤时不推测当前步骤。保留输入框现有进度胶囊及行为，两处消费同一投影。派生进程不能进入该完成比例的分母。
- Subagent：独立分组，不混入后台任务列表。紧凑标题按需报告非零的运行中、等待中和失败数量。展开后显示任务标题、当前活动和状态。先显示运行中，再显示失败，最后显示等待中；同状态内保留源顺序。已完成和已停止条目放入嵌套的“已结束”分组，默认收起。整个分组初始收起，无子智能体时隐藏。复用现有子智能体分类、任务身份和存活状态投影。不能分类且非 Shell/工作流的任务保留在“其他任务”分组，不误标为子智能体或丢弃。
- 工作流和 Shell 任务：分别使用紧凑分组，保留现有名称、活动、可用用量元数据、错误和停止操作。显示状态数量而非完成百分比。保留当前导航能力，不承诺尚不存在的任务详情目标。
- 产物：展示数量，展开后显示现有交付文件列表。打开支持的文件时复用当前预览/编辑目标及权限检查；不支持的目标保留现有回退行为。

直接复用 `AgentContextUsageSummary` 和 `ContextUsageSummary`，不改变其视觉结构：保留当前折叠标签、百分比/指示器、展开行为，以及展开后的 Token 总量、模型信息、分段条、分类表格和资源分组。不将这套 UI 替换为 T3 的单行进度条或仅显示计数的摘要。只调整容器区域间距，并移除原先多余的外层卡片边框。保留当前已支持的全部信息，并与输入框使用相同分母。缺少读数时明确标为不可用，不能当作零；真实测得的零仍是有效零值。压缩中、部分覆盖及估算读数保留现有语义。不用渲染层估算替代运行时负责的用量解释，也不把上下文占用混同于计费或订阅配额。

现有产物和任务操作继续打开原有工作面板目标。导航到目标后关闭浮层，并将焦点交给目标；内嵌卡片仅在仍能容纳时保留。停止任务不会导航或关闭卡片。任务执行视图的“返回”保留嵌套任务导航；到达根层时关闭任务工作面板并明确打开会话详情，不再请求已移除的状态能力。该返回操作属于用户打开意图，因此内嵌空间不足时允许打开浮层。

### 组件与状态方案

实现限制在智能体页面及其现有 `AgentRightPane` 集成边界内。以下职责按需要拆成本地文件，不引入通用面板框架。

- `AgentSessionDetails.tsx`：负责工具栏开关、共享的内嵌/浮层内容宿主及会话详情组合。同时只存在一份实时内容树。卡片消费智能体归属方传入的会话元数据、状态和现有操作，不新增主进程 API。
- `AgentSessionDetailsSections.tsx`：负责工作目录、计划、Subagent、工作流、Shell 和产物分组组合。复用或移动现有行/操作组件，不复制停止请求、文件打开或任务导航。资源用量明细继续留在当前共享组件中。
- `useAgentSessionDetails.ts`：负责临时浮层/展开状态，并通过现有渲染层内存缓存按会话 ID 保存内嵌显隐。缺少身份时不能写缓存项。身份变化时清除临时状态，卸载时释放订阅和尺寸观察。不维护另一套任务缓存或可变模块级会话 Map。
- `agentSessionDetailsLayout.ts`：根据测得的会话宽高执行纯布局适配/让位计算，不访问运行时或 DOM。初始使用 280px 卡片、12px 外侧边距、与聊天间的 32px 间隔及 640px 最小聊天列：可用宽度达到 976px、高度达到 160px 时允许内嵌；从浮层模式恢复时要求宽度达到 980px，避免小数宽度抖动。这些是详情专用常量，不降低或替换共享工作面板的最小宽度策略。
- `AgentChat.tsx` 集成：在现有工具栏下方，用一个可测量的详情布局包住中心内容，让消息和输入框接收同一预留宽度。布局切换过程中保持输入框/编辑器实例挂载。测量未让位的容器，而非已经加上自身内边距的子节点，并将卡片放在该容器右上角。现有工具栏插槽负责开关。保留自定义中心区域 ref、滚动、消息导航轨道和嵌入式智能体页面消费者。
- `AgentRightPane.tsx`：保留文件、浏览器、Trace、资源和执行面板注册；移除状态能力和悬停预览。为根层执行视图的返回，在现有智能体操作边界增加打开详情的回调。复用 `useAgentRightPaneStatus` 及其存活状态输入，仅在避免重复归属所必需时移动共享投影连接逻辑。

Subagent 行只有在现有执行详情能力可用且具有真实 `toolUseId` 时才能导航，否则显示不可点击的行。停止按钮独立于行导航，仅在现有运行时操作可用时提供。请求等待中禁用重复提交，运行时确认结果前保留该行的权威状态；失败时恢复控件并使用现有错误反馈。延迟的完成或停止响应始终绑定其发起时的会话/任务。

### 实施顺序

1. 建立详情布局适配/让位函数及独立的内嵌/浮层意图。用聚焦契约测试验证阈值边界、手动隐藏、缩窄/恢复、最大化/恢复及会话隔离。
2. 将内容高度的内嵌宿主和浮层接入 `AgentChat`，统一消息/输入框布局空间并保留 DOM 身份。通过真实 Electron 验证参考图的两种排列：聊天与内嵌详情，以及工作面板打开后在缩小聊天区上方显示浮层详情。
3. 用现有数据/操作组合工作目录、计划、独立 Subagent、工作流、Shell 和产物，并嵌入未改变的上下文用量组件。验证空/繁忙/失败/已结束分组、未分类任务、不可用目标及停止成功/失败，不改变运行时状态语义。
4. 迁移工具栏和根层执行视图返回的调用方，再删除旧状态能力与悬停内容。更新语言源键，同步并翻译全部语言。验证文件编辑、浏览器状态、任务导航及现有输入框消费者。
5. 执行受影响文档审查、聚焦验证及真实 Electron 验收矩阵。以证据更新本记录，仅在全部 AC 通过后将中英三件套移到 implemented。

计划覆盖的现有回归文件包括 `AgentRightPane.test.tsx`、`agentRightPaneProjection.test.ts`、`AgentChatArtifactPane.test.tsx`、`AgentChatLocate.test.tsx`、`AgentContextUsageSummary.test.tsx` 及受影响的智能体输入框测试。新增聚焦的详情布局/状态测试；仅在修改共享外壳代码时包含 `ChatAppShell.test.tsx` 和 `ConversationShell.test.tsx`。使用明确测试文件过滤，不运行整个项目套件。检查 `pnpm check --plan` 和 `pnpm docs:affected --base <verified-parent-ref>`，运行限定范围的 lint/格式检查及受影响的类型检查。Electron 覆盖明暗主题、窄版/全宽聊天、缩放、跨阈值调宽、长路径、大量子智能体/资源、浮层嵌套菜单、键盘焦点及会话切换。计划检查不是已通过的验收证据。

### 实现边界与交付

智能体页面负责卡片的会话级状态和数据订阅。仅按此边界需要从 `AgentRightPane.tsx` 提取详情展示，同时移除状态能力、旧悬停内容和失效导航路径。共享右侧面板注册表与展示 Provider 继续负责其余工作面板。复用现有用量 Hook、任务投影和操作，不构建第二套数据缓存或运行时归属。输入框和子任务的用量摘要保留现有展示。

当前 Spec 提交获得明确批准后，用一个聚焦的实现层交付卡片、集成、本地化和回归检查。渲染层测试验证开关、身份、导航和操作契约。真实 Electron 验证几何布局、焦点和滚动；组件测试或模型图截图不能证明视觉验收通过。每项验收标准都有实际证据前，本记录保持 proposed。

## 考虑过的替代方案

- 只缩小检查面板宽度或去掉边框：仍然分配全高区域，并保留两套竞争的展示方式。
- 所有宽度都只用浮层：更简单，但缺少参考中可持续显示且不干扰内容的内嵌卡片。
- 只把卡片放进已有空白且保持聊天边界不变：不符合参考中消息与输入框协调让位的行为。内嵌详情应占用布局空间，但不采用全高检查面板表面或可拖拽的额外工作面板。
- 重构所有右侧能力或复制 T3 的画布/密度系统：超出已确认范围，并给文件编辑、浏览器状态和执行导航引入风险。
- 用新的环境或配额功能填满卡片：引入没有现有数据契约的无关能力。

## 验收标准

- AC1 — 状态入口只打开新的详情表面；原全高状态面板及独立悬停预览已移除，其他工作面板目标仍可访问。 (verification: renderer — AgentRightPane 与 AgentChat 集成测试)
- AC2 — 内嵌详情预留横向布局空间，保持内容高度且下方为空白画布；消息与输入框一起调整布局，无重叠。剩余聊天区过窄时，明确打开的浮层覆盖聊天且不改变其几何布局。两种模式均适配窄版/全宽偏好，无横向溢出。 (verification: Electron — 明暗主题、聊天宽度及工作面板开关/尺寸切换矩阵)
- AC3 — 内嵌默认显示，浮层默认关闭；缩窄时暂停内嵌展示但不丢失意图、不打开浮层，变宽时恢复记住的内嵌选择并清除浮层状态，关闭浮层不改变内嵌意图。开关、点击外部和 Escape 保持规定的焦点行为，不重复挂载实时内容。 (verification: renderer and Electron — 独立显隐意图及键盘/尺寸转换)
- AC4 — 每个会话仅恢复自己的内嵌选择；新会话采用默认值，导航时清除浮层/展开状态，等待/不可用或最大化状态不会暴露陈旧内容或自动重开浮层。 (verification: renderer — 会话/就绪/最大化状态转换；Electron — 真实会话切换)
- AC5 — 工作目录操作和有序主任务计划使用现有数据；Subagent 是独立的状态计数分组，运行/失败任务优先，已结束任务初始收起。其他任务/产物分组保留条目、元数据、失败信息和停止操作；空分组消失，未知任务类型仍可见，长内容仍可访问。 (verification: renderer — 工作目录/计划/任务/产物契约及停止失败；Electron — 繁忙分组、长标签与溢出)
- AC6 — 现有上下文用量视觉结构和展开交互保持不变；用量保留有效零值、未知、压缩中、部分/估算读数、总量、分类和资源，与输入框使用同一分母，不新增模型工作或轮询。 (verification: renderer — 用量状态矩阵及受影响的输入框消费者)
- AC7 — 产物/任务导航打开原有目标，嵌套返回保持可用，根层返回打开详情，文件编辑、浏览器身份及自动打开行为保持原有契约。 (verification: renderer — AgentChatArtifactPane 及受影响的面板消费者；Electron — 目标/返回与活动文件/浏览器场景)
- AC8 — 所有变更文案已翻译，语义 UI Token 和无障碍名称在两种主题下可用，中英提案通过文档检查；生命周期转换前记录实现证据。 (verification: docs gate and Electron — 翻译/配对检查与主题下的键盘操作验证)

## 风险

可用空间取决于侧栏状态、消息宽度、导航轨道、工作面板、窗口尺寸和缩放。是否放得下应根据剩余会话区域与最小可读聊天列宽度计算，不能依据卡片自身已让位后的空白，否则测量与预留空间可能反复振荡。保持消息/输入框边界对齐，并在布局变化时保留原有滚动锚点。

任务列表和上下文资源可能很多。渐进展开和限高滚动不能隐藏待处理操作或丢失错误信息。浮层关闭必须正确处理任务操作打开的嵌套菜单与对话框。会话级展示不能重置工作区级文件状态或浏览器运行时资源。

参考中的小占地来自实际内容，而不是装饰性空白。真实 Cherry 验证场景既要展示紧凑空状态，也要覆盖繁忙会话；本 Spec 不宣称 UI 实现或 Electron 验收已经通过。
