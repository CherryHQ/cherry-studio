# Agent Note：允许在已有消息的 Agent 会话中重新绑定工作目录

Status: proposed

[English](2026-11-28-agent-session-workdir-rebind.md) | 中文

## 问题

在已经包含消息的 Agent 会话中，会话头部（窄窗口时在输入框下方）的工作目录控件点击后会在文件管理器中打开当前目录，而不是弹出目录选择器。用户无法把会话移动到其它目录，"添加新工作目录"也不可达，只能新建会话重新开始（[#22036](https://github.com/CherryHQ/cherry-studio/issues/22036)）。另一例报告从相反方向碰到同一道门：Pi 运行时的工作任务在没有选择工作目录的情况下启动，任务顶栏显示"无工作目录"，一旦有消息，选择器即被禁用。

这道门是端到端有意为之的，不是接线错误：

- 渲染端只为空会话传入工作目录变更回调（`AgentChat.tsx` 中的 `canChangeWorkspace`）。没有该回调时，`AgentConversationControls.tsx` 会把选择器替换为 `OpenTargetButton`（在文件管理器中打开）。
- 后端执行同一条规则：`PUT /agent-sessions/:sessionId/workspace` 拒绝已有消息的会话，见 `src/renderer/hooks/agent/useSession.ts` 中 `setSessionWorkspace` 的注释。
- 持久化的 DSH 会话在恢复时会因 cwd 不一致而以 JSON-RPC 错误拒绝（[#20457](https://github.com/CherryHQ/cherry-studio/issues/20457)）。仅仅放开 UI 和接口，只会把失败从选择器转移到运行时。

报告中期望的行为是：有消息的会话里该控件同样打开选择器；选择其它目录后会话随之移动；后续工具调用基于新目录解析路径。该 issue 上厂商自己的反馈回复也要求设计这个功能。

## 方案

允许在会话已有消息后重新绑定其工作目录，并给出明确语义以保证运行时边界安全。

*语义。* 重新绑定只影响未来的轮次。会话历史不可变：此前的工具输出、文件引用和路径都按当时的旧目录原样保留。重新绑定成功后，会话记录一条工作目录变更事件，携带变更前后的工作目录，使后续恢复能够区分有意的变更与损坏的恢复。下一轮同时把该变更告知模型，避免它假定变更前的路径仍然有效。

*后端。* `PUT /agent-sessions/:sessionId/workspace` 接受已有消息的会话。仅在有轮次进行中时拒绝重新绑定，原因为 `turn_in_flight`，因为在执行中途更换目录会让正在运行的轮次重新解析路径。空会话路径保持不变。

*运行时。* 每轮即时解析工作目录的运行时，在下一轮自动使用新工作目录。在构建引擎会话时绑定 cwd 的运行时（DSH 持久化会话路径）无法原地换绑：在记录了工作目录变更事件后的第一轮，它在新 cwd 下启动新的引擎会话，同时保留 Cherry 会话及其消息，而不是报 cwd 不一致错误。未记录事件的意外不一致仍然按失败关闭处理，保留 #20457 的防损坏护栏。

*交互。* 有消息的会话中，工作目录控件与空会话一样打开选择器，包括"添加新工作目录"入口。没有工作目录（系统工作区）的会话也以同样方式选择目录，覆盖 Pi 运行时的那一例。在有消息的会话上变更工作目录前需要先确认；确认文案说明后续工具调用将基于新目录解析路径，且此前输出保留原路径。轮次进行中该控件禁用，并在提示中说明原因。

## 已考虑的替代方案

- 维持限制、只改进文案：否决，因为 issue 要求的是能力本身，且厂商在该 issue 上的反馈回复也要求设计此功能。
- 换绑时分叉（把会话复制到一个绑定新目录的新会话）：保留了所有引擎不变量，但破坏会话连续性，并使会话列表翻倍混乱。可作为后续选项，不作为默认行为。
- 对所有运行时静默原地换绑、不记录事件：DSH 恢复路径会因 cwd 不一致而拒绝，且没有事件时运行时无法区分意图与损坏（#20457）。
- 只放开渲染端：后端本来就会拒绝非空会话的换绑，选择器只会在保存时以通用错误失败。

## 验收标准

- AC1 — 在有消息的会话中，工作目录控件打开选择器；选择其它用户工作区后会话换绑；下一轮的工具调用基于新目录解析路径（验证：renderer + unit）
- AC2 — 空会话保持现有选择器行为，无确认步骤（验证：unit）
- AC3 — 无工作目录且已有消息的会话可通过同一控件选择目录（验证：renderer）
- AC4 — 轮次进行中请求换绑时以原因 `turn_in_flight` 拒绝，工作目录保持不变（验证：unit）
- AC5 — 持久化 DSH 会话在记录了工作目录变更事件后恢复时，在新 cwd 下启动新的引擎会话，而不是报 cwd 不一致错误；未记录的不一致仍然失败关闭（验证：unit）
- AC6 — 对有消息的会话换绑前显示确认文案，历史中此前的工具输出保留原路径（验证：renderer）
- AC7 — 会话记录携带变更前后工作目录的变更事件，且下一轮把该变更告知模型（验证：unit）

## 风险

- 模型连续性：模型可能继续使用换绑前的路径。记录的事件与变更提示可缓解，AC7 对此验证。
- 与进行中轮次的竞争：轮次中途换绑会重新解析正在运行轮次的路径。AC4 使拒绝行为明确。
- 各运行时的采纳：每个运行时的恢复路径都必须识别记录的事件。漏掉的运行时会把失败从选择器推迟到恢复时；AC5 覆盖了 DSH 路径，其它运行时在验证时需要同样的检查。
