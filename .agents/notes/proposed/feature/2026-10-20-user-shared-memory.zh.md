# Agent Note: 桌面用户级智能体记忆

Status: proposed

[English](2026-10-20-user-shared-memory.md) | 中文

## 问题

智能体能保留各自的事实，但无法共享长期用户偏好。即使单次写入是原子的，并发替换共享 Markdown 文件仍可能丢失更新。

## 提案

用户于 2026-10-20 在任务对话中批准了先交付桌面端的实现计划。在注册的 `user.memory` 目录中，用 `USER_FACT.md` 和 `USER_JOURNAL.jsonl` 保存共享事实和事件。保留所有已有智能体文件。现有记忆工具增加默认值为 agent 的作用域及读取动作。用户事实替换必须携带内容版本，写入在唯一桌面主进程内串行执行。复用智能体配置 JSON 保存默认开启的退出开关。两个运行时分别刷新共享层和智能体层。设置页仅在用户主动请求后加载并展示共享记忆，提供 Markdown 编辑与日志浏览。身份文件写入规则允许记录用户表达的长期偏好和事实纠正，排除一次性指令与重复改写。渠道会话不能访问新增共享层。

## 考虑过的替代方案

- 新建数据库存储会重复现有文件记忆，没有必要。
- 只有锁而没有版本检查，仍然允许旧内容覆盖整份文件。
- 渠道身份和权威等级审阅暂缓，它们需要独立的产品与会话约定。

## 验收条件

- AC1 — 智能体共享用户事实但不共享各自的独立事实，省略作用域时保持旧工具行为。 (verification: unit)
- AC2 — 关闭用户记忆或使用渠道会话后，两个运行时均禁止共享注入及共享工具访问。 (verification: unit)
- AC3 — 并发旧版本更新失败且不改变当前文件；日志记录完整，界面发生冲突时保留草稿。 (verification: unit | renderer)
- AC4 — 编辑和删除会在后续轮次、会话恢复、压缩及本地心跳中刷新；两层冲突内容分别保留。 (verification: unit | Electron)
- AC5 — 初始化保留已有文件，新增共享文件可随备份恢复；分别报告平台验证范围。 (verification: unit | Electron | docs gate)

## 风险

记忆是上下文证据，不是指令权限。删除会撤销当前召回，但不会抹除历史对话或日志记录。任意外部编辑器不参与应用互斥锁。完整渠道身份隔离与推断记忆审阅不在本次交付范围内。
