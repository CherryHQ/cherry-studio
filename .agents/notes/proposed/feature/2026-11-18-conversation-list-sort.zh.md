# Agent Note: 独立的会话列表排序

Status: proposed

[English](2026-11-18-conversation-list-sort.md) | 中文

## 问题

聊天话题和 Agent 会话的行顺序由分组模式决定。时间分组按活跃时间排序，所有者和工作目录分组按 `orderKey` 排序；聊天右侧面板还有单独的手动排序例外。因此切换分组会在用户未明确选择时改变排序。集合分页始终读取手动顺序，仅对已加载行排序无法把后续页面中最近活跃的会话提到前面。

所有旧行都有 `orderKey`，包括从未拖拽过的行。没有历史拖拽标记。

## 提案

在共享会话列表菜单中，将 Sort by 子菜单放在 Group by 旁边。聊天和 Agent 各自持久化一个独立排序设置，同一类型的各会话列表共用。提供最近更新、创建日期、名称和手动排序。自动排序支持降序和升序；手动排序没有方向控件。分组继续决定区段位置和组顺序。置顶行保留独立的置顶顺序。

最近更新使用 `lastActivityAt`，重命名和排序写入不会让会话提前。自动模式禁用会话行重排；手动模式启用现有合法的组内拖拽和所有者转移。切换分组不改变已保存的排序设置。切换自动排序不会覆盖 `orderKey`。

在填充默认设置之前，分别用完整的活跃聊天和 Agent 会话表初始化缺少的排序设置。按 `orderKey ASC, id ASC` 读取行：只要 `createdAt` 出现递增，就说明当前顺序不同于默认的创建时间倒序，选择手动；否则选择最近更新降序。相同创建时间不能作为判断证据。排除已删除行、置顶行，以及 Agent 的任务和后台会话。设置存在后不再推断。这能保留当前自定义顺序，但无法识别已恢复为创建顺序的拖拽，或相关行被删除后的历史行为。

集合查询接受显式排序字段和方向。在游标分页前完成排序，保留置顶优先和 id 升序决胜规则，并把排序选择纳入渲染进程缓存键。所有会话列表使用相同的组内顺序。省略排序参数时保留现有 API 默认值，避免影响其他使用方。

名称排序共用一个 `Intl.Collator` 比较器，跟随应用语言，使用自然数字排序，忽略大小写、区分重音，并保留标点的排序意义。规范等价的名称以及数字或大小写等价项，在两个方向上都以 id 升序决胜。当前 17 种界面语言使用各自的 ICU/CLDR 规则，覆盖拉丁字母、希腊字母、西里尔字母、泰文、汉字和日文假名；标题中的其他文字也使用同一语言环境的混排规则。日文汉字不会自动转换为读音。

名称查询在查询参数和缓存键中携带经过验证的语言环境。切换应用语言会开始新的分页链。主进程只读取符合条件的未置顶 `(id, name)`，用共享比较器排序并应用名称/id 游标，再按该顺序读取当前页的完整数据。这样无需原生 SQLite ICU 扩展；其他排序继续使用 SQL 分页。置顶和所有领域筛选条件保持现有行为。

## 考虑过的替代方案

- 将所有非空 `orderKey` 当作拖拽标记：不采用，因为创建时也会分配。
- 根据 `updatedAt` 推断：不采用，因为消息和元数据也会改变它。
- 只对渲染进程已加载行排序：不采用，因为真正的首项可能在后续页面。
- 选择自动排序时改写手动键：不采用，因为切回时必须恢复自定义顺序。

- Unicode 二进制顺序：不用于名称排序，因为它不符合各语言的排序习惯。
- 增加原生 SQLite ICU 扩展：暂不采用，因为当前驱动没有 JavaScript 排序规则注册 API，原生扩展会增加各平台的构建和分发工作。

## 验收标准

- AC1 — 聊天和 Agent 菜单展示独立的分组与排序控件、当前值、四种排序模式和自动排序方向（验证：renderer 和 Electron）
- AC2 — 切换分组保留所选排序模式；活跃时间变化会影响最近更新排序，并保留手动顺序（验证：renderer）
- AC3 — 缺少的设置从完整活跃行推断手动或活跃时间排序；相同时间、空数据、排除行和重复运行遵守初始化契约（验证：main 数据库测试）
- AC4 — 各自动排序及方向都能跨置顶边界、相同值、空名称和含游标标点的名称完成确定性分页（验证：main 数据库测试）
- AC5 — 自动排序保留手动键并禁用行重排；切到手动恢复已存自定义顺序，置顶行保留置顶顺序（验证：renderer 和 Electron）

- AC6 — 名称排序在当前 17 种界面语言、混合文字标题、自然数字、重音、大小写和规范等价项中遵循应用语言规则，分页前与显示分组内使用相同顺序（验证：shared、main 数据库和 renderer 测试）
- AC7 — 切换语言开始新的本地化分页链并更新可见顺序；领域筛选、置顶、游标锚点删除和两个名称方向都保持完整分页（验证：main 数据库、renderer 和 Electron）

## 风险

旧数据推断识别的是当前顺序，而非历史操作。导入也可能产生非默认顺序，这类顺序会按手动保留。时间分组仍按活跃时间分桶，行排序作用于桶内。不改写任何已发布的结构迁移，设置初始化不修改会话行。

名称分页每次读取并排序所有匹配的名称/id：占用 O(n) 元数据，进行 O(n log n) 次比较，不加载全部会话内容。ICU 升级可能改变语言排序；切换语言时会刷新对应的分页链。
