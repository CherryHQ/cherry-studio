# Agent Note: 输入区展示 Pi Durable 后续消息队列

Status: proposed

[English](2026-11-26-pi-durable-queue.md) | 中文

## 问题

Pi Durable 会话忙碌时，后续消息进入可跨重启保留的原生队列。输入区的队列面板没有显示这些消息，用户看不到哪些消息还在等待，也无法调整顺序。

## 提案

在现有输入区队列面板中，按 Pi Durable 的实际取用顺序显示等待中的原生后续消息。原生队列变化或会话恢复时刷新面板。Pi Durable 取用或撤回消息后，面板移除对应条目。

允许用户编辑等待中的消息正文、拖动排序以及单独撤回一条消息。保留原来的提交标识和消息的其他部分。Pi Durable 串行处理队列变更和消息取用，变更结果持久化到自己的存储。编辑后的文字同时体现在模型输入和会话中。如果操作遇到消息已被取用或队列已被重新排序，刷新面板并告知用户该操作已过期。

忙碌时继续提供「排队」和「追加到当前轮」。Pi 和 Claude Code 保持现有队列行为。输入生命周期与恢复约定见 [Pi Durable 轮次权威来源](../../implemented/architecture/2026-11-18-pi-durable-turn-authority.md)。

## 考虑过的替代方案

单独使用渲染进程队列也能提供这些操作，但会延迟原生接收，渲染进程或应用退出后可能丢失等待中的消息。撤回再提交每条消息会改变原生标识，也可能与取队列交错。

## 验收标准

- AC1 — 等待中的后续消息按原生顺序显示在输入区面板中，应用重启后仍在等待的消息可以恢复显示（验证：Electron）。
- AC2 — 编辑等待中的后续消息保留提交标识，模型和会话收到编辑后的文字，重启后也一致（验证：单元测试和 Electron）。
- AC3 — 排序影响实际执行顺序，过期的编辑或排序不能更改已被取用的消息（验证：单元测试和 Electron）。
- AC4 — 撤回等待中的一条后续消息后，它不会执行，当前回复和其他排队消息继续运行（验证：单元测试和 Electron）。
- AC5 — 「排队」和「追加到当前轮」保持可用，Pi 和 Claude Code 保留现有输入区队列操作（验证：渲染组件测试）。

## 风险

锁定版本的 SDK 提供原生队列文档，尚无专用的原地编辑和排序操作。用锁定版本的 SDK 集成测试覆盖实际取用顺序。原生队列和 Cherry 会话使用不同存储，投影在取用、断开连接和重启后都需要保持一致。
