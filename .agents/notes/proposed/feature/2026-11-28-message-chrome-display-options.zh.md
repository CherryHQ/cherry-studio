# Agent Note：消息外观显示选项（头像、厂商名称、背景、时间戳）

Status: proposed

[English](2026-11-28-message-chrome-display-options.md) | 中文

## 问题

用户如果想在现有字体和消息样式选项之外调整聊天消息的外观，只能注入自定义 CSS（[#12917](https://github.com/CherryHQ/cherry-studio/issues/12917)）。这条路径对非技术用户门槛很高，而且在组件结构或类名随版本变化时会静默失效，每次更新都可能需要重新调试个人样式表。

该 issue 列出的具体显示控件在当前 main 上都没有原生设置：用户/模型头像可见性、消息头部厂商名称可见性、用户/模型消息背景可见性、用户/模型消息时间戳可见性。（issue 还要求调整思考组件和搜索组件的间距，以及开放式的未来更多选项；两者都不属于本 Spec，见替代方案。）这些控件所控制的消息外观由消息框架组件渲染（`src/renderer/components/chat/messages/frame/MessageFrame.tsx`、`MessageHeader.tsx`）。

## 方案

在 设置 > 消息设置 下新增一组"消息显示"原生开关，共七个开关：头像、背景和时间戳分别有用户侧与助手侧开关，另设一个仅适用于助手消息的厂商名称开关：

- 显示用户头像 / 显示模型头像。隐藏头像时移除其预留空间，同时保持其余头部与正文彼此对齐。作者名称等其他头部内容保留。
- 显示厂商名称。仅适用于助手消息。当前 `MessageHeader.tsx` 渲染作者/模型身份，没有单独的厂商名称前缀，因此该设置新增可选厂商标签，而不是隐藏已有前缀。默认关闭以保持当前显示。现有模型与作者标签不变；缺少厂商元数据时不显示该标签。
- 显示消息背景，用户消息和助手消息各一个开关。关闭背景后，该侧消息以纯会话背景渲染；开启时使用现有消息背景设计令牌。默认值保持所选消息样式的当前效果：保留当前用户气泡填充，助手消息仍无背景。现有消息样式选项继续控制布局，而不限制能否显示填充。
- 显示消息时间戳，用户消息和助手消息各一个开关。

每个开关都是现有显示设置状态中的一个布尔值，默认保持当前行为，包括目前不存在的厂商标签与助手背景，无需重启即时生效。实现时为全部 18 个语言区域补齐设置文案。保留现有自定义 CSS 所用的 DOM 钩子。CSS 可以覆盖填充等表现属性，但不能恢复因关闭开关而未渲染的元素。不要承诺 CSS 对可见性开关无条件优先。

## 已考虑的替代方案

- 继续只提供自定义 CSS：否决，理由即 issue 所述——门槛高，且组件重命名时会静默失效。
- 用一个"紧凑消息"总预设代替独立开关：更简单，但 issue 的需求按元素、按侧（用户/模型）相互独立，预设无法表达"只隐藏我自己的头像"。
- 把思考组件和搜索组件的间距调整纳入本 Spec：暂缓。间距是数值控件而非可见性开关，其默认值和范围需要设计输入；混在一起会拖住四组开关。
- 把 issue 第 6 条（"持续开放更多选项"）纳入范围：否决，开放式范围无法验证。新选项各自立项。

## 验收标准

- AC1 — 设置 > 消息设置 下恰有七个开关：用户侧/助手侧头像、背景和时间戳，以及仅助手侧厂商标签。初始值保持当前显示，包括不新增厂商标签或助手背景（验证：renderer）
- AC2 — 任何开关的切换立即作用于已渲染的会话，无需重启，并在重启后保持（验证：renderer）
- AC3 — 隐藏头像时移除预留空间，其余头部与正文彼此对齐，作者名称保留（验证：renderer）
- AC4 — 厂商名称开关仅控制新增的可选助手厂商标签；模型与作者标签保留，缺少元数据时不显示厂商标签（验证：renderer）
- AC5 — 背景开关独立控制每侧现有背景令牌的显示，不改变所选消息样式布局；默认值匹配当前各样式的显示（验证：renderer）
- AC6 — 全部新增设置文案在 18 个语言文件中齐备（验证：unit）

## 风险

- 设置膨胀：一组七个新开关对设置页是可见的成本。归入一个"消息显示"分组可保持页面可扫读；issue 第 6 条有意排除在外，避免无止境堆积。
- 与自定义 CSS 的交互：针对旧 DOM 的用户样式表可能覆盖开关或与开关冲突。尽可能保持 DOM 钩子稳定，并说明 CSS 表现覆盖不能恢复被可见性开关移除的元素。
- 各界面漂移：Agent 与聊天界面共用消息框架组件，开关对两者同时生效；将来如有界面分叉出自己的消息外观，必须遵守同一组设置。
