# Agent Note：消息外观显示选项（头像、厂商名称、背景、时间戳）

Status: proposed

[English](2026-11-28-message-chrome-display-options.md) | 中文

## 问题

用户如果想在现有字体和消息样式选项之外调整聊天消息的外观，只能注入自定义 CSS（[#12917](https://github.com/CherryHQ/cherry-studio/issues/12917)）。这条路径对非技术用户门槛很高，而且在组件结构或类名随版本变化时会静默失效，每次更新都可能需要重新调试个人样式表。

该 issue 列出的具体显示控件在当前 main 上都没有原生设置：用户/模型头像可见性、消息头部厂商名称可见性、用户/模型消息背景可见性、用户/模型消息时间戳可见性。（issue 还要求调整思考组件和搜索组件的间距，以及开放式的未来更多选项；两者都不属于本 Spec，见替代方案。）这些控件所控制的消息外观由消息框架组件渲染（`src/renderer/components/chat/messages/frame/MessageFrame.tsx`、`MessageHeader.tsx`）。

## 方案

在 设置 > 消息设置 下新增"消息显示"可视化预览，而不是开关列表。展示示例用户消息和助手消息，让用户直接在预览中选择显示或隐藏效果。共有七个独立显示选项：头像、背景和时间戳分别区分用户侧与助手侧，另设仅助手侧的厂商名称选项。预览控件须有无障碍标签、键盘操作及明确选中状态；隐藏元素后保留可发现的预览操作入口，便于恢复：

- 显示用户头像 / 显示模型头像。隐藏头像时移除其预留空间，同时保持其余头部与正文彼此对齐。作者名称等其他头部内容保留。
- 显示厂商名称。仅适用于助手消息。当前 `MessageHeader.tsx` 渲染作者/模型身份，没有单独的厂商名称前缀，因此该设置新增可选厂商标签，而不是隐藏已有前缀。默认关闭以保持当前显示。现有模型与作者标签不变；缺少厂商元数据时不显示该标签。
- 显示消息背景，用户消息和助手消息各一个显示选项。每个背景偏好有三种存储状态：`null` 表示跟随当前消息样式，`true` 明确显示填充，`false` 明确移除填充。schema 默认值为 `null` 而不是布尔值；切换样式不能写入背景偏好。值为 `null` 时，Plain 的两侧均无填充；Bubble 保留现有用户填充，助手侧仍无填充。已保存的 `true` 或 `false` 在切换样式和重启后继续覆盖该侧的样式默认填充。预览显示实际生效状态，并提供“使用消息样式”操作以保存 `null`。背景选择不改变布局、内边距或对齐。
- 明确开启用户填充时使用 `--chat-user`。现有令牌中没有助手消息填充，因此允许实现在共享产品令牌注册表、主题定义和变量目录中新增 `--chat-assistant`，在浅色与深色主题中均默认引用 `var(--chat-user)`。这样明确开启的助手填充沿用已有消息表面的对比度，而不是把凹陷会话底色 `--chat-message-well` 当作凸起消息表面。保留助手现有语义前景色。新令牌仅用于助手偏好明确为 `true` 的情况，不能为未设置的助手偏好新增填充。两个令牌都允许自定义 CSS 覆盖。
- 显示消息时间戳，用户消息和助手消息各一个显示选项。

头像、厂商名称和时间戳选项存为布尔值；两个背景选项按上述定义存为可空布尔值。全部选项使用现有显示设置状态，默认保持当前行为，包括目前不存在的厂商标签与助手背景，无需重启即时生效。实现时为全部 18 个语言区域补齐设置文案。保留现有自定义 CSS 所用的 DOM 钩子。CSS 可以覆盖填充等表现属性，但不能恢复因关闭开关而未渲染的元素。不要承诺 CSS 对可见性选项无条件优先。

## 已考虑的替代方案

- 继续只提供自定义 CSS：否决，理由即 issue 所述——门槛高，且组件重命名时会静默失效。
- 用一个"紧凑消息"总预设代替独立预览选项：更简单，但 issue 的需求按元素、按侧（用户/模型）相互独立，预设无法表达"只隐藏我自己的头像"。
- 把思考组件和搜索组件的间距调整纳入本 Spec：暂缓。间距是数值控件而非可见性选项，其默认值和范围需要设计输入；混在一起会拖住四组显示选项。
- 把 issue 第 6 条（"持续开放更多选项"）纳入范围：否决，开放式范围无法验证。新选项各自立项。

## 验收标准

- AC1 — 设置 > 消息设置 使用交互式消息预览而非开关列表，恰有七个独立显示选项：用户侧/助手侧头像、背景和时间戳，以及仅助手侧厂商标签。初始值保持当前显示，包括不新增厂商标签或助手背景（验证：renderer）
- AC2 — 改变预览选项立即更新示例与已渲染的会话，无需重启，并在重启后保持；支持键盘操作，隐藏元素后有可发现的恢复入口（验证：renderer）
- AC3 — 隐藏头像时移除预留空间，其余头部与正文彼此对齐，作者名称保留（验证：renderer）
- AC4 — 厂商名称选项仅控制新增的可选助手厂商标签；模型与作者标签保留，缺少元数据时不显示厂商标签（验证：renderer）
- AC5 — 背景偏好默认值为 `null`，跟随当前各样式效果：仅 Bubble 用户侧有填充，两种样式的助手侧均无填充。明确的 `true`/`false` 在切换 Plain/Bubble 和重启后继续生效；重置为 `null` 恢复继承。用户填充使用 `--chat-user`；明确开启的助手填充使用新增的 `--chat-assistant`，在两种主题中均默认引用 `var(--chat-user)`，并补齐令牌注册表与变量目录记录。验证每侧在两种样式下的三种偏好状态、不写入偏好的样式切换、重置、持久化以及布局不变（验证：renderer）
- AC6 — 全部新增设置文案在 18 个语言文件中齐备（验证：unit）

## 风险

- 设置膨胀：七个独立选项增加交互复杂度。单一消息预览配合清晰标注且可恢复的选择，让效果直接可见；issue 第 6 条有意排除在外，避免无止境堆积。
- 与自定义 CSS 的交互：针对旧 DOM 的用户样式表可能覆盖显示选项或与其冲突。尽可能保持 DOM 钩子稳定，并说明 CSS 表现覆盖不能恢复被可见性选项移除的元素。
- 各界面漂移：Agent 与聊天界面共用消息框架组件，显示选项对两者同时生效；将来如有界面分叉出自己的消息外观，必须遵守同一组设置。
