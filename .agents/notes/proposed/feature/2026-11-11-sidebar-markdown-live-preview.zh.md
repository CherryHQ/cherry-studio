# Agent Note: 右侧栏可编辑 Markdown 即时预览

Status: proposed

[English](2026-11-11-sidebar-markdown-live-preview.md) | 中文

## 问题

右侧栏使用 `StaticMarkdown` 渲染 Markdown，修改时切换到独立的源码编辑器。用户希望直接编辑渲染后的文档，通过现有文件会话保存，同时保留当前预览的排版和富内容。

[Composer 即时预览 Spec](2026-11-08-composer-markdown-live-preview.md) 明确将表格、图片、公式和任务复选框保留为源码。仅靠行内和整行装饰无法在不丢失渲染内容的情况下替换文件预览。本提案为文档编辑扩展共享即时预览能力，不会悄悄改变 Composer 现有的渲染契约。

## 提案

### 共享编辑与渲染

将保留源码的即时预览编辑器核心从 Composer 专属行为中提取到共享渲染进程组件。Composer 继续作为其令牌、建议和发送行为的适配层。文档界面没有发送操作，也不解释令牌：`${name}` 等源码文本保持字面含义。

以 Markdown 源码作为编辑依据。非编辑区域复用现有 Markdown 渲染器和共享样式，包括表格、图片、行内和块级公式、Mermaid、列表及任务复选框。不引入第二套 HTML 净化器、图表渲染器或公式渲染器。渲染必须保留引用链接、图片定义和脚注所需的文档上下文，不能将片段拆开解析而丢失定义。

进入可编辑区域时显示源码，但不改变文档；离开时恢复渲染视图。鼠标和键盘进入时，光标必须落在对应源码区域；进入渲染块时从该块源码起始位置开始。跨区域选择、撤销与重做、粘贴和输入法组合输入必须操作源码，不重建编辑器，也不提交组合输入的临时文本。渲染控件和链接保留原有操作，只有编辑手势才显示源码。渲染失败时仍可访问源码进行修正。

### 右侧栏接入

右侧栏中的可写 Markdown 文件默认打开即时预览编辑。通过侧栏模式控件保留现有源码编辑器入口。两个视图共享一个 `useFileEditSession` 草稿和保存生命周期；切换视图不从磁盘重新加载，也不丢失未保存修改。复用自动保存、手动保存、冲突处理、保存失败恢复和离开保护。渲染本身不写入磁盘，也不将会话标记为已修改。

只读文件保持不可编辑。通用 `FilePreview` 宿主对其他调用方保持只读 API。非 Markdown 文件行为不变。相对图片继续相对于文档解析，文件导航保留宿主的工作区解析方式，外部链接保留当前安全规则。Frontmatter 可以像现在一样在视觉上隐藏，但保留在源码中，并能在源码模式编辑。沿用现有文件会话的编码和换行符行为，不经过 Markdown 解析再序列化的往返转换。

### 视觉契约

以当前右侧栏预览为基线：保留内容宽度、外层内边距、字体、字号、标题层级、段落与列表间距、代码配色、表格边框、图片尺寸、公式布局和 Mermaid 样式。在浅色和深色主题下使用共享设计令牌。长表格和代码在侧栏内部滚动，不撑宽侧栏。显示源码是有意的编辑状态；周围已渲染内容必须保持样式。必要的样式变更应放在共享实现中，而不是另建一套会逐渐偏离的侧栏样式表。

### 交付

先实现共享编辑器和渲染契约，再接入文件会话与侧栏控件。在全部验收项获得证据前，本说明保持 proposed。只有当前 Spec head 获批后才能开始实现。

## 考虑过的替代方案

- 用当前 Composer 界面替换 `StaticMarkdown`：不采用，因为会丢失富内容渲染，并将聊天专属行为带入文件编辑。
- 只在右侧栏补充富内容渲染：不采用，因为共享即时预览的限制仍然存在，渲染行为也会分叉。
- 将 Markdown 转为富文本文档并在保存时序列化：不采用，因为打开文档或编辑无关文本可能重写源码格式和 frontmatter。

## 验收标准

- AC1 — 可写 Markdown 文件以可编辑即时预览打开；编辑内容在切换源码模式并切回、手动保存及重新打开文件后保持，自动保存遵循现有偏好。 (verification: renderer and Electron)
- AC2 — 表格、相对路径和引用式图片、行内及块级公式、Mermaid、列表、任务复选框、引用链接和脚注保留当前预览的渲染含义；格式错误的内容仍可访问并修正。 (verification: renderer and Electron)
- AC3 — 在窄侧栏和宽侧栏、浅色和深色主题下，相同样例保持基线排版、内边距、颜色与富内容布局，不出现整个侧栏的横向溢出。 (verification: Electron)
- AC4 — 光标进入与离开、跨区域选择、键盘导航、粘贴、撤销与重做以及中文输入法编辑保留源码，只提交预期编辑；仅查看文档不会标记修改或保存。 (verification: renderer and Electron)
- AC5 — Frontmatter、模板形式的字面文本和未改动的源码格式在编辑后保留；只读文件不可修改，保存失败、外部冲突和切换文件保留现有恢复能力与未保存修改保护。 (verification: renderer and Electron)
- AC6 — 现有 Composer 的令牌、建议、发送、代码编辑和即时预览行为保持正常；其他文件预览调用方保留只读行为及现有图片与链接安全策略。 (verification: renderer)

## 风险

渲染部件可能使内容在鼠标下移动，或打断输入法。共享核心必须保留组合输入和鼠标保护，并验证连续交互而不只是孤立渲染。每次按键都渲染整篇文档可能导致大文档性能退化；交付前应使用同一个有代表性的大文件，对比现有源码编辑器的编辑延迟和长任务，并报告测得的限制。

现有富内容渲染器依赖宿主上下文和异步资源。其挂载、待处理工作及回调必须随编辑器销毁而清理，过期渲染不能覆盖更新的草稿。文件会话继续独占持久化与冲突决策的所有权。
