# Agent Note: 分离快捷键触发条件与命令目标

Status: proposed

[English](2026-11-09-command-target-routing.md) | 中文

## 问题

组件获得焦点，不应隐式禁用所属活动 tab 或窗口的命令。反过来，可见列表也不应仅因注册了 handler 就收到删除操作。键盘触发条件与命令目标选择回答的是不同问题。

当前 main 基线 `9985917a436a82debfde647bf25a88f680415cab` 的 renderer handler 是窗口级的。尚未合并的 [#23917](https://github.com/CherryHQ/cherry-studio/pull/23917) 引入焦点作用域、显式交互边界和捕获的菜单来源。其评审修复通过 `useTabCommandRuntime` 注册 handler，恢复 Chat/智能体输入框中的数字导航，同时保留列表激活与排序保护。这恢复了行为，但仍要求各消费者自行选择注册 runtime。

本 Spec 部分接替 #23917 的注册与 handler 路由决策。其边界生命周期、可编辑目标保护、菜单来源捕获和快捷键展示契约仍是必要条件。本 Spec 基于 main 独立评审；实现时必须纳入届时可用的前置改动，而非将其删除功能复制到另一个 PR。本 PR 不包含实现。

## 提案

### 参考模型与归属

参考 VS Code 的职责分离，不将组件 handler 链描述为其架构。在 [VS Code 提交 864824b432e6fb153a3b4dfa1e0f96744ebcf6a4](https://github.com/microsoft/vscode/tree/864824b432e6fb153a3b4dfa1e0f96744ebcf6a4) 中，[ContextKeyService](https://github.com/microsoft/vscode/blob/864824b432e6fb153a3b4dfa1e0f96744ebcf6a4/src/vs/platform/contextkey/browser/contextKeyService.ts) 解析目标局部上下文并继承父值；[KeybindingResolver](https://github.com/microsoft/vscode/blob/864824b432e6fb153a3b4dfa1e0f96744ebcf6a4/src/vs/platform/keybinding/common/keybindingResolver.ts) 匹配有序规则及其 `when` 条件；[CommandService](https://github.com/microsoft/vscode/blob/864824b432e6fb153a3b4dfa1e0f96744ebcf6a4/src/vs/workbench/services/commands/common/commandService.ts) 执行已注册命令。[编辑器导航](https://github.com/microsoft/vscode/blob/864824b432e6fb153a3b4dfa1e0f96744ebcf6a4/src/vs/workbench/browser/parts/editor/editorActions.ts) 从所属服务取得活动编辑器组。局部上下文不要求所有 handler 都属于当前获得焦点的 DOM 组件。

Cherry 保留现有命令 ID、快捷键偏好和表达式求值器。Renderer 命令贡献集中声明目标语义；可变拥有者注册仍留在 renderer。现有共享 `CommandScope` 继续表示进程范围（`main`、`renderer`、`both`），不表示 UI 目标范围。Renderer 服务或可变注册表不进入 `src/shared` 或 `packages/ui`。

### 触发条件与目标选择

键盘分发读取事件所属的已注册 ContextKey 作用域，包括继承值及事件局部的可编辑/IME 状态。对于每条匹配的绑定，`when` 判断触发资格，renderer 独立检查声明目标上是否存在已启用的 handler。保留符合条件的绑定之间的既有优先顺序。拥有者缺失、禁用或有歧义时，该命令对此次事件不可用，不能借用其他拥有者的 handler。选定候选项后，若随后被拒绝，不再尝试其他绑定。仅增加一个组件作用域，不应压制 tab/窗口命令。

目标策略仅覆盖现有需要：焦点拥有者、活动 tab 拥有者和窗口拥有者。这是 Cherry 的适配，不代表 VS Code 提供这三种策略。拥有者通过共享 renderer 命令机制注册业务回调；分发器按声明策略选择，而非要求各消费者另取 runtime。分发器中不允许命令名、路由名或 Chat/智能体分支。同一命令/目标有多个符合条件的拥有者属于冲突，不通过注册顺序选举。

| 命令类别 | 键盘触发条件 | 目标 |
| --- | --- | --- |
| 永久删除 | 焦点资源符合条件，且不处于可编辑/重命名状态 | 焦点列表/分组/History 拥有者及其焦点项 |
| 会话数字导航 | 活动 tab 有可见、空闲的会话来源，且对应排序位置存在 | 活动 tab 内的会话导航拥有者 |
| 窗口命令 | 现有功能、平台及命令特定条件 | 当前窗口拥有者 |

会话导航保留现有 section 折叠过滤与分组排序、缺失位置行为、加载保护和列表激活条件。输入框获得焦点不禁用导航。目标归属来自 tab 生命周期，而非当前焦点子组件；隐藏或过渡中的 tab、未激活的面板不能提供符合条件的拥有者。目标策略不授予穿过对话框/菜单边界的权限。保留 #23917 的显式跨界策略及逻辑交互层优先级，包括 Activity 重放。

### 调用与迁移

解析出包含命令 ID、拥有者身份、handler 身份及参数的一次调用。键盘执行使用匹配后捕获的 handler；同步谓词不能重定向它。显式组件/程序调用和菜单操作保留其绑定或捕获来源，而非重定向到稍后变为活动状态的 tab。显式执行检查业务 enablement，但不应用仅限键盘的 `when`。延迟菜单结果重新检查拥有者生命周期、回调身份及业务资格，拒绝过期来源且不重新指向其他目标。

一并迁移受影响的 renderer 注册：会话数字导航、资源列表/分组/History 删除类别，以及现有窗口搜索/tab/全屏注册。检查其他命令注册是否依赖旧查找规则；仅迁移归属发生变化的消费者。在同一次实现中移除消费者侧的 `useTabCommandRuntime` 路径，以及迁移后失去用途的 API。不保留两套竞争的目标选择系统。更新命令参考文档；当 #23917 的说明已存在于实现基线时，建立相互链接，保留其独有决策依据与验证历史。

设置、快捷键提示和菜单展示继续区分已配置绑定、功能可用性、命令 enablement 与仅限键盘的条件。不改变默认快捷键、偏好存储、IPC、主进程/全局快捷键归属、删除确认或数据库保护。替换 Radix 焦点陷阱，以及修复另行观察到的嵌套 Activity 遮罩/指针恢复问题，不在本提案范围内。

## 考虑过的替代方案

- 保留消费者自行选择 runtime：维持当前修复，但在调用处重复目标选择，使较宽范围的快捷键易受组件嵌套变化影响。
- 将所有命令全局化，或为 Chat/智能体快捷键建立白名单：丢失破坏性操作的焦点目标归属，或将业务例外编码进分发器。
- 让最近组件或注册顺序决定所有命令：混淆上下文、触发条件与目标选择；兄弟输入框无法可靠访问 tab 导航。
- 复制整套 VS Code 命令基础设施：超出所需改动。复用 Cherry 的注册表、条件和偏好，采用职责分离。

## 验收标准

- AC1 — 新增嵌套焦点组件不会压制符合条件的 tab/窗口命令；重叠按键保留显式规则顺序和 `when` 行为，目标不可用时，该命令不会消费按键或对其他拥有者执行。（验证：明确列出的解析器/renderer 测试；负责人：renderer 命令系统）
- AC2 — 在真实 Chat 和智能体输入框中，数字导航仅切换活动 tab 中排序后的可见会话，并保留草稿；缺失位置、折叠 section、加载中的来源和未激活面板不会导航到非预期会话。（验证：受影响消费者测试和有界 Electron 场景；负责人：会话导航）
- AC3 — 永久删除仅解析符合条件的焦点列表/分组/History 项；输入框、重命名状态、受保护/缺失项、隐藏 tab 和多个兄弟列表均不能重定向或消费无关删除。（验证：受影响消费者测试和 Electron 焦点资源场景；负责人：资源消费者）
- AC4 — 对话框/菜单边界继续隔离背景命令、保留允许的窗口操作，并在 Activity 隐藏/恢复后维持嵌套/兄弟层的逻辑优先级；仅声明目标策略不能绕过边界。（验证：真实原语 renderer 测试和 Electron 键盘场景；负责人：renderer 命令系统/UI 适配器）
- AC5 — 键盘谓词、延迟原生菜单、焦点/tab 变化、回调替换和拥有者销毁均不能重定向已捕获调用；显式菜单/程序调用仍独立于仅限键盘的条件。（验证：命令/菜单测试和有界原生弹出菜单 Electron 场景；负责人：renderer 命令系统）
- AC6 — 设置、提示、重新绑定、平台/功能开关、IME 和窗口搜索/tab/全屏行为保留原有契约；主进程/全局快捷键归属、IPC 和持久化数据不变。（验证：明确列出的受影响 renderer/shared/UI 测试及限定范围的类型检查；负责人：命令消费者）
- AC7 — 集中目标声明与生命周期拥有者注册替代消费者自行选择 runtime；不再保留 Chat/智能体分发分支、全局 DOM 扫描、按注册顺序选举目标或旧 tab-runtime 路径，命令参考文档和双语说明准确描述实现行为。（验证：源码/改动范围检查和文档检查；负责人：renderer 命令系统/文档）

## 风险

- 在分屏或保留挂载面板中选择活动来源属于业务归属决策；不得通过挂载顺序解决来源歧义。实现必须使用现有面板可见性和 tab 过渡事实，并证明会拒绝重复拥有者。
- 若混淆绑定条件与目标激活，扩大触发范围可能拦截文本编辑或背景删除。回归检查必须独立改变焦点、活动 tab、来源可见性和业务资格。
- React Activity 和延迟原生菜单使 DOM 存在状态与拥有者生命周期分离。复用显式生命周期和调用身份；不引入第二套全局焦点/活动目标缓存。
- 本 Spec 改变尚未合并的前置改动的一部分。编码前按实际已合并或获批的实现基线协调，保留其边界保证，并取得当前 Spec 提交的批准。分别报告键盘、指针/无障碍、原生回调和实际操作系统交互证据。
