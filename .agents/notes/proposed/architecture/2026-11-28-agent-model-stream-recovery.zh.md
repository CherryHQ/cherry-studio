# Agent Note: 恢复中断的智能体模型流

Status: proposed

[English](2026-11-28-agent-model-stream-recovery.md) | 中文

## 问题

桌面 Pi 和 Pi Durable 经内部 Gateway 发出模型请求。Gateway 会在转发首个内容块之前重试临时错误。模型流在转发内容后失败时，由于桌面端关闭了原生模型重试，Pi Durable 会将生成任务记录为失败。进程退出后重新打开存储只能恢复尚未结束的任务，所以这条恢复路径无法接续应用运行时已经标为失败的生成任务。 [现有桌面重试策略](../../implemented/bug-fix/2026-11-19-subagent-retry-error-projection.md)

## 方案

### 跨模型边界保留失败信息

经受信任的对象传输报告连接失败、响应流中断、真实上游 HTTP 错误和取消。在将错误转换成提供商协议格式前，保留原始传输错误码，以及是否收到了上游 HTTP 错误。Gateway 生成的 HTTP 状态码或没有响应头的未知错误，都无法证明提供商返回了该状态，或本机已经断网。

现有调用方沿用当前 Gateway 重试策略。对启用恢复的 Pi Durable 模型调用，下表覆盖的传输失败直接交给 Harness，跳过 Gateway 对这些失败的重试预算。其他提供商错误沿用现有策略。Pi 和 Pi Durable 的绑定可以共享错误分类。本次先在 Pi Durable 启用恢复。普通 Pi 可以在其原生循环能够于进程内应用规则后接入。Claude Code 展示 SDK 上报的重试，沿用原生执行策略。

### 在原 run 内重试中断的生成

复用 Pi Durable 的生成重试 checkpoint，保留 run、已提交的输入和已提交的工具结果。部分输出作为一次中断的尝试保留，和最终答案分开，且不进入重试请求的上下文。通过同一模型路由，从已提交的上下文重新发起请求。失败尝试中未完成的工具调用不会派发。

| Harness 收到的失败                                         | 行为                                                                                                 |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 明确的断网或网络挂起传输错误                               | 持久化等待状态，按有间隔上限的退避重试同一生成，直到新请求成功、遇到适用其他策略的失败，或用户取消。 |
| 缺少明确断网证据的连接重置、响应流提前结束或上游流空闲超时 | 在 Harness 现有重试预算内重试生成。每次尝试重新分类。                                                |
| 真实 HTTP 错误、显式取消、永久传输错误或无法分类的失败     | 按原因沿用现有的 Gateway、取消或终态错误处理。                                                       |

复用当前 run 的重试状态投影，调度状态由 Harness 持有。调度器支持时，系统唤醒可以提前触发一次已经安排的网络尝试。实际收到提供商的响应才能确认恢复。取消会使等待中的尝试失效。旧尝试的调度或回调不能多发一次请求，也不能结束新的尝试。

## 考虑过的替代方案

- 在 AI SDK 重试整个流。内容已转发时，SDK 不掌握原生历史中的尝试边界，也不负责已经派发的工具。
- 唤醒后重新发送用户消息。这样会开启新轮次，并可能重复已经生效的操作。

## 验收标准

- AC1 — 提供商发出文本后提前关闭响应流，桌面 Pi Durable 通过新的模型请求，在原输入和 run 标识下完成。第二次请求排除未完成的输出，包含已提交的工具结果，已完成的工具只执行一次。 (verification: Electron, owner: Pi Durable runtime)
- AC2 — 明确断网时，反复连接失败仍保留等待中的 run。缺少断网证据的连接重置或响应提前结束消耗有限预算。HTTP 授权及 TLS 证书失败保留原有原因，不进入断网等待。 (verification: unit, owner: AI Gateway and Pi Durable runtime)
- AC3 — 取消等待中的 run 后不再发出网络请求。在等待期间退出后重新打开存储，会恢复原先等待中的生成，无需提交新的用户输入。 (verification: unit, owner: Pi Durable runtime)
- AC4 — 每个可恢复的传输失败仅消耗一次 Harness 尝试。Gateway 对其他错误的处理和 Claude Code SDK 的重试事件仍可通过各自的正常入口使用。 (verification: unit, owner: AI Gateway and Agent runtime)

## 风险

- 新请求可能产生额外的提供商用量，也可能生成不同的文本。界面上保留部分输出和中断尝试的归属。
- 缺少传输证据时应保留未知状态。将所有超时或 Gateway 生成的错误判为断网，可能让永久失败一直处于等待。
