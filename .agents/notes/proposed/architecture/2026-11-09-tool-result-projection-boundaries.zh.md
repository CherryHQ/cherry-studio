# Agent Note: 工具结果存储、投影与详情边界

Status: proposed

[English](2026-11-09-tool-result-projection-boundaries.md) | 中文

## Problem

用户需要在智能体持续流式输出时展开和关闭工具卡片。目前，完整工具结果仍参与只改变正文的处理。延迟传给 renderer 可以减少这类工作，但存储读取、结果投影、详情加载和交付订阅的边界仍不一致。

在本次检查的基线 `c9426d07704407106e23f03ee6aca9e3938df8ef` 上：

- `TopicMessageProjection.publish` 每批发布时都会重新投影累计消息。`projectToolOutputForRenderer` 会重新序列化并哈希大结果。
- `MessageProjection.flush` 先复制并深度比较整个新视图，再生成追加 patch。把这项成本移到 Main 并不等于增量发布。
- `useResolvedToolResponse` 在工具组件挂载时就启动 `useToolResult`。加载详情会暂时把显示的工具状态改成 `invoking`，读取失败则改成 `error`。
- `useToolResult` 用结果 revision 构造不可变缓存键，但 `ai.tool.get_result` 的请求不包含该 revision。因此，旧缓存键对应的请求可能读到替换后的值。
- 生产者尚未建立“完成状态即不可变”的契约。Pi 保留 preliminary 结果，现有投影和 hook 回归测试也明确支持同一消息、同一工具调用的结果替换。

本说明细化[运行时契约](2026-10-17-agent-runtime-contract.md)中的载荷和消费者边界，保留原生执行、归档所有权和有序投影交付。[PR #23873](https://github.com/CherryHQ/cherry-studio/pull/23873) 是同一栈中位于本 Spec 之上的首个存储实现层。该层的实现与验证不代表其余层已经完成。

## Proposal

### 每个调用只有一份最新结果与一个交付序号

工具调用由产品会话、消息和工具调用标识共同定位。其引用始终读取最新接纳的结果。preliminary 或替换输出直接覆盖当前值。不保留历史输出，不引入内容哈希、持久化结果 revision 或版本寻址读取。

输出所有者为最新接纳的结果创建不可变快照。在实际接纳结果时序列化该值，并生成有大小预算的预览。存储和投影复用这些产物。正文追加、折叠状态变化和重复发布不重新处理工具全文，也不重写结果行。即使原生来源原地修改对象，生产者集成也必须建立这一边界。对象身份本身不能证明内容未变。

实际结果更新会替换当前值，并使详情消费者失效，即使紧凑引用和预览比较相等也如此。快照重放可在附着或来源替换时对账一次；普通正文变化不触发对账。使用原生更新契约或结果边界上的比较抑制重复写入，不能在每次消息发布时计算哈希。不能从 `output-available` 推断内容永久不可变。

`MessageProjectionUpdate.revision` 仍是发布者及其订阅范围内连续的交付序号，用于检测重复和缺口。它不标识工具输出，也不授权存储写入。

### 现有所有者继续管理各自资源

| 所有者 | 职责 |
| --- | --- |
| 运行时适配器 | 报告原生内容和实际替换边界。不拥有 Cherry 数据库、renderer 缓存或展示预算。 |
| `AiStreamManager` 与绑定的实时投影 | 在持久化交接前持有已接纳的实时结果。查找包含捕获的产品消息和 attempt，不仅依赖可能复用的工具调用 ID。 |
| `AgentSessionMessageService` | 拥有持久化结果字节、消息中的结果引用、原子写入、全文读取和级联清理。 |
| `MessageProjection` | 发布紧凑不可变视图及受影响的 patch。拥有交付顺序，不拥有工具执行或详情存储。 |
| Renderer 详情消费者 | 拥有展开状态、详情读取状态和有上限的共享详情缓存。不把还原后的结果写入流式消息 parts。 |

实时副本和持久化副本在交接时标识同一调用。原子保存最新结果、紧凑引用及预览，替换该调用键下的旧结果。只有在持久化交接完成或明确判定不可用后才释放实时副本。归档写入失败仍是持久化失败，不能重复执行工具。关闭流程沿用现有运行时屏障，排空已接纳的写入。

首个实现层 #23873 提供独立结果表。每个消息和工具调用只存一份当前输出，不保留内容 revision 列或基于哈希的写入条件。若该列已经发布，通过生成的新追加迁移移除。针对实现基线重新生成迁移；本提案不预留该 PR 的迁移编号，也不修改其分支。保留旧内联记录的可读性，在写入时拆分，不在启动时批量回填。

对于已拆分记录，紧凑消息分页不读取结果表。完整模型上下文、恢复、分叉、诊断和明确需要全文的消费者，只在其契约需要时还原结果。存在性检查和投影内部处理不能意外选择或还原结果正文。

### 带明确用途的最新值读取

扩展现有 `ai.tool.get_result` 路由，要求读取用途。请求标识调用并读取最新接纳值，不携带预期输出 revision。同一层迁移全部调用方。请求按 `preview`、`text-range`、`full` 区分；响应按 `ready`、`pending`、`unavailable` 区分。不设输出版次不匹配或历史结果查找。

| 读取用途 | 消费者与上限 |
| --- | --- |
| `preview` | 有类型的工具展示、引用预览或活跃产物消费者。序列化响应不超过现有工具传输预算 32 KiB。图片及其他大资源使用资源引用。 |
| `text-range` | 已展开的原始结果查看器。每次响应最多包含 256 KiB UTF-8 文本和经校验的下一段游标。结果失效后丢弃已加载范围，从头重新读取。 |
| `full` | 图片导出、复制等明确的全文操作。保留原始类型值，普通卡片挂载不调用它。 |

这些上限是初始设计限制，不是实测性能结果。文本范围保留 Unicode 边界。范围读取直接读取已存序列化字节的有限片段，不先解析和格式化整个对象再截断。为模型及全文读取者保留原始类型对应的字节。

所有者校验捕获的会话、消息、调用及实时 attempt，然后读取当前值。请求在 A 存在时发起，但返回替换后的 B，符合最新值读取契约。详情视图不承诺多次请求对应同一历史快照。一旦观察到结果变化通知，就丢弃旧缓存及已加载范围，使用本地请求代次隔离已启动读取，并为活跃消费者重新读取。旧代次的迟到完成不能覆盖新的展示或缓存。

旧持久化引用按同一调用身份读取，忽略其中遗留的输出 `revision` 字段。不需要发现读取或旧版本恢复。将不可变全文结果缓存替换为在结果变化及附着时重新验证的最新值缓存。`pending` 表示已接纳的值尚未就绪供读，不能缓存为永久不存在。`unavailable` 是详情读取结果，不是工具执行失败的证据。

### 详情状态与执行状态分开

通用折叠卡片使用元数据和有大小预算的预览，不获取完整结果。仅在展开后挂载详情消费者。关闭卡片会释放详情订阅，并阻止迟到响应重新展开卡片或覆盖其内容。

工具执行状态来自已接纳的运行时 part。详情状态单独建模为 `idle`、`loading`、`ready`、`error`。加载、已失效读取、详情缺失和详情错误都不能把已成功工具改成执行中或失败。读取失败不重试执行。

明确检查现有消费者：

| 消费者 | 目标行为 |
| --- | --- |
| `useResolvedToolResponse` 与通用工具卡片 | 删除提前读取全文的入口。只为可见内容请求有大小预算的展示结果，为已展开的原始详情请求文本范围。 |
| `AgentRightPane` 子线程流程面板 | 订阅现有子线程投影。仅在面板活跃时获取依赖结果的预览字段。 |
| `useAgentPreviewUrl` | 仅在消费者活跃时解析预览资源，不还原无关工具输出。 |
| 引用、专用卡片与图片展示 | 使用有大小预算的类型化预览或资源读取器。保留来源身份与顺序。 |
| `markdownImageExport`、全文复制、模型上下文和恢复 | 使用明确的全文读取。不导出延迟标记，也不悄悄用预览代替完整输出。 |

每个 renderer 窗口保留一份详情缓存，以调用身份和读取用途或范围为键。缓存序列化载荷上限为 16 MiB，采用 LRU 淘汰。超过上限的单个值不保留。会话的最后一个消费者释放后，删除该会话的非活跃条目；关闭一个面板不能清掉另一个活跃面板的数据。取消或分离过期读取，并以会话、调用身份和本地请求代次隔离迟到完成。代次仅属于临时 renderer 状态，不持久化，也不作为结果 revision 传输。

16 MiB 上限针对保留的缓存载荷，不代表总 JS 堆或 DOM 内存。不能在此预算下再叠加一层无上限的 SWR 全文结果缓存。

在现有有序投影批次中携带定向结果变化失效通知，即使紧凑结果 part 没有其他变化也必须发送。在通知详情消费者之前应用失效。重复变化合并为最新值。持久化仅在提交后发出现有对应数据变化通知。覆盖根线程与子线程视图、重复交付，以及首次附着期间的变化。交付缺口、基线替换或来源替换时，先使相关详情缓存失效，再重新验证。未被观察的会话不能在分离期间保留缓存条目。不增加第二套结果事件日志或内容计数器。

### 增量发布与订阅

保留现有 `CherryUIMessage`、`ai.projection` 传输、附着握手和缺口恢复。结果值与发布后的 part 越过所有者边界后不可变。只替换变化路径，保留已稳定 part 的身份。在根线程和子线程生产者中先建立这一不变量，再移除保护性的整份视图复制。

根据已接纳的变化生成追加或替换 patch。普通正文发布不能复制或深度比较全部累计消息，不能序列化已稳定的工具结果，也不能重建未变化的顺序数组。实际内容替换、重排、附着和恢复仍可发布受影响的替换或新基线。

纯正文更新期间，renderer 保持结构稳定。正文消费者按消息和 part 订阅。工具消费者只订阅自己的状态及紧凑结果引用。其他已完成卡片和历史行不因另一条消息增长而更新。展开状态变化期间保留独立子线程所有权和现有滚动运行时。

### 交付顺序与验证所有者

1. #23873 中的存储与已接纳结果。集成存储修复，将最新结果写入、序列化和预览集中到实际变化边界。Main 数据与运行时维护者验证紧凑分页、已有数据迁移、交接和替换行为。
2. 最新值读取与有上限的详情状态。同一层迁移全部路由调用方，并删除提前读取全文的入口。IPC 与 renderer 维护者验证失效、迟到响应、展开关闭、专用预览、导出和缓存释放。
3. 增量发布与订阅。一起修改根线程、子线程生产者及受影响的 renderer 订阅。运行时与 renderer 维护者验证交付缺口、来源替换、消费者稳定性和滚动所有权。
4. Electron 验收与最终文档。实现所有者记录实际交互轨迹、定向检查、剩余平台缺口及 AC 证据。只有这一最终层将双语说明移动到 implemented。

实现 PR 堆叠在获批 Spec 上，并列出各自 AC 覆盖。每层均可独立评审。使用明确受影响文件路径运行测试，执行定向 lint、格式检查和 `docs:affected`；更广检查交由 CI。不能用渲染次数或模拟耗时测试声称获得实测性能提升。

## Alternatives considered

- 为旧输出引用保留历史结果或内容 revision。拒绝，因为全部消费者需要的是最新值或明确的全文读取，而非过去的结果。同调用结果替换需要缓存失效，不需要版本寻址存储。
- 增加结果计数器、内容哈希或新输出 ID 来使缓存失效。拒绝，因为现有有序投影交付可以携带定向失效，不需要另一套持久化身份。
- 每次投影都哈希完整结果，或通过更多 memoization 将全文保留在 renderer 消息中。拒绝，因为未变化内容仍产生复制、序列化或比较成本。
- 增加 DataApi 超时，或始终先还原全文再截断预览。拒绝，因为两者都不能约束同步工作量。
- 采用 T3 的整套事件日志和 turn-item 存储模型。拒绝，因为 Cherry 已拥有运行时投影、patch 交付和历史。本提案采用更小的边界。
- 在新契约旁保留旧内部读取 API。拒绝，因为进程内调用方可以一起迁移。需要兼容的是持久化记录，不是已被替代的 renderer API。

## Acceptance criteria

- AC1 — 接纳大结果后，纯正文追加和重复发布不再序列化、哈希或提取该未变结果的预览；变化的 preliminary 或替换结果覆盖同一当前结果行，不生成持久化或 wire 输出 revision。(verification: unit; Main runtime owner)
- AC2 — 已拆分消息分页和存在性检查不读取完整结果正文，已有旧数据库可前向迁移，全文读取输出不变，并随消息级联删除结果。(verification: unit with setupTestDatabase; Main data owner)
- AC3 — 结果变化失效后，旧在途响应不能覆盖当前缓存或展示，活跃消费者读取最新结果，已加载范围从头重新读取；待就绪、旧格式、移除及不可用引用遵守最新值契约，不查找历史结果。(verification: unit and renderer; IPC owner)
- AC4 — 折叠的通用卡片不发详情请求；展开只读取自身结果，关闭会分离消费者，详情加载或失败保留运行时执行状态。(verification: renderer; tool presentation owner)
- AC5 — 预览和文本范围响应遵守 32 KiB 与 256 KiB 上限，保留 Unicode 和资源引用，且提供文本范围前不完整解析已存的大结果。(verification: unit and renderer; Main data and IPC owners)
- AC6 — 详情缓存载荷不超过 16 MiB，过期响应不能恢复已关闭消费者，会话最后一个消费者释放后删除非活跃条目且不清除其他活跃消费者。(verification: renderer; cache owner)
- AC7 — 引用身份及编号、专用卡片、活跃子线程面板、预览资源、图片导出、全文复制、模型上下文、恢复和分叉保留各自的完整内容或有限预览契约。(verification: focused unit and renderer tests plus Electron scenarios; affected consumer owners)
- AC8 — 纯正文发布使用受影响 patch 和稳定列表结构，不进行整份视图复制或深度比较；根线程及子线程的附着、重复交付、缺口、替换、关闭和持久化失败保留现有契约。(verification: unit and renderer; projection owners)
- AC9 — 持续流式输出期间，对 256 KiB、2 MiB、16 MiB 已稳定结果夹具分别执行二十次展开关闭，输入到展开状态可见的延迟 p95 不超过 100 ms，且没有可归因于重复处理该未变结果的至少 50 ms renderer 任务；记录硬件、构建、负载、Main 与 renderer 轨迹，以及一次单独的真实智能体运行。(verification: Electron; implementation owner)
- AC10 — 全部内部结果读取消费者采用明确用途契约，删除提前读取全文的旧入口及输出 revision 缓存键，两种语言文档描述最终已验证行为，不把夹具或组件测试当作完整系统验收。(verification: source audit and docs gate; implementation owner)

## Risks

- 原生生产者可能修改或替换看似已完成的值。接纳边界必须先证明不可变，才能移除复制。不能从终态显示或 WeakMap 键推断该属性。
- 有上限的详情缓存不能让任意大的全文操作成本变低。明确的全文读取仍可能分配大对象；若影响响应，需要单独分析。
- 旧内联记录在重写前仍需解析。不读取结果表的保证针对已拆分记录；本提案不隐藏兼容性成本。
- 初始响应和缓存限制可能影响大型结构化展示。必要消费者若失败，需要明确的类型化预览或资源读取器，不能使用无上限的通用绕过路径。
- #23873 在实现前可能变化，Main 也已有更新迁移编号。需对齐其实际合入契约并重新生成迁移，不能复制已有编号的迁移。
- 最新值范围读取不是历史快照。结果失效会重置查看器；通知顺序、附着、缺口恢复和迟到响应隔离需要明确的回归覆盖。
- Electron 延迟指标是拟议验收目标。本提案尚未测得性能轨迹或提升幅度。
