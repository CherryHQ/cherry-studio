# Agent Note: Harness 拥有的上下文用量

Status: proposed

[English](2026-10-30-agent-context-usage.md) | 中文

## 问题

桌面上下文面板目前消费 `AgentSessionContextUsage`，这是按 Claude 原生响应形状定义的宿主类型。Claude 通过 `handle.claude.contextUsage()` 暴露 SDK 响应，Pi 通过 `handle.pi.contextUsage()` 暴露不同的原生读数，Durable 则没有对应接口。Renderer 识别英文分类名、解释延迟加载工具，并处理模型窗口差异。因此，外观统一的 UI 并不意味着 harness 具有统一能力。

本提案部分替代[运行时契约](2026-10-17-agent-runtime-contract.md)中“上下文用量保留在 Pi 专属 facet”的约定。原生执行、输入、历史、计费和压缩的归属不变。本提案扩展公共观察边界，不将上下文管理策略移入 Renderer 或 `agent-behavior`。

## 提案

### 公共边界与归属

`@cherrystudio/agent-runtime` 拥有上下文用量类型，以及 `ThreadHandle` 上必需的读取操作：

```typescript
contextUsage(): Promise<OperationResult<ThreadContextUsage>>
```

每个具体 runtime 都实现该操作。它是被动读取：不提交输入、不运行工具、不压缩历史、不恢复 Durable 调度器，也不发起收费的模型请求。已释放的 handle 返回 `rejected`；原生访问不支持时返回 `unsupported`，包括原生 API 无法检查的子线程。暂时无法获得测量结果返回 `unknown`，不能返回零用量。沿用现有 `OperationResult` 的状态语义。

适配器将原生数据转换为公共契约。Main 配置 runtime 时提供解析后的模型容量和资源来源，随后负责产品会话关联、缓存和刷新协调。Main 不得根据模型名称前缀猜测并覆盖返回的分母。Renderer 只翻译公共分类键、格式化数值和渲染资源列表；不导入原生 SDK 类型，也不按原生英文名称分类。

`agent-behavior` 继续负责压缩、goal 等决策，不拥有这项只读展示能力，也不从上下文占用推导货币费用。

### 读数语义

| 字段 | 契约 |
|---|---|
| 模型身份与上下文版本 | 标识读数对应的模型和原生上下文边界。模型配置或选定上下文变化时，适配器的不透明版本标识随之变化。宿主连接代次另行隔离已替换的访问。 |
| 完整上下文窗口 | 应用原生能力限制之后、扣除输出或压缩预留之前的可用模型窗口。宿主目录中的容量不能单方面扩大原生套餐限制。 |
| 输入上限与压缩阈值 | 独立的可选限制，不是完整窗口的别名，也不一定是可相加的预留量。 |
| 已用 token | 当前占用，标记 `reported` 或 `estimated` 来源，以及当前上下文或最后一次模型请求的计量基准。未知的当前值保持缺失。跨轮次调用 token 总和不代表占用。 |
| 预留和空闲 token | 使用相同完整窗口单位的可选分配事实。只有已知且互不重叠的预留可以相加。仅在所需分配事实完整时推导空闲量；缺失的预留不等于零。 |
| 分类 | 稳定的公共键、token 数、来源，以及 `included` 或 `deferred` 占用类型。缺失明细表示不可用；支持明细但列表为空表示没有条目。部分覆盖必须显式标明。 |
| 资源 | 原生资源身份、分类、显示名称、来源、可选 token 数和可选已加载/延迟加载状态。未知信息保持缺失。资源列表解释分类，不能再次累加到总量。 |

公共分类覆盖消息、系统提示词、系统工具、MCP 工具、MCP 指令、记忆文件、技能和自定义智能体。`other` 分类为扩展保留适配器提供的稳定 ID 和标签。缓冲区和空闲空间属于分配字段，不是消息或工具消耗分类。延迟加载 schema 没有窗口占比，也不进入占用条。

报告的总量可以与估算分类并存。适配器标明来源和覆盖程度，不能通过虚构剩余分类或按比例缩放，强行让它们加总相等。只有完整分类共享同一计量基准时，其和才必须等于已用总量。所有显示百分比使用同一读数返回的完整窗口。

### 适配器实现

| Runtime | 实现边界 |
|---|---|
| Claude Code | 在 `agent-runtime-claude-code` 内归一化 `Query.getContextUsage()`，映射原生稳定 ID/kind 和资源列表；原生名称兼容仅留在该适配器。显式解析声明的网关容量与原生套餐限制。已观测到网关 `maxTokens` 和 `rawMaxTokens` 都可能是缩减预算，不能无条件将其中任意一个作为完整窗口。 |
| Pi | 使用 `AgentSession.getContextUsage()` 获取原生占用估算和模型窗口。额外分类只从原生实际准备的系统提示词、活跃工具 schema 和投影后的上下文推导，并复用原生估算能力。保留 loader 的资源来源。如果公共 API 未暴露一致的已准备上下文，应补上游读取接口，而非在 Main 重建。 |
| Pi Durable | 在生成和阈值压缩使用的上下文准备边界增加被动原生读数，复用选定上下文范围、已解析模型、工具过滤/加载及 `estimateContext` 语义。通过 Durable 公共 API 暴露，在 `agent-runtime-pi-durable` 内归一化；不得深导入依赖私有路径或在 Cherry 重写生成流程。 |

Pi 当前原生实现可能在压缩之后、下一次响应之前返回未知占用，应保留这个合法状态。Durable 内部已经为压缩估算上下文；缺少公共读取 API 是上游能力缺口，不能据此将 Durable 永久排除在公共契约之外。必要的固定版本依赖补丁仅限于该原生读取接口，并须有上游层测试。

### 刷新、隔离与迁移

读数属于被访问的线程，也包括受支持的子线程，不能借用父线程读数。适配器为每次读取捕获一致的上下文版本；原生来源无法建立该版本时，返回不可用或明确过期的结果，不能拼接不同状态。Main 拒绝来自已替换连接、模型或选定分支的迟到读取结果。

在连接建立、模型输出完成、工具/资源配置变化、成功或无操作压缩、原生重置和分支选择时刷新。现有原生实时读数也必须经过适配器归一化。实时投递使用现有观察流中的 `context.changed` 事件承载同一操作结果，线程快照包含最新上下文读数，不得建立第二个订阅所有者。重复读取相同内容不发布新变化。

压缩、重置或模型切换后立即使旧计数失效。临时刷新失败时，只能为同一上下文版本保留明确标为过期的上次读数，不能静默沿用前一个模型的值。单飞刷新和尾随刷新必须保留最终当前读数，且不产生轮询循环。

以公共契约替换宿主 DTO 和原生 facet 用量路径。将 Renderer 的原生分类归一化移入 Claude 适配器，将分母解析移入已配置的 runtime，同时迁移输入框和状态面板。不需要改写已持久化的计费数据或新增 SQLite 迁移。保留此前实现的资源 UI，但改为消费中立资源和分类键。

### 交付与验证

本 Spec 是现有桌面集成之上的后续层。批准后先交付公共契约、三个适配器及原生依赖改动，再迁移桌面消费者。保留现有栈基底和 PR 状态。只要某个 runtime 的根读数仍只是返回不支持的占位实现，就不能宣称整体验收完成。

三个适配器测试套件使用真实原生循环和确定性模型端点。同一契约矩阵覆盖分母一致、未知/估算数据、延迟加载资源、被动读取、子线程隔离、压缩、fork/rewind、模型切换、释放和重开。缺失读取能力在哪个原生包实现，就在哪个包测试。Renderer 测试使用同一中立 fixture 形状，不选择 runtime。最后在 Electron 中验证真实根/子面板、实时刷新和读取不新增计费。

## 已考虑的替代方案

- 保留 Claude 形状的宿主 DTO，在 Renderer 增加 runtime 分支：拒绝，因为原生解释和能力缺失仍未回到其所有者。
- 累加可见消息 token 或调用账本记录：拒绝，因为展示历史、请求时上下文和累计收费使用量并不等价。
- 所有不支持的测量都返回空分类或零：拒绝，因为不可用与测得为空具有不同的用户含义。
- 在公共包构建通用 tokenizer 或新的上下文管理器：拒绝，因为原生准备、多模态计量和压缩已经拥有这些决策。
- 新增独立上下文用量事件总线：拒绝，因为线程访问和观察已经定义了身份与生命周期。

## 验收标准

- AC1 — 三个适配器均暴露同一个必需的被动上下文用量操作；缺失、已释放和不支持的子线程访问返回明确结果，且不执行模型或工具。 (verification: unit — 真实适配器上的公共契约矩阵)
- AC2 — Claude 原生、Claude 网关和 Pi 模型读数区分完整窗口、输入上限与压缩阈值；输入框和明细使用同一分母，包括已观测到的 854560 预算/1000000 窗口网关情况。 (verification: unit — 适配器 fixture 和 Renderer 集成)
- AC3 — Pi 和 Durable 从原生上下文准备过程提供真实根读数；估算值与压缩后未知值可区分，根实现不能无条件返回不支持。 (verification: unit — 原生包及适配器集成)
- AC4 — 已包含、延迟加载、预留和空闲 token 不重复计数；部分明细和未知分配事实保持明确，资源列表保留身份、来源与加载状态。 (verification: unit — 原生 fixture 和公共语义矩阵)
- AC5 — 子线程读数保持线程隔离；压缩、重置、fork/rewind 和模型切换使旧读数失效，替换连接的迟到读数不能覆盖当前状态。 (verification: unit — 原生状态转换与宿主竞争测试)
- AC6 — Main 和 Renderer 不含原生分类名匹配、SDK 响应类型或按 runtime 猜测分母的逻辑；现有实时和轮后路径使用同一中立契约。 (verification: unit — 消费者集成与源码边界检查)
- AC7 — 重复读取未变化的数据不会形成事件反馈循环、启动原生执行或增加计费记录；关闭/重开保持原生归属并释放观察者。 (verification: unit — 真实适配器生命周期与账本集成)
- AC8 — 实际 Pi、Durable 和 Claude 会话在输入框与状态面板一致展示受支持的分类/资源及明确未知状态，覆盖窄布局和明暗主题。 (verification: Electron — 各 runtime 根/子线程及状态转换矩阵)

## 风险

原生 API 可测量的内容不同，尤其是资源归属、多模态 token 和子线程控制。统一接口无法制造相同精度。原生准备可能包含宿主资源配置中没有的注入或过滤内容；只有观察到实际纳入上下文，才能为分类计数。

上游读取必须保持被动，不能在持有写事务时执行昂贵估算。长历史需要复用原生版本状态，不能重复全量扫描。容量限制和重叠预留策略需要明确原生证据。展示文件名与工具来源遵循现有授权会话边界，本改动不授予文件系统访问权。
