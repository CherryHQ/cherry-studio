# Agent Note: 先绑定会话 runtime，再将智能体统一为 Pi Durable

Status: proposed

[English](2026-11-12-session-runtime-binding.md) | 中文

## 问题

智能体会话目前通过可变的智能体 `type` 选择执行驱动。将所有智能体改为 `pi-durable` 会让旧 Pi 和 Claude Code 历史进入另一种引擎。用户要求旧历史保留原生续聊能力，全新会话使用 Pi Durable，智能体创建和编辑表单不再展示 runtime。

本次检查的基线是 `bc215da7204393c838b92bd19a4cfad20ec7d78d`。`AgentChatContextProvider`、`AgentSessionRuntimeService` 和 `AgentSessionForkOperations` 都通过智能体选择驱动。`agent_session` 没有 runtime 字段，但已有上下文引用的 backend 在 locator 中记录了类型。并非所有旧会话或空会话都已建立上下文。创建向导已默认使用 Pi Durable 并隐藏 runtime；编辑器仍展示 runtime 摘要。

本提案补充 [runtime 契约](2026-10-17-agent-runtime-contract.md)和[历史操作边界](2026-11-08-agent-history-operation-boundaries.md)，不替代原生 backend 身份，也不授权删除旧驱动。

## 提案

### 先持久化会话归属，再修改智能体

在会话 schema 和共享会话实体中增加持久化的 `runtimeType`。该字段分配后不可修改，表达执行归属，不是用户可编辑的设置。已有 backend locator 仍是原生存储身份的权威来源，必须与会话归属一致。不得仅为记录 runtime 而制造原生上下文。

追加新的 schema migration，并在会话可以执行前完成有序、事务化的数据升级。先绑定所有已有会话，再归一化任何智能体类型。有上下文／backend 证据时据此确定会话 runtime，否则使用升级前的智能体类型。保留已知的待处理退役 runtime 转换及其目标归属，不重新解释旧 resume token。检查现有退役 runtime 和上下文 seeder，将本次升级安排在建立其归属的迁移之后。

纳入软删除记录，确保恢复不会改变引擎。重试时保留已记录的绑定。缺少足够证据的未知、冲突或孤立历史保持未解析且不可执行，绝不猜测为 Pi Durable。使用显式未解析状态，不能通过 schema 默认值悄悄给旧行标记类型。未解析会话不得阻止其他有效会话升级。不转换或丢弃任何转录、原生存储、checkpoint、resume token 或附件。

捕获绑定后，在同一事务化升级中将已有智能体归一化为 `pi-durable`。保留 ID、模型选择、指令和配置。新建、复制、导入、内置 seeding 和更新智能体都必须在数据所有者处统一到 Pi Durable，不能只在向导中限制。备份恢复和旧数据导入必须先绑定会话，再归一化其智能体，并保留显式绑定。已有智能体配置继续提供模型和工具；runtime 能力按会话引擎解释。

### 按会话路由执行和展示

全新会话使用 Pi Durable，包括任务／频道创建的会话。复用旧会话时保留其原 runtime。分叉、编辑重发分支和子上下文继承来源的执行归属；它们属于历史续接，不属于全新会话。绑定必须与会话分配一起提交，包括无界面入口。

派发、连接预热、恢复、历史操作、分叉发布校验、诊断访问和 runtime 清理都从会话归属解析驱动。渲染器的会话能力消费者也必须根据同一归属确定命令、权限和历史操作。继续读取共享智能体设置，但不得用升级后的智能体类型覆盖会话执行。backend 与会话不一致时明确失败，不能打开另一份存储。删除智能体后，不为孤立会话虚构替代配置。

保留 Pi 和 Claude Code adapter，支持旧会话及其原生历史操作。全新主智能体会话的产品开发可以集中在 Pi Durable，但旧引擎的兼容修复和依赖仍需维护。本改动不宣称应用只剩一个 runtime。

### 移除表单 runtime 展示

创建表单继续不显示 runtime，删除编辑器的 runtime 摘要和提示。仅当本改动使展示辅助组件不再被使用时才删除它们。保留表单其他部分和设置，不增加替代的 runtime 标签或选择器。即使所属智能体已变为 `pi-durable`，会话控件仍应反映实际引擎。

## 考虑过的替代方案

- 只修改智能体类型：拒绝，因为派发会为已有历史选择错误引擎。
- 只根据上下文／backend 行推导归属：无法覆盖空会话和未记录上下文的历史；保留原生证据，同时增加显式会话归属。
- 将所有原生历史转换为 Durable：拒绝，因为产品消息投影不包含原生 checkpoint、任务图或恢复状态。
- 将旧历史改为只读：用户已明确选择原生续聊，因此拒绝。
- 保留全部 runtime 配置展示：数据所有者强制 Pi Durable 后，全新会话不再需要这些展示。

## 验收条件

- AC1 — 对有数据的数据库升级时，先保留 Pi、Claude Code 和 Durable 会话归属，再将所有已有智能体改为 Pi Durable，包括软删除行；重跑或中断升级不能覆盖归属或只归一化部分智能体。 (verification: 实现者，真实 SQLite 向前迁移及事务／重试测试)
- AC2 — 空旧会话从升级前的智能体绑定；已有 backend 证据和待处理退役 runtime 转换的归属保留；冲突或未知孤立历史仍可阅读，但不能通过猜测引擎执行。 (verification: 实现者，真实 SQLite 迁移及会话路由测试)
- AC3 — 全新交互、任务和频道会话通过 Pi Durable 执行；旧会话复用、分叉、编辑重发和子操作在智能体归一化及进程重开后仍保留原引擎和原生身份。 (verification: 实现者，受影响 Main 契约测试及各引擎隔离 Electron 续聊)
- AC4 — 派发、预热、恢复、诊断、清理及渲染器能力控件与会话归属一致；原生 backend 冲突时拒绝执行，不创建或替换存储。 (verification: 实现者，定向 Main 和渲染器契约测试)
- AC5 — 创建、编辑、复制、导入和重新 seeding 智能体均不能重新引入其他智能体类型；创建及编辑表单均不展示 runtime 选择器、摘要或提示。 (verification: 实现者，数据所有者测试及真实组件表单测试，加隔离 Electron 检查)
- AC6 — 备份导出／恢复和支持的旧数据导入保留消息、附件、原生身份及 runtime 绑定；旧会话仍可续聊，全新会话使用 Durable。 (verification: 实现者，有数据的数据库导入测试及隔离 Electron 备份往返)

## 风险

旧 adapter 及其依赖仍不可移除。共享智能体设置可能有引擎特定的解释，隐藏 runtime 不能隐藏旧会话必需的能力。导入、恢复、分叉和后台会话分配是不同写入路径，均不得绕过绑定。已有待处理退役 runtime 转换必须明确排在智能体归一化之前。除定向测试外，还需要真实提供商续聊和备份证据；本 Spec 仅包含源码检查，不包含实现验收证据。
