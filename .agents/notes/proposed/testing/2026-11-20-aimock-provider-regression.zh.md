# Agent Note: 用 AIMock 扩展供应商协议回归

Status: proposed

[English](2026-11-20-aimock-provider-regression.md) | 中文

## 问题

[桌面回归控制器](../../../../scripts/e2e/regression/README.md) 使用共享的严格模式 AIMock worker 提供模型夹具。部分故障场景使用用例独占的 HTTP 服务。[流式失败用例](../../../../tests/e2e/regression/README.md#local-streaming-failure-regression) 验证了 OpenAI 兼容聊天响应中断后的持久化。其他供应商适配器遇到流中断时的表现，以及 AIMock 能否以同等时序精度复现该中断，仍待验证。

## 提案

以现有控制器和用例 ID 为基线。先在托管 macOS 和 Windows 上运行流中断用例 C-03 和手动重试用例 MP-17。记录应用 SHA、各用例结果与耗时，以及供应商或夹具来源。

使用用例独占的 AIMock 实例复现确定性故障。共享 worker 当前将所有 HTTP 400 及以上的状态视为意外请求。独占实例必须核对预期失败的请求与后续请求，拒绝意外请求，并随用例清理关闭。结构化夹具能表达契约时优先使用它，涉及供应商特有报文时使用原始事件。若用例需要在观察到指定 UI 状态后才能断开连接，而 AIMock 无法提供同等控制，则保留用例独占的 HTTP 服务。

先通过现有桌面 UI 和供应商选择，测试 Chat Completions 与 Claude Messages。前两种协议通过后，为 Responses 和 Gemini 各新增一条成功场景和一条协议特有的边界场景。随后覆盖多轮 MCP 和智能体运行时，再补充有针对性的知识库、翻译和图片场景。只选取能验证不同产品行为的供应商和场景组合。

沿用现有托管回归工作流和阶段顺序。两平台使用聚焦任务验收，在现有证据中记录协议、场景、夹具版本和观察结果。模拟回归验证应用对预设输入的处理。真实供应商检查继续用于验证当前上游兼容性。

## 考虑过的替代方案

- 一次替换所有本地夹具服务。这会在确认时序和产品断言等效之前，就丢失部分用例所需的控制。
- 每个场景都运行全部供应商。相同产品路径处理响应时，大量重复组合会增加托管运行时间，只能补充少量证据。

## 验收标准

- AC1 — 托管基线证据列明准确的应用版本、两个平台以及 C-03 和 MP-17 各自的结果与耗时。 (verification: 托管回归报告; owner: E2E 工作流维护者)
- AC2 — OpenAI 兼容聊天与 Claude Messages 在断流后保留部分文本，持久化错误状态且重启后仍可读，并能完成新一轮对话。 (verification: macOS 和 Windows 托管桌面 E2E; owner: 聊天维护者)
- AC3 — 用户停止后，迟到内容不会显示或持久化。预设限流后手动重试只产生一条完成的回复。意外请求会独立于预期故障使场景失败。 (verification: 托管桌面 E2E 和聚焦控制器测试; owner: 聊天和 E2E 维护者)
- AC4 — Responses 和 Gemini 通过产品配置走各自的实际报文协议，验证一条持久化的成功回复，并断言用量、目录或错误处理等已执行的协议特有边界。 (verification: 托管桌面 E2E; owner: 供应商维护者)
- AC5 — 预设工具轮次使用真实工具结果，工具拒绝或失败如实显示，取消后不再执行工具。重新打开对话后仍可看到工具结果。 (verification: 托管 MCP 和智能体桌面 E2E; owner: 智能体运行时维护者)
- AC6 — 知识库、翻译和图片的针对性场景分别验证真实检索引用、持久化的翻译历史或用量，以及图片显示与保存或可见的生成失败。 (verification: 托管桌面 E2E; owner: 各功能维护者)

## 风险

固定延时可能在较慢的 runner 上先于部分文本显示而到期。必要时根据可观察事件触发断流。夹具漂移可能掩盖线上供应商变化，因此保留真实供应商检查。明确记录失败和缺失的平台证据。夹具使用合成对话内容，并沿用现有报告脱敏。
