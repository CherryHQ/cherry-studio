# Agent Note: 全量采用 anti-slop 并逐步清理

Status: proposed

[English](2026-11-18-anti-slop-lint.md) | 中文

## 问题

一次性启用 anti-slop 的完整预设会暴露大量存量违规，使 lint 门禁持续失败。迁移需要先清理每条规则，再启用该规则，同时提供全部通用规则，去掉未使用的框架专属源码。

## 提案

明确关闭 `no-shape-in-symbol-names`。它的子串禁令会拒绝正确的几何术语、schema 定义及持久化属性名。即使只限制裸名 `Shape` 声明，也仍只是命名偏好，不能建立领域或安全契约。保留上游源码，不维护本地分叉；不为满足这条规则而修改正确的标识符。

接入全部 18 条通用 anti-slop 规则及原生 `oxc/no-accumulating-spread` 配套规则。对选定的 17 条通用规则及原生配套规则，只有在约定范围内的违规已清零、相关契约验证通过后，才逐条启用。接入层注册插件，不启用尚未完成清理的规则。每条规则对应的 stack 层包含清理改动，并将该规则开启为错误。保留现有 lint 范围及无关规则。仓库不使用 Effect，因此不保留 Effect 专属插件源码。不得弱化已启用的生产代码规则、增加生产目录豁免或伪造类型信息来规避发现。测试文件及测试专用目录豁免 `no-unknown-parameters` 和 `no-chained-type-assertions`：非法输入 fixture、局部原生 mock 及历史数据可能需要未知输入或连续类型断言。保留实质契约修复；不为消除这些断言而扩充 fixture。其他测试 lint 规则保持原有配置范围。

将复制的插件放在 `scripts/lint/anti-slop/`，保留确切上游版本及 MIT 声明，并将 `@oxlint/plugins` 固定为与 Oxlint 完全相同的版本。上游明确支持复制源码且没有官方 npm 包；其包导出未编译的 TypeScript，而 Node 不会在 `node_modules` 内执行类型擦除。Git 依赖需要额外的编译或加载机制。本次集成保留受支持的本地源码机制，去掉多余的外层 vendor 目录。插件内部的第三方声明保留上游布局。

按规则和文件盘点违规，再分模块清理，保留可观察契约。只在选定批次内应用空行修复，区分语义审查和格式化。用真实领域信息或现有 schema 替换不安全类型；保留字段省略、回调顺序、代理接收者语义及测试隔离。不得通过别名隐藏模块 mock 来规避规则。全仓库存量清理是一项持续迁移；首个实现覆盖经过测试的初始批次，并明确报告剩余发现。完整仓库迁移完成前，Spec 保持 proposed。

ai-core 的 `AiPlugin.transformParams` 契约从局部补丁改为完整参数。将每次返回值直接传给后续插件，管理器不再隐式合并或复制。迁移仓库内全部插件，说明外部插件如何保留未改动字段，并将公开 API 变更作为破坏性变更发布。插件可以原样返回收到的参数；返回值中省略的字段会被移除，不再通过合并恢复。

自定义参数分流必须将 `__proto__` 等保留属性名作为自有数据字段保留，并保持普通对象的原型。构造数据属性可避免调用原型 setter；回归测试保护这一契约。

插件与技能的 Markdown 元数据支持 YAML 和 JSON frontmatter。禁用 gray-matter 内置的 JavaScript 引擎及其 `js` 别名，确保解析元数据不会执行代码。这会移除 JavaScript frontmatter 支持；受影响文件必须将元数据迁移为 YAML 或 JSON。保留现有的宽松 YAML 恢复与元数据默认值。

## 考虑过的替代方案

- 仅因存量代码违规而关闭规则：有价值的规则应先清理再启用。排除 `no-shape-in-symbol-names` 是因为其命名策略价值有限，而非迁移量大。
- 使用非官方 npm 包或 Git 依赖：会增加发布维护方或编译机制，而非使用上游支持的安装方式。
- 一次性改写整个仓库，形成难以审查的大改动：边界和测试迁移需要针对具体契约验证。

## 验收标准

- AC1 — 每条规则只有在约定范围内的违规已清零后，才启用为错误；真实 CLI 探针验证启用状态。迁移完成时，选定的 17 条通用规则及原生配套规则均已启用；`no-shape-in-symbol-names` 明确保持关闭。 (verification: unit)
- AC2 — 插件从 `scripts/lint/anti-slop/` 加载，依赖版本匹配且固定，上游通用生产源码未修改，不保留未使用的 Effect 插件，许可证和来源记录完整。 (verification: unit)
- AC3 — 有界的首批清理通过针对性 lint 及受影响契约的现有测试；后续批次遵循相同验证要求。 (verification: unit)
- AC4 — 准确报告剩余规则盘点及验证边界；文档说明全量采用和迁移尚未完成的状态。 (verification: docs gate)

- AC5 — `transformParams` 要求返回完整参数，仓库内调用方全部迁移，契约测试验证串联及省略字段的移除。包文档与 major Changeset 说明破坏性迁移。 (verification: unit)
- AC6 — 插件与技能的元数据解析不求值 JavaScript frontmatter 及其别名；YAML 与 JSON 仍可读取。回归测试覆盖两个入口。 (verification: unit)

## 风险

某条规则仍有存量违规时，不得启用该规则。未配置的规则表示尚待迁移，不代表其源码已清理完毕。CLI 探针必须区分插件提供的规则能力与仓库实际执行的规则。未知输入限制、模块 mock、反射和类型断言需要领域内修改，不能机械替换。空行修复可能与格式化相互影响，需要第二轮稳定性检查。AST 和词法作用域规则不能证明跨文件类型安全或普遍性能提升。初始批次不代表全仓库验证通过或完整迁移完成。
