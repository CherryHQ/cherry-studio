# Agent Note: 显式选择热修复的回移分支

Status: proposed

[English](2026-11-09-active-release-backport.md) | 中文

## Problem

热修复工作流通过匹配 GitHub Release 草稿与发布分支来选择目标。首次成功构建才会创建草稿，所以在此之前合并的热修复需要手动回移。[#24023](https://github.com/CherryHQ/cherry-studio/pull/24023#issuecomment-6738737793) 就遇到了这个问题，当时 v2.2.0 的发布分支已经存在。

## Proposal

仅通过 GitHub 仓库变量 `ACTIVE_RELEASE_BRANCH` 选择目标。发布维护者在准备流程创建分支后，将变量设为完整分支名，例如 `release/v2.2.0`，并在放弃或完成发布时清除变量。未设置变量时暂停自动回移，并在运行日志中明确说明。按现有发布分支命名规则校验变量，解析仓库中的精确引用。值不合法或分支不存在时，报错并说明原因。

目标版本尚无 GitHub Release 或已有草稿时，均可回移。版本已发布时，即使变量仍指向其分支，也应阻止写入。读取配置、引用或发布状态失败时应报错。读取可信的仓库配置，并确认工作流凭据有权访问。在修改回移分支或创建 PR 前，重新检查当前选择、发布状态和预期的发布分支 HEAD。保留现有的发布状态锁、回移分支租约、PR 聚合和重试行为、来源追踪及双语发布说明处理。

在文档中说明如何设置和清除变量。上线实现时，为当前活跃发布设置该变量，确保符合条件的热修复仍能找到目标。创建草稿、触发构建和正式发布继续由发布工作流负责。

## Alternatives considered

- 继续用草稿选目标。首次构建故障期间仍然无法自动回移。
- 选择最新的发布分支。历史分支会保留，多个版本也可能同时准备，版本顺序无法可靠反映维护者的意图。

## Acceptance criteria

- AC1 — 已显式指定发布分支、对应版本尚无 GitHub Release 时，合并符合条件的热修复会创建或更新以该分支为目标的 PR，并保留来源标记及双语发布说明。已有草稿时行为相同。验证负责人：实现者，通过 GitHub 工作流演练验证。
- AC2 — 目标未设置、值不合法、分支不存在、版本已发布或 API 读取失败时，工作流不会创建或更新回移分支或 PR。验证负责人：实现者，通过定向工作流测试验证。
- AC3 — 若写入前复查发现所选目标或发布分支 HEAD 已变化，或版本已发布，工作流停止写入过期状态。重试同一符合条件的热修复时，保留现有的聚合及幂等行为。验证负责人：实现者，通过定向工作流测试验证。
- AC4 — 发布指南说明启用和停用的方法，包括首次构建失败时的恢复流程。验证负责人：实现者，通过文档检查及双语审阅验证。

## Risks

开启新一轮发布时，维护者需要设置目标变量。实时读取变量需要凭据具备仓库变量的读取权限。上线前需在 GitHub 验证该权限。
