# Cherry Studio 回答插图：修改说明

本文仅介绍本 Cherry Studio fork 的回答插图功能、上游同步、贡献规范改进和验证结果。

截至 2026-11-04，功能已在 Cherry Studio fork 实现并完成下述验证。上游 [Spec PR #23551](https://github.com/CherryHQ/cherry-studio/pull/23551) 仍待维护者批准；实现以 Draft PR 提供，批准方案并同步基线后才能进入正式评审。使用本功能需要包含这些修改的 Cherry Studio 构建。

## 使用方式

本仓库为 [leezehuan/cherry-studio](https://github.com/leezehuan/cherry-studio)，fork 自 [CherryHQ/cherry-studio](https://github.com/CherryHQ/cherry-studio)。

内置功能直接调用 Cherry Studio 已有的绘画模型、服务商凭据和文件管理能力，无需额外启动 MCP 服务或配置本机图片 HTTP 地址。

1. 使用包含本功能的构建，并配置可用的图片生成服务商与绘画模型。
2. 打开 **设置 → 外观 → 消息 → 回答插图**，选择自动或强制插图。
3. 自动模式设置上限张数，强制插图模式设置目标张数，在普通单模型聊天中发送问题。

## 主要功能变化

### 提示词成为回答的一部分

回答模型在同一次回答中，在需要插图的位置输出以下格式：

```text
这是一段解释文字。

[[IMAGE]]
一幅展示水循环的科普插图：包含海洋、蒸发、云层和降雨，以箭头说明流向。
[[/IMAGE]]

这里继续解释后面的内容。
```

这段生图提示词与正文一起流式输出，无需额外调用一次语言模型生成提示词。应用自动注入格式要求，用户无需手动粘贴这段协议。

处理顺序如下：

1. 识别到起始标记，在回答对应位置预留灰色占位和加载动画。
2. 收到完整结束标记，立即将提示词加入生图队列，不等待整条回答结束。
3. 生图与后续文字输出异步进行，正文继续显示。
4. 图片返回后原位替换占位，保持文字与图片的顺序。

当前最多同时执行 **2 项**生图请求，其余请求排队；每项活动请求的超时为 **5 分钟**。所以“立即提交”指立即进入队列，实际发出请求还受并发限制。

### 三档插图模式与数量设置

入口：**设置 → 外观 → 消息 → 回答插图**。

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 插图模式 | 关闭 | 可选自动、强制插图、关闭 |
| 上限张数 | 1 张 | 仅自动模式显示，可设为 1–10；超过上限的意图不提交生图 |
| 目标张数 | 1 张 | 仅强制模式显示，可设为 1–10；提示词要求目标张数，解析器以目标作为硬上限 |
| 绘画模型 | 复用已有默认绘画模型 | 使用其服务商配置和凭据，可在插图设置中选择 |

三档模式通过系统提示词控制：

- **自动**：告诉模型可以按需要插图，由模型决定是否插入、插入位置和张数。
- **强制插图**：要求每条回答恰好输出目标张数，系统最多接纳相同数量。
- **关闭**：不注入插图要求，不处理该回答的新插图意图；已有图片仍可查看。

两种数量分别保存，切换模式或降低自动上限不会覆盖强制目标。例如：自动上限为 3 时，可以生成 0–3 张；切换强制模式并设置目标为 6 时，提示词要求 6 张，系统最多接纳 6 张。

2026-11-05 的数量设置调整移除了独立的“强制插图张数”开关。旧版开启该开关的自动或强制模式会一次性转换为强制插图，保留按旧上限裁剪后的目标；未开启该开关的强制模式从一张开始。关闭状态保持关闭，自动上限保留，后续选择分别记忆。

**数量上限由程序执行；强制目标依赖模型遵循提示词。** 模型可能漏写或截断标记，生图也可能失败；应用不会额外调用语言模型补齐，不能保证成功得到目标数量的图片。

模式与数量在每条回答发起时确定。修改这些设置不会重写正在生成的回答，从下一条回答生效。

### 查看图片生成提示词

每张图片或占位旁都有 **查看生图提示词** 按钮，点击后展开模型实际写出的提示词，再点击 **收起生图提示词** 折叠。

提示词以纯文本展示，不直接混入回答正文。生图过程中或失败后都可以查看已经完整收到的提示词，保存后的回答也保留该内容。

### 取消、重试和保存

- 可以单独取消未完成插图；停止整条回答也会取消尚未完成的生图，已完成图片保留。
- 生图失败或取消后保留已有文字，并显示对应状态。存在完整有效提示词且插图模式已启用时，可以显式重试；不自动重试。
- 已保存的普通聊天回答保留图片及提示词。重新打开回答、组件重新挂载或重复更新不会自动再次提交同一生图意图。
- 应用重启后，未完成请求标记为中断，不自动续跑；已经保存的图片仍可查看。
- 支持临时聊天中的插图，聊天数据仍遵循临时聊天原有生命周期。

| [消息插图组件](./src/renderer/components/chat/messages/blocks/MessageIllustrationBlock.tsx) | 展示加载、图片、错误、取消重试及提示词展开按钮 |

解析发生在实时显示和消息累积的分流之前，使界面与保存内容使用一致的文字／插图顺序。后台生图结果独立更新，避免文字回答结束时覆盖较新的图片状态；旧的已取消请求即使稍后返回，也不会覆盖重试结果。

代码示例中的标记保留为文字，不触发生图；已补充跨行反引号代码片段的识别修复和回归测试。

此外已补齐 E2E 配置中的 DOM 异步流类型声明，修复网站准备脚本在 Windows 下的 Git 路径比较，以及无需 shell 调用 pnpm 入口的问题，并补充中英文用户指南。

## 当前范围与限制

- 首版支持普通单模型聊天，包括临时聊天；尚不覆盖 Agent 编程会话和多模型回答组。
- 尚未验证真实付费服务商；Electron 场景使用本地模拟服务，远端官方 CI 结果也未确认。实际生图及显式重试可能产生服务商费用。
- 强制模式的目标张数属于提示词要求，模型漏写、标记截断或生图失败都可能使最终图片数量不足。
- 关闭功能后，支持该功能的构建仍可查看已有图片；降级到不支持插图消息类型的旧版则不能渲染新插图片段。
- 上游方案尚待真人审批，实现尚未合入上游；本地签名和 DCO 验证通过也不等于 GitHub 已显示 Verified。

具体操作可继续阅读[中文用户指南](./docs/website/content/pre-basic/settings/display.md#回答插图)与[英文用户指南](./docs/website/content/i18n/english/personalization-settings/README.md#reply-illustrations)。
