# 批扫规则（对含中文/多字节文本做正则批扫时的硬约束）

适用：任何"用正则扫代码/文本、结论是 0 命中才算干净"的检查（禁止项扫描、残留检查、口径一致性检查）。

## R-1 不用 macOS 自带的 BSD grep 扫多字节文本

- 必须用 Python `re`（Unicode 语义），或 `grep` 的 GNU 版本。
- 实测：BSD grep 对 `工作项键[^\n]{0,80}轮次` 这类「多字节字符 + 字节上限量词」不可靠——同一模式在中文行漏报、在 ASCII 行命中。
- 危害形态：**工具沉默，不是文件干净**。与 `verify_u2_0.py` 静默忽略 argv 属同一族问题。

## R-2 正控样本必须中文行、ASCII 行各一条

- 只植入中文写法的正控，证明不了 ASCII 写法被覆盖，反之亦然。
- 判定要求：`中文行命中=True` 且 `ASCII 行命中=True`，缺一即判正控不成立。

## R-3 排除即盲区，必须同时给 A / B 两份结果

```
A) 排除自指文件的负控（日常判定用）→ 报 files_scanned 与 hits
B) 不排除任何文件的完整扫描（一次性留存）→ 自指命中逐条列出，落盘单独文件
```

- 按名排除等于「因为它在名单里所以不扫」；若自指文件里混进一条真违规，A 永远看不见。
- B 不进自动判定，但必须存在且结果落盘，供人工核。
- 禁止用「删掉自指文件」来消灭命中：扫描器迟早还要放正控样本，B 就是给这种情况留的出口。

**B 的 hits 只能当证据，不能当指标。** 它会随正控样本与模式数量变化（13 → 24 就是加了模式的结果），所以：

```
允许用途：证明盲区存在且被看到 / 供人工核对自指文件里有没有混进真违规
禁止用途：把 B hits 的增减当作"有没有问题"的信号、写进阈值、写进告警
```

任何一处若把 B hits 当阈值或回归判据，即视为违反本规则。

## R-4 0 命中必须带扫描规模，且下限来自 PIN 登记值（不写死数字）

- 报 `files_scanned`；只有"0 命中 + 扫描集非空且够大 + 正控命中"三者同时成立，才能说干净。
- **下限不许写成常量。** 写死 28 的失效路径：树长到 40 个文件后，若扫描根写错只扫到 28 个 → 下限通过 → 假绿。
- 下限来自 `tests/scan-scope-pin.json`（登记 `files_scanned` / `scan_root` / 排除项），每次运行 preflight 校验：

```
实测 files_scanned 与 PIN 偏差 > 10%  → rc=3 SCAN_SCOPE_DRIFT（点名两侧数）
PIN 缺失或不可读                     → rc=3 SCAN_SCOPE_UNDECLARED（不得默许通过）
更新 PIN 只能用显式 --write-pin，且需人先核因（树真变了 / 还是扫描根写错）
```

- 效果：树变了会强制更新登记值，而不是靠人记着改脚本里的魔数。
