## 1. 行的语义单位与主键

```
行 = 某一轮对某个事件的一次检查明细
主键 = (事件标识, 工作项键, 内容指纹)
```

理由（实测）：存量 743 行里 15 组同 ref 两行，其中 11 组工作项键不同（`1400:x` 与 `2200:x`），是同一事件在 14:00 轮登记、22:00 轮复查各落一行。**事件标识不是行的主键**——它标识事件，不标识行。工作项键已经含轮次前缀（`1400:` / `2200:` / `0800:` …），所以把工作项键放进主键，跨轮复查天然放行，**不需要任何“跨轮例外白名单”**。例外白名单是长期维护面，最先失效，不采用。

## 2. 内容指纹

```
内容指纹 = sha256( 行内容按键名排序后的 JSON )[:16]
行内容 = 该行全部字段，剔除：
  - 记录 ID（record_id / 飞书记录 ID）
  - 时间戳类字段（日期、更新时间、抓取时间等）
  - 派生字段（明细行键、日报键）
  - 主键字段本身（来源事件标识、工作项键）
```

判定时不比 `明细行键`：它是 `sha256(工作项键+事件类型+事件序号)`，天然随行变化，用它比等价于“永远不同”。

## 3. 三类判据（不可合并、不可互替）

| 情形 | 判据 | 处置 |
|---|---|---|
| 同 事件标识 + 同 工作项键 + 内容相同 | 真重复 | `DUPLICATE`：skip，不插、不覆盖、不自动删 |
| 同 事件标识 + 同 工作项键 + 内容不同 | 合法多明细（同一事件拆多条） | 放行插入，记 `MULTI_DETAIL` |
| 同 事件标识 + 不同 工作项键 | 关系未知 | 放行插入，记 `round_relation=unknown`，**不熔断** |
| 同 事件标识 + 不同 工作项键 + **生成侧显式声明的轮次相同** | 真冲突 | `rc=3 REF_CONFLICT`，不写、不 skip、不覆盖；点名 ref、表内已有工作项键、本批工作项键、record_id |

### round_relation 三元：same / different / unknown

```
round_relation = same        生成侧显式给出两侧轮次字段且相等
round_relation = different   生成侧显式给出两侧轮次字段且不等
round_relation = unknown     生成侧未提供轮次字段（本轮默认形态）
```

**绝不从工作项键里解析/推断轮次。** 存量工作项键至少三种形态（`1400:x`、`1021-2200-skip:x`、`20261117-2021:x`），用正则猜轮次猜对是侥幸，猜错就会把合法的跨轮复查判成 rc=3 熔断——误伤只是从白名单挪到了正则，性质没变。规则要求：**推断出来的值不得与声明出来的值同权使用**。

**`unknown` 不得参与任何 rc 判定。** unknown 只表示「不知道关系」，不等于「已知冲突」；用不可靠的轮次值触发不可回滚的熔断，是本条规则要禁止的错误形态。因此 `REF_CONFLICT` 只在 `round_relation = same`（显式声明相同）时触发。

`skip` 只剩一种情形：同 事件标识 + 同 工作项键 + 内容指纹相同。

## 6. 验收判据（实现后逐条核）

1. 同 ref 同工作项键同内容 → skip，`DUPLICATE=1`，并显式给 `inserted/duplicate/failed` 三计数。
2. 同 ref 同工作项键不同内容 → 插入，`MULTI_DETAIL=1`。
3. 同 ref 不同工作项键、生成侧未给轮次 → 插入，`round_relation=unknown`，**rc 正常（不得是 3）**。
4. 同 ref 不同工作项键、生成侧显式轮次相同 → `rc=3 REF_CONFLICT`，四个字段点名齐全，表内零变化。
5. 同 ref 不同工作项键、生成侧显式轮次不同 → 插入，`round_relation=different`。
6. 空 ref → `rc=3 EVENT_ID_MISSING`，零写入。
7. **`round_relation=unknown` 在任何输入下都不得改变 rc**：构造 unknown + 各种组合，逐一确认退出码与「无重复」时一致。
8. 代码里不存在「从工作项键解析轮次」的分支：grep 工作项键与轮次正则的组合，命中即判定为不合规实现。
9. 用 743 行全量跑影子统计：`unique_keys=70`、`duplicate_pairs=0`、`多明细组=4`，与 §5 一致；`MULTI_DETAIL` 偏离 4 须说明是同键不同内容的行在增加，还是内容指纹口径变了。
