# 文件编辑会话

[English](file-editing.md) | 中文

## 所有权

`FileEditSessionProvider` 创建窗口持有的 `FileEditSessionManager`。`useFileEditSession(handle, ownerId)` 订阅其快照；Hook 不持有草稿、保存计时器或 SWR 缓存。

| 所有者 | 职责 |
|---|---|
| Renderer 管理器 | 独立草稿、磁盘基线、修订号、保存队列、挂载代次、变更屏障及保留草稿清单 |
| 编辑器 | 交互文档和撤销历史；回调携带挂载代次与文档代次 |
| `FileEditService` | 窗口持有的编辑租约、固定的文件系统目标、不可变写入尝试和终态回执 |
| `DirectoryTreeManager` | 现有目录树 watcher 与树失效事件 |

笔记、每个 Skill、每个 Agent 产物界面使用不同且稳定的 owner ID。注册表按 owner、句柄类型及原样 locator 匹配。同一 owner 重新打开该 locator 时恢复保留的草稿。替代挂载会使旧挂载的回调失效。不同 owner、路径别名以及 entry/path 句柄之间不共享草稿，也不选举写入者。恢复操作使用唯一 `sessionId`，不使用文件路径。

## 持久化契约

| 路由 | 契约 |
|---|---|
| `file.edit.open` | 解析句柄、检查路径策略、固定目标并返回不透明的 `editId` |
| `file.edit.read` | 返回有大小限制的一致二进制快照及这些字节的哈希 |
| `file.edit.write` | 携带必需的预期版本/哈希和租约内序号，提交不可变字节 |
| `file.edit.settle_write` | 恢复终态回执；阻止尚未开始的序号执行 |
| `file.edit.close` | 停止接收请求，等待已接受的读写完成，释放租约和临时条目保留 |

Main 对原始文件系统 locator 异步调用 `realpath`，不预先折叠点路径段。解析后的目标仅在 Main 内部保存，后续读写再次检查 locator。符号链接改指向或条目移动会使旧租约失效。写入替换解析后的目标，同时保留末级符号链接。原始路径访问的请求地址和实际目标都必须通过托管存储策略检查。这里固定的是地址，不是在任意外部替换期间保持 inode 身份。

8 MiB 限制用于加载前和加载中检查；已打开的编辑器可以继续增长。编解码器保留 UTF-8 BOM 和 LF/CRLF，拒绝不支持的编码或混合换行。打开文件或切换编辑模式不会把未经编辑的富文档重新序列化并写回磁盘。

写入返回 `committed`、`not-committed` 或 `not-started`。已提交回执包含新基线和 `metadataRecoveryPending`；元数据收尾失败不能重放已提交字节。传输丢失回执时，Renderer 先确认同一序号的结果，再发起下一次写入。结果仍未知时保留写入尝试和草稿。

`flush()` 立即捕获当前草稿和修订号。其目标排在旧写入之后，不能被后续编辑替换。另一份保存尚未完成时，即使撤销到此前的磁盘文本，也仍需后续写入。自动保存对尚未发送的编辑进行防抖。持续失败暂停自动重试，同时保留草稿与显式重试能力。

条目写入、条目重命名/删除/清理和路径变更按条目锁 → 路径互斥锁顺序协调。即使大小和时间戳相同，哈希校验仍能发现字节变化。独立打开的编辑器均可编辑；基于旧基线的保存报告冲突并保留本地草稿。原子替换不提供相对于任意外部程序在校验与 rename 之间的比较并交换保证。

## 替换与文件变更

如果当前获取请求在编辑实例建立前失败，`flush()` 和 `discard()` 无需处理工作即可完成，允许继续导航。加载中的获取请求仍拒绝这些命令；已有实例上的错误保留正常的草稿保护和写入结果确认流程。`reload()` 和 `keepLocal()` 需要已有实例。

`documentEpoch` 在初始文档或显式替换时变化，不随普通编辑或保存回执变化。笔记按会话/代次挂载编辑器，程序化富文本水合不触发编辑事件。独立的挂载代次拒绝来自旧挂载或变更屏障之前的回调，同时保留当前文档和撤销历史。

`discard()` 等待写入结果后恢复已确认的基线。`reload()` 等待写入结果后采用新磁盘文档。`keepLocal()` 封闭输入、捕获草稿、读取最新基线，再条件保存捕获的文本。失败时保留草稿。

`prepareMutation()` 封闭并刷写窗口内全部保留会话。输入法组合输入、并发切换、冲突、保存失败和未确定的写入结果会阻止准备完成。新获取请求等待；被打断的获取请求释放过期租约后重试。这个保守的窗口级屏障避免通过路径前缀推测受影响资源。

准备完成后，调用方执行重命名、移动或删除，并在 `finally` 中调用幂等的 `finish()`，包括文件系统操作失败时。它重新验证仍挂载的会话，再释放屏障。目标缺失或变化会使旧实例不可用；调用方把目的地作为新的编辑实例打开。管理器不重映射路径，也不在 owner 之间转移草稿。已分离的干净会话被回收，失败或未保存的会话仍可恢复。

## 重新验证

笔记和 Skills 复用现有目录树失效回调。活动编辑器也在窗口聚焦、文档变为可见和重新激活时重读。编辑功能不新增专用 watcher 服务或共享 watcher 池。通知只使已知状态失效，不提供替代草稿。即使通知延迟或缺失，保存正确性仍依靠条件写入。

重读结果在采用前检查读取代次、草稿修订号、待完成写入和变更屏障。干净内容可以刷新；脏内容留在内存，磁盘字节不同则标记冲突。保存或屏障期间推迟的通知在会话可用后重新验证。

临时观察读取失败会记录日志并保留未知的新鲜度，不会清除草稿或产生保存失败。租约目标缺失/改指向，或变更完成阶段重新验证失败，会使当前绑定不可用。显式重新加载成功后可以清除读取错误；真正的保存失败保留独立的重试状态。

## 关闭与恢复

关闭文件视图会释放挂载，并在 Renderer 仍存活时尝试刷写已接受的编辑。窗口恢复界面列出已分离草稿的 owner 和 locator，提供复制、重试和丢弃。所有挂载离开后，干净且已完成操作的会话释放 Main 租约。Main 也会在所属窗口销毁或服务停止时释放租约，并等待已接受的操作完成。

窗口关闭、应用退出、重启、Renderer 重新加载和窗口池重置保留现有生命周期行为，不具有文件编辑准备屏障。Main 清理无法保存尚未到达 Main 的编辑，Renderer 重新加载本身也不保证释放旧文档租约。内存草稿不保证跨这些操作存活。保留机制不是崩溃恢复日志或协作历史。

## 验证边界

服务测试覆盖真实文件系统哈希、符号链接遍历及改指向、独立租约竞争、重命名顺序、结果确认屏障和元数据恢复。Renderer 测试覆盖独立 owner 草稿及冲突、文件切换、过期回调、固定的刷写目标、保存期间撤销、草稿保留、文档替换、变更屏障和组合输入否决。Electron 验收和更广泛的 CI 与这些契约分别报告；本地文件系统测试不构成网络文件系统保证。
