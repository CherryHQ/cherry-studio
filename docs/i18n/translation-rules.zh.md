# 文档翻译规则

[English](translation-rules.md) | 中文

以技术作者的方式翻译，而不是逐词转写。保留每个主体、条件、时序规则、语气、否定保证、例外、副作用、失败模式和后果，不得添加新主张。

## 事实源

- 翻译前使用生成的[术语表](terminology.md)；受治理术语不得在局部自行创造译法。
- 对照当前代码和归属 reference 验证技术主张。翻译不能静默修复不准确的源文档。
- 每次更新都可以把任一语言作为 authored side。未变化的一侧没有永久优先级。

## 结构

- 保留标题深度/顺序、列表类型/起始值/数量、表格尺寸、链接目标和代码围栏。
- 代码 span、路径、标识符、命令、插值 token 和协议值保持不变。
- 链接标签可按自然语言翻译，但普通相对目标保持英文 `.md` 路径。
- Frontmatter `sources` 精确保留。只翻译契约明确允许本地化的字段，目前为 `description`。

## 更新已有 pair

通过比较当前 blob 与 sidecar 判断哪一侧发生变化。以覆盖 diff 的最小语义单元修补对侧，保留该单元之外所有已经评审的措辞。如果两侧都变化或记录的 blob 不可用，就人工协调完整受影响章节，不得猜测方向。

对照完成后，单独阅读翻译段落并消除源语言句法。然后逐句核对、重录 pair，并运行 scoped check。

## 创建新 pair

逐节翻译，同时锁定结构。大规模 domain 回填中，worker 获得互不重叠的文件；integrating agent 负责术语、链接、生成物、sidecar 和 corpus-wide gate。

## 评审边界

自动化无法判断语义等价。Reviewer 应拒绝遗漏条件、增加承诺、弱化 MUST/never 语气、错误术语、翻译标识符，以及虽自然但改变契约的文本。
