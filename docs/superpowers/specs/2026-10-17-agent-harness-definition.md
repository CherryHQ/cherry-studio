## 2. Harness 的定义与行为

**Agent harness 是组织 agent 执行的系统：接纳输入、管理上下文、协调模型和工具、处理外部交互、推进工作，并暴露可观察和可控制的事实。**

它可以是嵌入式库、独立服务或 CLI 背后的执行系统。进程形态、传输协议和是否持久化，都不是定义前提。

| 行为 | 责任 | 必须区分的事实 |
| --- | --- | --- |
| 接纳与安排输入 | 按原生规则处理用户输入、干预、工具结果和通知 | 接纳、排队、进入上下文、模型消费、完成 |
| 管理上下文 | 为模型组织指令、历史、工具及压缩后的内容 | 展示历史与模型实际上下文 |
| 推进执行 | 组织模型调用、工具反馈、等待和后续调用 | 工具失败、执行结束与用户目标完成 |
| 管理工作归属 | 确定父子工作、等待、取消传播和结果交付关系 | 子会话、一次委派与某次执行 |
| 接受控制 | 校验目标和条件，报告实际作用范围 | 请求已收到与效果已完成 |
| 暴露与恢复事实 | 提供可用的观察、查询和恢复路径 | 重新连接、恢复上下文与恢复执行 |

子 agent、后台工作、审批、恢复和精确执行控制并非每个 harness 都必须具备。不支持的行为不能用猜测状态或静默降级代替。

## 3. 术语与所有权

| 概念 | 含义与所有者 |
| --- | --- |
| Agent | 角色、指令、模型、工具和策略配置；不是某次执行 |
| Harness | 原生上下文、接纳后的输入安排和执行推进的所有者 |
| AgentRuntime | 宿主访问某个已配置 harness 的公共入口，由适配器实现；不再设同义 Backend |
| 适配器 | 解析原生引用、映射事实、管理接入资源；不另建竞争的执行调度器 |
| 宿主 | Cherry 产品入口、授权、投递记录、资源政策、投影与展示的所有者 |
| 产品会话 | Cherry 的标题、归档、导航等业务对象；与原生上下文显式关联，不强制一对一 |
| Session | 原生可独立延续的上下文；是否落盘、如何恢复由 harness 决定 |
| ThreadHandle / Observation | 本地访问句柄与订阅；不拥有原生会话的业务生命周期 |
| Input / Item | 一次逻辑输入 / 可独立更新的内容；两者不要求一一对应 |
| Execution / Interaction | 有证据的工作边界 / 有效的外部请求；当前公共 API 不导出这两类对象 |

宿主提供模型调用、工具、存储或审批端，不改变接纳后推进工作的所有权。每类重试、队列安排和结果交付只能有一个决策者；例如模型调用层的重试不能与 harness 的重试无约束叠加。

宿主拥有期望配置，执行端确认实际采用的配置和生效边界。一个工具结果、一次输入回执或一个 UI 状态，都不能证明超出自身范围的事实。公共包不负责登录、CLI 安装升级、业务数据库或跨 harness 无损迁移。

## 4. 子输出与 Lane

**子 agent 流式输出属于执行可观察性；Lane 属于宿主投影。**

```text
Harness 事实 → 适配器规范化 → 宿主 Lane / 历史投影 → UI
```

Lane 是按明确来源组织流式内容、历史关联和订阅的逻辑通道，不调度执行，也不等于一个面板或连接。投影可以由主进程或独立服务持有并持久化，不必随窗口退出。

必须分别识别：稳定 child Session、一次委派、原生可确认的 Execution、触发工具、内容 Item 和展示位置。父工具卡片可以引用 child Lane，但父工具或父消息不能成为子输出的永久身份。前台转后台不改变同一子来源；父消息结束不应关闭仍在产出的 child 观察。

流式累积跟随内容身份，不能跟随组件挂载或父回合切换。保存的展示 parts 不等于流解析器状态；重连需要明确的快照衔接与缺口处理。仅把 background flow 改名为 Lane，不解决父消息锚点依赖。

观察子输出与向父模型交付结果是不同数据流。原生已经交付结果时，宿主不因观察到完成再注入一份。跨 harness 委派由明确的宿主编排服务负责关系和交付，各 harness 负责自身执行。

## 5. 存储边界

| 内容 | 语义所有者与保存责任 |
| --- | --- |
| 原生上下文、队列、checkpoint | Harness 决定内容和写入边界；存储设施可由宿主提供 |
| 公共与原生引用映射 | 适配器解释；需要跨重启的映射由指定存储保留，不能只存在内存 |
| 产品会话、逻辑输入、传输尝试与回执 | 宿主保存，记录原生交接证据；不把未知结果标成未执行 |
| 可读历史、Lane 和多窗口投影 | 宿主保存；原生历史不可重读时，观察归档不是可随意丢弃的缓存 |
| 附件和产物 | 明确资源所有者与保留期限；不能只留下随进程结束失效的路径 |

展示与原生历史双存不是天然错误；同一事实有两个互相猜测的权威写入者才是问题。展示删除不等于上下文删除，通用可读历史也不承诺无损恢复任意 harness。

## 6. 包边界

```text
packages/agent-runtime             公共行为契约、类型及验收工具
packages/agent-runtime-pi          Pi coding-agent 接入与专用实现
packages/agent-runtime-pi-durable   Pi Durable 接入与专用实现
```

Pi 在此指 pi-coding-agent；Pi Durable 是独立执行系统，不是 coding-agent 的持久化开关。两个适配器依赖公共包、互不依赖；公共包不反向导入 SDK、Electron、业务实体或 UI chunk。

模型、工具、存储和原生扩展先保留在各适配器的强类型配置边界。只有真实消费者需要且语义相同的能力才提取公共 port。[agent-runtime 包](../../../packages/agent-runtime/README.md) 已保留公共契约与观察交付工具；既有 Pi 实现迁到 [agent-runtime-pi](../../../packages/agent-runtime-pi/README.md)，[agent-runtime-pi-durable](../../../packages/agent-runtime-pi-durable/README.md) 独立接入原生 Harness。桌面服务仍使用原路径，尚未迁移。
