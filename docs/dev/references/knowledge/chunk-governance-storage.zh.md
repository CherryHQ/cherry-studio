# Knowledge 分块治理存储

[English](chunk-governance-storage.md) | 中文

这些层实现了[拟议分块治理功能](../../../../.agents/notes/proposed/feature/2026-11-22-knowledge-chunk-governance.md)中的持久决策、检索安全以及排除/标签控件，但没有完成文字修正、源复核处理、引用或备份/恢复。Spec 保持 proposed，issue #19001 保持开放。

## 所有权

`KnowledgeChunkGovernanceService` 拥有主数据库中的 `knowledge_chunk_governance` 和 `knowledge_chunk_governance_history` 表。每知识库索引仍可丢弃重建。此数据服务不执行文件系统、提供商或嵌入工作。

记录将知识库/条目和精确分块 ID 绑定到源内容哈希、原始 UTF-16 偏移、原文及其 SHA-256 哈希。源条目与知识库必须已完成，条目必须属于该知识库且不是目录。复合外键保留所有权约束。永久删除条目/知识库会级联删除记录及历史。

`KnowledgeChunkGovernanceWorkflow` 对照实际索引分块、当前源哈希、原始源切片及派生分块身份验证选中的 ID。调用方不能提供替代源证据或修正内容。它与索引、重新索引和删除共用每知识库 `KeyedMutex`。运行时编排通过 `knowledge.apply_chunk_governance` IPC，数据库服务仍为内部接口。

## 修订与历史

创建在一次同步写事务中写入修订 1 及历史。状态包含排除、标签和可选修正。标签会去除首尾空白，要求非空，去重并排序。状态变化不会覆盖原始源证据。

`updateState` 要求精确的已存源哈希和预期修订。源/修订过期时，两张表均不改变。规范化状态变化会原子递增修订并追加历史；相同状态不写入。历史失败也会回滚当前状态。读取限定知识库、条目和分块；`listByBase` 按确定顺序返回记录。

`applyBatch` 在一次 `withWriteTx` 事务中提交所有选中变化及历史。修订 0 表示选中时尚无记录。纳入未修改的分块，或从其移除不存在的标签，不会虚构记录。重新启用仅改变排除状态，保留标签/修正。后续选择过期或历史写入失败会回滚同批次先前的写入。

增量迁移不会虚构决策。测试通过独立连接读取记录并重新打开派生索引。此功能的完整应用重启、知识库导入/导出和恢复仍未验证。

## 检查器工作流

打开已完成源的分块检查器，选择要修改的分块，每批最多 500 个。每张卡片保留原文、源身份、标签及生效中/已排除/待处理/需要复核状态。选择排除/纳入，或输入最多 80 个字符的单个标签并选择添加/移除。预览显示数量和操作。只有保存才会提交捕获的身份、哈希和修订；打开、选择、预览及取消均不写入。

排除仅影响检索，不影响源访问，也不是安全删除。标签是组织元数据，绝不进入模型提示、搜索文字或嵌入。这些操作不调用提供商。重新启用含未发布修正的分块不会发布该修正；其待处理状态仍不参与检索。

成功后，检查器重新加载已提交状态。冲突/错误会清除待执行意图，要求刷新并重新选择，不会自动重试。切换源会清除选择；延迟的列表/保存响应不能覆盖新源状态，包括先切走再切回的情况。源变化且仍有当前索引分块时，决策显示复核横幅并禁止编辑。没有当前分块的源仍需后续材料级复核视图。已有修正可显示为待处理，但这里不能编辑或发布修正。

## 检索权威边界

搜索前，`KnowledgeQueryService` 读取持久记录 ID/修订，并根据实际索引计算排除集合。精确分块/材料 ID、源/内容哈希、偏移及正文必须匹配。不按标题、单独序号或相似度匹配。

- 精确匹配的已排除分块在所有通道中被屏蔽。
- 非空修正保持待处理并被屏蔽，直到有效文字/嵌入发布路径完成。
- 任一记录无法匹配时，暂停其材料并保留证据/历史；其他材料仍可搜索。相同内容、相同身份的重建会复用决策。显式重新绑定/丢弃仍不可用。
- BM25 MATCH、放宽的短词搜索、短词 LIKE、向量及混合搜索两条通道均在 SQL 限额和 RRF 前过滤。共享嵌入哈希不会屏蔽无关分块。绑定 JSON 避免逐 ID SQL 变量上限及插值。

Main 在重排前和返回前重新验证修订及精确索引匹配。并发变化返回冲突，不会重复可能收费的提供商调用。策略读取失败或索引关闭时，检索被阻止。不会将两个数据库视为同一事务，不缓存渲染进程策略，也不记录原文/修正文。

## 仍待完成的边界

- 有效文字/嵌入任务、完整词法/向量发布、崩溃恢复及修正编辑/移除。
- 对无法匹配记录的显式复核、重新绑定和丢弃。
- 持久决策与历史的知识库备份/恢复。
- 原文/修正文引用修订及历史引用。
- 后续修正工作的提供商费用说明及原生 Electron 验收。

在这些路径落实 Spec 前，不要开放修正编辑，也不要将待处理修正称为已索引/已生效。目前证据仅覆盖 AC1/AC2/AC3/AC4/AC6 的一部分，不代表完整解决 issue。

## 验证

存储测试使用 `setupTestDatabase()` 与生产迁移，覆盖原始证据、独立读取、规范化、过期修订、所有权级联删除、无变化语义及历史回滚。迁移测试保留已有 Knowledge 数据，不虚构决策。

Main 集成使用迁移后的数据库、文件 SQLite 索引、生产 FTS/向量/查询/重排路径及真实批量工作流，仅模拟提供商方法。场景包括候选限额安全、全部通道/回退、共享哈希、数千 ID、UTF-16、精确重建/重新打开、源不匹配、原文检查、处理中冲突、后续条目/历史失败的原子性、多窗口竞争、生命周期/所有权验证及保留待处理修正。

检查器测试覆盖仅确认后写入、精确选择/修订传递、冲突恢复和跨源切换的过期响应。视觉检查使用真实检查器、共享控件与虚拟列表，覆盖英文/浅色桌面及中文/深色窄屏，IPC/数据为测试夹具。不宣称已完成原生 Electron、真实提供商、修正发布、引用或恢复验收。
