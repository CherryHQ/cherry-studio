# Knowledge 分块治理存储

[English](chunk-governance-storage.md) | 中文

这是[拟议分块治理功能](../../../../.agents/notes/proposed/feature/2026-11-22-knowledge-chunk-governance.md)的存储与检索安全基础。目前没有用户写入端点或检查器控件调用此服务。内部已提交的排除决策现在会影响搜索，但这并非完整的编辑、修正、复核或恢复工作流。

## 所有权

`KnowledgeChunkGovernanceService` 拥有主数据库中的 `knowledge_chunk_governance` 和 `knowledge_chunk_governance_history` 表。每个知识库的派生索引仍可丢弃重建。此数据服务不执行文件系统、提供商或嵌入工作。

记录将知识库/条目和精确分块 ID 绑定到源内容哈希、原始 UTF-16 偏移、原文及其 SHA-256 哈希。创建操作检查源条目属于该知识库、是已完成的非目录条目，并且知识库也已完成。即使绕过服务，复合外键仍保留知识库/条目所有权约束。永久删除条目/知识库会级联删除所属记录及其历史。

后续写入工作流必须先取得并验证实际索引源快照，再调用 `create`，并通过每知识库写入锁协调写入、验证完整的批量选择。仅匹配偏移长度不能证明提交的文字确实来自源。检索防护会独立对照当前索引检查已存证据，但不会因此授权或开放写入端点。

## 修订与历史

创建会在一次同步写事务中写入修订 1 及其状态历史。状态包含排除标记、标签和可选文字修正。标签会去除首尾空白，要求非空，去重并排序。`null` 表示移除修正；空修正会被拒绝。状态变化不会覆盖原始源证据。

`updateState` 要求精确的已存源哈希和预期修订。源/修订过期时，两张表均不改变。状态变化会原子递增修订并追加历史。规范化后相同的状态不会产生新写入。历史写入失败也会回滚对应的当前状态写入。读取/历史查询限定知识库、条目和分块；`listByBase` 仅按稳定的记录 ID 顺序读取指定知识库。这些是内部数据库行，不是已发布的跨进程实体端点。

增量迁移不修改现有源，也不生成虚构的治理记录。这些表保存在正常业务数据库中，而非可替换索引中。测试通过独立的文件数据库连接读取记录，并重新打开派生索引。此功能尚未验证完整应用重启、知识库导入/导出或恢复工作流。

## 检索权威边界

`KnowledgeQueryService` 在搜索前同步读取 Main 拥有的持久记录 ID/修订及派生排除集合快照。`KnowledgeIndexStore.resolveGovernanceExclusions` 对照实际分块 ID、材料 ID、材料/当前内容哈希、偏移和原始正文检查每个绑定。它不会按标题、单独的序号或文字相似度匹配。

- 精确匹配的已排除分块在所有检索通道中均被屏蔽。重新启用仅移除排除状态；已存标签/修正保持不变。
- 非空修正处于待处理状态，对应分块继续被屏蔽。此层无法准备或发布修正后的词法文字/嵌入，因此不会将旧文字或尚未准备好的修正宣称为当前检索视图。
- 任一记录无法匹配时，暂停其整份材料的检索，并保留原始证据和历史。其他材料仍可搜索。内容和精确身份均相同的重建可复用决策，无须将其复制进索引。目前没有重新绑定/丢弃或可见的复核工作流。
- BM25 MATCH、其短词条件放宽路径、短词 LIKE 回退、向量搜索及混合搜索的两个通道，均在各自 SQL 限额和 RRF 候选选择前应用排除条件。分块级过滤不会屏蔽共享同一嵌入哈希的其他允许分块。绑定的 JSON 数组避免逐 ID SQL 变量上限，也避免将 ID 插入 SQL 文本。

索引搜索完成后，Main 会在调用重排器之前重新验证持久修订和精确索引匹配结果。重排后、返回结果前会再次检查。并发决策变化或导致治理绑定变化的重建会返回可重试的冲突，而不会自动重复可能收费的提供商调用。策略读取失败、受治理索引已关闭时，检索会被阻止。Main 不会将业务数据库与索引数据库视为同一事务，不缓存渲染进程策略，也不记录决策正文。

排除不是删除或访问控制。分块检查和显式原始源读取仍保留原文及偏移；引用和源文件不会被重写。标签不会进入查询文字、模型提示或嵌入。

## 仍待完成的边界

- 写入端点、每知识库串行化写入、批量预览和原子选择验证。
- 源/分块身份变化后的可见待复核状态，以及显式重新绑定/丢弃操作。
- 有效文字/嵌入任务、匹配的词法/向量修订发布及崩溃恢复。
- 持久决策与历史的知识库备份/恢复集成。
- 原文/修正文引用修订及历史引用。
- 检查器控件、用户确认、费用说明及原生应用验收。

在后续工作流落实 Spec 前，不要开放编辑，也不要将修正描述为已索引/已生效。Spec 保持 proposed。这些层仅提供 AC1/AC2/AC3/AC4 的部分基础，不代表完成全部验收或解决 issue #19001。

## 验证

存储测试使用带生产迁移的 `setupTestDatabase()`，覆盖原始证据、独立连接读取、规范化变化、过期修订/源冲突、移除/无变化语义、注入历史写入失败、范围守卫及所有权级联删除。向前迁移测试从增量迁移之前、含已有 Knowledge 数据的状态开始，检查现有数据保留且不会虚构决策。

检索集成测试使用真实迁移后的 Main 数据库、每知识库文件 SQLite、生产 FTS/向量引擎、查询服务和重排路径，仅模拟配置的提供商方法。场景覆盖超过候选上限的排除、所有搜索通道及回退、共享嵌入哈希、数千个绑定 ID、UTF-16 证据、可逆重新启用、待处理修正、精确重建/重新打开、保守处理源/分块不匹配、伪造绑定、原文检查，以及重排前和返回前的修订/索引变化。不宣称已验证真实提供商、原生 Electron、修正发布、恢复或检查器验收。
