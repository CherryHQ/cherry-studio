# 多模型回复与对话分支

同一个问题可以有多个回答，每个回答后面也可以继续自己的讨论路径。切换当前回答决定后续消息沿哪条路径继续；它不会合并不同模型的结论，也不会撤销已经执行的工具操作。

## 一次请多个模型回答

1. 在本机文字对话中打开模型选择器，进入多选模式。
2. 选择 **2–8 个文字模型**，返回输入框并发送问题。
3. 等各模型分别回答，再选择其中一个结果阅读和继续。

多选会立即影响后续发送，但**不改写智能体原来的默认模型**。退出多选、恢复单模型选择后，继续使用对应的智能体模型。普通单选则会更新当前智能体的模型。

多模型回复分别产生模型用量，推理深度使用各模型自己的默认设置；图片生成模型不能加入这组并行回复。

## 阅读与继续某一个回答

在 **设置 → 通用设置 → 多模型回复卡片** 选择展示方式。卡片模式可以进入完整阅读并切换其他回答；普通模式也可在问题的回答版本间切换。

先选中要继续的回答，再提出追问。后续内容属于该路径，其他回答及各自的后续讨论保留。分享只读取所选路径与勾选的消息，不会自动导出所有备选回答。

多模型并行只使用受限制的只读工具集合，不能因为平时使用自动批准就执行写文件、修改日历等动作。需要实际修改时，选择一个回答，回到单模型继续。

## 重新回答和追加模型回答

旧版“重新回答会直接替换唯一答案”的说明已不适用：

* **重新回答**或为同一问题追加另一个模型的回答，会保留可切换的回答路径。
* 回答区提供追加模型的入口时，选择模型再发起；可从该回答继续独立追问。
* 正在执行、忙碌或不支持的消息可能不显示操作；先等任务结束或按页面停止。

重新生成是新的请求，可能产生新的模型费用。保留旧路径也不表示外部操作会回滚，修改文件或发出的内容应到实际目标核对。

## 修改已发送的问题或回答

* **编辑问题**：从已发送问题的菜单选择编辑，修改后重新发送，会从那里建立新分支，保留原问题、原回答与原来的后续讨论。
* **编辑回答**：在本机对话空闲、回答已完成且提供编辑入口时，修改回答正文并保存。保存后的文字会参与之后的对话与分支；这不是重新调用模型，也不会重做或撤销旧工具操作。
* **在新聊天中创建分支**：复制到那个位置的对话上下文，在独立会话中继续，原会话仍保留。

离开回答编辑页前处理未保存提示。需要只引用一部分时，可以选中回答文字插入引用；同一条消息中可穿插多个引用和自己的追问，点击已发送引用可返回来源。

## 在侧边栏查看树形或平铺列表

**设置 → 通用设置 → 分支对话树形视图** 控制列表展示，默认开启。关闭后按最近活动平铺显示，不会删除或合并已有分支；最近列表按智能体/会话分组是另一个选项。

## 排队、取回与“引导”

回复进行中可以继续提交后续消息，队列显示顺序。打开队列项可查看完整文字与附件；尚未开始的消息可移除，或取回输入框修改后再发。已有草稿发生变化时，按冲突提示处理，避免覆盖新内容。

队列提供 **引导** 时，可以把补充要求交给当前任务，让它在之后合适的执行边界采纳。它不等于打断并重写已经完成的输出，也不同于另起一轮排队问题。

队列可随会话状态恢复，离开页面不是取消。先查看运行、等待和审批状态，再决定停止或重发，避免重复执行。普通附件操作见[对话与文件](chat-and-files.md)。
