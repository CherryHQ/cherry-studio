# 本地会话历史导入

- `ConversationImportService.ts` 管理窗口归属、只读预览、取消和逐会话提交。
- `claudeCode.ts` 解析 Claude Code 2.1 系列的 UUID／父链 JSONL 布局。当前夹具版本为 2.1.284。未知布局须报告，不代表已验证全部发布版本。
- `files.ts` 限制输入体积。预览快照只留在内存。
- Codex 工具输入、嵌套命令输出、环境上下文和引用标签由数据服务的 importedCodexText.ts 转成可读历史文本。新导入与旧记录读模型共用转换，不覆盖旧持久消息。旧 Codex 记录的纯环境、项目指令和应用上下文按系统角色显示；混有真实用户正文时保留用户角色。
- 跨进程契约位于 `src/shared/ipc/schemas/conversationImport.ts`。来源身份由数据服务写入，界面不能提交数据库记录。
- Pi 历史初始化位于 `src/main/ai/runtime/pi/importedSessionHistory.ts`。失败后保留可读历史，禁止空上下文续聊。

首版只支持 Pi 目标。保留原时间；未来时间在预览及提交前拒绝。前三个来源仍拒绝时间倒退。
WorkBuddy 通过 app_state 中的 provenance.sourceOrder 保存因果顺序，不新增表、列或数据迁移。导入历史构成固定前缀，续聊按现有规则接在后面。分页、定位、分支和 Pi 初始化使用同一顺序；日期筛选仍用原时间。分支保留消息来源信息，不继承会话级去重身份。
来源文件不写入。每个会话单独使用同步事务。复制清除会话级导入身份，备份恢复保留身份。

测试位于 `__tests__/`。数据库用例使用生产迁移和真实 Pi 历史；模型输入用本地网关夹具捕获。
产品方案见 [本地历史导入方案](../../../../.agents/notes/proposed/feature/2026-11-02-local-agent-history-import.md)。
打开导入弹窗后自动扫描来源默认目录，支持环境变量覆盖；找不到时可手动指定。Claude 候选与预览优先显示来源标题，否则显示第一条非命令用户正文。无法确定是否有用户任务时，仍保留候选；没有可用标题时用来源名称和日期。Claude 命令标签、ANSI 控制码和工具 JSON 转为可读历史文本。旧导入记录通过消息读模型显示相同格式，不覆盖持久历史。
导入窗口只保留“导入选中对话”主按钮。点击后自动校验，再提交同一快照；逐条跳过阻塞项并保存有效会话。界面保留成功结果，重试时只提交未成功的选择。全选作用于当前搜索结果中显示的最多 100 项，保留其他已选项且批次仍不超过 100。标题单行截断，完整文字可悬浮查看。
错误在独立弹窗中按失败会话分组，合并重复原因。仅可修复的问题提供分支、目录和重试操作。含不可恢复错误的会话只显示失败原因，移出待重试选择，也不显示无效的目录或分支建议。关闭错误弹窗保留选择。外部应用与本地应用使用两个设置卡片。
工具内容以静态文本持久保存。读模型将工具标记转为已完成的展示工具项，复用“已处理”折叠区；工具项不请求审批或执行历史工具，也不改变续聊历史。连续的历史思考和工具记录在显示层共用一个“已处理”，包含已终止的错误或中断工具；遇到正文或用户消息即断开。保留原消息 ID，多选和截图仍按原记录处理。旧记录同样适用。
导入消息的名称和头像使用当前智能体，模型信息保留来源快照。完整历史加载后，以首条真实用户消息为显示起点，隐藏之前的项目指令、环境信息等前置信息。分页尚未到开头时不截断。原始消息及续聊上下文保留；图片导出使用相同显示规则。
历史聚合读取由 AgentSessionMessageService 管理，状态模块不反向依赖排序模块。编辑重发删除消息尾部后，只刷新一次初始化消息数量。
来源身份、初始化状态和消息来源由 importedSessionHistory.ts 管理，存入 app_state。会话键为 conversation-import:session:<sessionId>，消息键为 conversation-import:message:<sessionId>:<messageId>。只长期保存来源、原会话 ID、消息顺序和初始化所需状态。
去重查询会话键范围并关联实际会话，包含归档会话。相同来源和原会话 ID 直接跳过，不比较旧文件版本；首次导入仍复查预览指纹。永久删除清理状态后允许重新导入。若旧预览显示已存在，而提交时该会话已删除，则要求重新预览。写入和清理均在原生数据事务内完成。分支复制消息来源但不复制会话身份。未发布的导入迁移已撤回；新结构验证使用独立 profile，不修改旧草稿数据库。

发现阶段排除已确认的非对话会话，接口返回内部原因和计数。界面不显示“已过滤”统计，只在无可导入会话时显示空状态。Claude 仅在已核对的 2.1.207、2.1.211、2.1.284 布局中，完整父链和全部分支均无真实用户任务时排除。图片、文档、短提问和混有任务的设置会话保留；自定义命令、未知版本、未知记录及损坏历史保留待校验。选中纯设置分支但另有任务分支时，要求选择有效分支。预览复查后被排除的记录返回 filtered，不计入成功或失败，不提供强制导入或重试。提交仍核对指纹；排除不写库、不初始化 Pi，不改来源文件或已有会话。
`codex.ts` 读取 legacy 完整 rollout，以及无继承依赖、ordinal 从 0 连续递增的 paginated rollout。按 `session_meta.id` 区分线程，只用索引补名称。事件镜像不重复写入。分页继承、序号缺口、多物理副本、回滚、压缩与加密正文在校验时拒绝。加密推理无法迁移，计入降级并保留可见正文。结构依据为 openai/codex 的 dbaead0106de82bd129a4f6f503d173ad5109f68；夹具覆盖 0.114.0 和 0.154.0-alpha.6.2 布局；另只读核对了用户提供的 0.164.0-alpha.11.1 结构。不承诺全部 0.x 发布版。

Codex Guardian 过滤只识别已核对的 0.164.0-alpha.11.1 布局，依据 session_meta.payload.source.subagent.other=guardian，不依据标题。先按来源 ID 汇总全部物理副本；存在副本冲突、缺失分页或损坏记录时保留校验。普通子代理及同名用户会话保留。
`opencode.ts` 在只读 SQLite 事务中读取同一快照。识别旧版 session/message/part，以及新版 session_v2/session_message，后者可带 session_part。按 seq 或旧版 time_created、id 排序。版本夹具为 1.2.0 和 2.2.5；新版结构依据 anomalyco/opencode 的 1bf08ae46a91f7793c756e4ee521e37b6b554064。旧版结构依据该提交的 v1-migration 源类型。夹具为合成数据，不能替代真实安装版验证。回退、继承 fork、压缩和未知表结构均明确拒绝。数据库指纹覆盖被选会话的逻辑快照，包含 WAL 已提交行，不要求复制数据库。

`workbuddy.ts` 关联只读 sessions 索引和 projects 下的直属 JSONL。结构依据为 Windows 桌面 5.9.3 与运行时 2.165.0 的本地样本。支持顶层正文、rawContent 思考及静态工具记录；缺少本地正文、未知附件和不完整父链会阻止导入。不同路径分隔符按来源平台语法比较。索引行和正文共同参与指纹；无关行更新不使预览失效。
WAL 模式要求现有 WAL/SHM 边文件，避免只读打开时创建来源边文件。无法安全读取时明确拒绝，不 checkpoint 或修复来源。
WorkBuddy 入口仅在开发环境可操作，正式构建保持禁用。三平台真实来源和打包验收尚未完成。此限制不代表读取器已覆盖所有发布版本。

WorkBuddy 优先保存 providerData.model 中的实际模型。快速／均衡属于请求路由；只有路由信息时明确标为 WorkBuddy 路由名称，不猜测实际模型。
