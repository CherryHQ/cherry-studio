# Terminal Host runtime

Child-safe modules own the conversation's processes, bounded capture, operation receipts, and VT state. They import neither the Main application container nor lifecycle services. `terminalHostEntry.ts` is the production entry; tests import the kernel and backend directly.

`ManagedProcess` launches the native scope helper under either pipe stdio or node-pty. A scope starts only after its UUID-checked `ready` frame and Host acknowledgement. PTY input uses the patched public `writeAsync()` API so pending writes remain bounded and write failures remain observable. Stop targets the live private scope connection, never a remembered PID or node-pty's PID-based kill method.

Command exit and helper exit are separate facts. Only a scope-empty event followed by helper/stdio closure confirms cleanup. A failed or timed-out close retains the connection and resource for safe retry. Observation cancellation does not close resources.

`ShellIntegration` consumes bounded, chunk-safe, nonce-tagged private OSC frames from the Bash/zsh/PowerShell integrations. Prompt facts and command completion come from those frames, not output silence or process liveness. Invalid frames leave shell state unknown. The Bash script preserves prompt hooks and owns its DEBUG trap; custom shell integrations that replace these hooks can make command facts unavailable.

The Host owns one Ghostty core per PTY, configured for native unlimited scrollback. View offsets are bounded by the actual retained history rather than a fixed line-count ceiling; each response still contains only a bounded viewport frame. Raw-capture and block-metadata eviction do not erase Ghostty cells. View snapshots temporarily select their independent scroll position, then restore the core to the live bottom. Key, paste, mouse and wheel input is encoded against current terminal modes. Geometry epochs reject input captured before resize or alternate-screen changes. Views never write terminal-generated replies.

Terminal-generated replies coalesce in a bounded 64 KiB buffer and drain through the same two PTY write slots as user input. A burst of capability queries waits for capacity instead of closing the terminal. Replies are produced by the Host even when no view is attached.

`TerminalBlockIndex` owns per-PTY metadata and tracked anchors, not a transcript. Verified program and prompt boundaries record command timing. A monotonic Host clock measures the completed interval; running summaries carry the wall-clock start for local display. An unknown boundary or process loss discards unfinished timing. `TerminalSearch` owns per-view query state under the Host's scheduler. Block search reads a dedicated bounded snapshot: native OSC 133 input cells supply command text and coordinates, and the existing output range supplies output text and coordinates. Primary and continuation prompts and attachment-only metadata are excluded. Missing display ranges and genuine size/mapping limits remain explicit. Output mapping charges only retained text spans against its budget, excluding trimmed row padding; wide-cell mappings include the trailing column. Copy/Attach keep their separate metadata-rich snapshot format. Neither is a lifecycle service or another process. Search projections number matches in terminal reading order, from top to bottom and left to right. Next moves forward and Previous moves backward, with wraparound; the Host adapts native newest-first indexing without changing engine ownership. Main supplies only authorized view identities; native handles stay inside the Host. Frames freeze cells, block summaries, search projection and row mapping under one baseline. Renderer layout spans are accepted only for their native revision and geometry epoch.

The real shell integration fixture includes optional PowerShell coverage when `CHERRY_TEST_PWSH` supplies an absolute executable path. Its isolated home covers native failures, cmdlet failures, multiline Unicode metadata, duplicate Run again, interactive input and dirty-editor rejection alongside Bash/zsh.
