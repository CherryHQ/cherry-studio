# Terminal execution

The [shared Agent terminal Spec](../../../../.agents/notes/proposed/architecture/2026-11-14-shared-agent-terminal.md) assigns one lazy utility Host to each product conversation. `TerminalService` is its Main lifecycle owner. Each Host owns independent fresh pipe executions and persistent node-pty resources. Pi and Pi Durable forward native shell calls through this owner. The Agent terminal pane uses window-bound IpcApi views; Claude Code and ACP keep their native execution paths.

`attachRuntime()` binds a runtime context without starting a Host. `start()` reserves capacity before awaiting startup and binds the runtime's stable replay key to one immutable launch. Concurrent first admissions join the same generation. Completed receipts remain in Main after Host recycling; `list()` and `read()` never create a Host. Callers supply an absolute executable, exact argv, cwd and full environment. Pipe stdin closes after the supplied input. The user terminal starts the configured default shell. Managed Bash, zsh and PowerShell integrations verify prompt, cwd, command start and completion; [shell startup](../../../../resources/terminal/shellIntegration/README.md) preserves the user's configuration. Agent command submission requires the current prompt revision; raw stdin requires the current command and program revision. Unknown or busy shell state refuses a new command. User input requires the controlling view; observing never acquires control.

Host operations record their decision before effects and fence generation, context, control and cancellation revisions. Bash promotion changes retention on the same execution and preserves its deadline. Agent Stop targets turn-owned pipes; retained work survives runtime release. User takeover survives old-runtime release, including a pipe execution. Control changes refuse pending writes rather than grant a new holder while an old write remains outstanding.

Main owns the bounded observation stream independently of views. Capture gaps remain visible in byte cursors and truncation flags. Confirmed final output and cleanup permit resource release; only an empty Host with no pending admission can retire. New admission waits for confirmed old Host exit. Host loss preserves unresolved cleanup records and resource quotas; it never replays executions.

Limits are eight unretired Hosts, sixteen active pipe scopes globally, four pipe and four PTY resources per conversation, eight pending admissions per conversation and thirty-two globally. Replay bindings cap at 1,024 per conversation and 4,096 globally; exhaustion refuses admission. Each resource has a fixed 2 MiB raw capture ring; Main retains a 64 KiB suffix per execution. PTY writes cap at two outstanding writes and 128 KiB, with 64 KiB per write. The Host operation index holds 1,024 entries; retired sequence identities cannot become fresh operations. These limits are not measured capacity claims.

`ghostty/GhosttyRuntime.ts` instantiates the pinned WASM from supplied bytes, checks its embedded source revision, and routes terminal-generated replies without a view. A Host owns one runtime; there is no application-wide singleton. Its log callback uses the utility runtime's logger.

`ghostty/GhosttyTerminalCore.ts` owns per-terminal handles for VT parsing, cell snapshots, keyboard/paste/mouse encoding, selection, scrolling, and geometry. Browser events are normalized before entering it. Dispose individual cores before releasing their owning runtime. Disposing one core leaves sibling cores usable.

The engine and `utilityEntries/` are child-safe implementation modules with direct imports and no barrel. Main supplies registered asset/helper paths through init data; child modules import neither the application container nor Electron. Binary provenance, licenses, and rebuild instructions live with the [assets](../../../../resources/terminal/ghostty/README.md). The [native scope supervisor](../../../../native/terminal-scope/README.md) owns OS cleanup evidence.

Each view pulls compact, bounded cell frames with an explicit baseline revision and geometry epoch. Views scroll independently; a gap requests a new baseline without replaying input. Only the controlling view can resize or send input. Closing a window or detaching a view leaves processes running. Main retains a bounded final-screen projection after confirmed cleanup, with a raw-output fallback when the screen budget is exceeded. Terminal state is ephemeral; no database records are introduced.

The [Canvas surface](../../../renderer/components/terminal/README.md) draws these cells without parsing VT. The 5,000-line engine history cap, aggregate 64 MiB accounting, bounded parser scheduling and representative memory/process measurements remain follow-up work. PTY `scrollbackBytes` is 1 MiB here; it is not an RSS or aggregate-memory guarantee.

Root-process exit does not prove descendant cleanup. POSIX scopes retain their supervisor session and root identity; Windows scopes retain a Job Object assigned before execution. A stop waits three seconds before force termination and five seconds before returning unconfirmed cleanup. Unconfirmed resources retain their slots and current scope connection for retry; late scope-empty evidence can confirm cleanup. No stored PID or node-pty kill method is used. The supervisor is for trusted local execution, not daemon containment or a security sandbox.
