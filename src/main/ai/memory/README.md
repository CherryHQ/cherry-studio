# 记忆存储底座

本模块实现 [共享记忆 Spec](../../../../.agents/notes/proposed/feature/2026-10-29-shared-memory.md) 的文件提交、访问权限、入口加载、编辑、最近操作恢复、旧 FACT 迁移和 Dreaming。Pi 已接入受控读取、写入和编辑。已恢复定向测试并补充迁移、整理和生命周期回归。完整行为验收尚未完成，Spec 保持 proposed。

- `MemoryStore.ts`：一个作用域由一个实例串行提交。调用方身份使用主进程持有的 `MemoryAccess` 对象，不能从模型或 IPC 输入反序列化。
- `MemoryService.ts`：生命周期服务。按作用域复用存储实例，绑定调用方凭据，提供暂停、排空和恢复失效入口。
- `memoryAuthority.ts`：从主进程会话、实体配置和受管理窗口确定权限。每次操作重查数据库，不接受模型提供的身份。
- `memoryPrompt.ts`：按当前权限读取入口，标明截断和未加载的主题。加载后释放会话，组装引用前再次检查权限。
- `memoryTarget.ts`：识别请求路径和真实目标中的受管理文件，阻止通过普通文件工具读取恢复备份。
- `MemoryEditorService.ts`：把编辑会话绑定到主窗口。窗口关闭后释放会话，其他窗口不能复用凭据。
- `MemoryMigrationService.ts`：串行迁移私有 FACT，备份原文并核对目标后才启用。`legacyMemoryPlan.ts` 保留完整 Markdown 小节，不能安全拆分时停止迁移。含引用式链接或图片的 FACT 超出入口容量时保留原文件并停止迁移，避免引用与定义分离；能完整放入入口时仍按原文迁移。
- `MemoryDreamingService.ts`：维护单个全局整理队列、代次、取消和空闲检查。`memoryDreamingState.ts` 独占永久复核元数据；模型调用与提案校验分别在 `memoryDreamingModel.ts`、`memoryDreamingPlan.ts`。
- `memoryFiles.ts`：管理文件白名单、真实路径、完整读取、容量检查和文件替换。
- `memoryBackups.ts`：保存原始字节、预期哈希和逐项结果。备份位于活动目录之外。

服务从路径注册表获取根目录。私有范围检查现有 Agent 目录。人工 `read()` 返回完整正文与调用方绑定的凭据。模型 `read()` 返回按用途过滤的视图；结构化范围不给覆盖凭据。`entry()` 可能截断，因此不返回编辑凭据。

启动监听与开放服务使用 `override onReady()`。生命周期不会调用 `onStart()`。测试通过 `_doInit()` 和 `_doStop()` 验证真实入口，不能直接调用自定义启动方法。

Agent 的 `configuration.shared_memory_enabled` 缺省为开启。持久助手的 `settings.enableSharedMemory` 缺省为关闭。临时、辅助和普通 headless 助手不开放记忆。渠道 Agent 只能访问所属私有范围。编辑器要求真实的主窗口身份。Pi 在新轮次、结束和关闭时释放文件会话及读取关联。

关闭共享开关后，旧会话凭据不会因重新开启而恢复。实体数据服务只发布权限失效事件，文件操作仍归本模块。完整备份已接入 `pause()` 和 `drainInFlight()`；恢复提交启动日志后调用 `invalidateAll()`，保持暂停直到重启。

Pi 在每次模型请求前替换 `cherry_memory` 系统区块，保留其他提示词和工具声明。Claude Code 在 `UserPromptSubmit` 和 `SessionStart` 提供完整引用，空引用撤回先前内容。已发送的上下文不能收回。助手入口仅接受持久聊天 owner 创建的主进程 `memoryContext`，每次 `prepareStep` 重新读取，覆盖压缩后的请求。入口引用不代表获得保存能力。

Pi 的原生 `read`、`write`、`edit` 在执行入口调用原有审批器。受管理完整读取返回 `memoryReceipt`，修改必须显式带回同一轮次、同一文件的凭据。编辑继续使用 SDK 的替换算法，但最终保存归 `MemoryService`。审批带准确的完整提案；流式审批先刷新工具输入，再发出审批请求，卡片以只读正文展示拟保存内容和文件名。模型传入的预览字段不作为审批依据。审批中编辑输入后需重新发起操作，不能沿用旧提案。最终替换前检查权限、取消、工具开关和审批模式。普通文件继续走原工具。

Claude Code 的原生钩子尚不能提供完整执行接管，因此拒绝命中受管理记忆的原生文件操作和包含它的搜索。没有调用方身份的内置 filesystem MCP 也拒绝受管理目标、恢复备份和相关目录操作。Shell 与外部工具仍不属于保护范围。当前未提供原生删除、重命名或主题搜索能力；这些能力不能宣称已完成验收。

Pi 的可选 grep、find 和 ls 也拒绝受管理目标及其祖先目录，防止 SDK 动态启用这些工具后绕过主题读取边界。审批中改动搜索目标后再次检查。

设置页 `/settings/memory` 不展示文件区域，不列举或读取正文，不提供 Agent 私有记忆入口。“恢复备份”和“清除全局记忆”分别使用独立的 `SettingRow`，右侧为“恢复”和红色“清除”按钮，操作前确认。清空窗口不列文件，后台 token 仍绑定文件集和版本；恢复窗口保留列表。恢复成功显示“已保存”，清空成功显示“清除成功”；各自显示在对应操作行的按钮左侧，并与按钮垂直居中对齐。操作使用 `memory.*` IpcApi；表单中的“使用共享记忆”沿用实体 DataApi，与其他基础字段使用相同布局和小尺寸开关。Agent 的该行放在整个心跳检测区域之后。状态只来自实际提交结果，不展示索引、条目计数或容量，不自动重试写入。开关旁复用默认模型页的 `InfoTooltip`，支持悬停和键盘聚焦说明。

渠道停用、删除或变更所属 Agent 后，原渠道会话永久失效；重新启用需重新读取。Agent 删除同样使已打开的私有编辑器失效，恢复 Agent 不恢复旧凭据。渠道更名和无关渠道变更不撤销当前会话。

模型入口先在 20 MiB 预算内核对完整作用域状态，再按完整行截取至 25,000 字节。超出检查预算时保留原文件并拒绝注入。完整原文读取同样受 20 MiB 预算限制。

`commit()` 向权限层提供不可修改的准确提案。权限层返回授权存续检查。自动批准仍需此检查。调用方权限由 `MemoryAccess.assertAuthorized()` 的会话存续检查撤销；清空、恢复或删除作用域时使整个作用域失效。

授权存续检查必须同步执行，临时文件准备完毕、替换前再次调用。最后一轮异步验证后仍核对提案原始代次，并显式传入写入流程，不能重新取得当前代次。清空和恢复仅在验证后允许推进一次代次；备份写入期间发生的额外撤销仍使操作失效。整理提交通过 `readReceipts` 绑定全部输入，即使其中部分文件不修改或整批无需修改。

`previewClear()` 只保留已核对的文件集、哈希和读取凭据。`clear()` 在作用域锁内复查文件集和版本；新出现的受管理文件会使确认失效。清空移除正文，为非空旧正文保留无来源 forgotten 标记。未知文件和历史文件不变。备份仍保存，但应用内恢复不能移除遗忘标记或恢复受保护正文；此类恢复返回 conflict。

原生工具适配器必须保留真实读取与具体编辑的关联。不能把最近一次读取凭据自动套给更早的编辑。工具截断了正文时，不能将该次读取用于编辑。

同批次在审批前和写锁内按文件实际标识排除别名，包含大小写不敏感卷和硬链接。最新恢复批次记录入口删除时，初始化保留缺失状态；用户后来创建的同名文件仍按冲突处理。崩溃批次复核为全未修改时，恢复预览继续选择上一份有效批次。

Agent 目录已存在 `.memories/` 时，目录初始化不自行补建缺失入口；由记忆存储结合恢复历史判断，避免早于存储初始化破坏删除基准。

备份清单使用 JSON，原始字节以 Base64 保存。20 MiB 限额按实际清单字节计算，包含编码开销。文件与 SQLite 不构成同一事务。恢复检查磁盘结果，不重放旧操作。

混合已提交、未提交或冲突的批次保留为 partial，不进入自动配额清理。恢复前也先保护原批次。只有全部恢复成功且没有冲突时才解除该保护，避免新恢复批次取代它后丢失剩余原文。准入时为新旧批次都预留最长状态文本的空间，避免恢复状态变长后超过容量。

迁移批次可额外保存旧 FACT 的原始字节和哈希，仍计入同一容量限制。该原文不是受管理恢复目标，不能伪装成新入口修改前的内容。提交前和锁内都检查旧 FACT 基准。`initializeMemoryFiles()` 统一初始化活动文件，供 Agent 目录 owner 复用；不覆盖已有正文。

完整备份在首个写入前落盘，结果在批次完成或失败时保存。避免每写一个文件就重复序列化整批原文。崩溃留下的 pending 步骤按实际哈希复核，不重放。只读旧 FACT 回退可复用有界入口读取，不产生编辑凭据。

迁移状态由本模块独占的 `app_state` 键保存，只有文件名、哈希、批次引用和状态。完整迁移退出旧 FACT 注入。失败保留只读旧事实，新私有范围不启用；不会重放部分完成的旧计划。相对链接、片段链接、HTML 链接和 wiki 链接需人工复核，不自动搬迁或拆分；绝对链接及代码中的示例保持原文。当前没有私有编辑页入口；混合版本需先处理恢复。旧 Agent Memory MCP 停止挂载，JOURNAL 不再追加；原生文件和内置 filesystem 工具也拒绝历史目录。旧文件、身份文件、独立图谱 MCP 和知识库保留。

“聊天中生成记忆”和“自动整理记忆”是两个独立全局开关，默认均开，分别保存为 `feature.memory.generation.enabled` 和 `feature.memory.dreaming.enabled`。关闭生成只停止提炼并撤销其未提交输出，不影响已有记忆的自动或手动整理。关闭自动整理仍允许生成和手动整理。

`memoryExtraction.ts` 从主进程成功完成事件接收新桌面对话。Agent 仍需开启共享访问，Assistant 必须明确开启。渠道、后台、临时、合成消息和跨会话投递不参与。核对当前归属、回复作者快照、消息版本和访问开关，只向模型传用户文本和共享入口。实体配置更新后只接受更新之后的新消息，保守跳过更新前的进行中轮次。

提炼与整理共用一个物理互斥锁和 `memory.dreaming` worker。待处理队列最多 32 项，仅存主进程内存中的 ID、哈希和时间。每个对话的 `memory:extraction:<kind>/<id>` 游标持久保存已接收位置与结果，不存正文。准入推进游标，溢出和失败不自动重试。重启、取消、清空、恢复和开关变更丢弃旧任务；开启后和清空后不补跑历史。实体撤权使其任务失效，不影响其他调用方。

提炼指纹绑定消息内容、回复、所属实体和授权边界，不使用会话的通用更新时间。自动命名或单纯改标题不丢弃任务。Topic 删除或变更所属助手、Agent Session 删除后，由数据服务提交后的事件撤销相关任务；恢复原会话或原归属也不会复活旧任务。

每次提炼最多读取 8,000 UTF-8 字节用户文本，提示词最多 50,000 字节，并核对模型容量。只调用一次默认模型，禁用工具和重试。模型最多选择五段原文，每段最多 500 字符，并给出通用偏好、个人事实、项目、客户或不确定分类。共享按未来用途接收通用偏好和有依据的个人事实，个人事实可包含计划、决定、约束和有意义的经历。不再要求用户明确说“记住”，也不要求反复出现或永久有效。一次性指令、无持续用途的闲聊及明确要求不记住的内容不收；项目、客户及不确定类别跳过，缺少或未知分类拒绝保存。混合消息保留归属和条件，不能截掉项目限定后冒充个人偏好。分类仍可能误判，不构成语义隔离证明。程序逐字核对，去除已保存引文，再追加到入口。已有正文不改写。入口容量不足时拒绝保存。保存复用完整读取凭据、备份和最终同步授权检查；来源编辑、删除或撤权会阻止旧结果落盘。已保存的记忆不会随来源删除自动消失，可通过现有删除或恢复操作处理。模型对长期价值、敏感信息及条件完整性的选择仍需代表性模型验收。

Dreaming 使用应用默认模型。`memory.dreaming` 处理器在初始化时注册，恢复策略为 abandon，所有作用域共用并发为 1 的队列。只有一个每分钟唤醒的持久调度，错过时间点不补跑。每次轮转检查一个作用域的入口和最多九个主题，优先处理已变化且符合条件的文件。未选中文件不推进已处理标记。

十次受控内容修改、最早待处理变化七天、变化后的容量预警或手动请求触发整理。旧文件观察使用哈希，不从哈希推算修改次数。无修改、失败、Dreaming 和恢复不增加计数。每份未变输入最多尝试两次，间隔十分钟；新内容、明确手动请求或更换默认模型提供新的机会。永久标记只存哈希、时间、计数、代次和短状态，不依赖任务历史，也不保存正文。

模型输入不超过十个完整文件和 50,000 UTF-8 字节。入口必须完整保留，主题按模型上下文、输入和输出上限逐个装入。单独也无法与入口装入的主题标记为预算阻塞，继续处理较小主题；仅因当前批次已满而未选中的文件留待后续。预算阻塞不会反复尝试，新内容、手动请求或更换默认模型可重新检查。每批只调用一次模型，关闭工具、自动重试和上下文裁剪，不传聊天、JOURNAL、身份文件或其他作用域内容。推理不持有文件写锁。

提交复查全部输入凭据。删除还在锁内复查完整活动文件集，要求源和目标是不同主题，禁止以 `MEMORY.md` 作为删除源或转移目标；原文含空白字符须逐字保存在完整写出的主题目标，并检查剩余 Markdown 和 wiki 链接；HTML 链接交给人工处理。先写目标和链接，再删来源。成功文件才更新进度，失败保留恢复资料。程序不证明模型改写语义等价。

清空、恢复、暂停和完整恢复通过 `MemoryService.onInvalidated` 先撤销尚未提交的维护输出。关闭生成只使旧提炼失效；关闭自动整理只影响整理。手动取消、Agent 删除和重启也撤销相关任务。前台对话开始后取消模型调用，提交时同步复查空闲状态。最近完成、失败或取消的结果保存在 `lastResult`，切换开关不伪造成功。设置展示独立开关、整理/取消和最近结果，不展示内部队列、计数或容量参数。

该保护只覆盖经过本模块的写入。外部编辑、Shell 和其他直接磁盘访问不受作用域锁约束。当前测试覆盖 Windows；其他平台原生文件检查仍需补齐。

文件保存复用通用原子写入。临时文件排他创建并使用 0600 权限。异步路径校验结束后，同步权限检查紧邻 rename 发起；这不代表 JavaScript 检查与系统 rename 构成原子撤权。

界面仅开放共享记忆的清空与恢复。文件读写由 AI 工具和后台维护使用，不提供 memory.file.* 接口或独立重命名操作。

私有编辑器没有产品入口，不保留从编辑器重试迁移的支线。失败迁移保留原文；修正原文后，重启可重新检查。

## 指定片段的候选提炼

自动摘录、候选提炼、跨批核对和文件整理不设置调用级输出 token 上限。容量检查中的输出估算只用于给输入留出空间，不传给模型作为截断阈值。服务商默认值和模型容量仍然有效；返回正文的字节限制、结构及证据校验保持不变。

`MemoryDreamingService.previewExtraction()` 通过 `memory.dreaming.preview_extraction` 提供主窗口专用的候选验证接口。当前没有界面入口，也没有保存接口。自动摘录与候选提炼使用相同的未来用途判断；自动摘录仍只取单条原文，不能把候选链路当作已上线的自动提炼。文件整理不变。

调用方给出首条用户消息及末轮成功回复。`memoryExtraction.ts` 沿父节点读取同一分支，最多 64 条、64,000 UTF-8 字节，每条最多 8,000 字节。只读取本次启动、生成开关变化、清空及实体授权边界之后的片段。不扫描其他会话或旧历史。输入仅含用户与助手的可见文本；助手文字不作为事实证据。超出范围直接报告预算不足，不静默截断。

每批最多 16,000 字节消息，保留最多两条完整重叠消息。读取共享入口及所有主题，最多 40 个文件、32,000 字节；放不下时停止，不假装已检查全部记忆。输出包含完整正文、主体、条件、时间、用途、动作及逐字证据。模型只返回消息 ID、旧文件路径和逐字引文，不接收或生成版本串。程序从本次读取的快照补齐消息和文件版本，再校验完整候选。跨批核对也不向模型传版本串。返回前仍复查来源、文件集、文件版本和权限；无效引用或来源变更仍使预览失败。按未来用途选择内容：减少重复询问、改善建议、跟进计划、回忆重要事件或避免重复错误。个人事实、经历、计划、决定和约束不需要明确的记忆请求；用途须写明，不能以“也许有用”为由收下全部聊天。项目与客户候选不进入个人共享范围。相同内容、冲突、证据不足和无合格内容分别返回，不自动覆盖旧事实。

提示词要求一条候选只说一件事。事实的必要条件不能拆掉，当前活动与未来目标应分开。愿望或目标不等于已作出的决定，也不应再生成重复包含它们的综合条目。

多批产生多条候选时，再调用一次模型核对全部候选及其证据。程序先按主体、范围、分类、动作、条件和时间的精确值划分可合并组。模型只在组内判断重复，但仍检查所有候选之间的冲突。字段一致不代表内容重复；部分重叠不能直接合并。明确重复才合并，并保留全部来源和旧记忆引用。跨组、单条或引用合并超限的重复组不合并，保留原来已验证的各条内容，不影响其他组。

冲突或关系不明时保留各条正文，将原本的新增或已存在动作降为证据不足，不自动选取最新说法。候选编号必须完整覆盖且不能重复。核对超预算、返回结构错误、编号缺失或重复等问题仍使整次预览失败。冲突组的引用超限仍报错，不退回未经冲突处理的新增项。核对依赖模型判断，不能证明语义正确。

提炼复用原互斥锁、默认模型和无工具调用。来源编辑、手工改记忆、撤权、清空、取消、前台抢占或调用窗口失效后，不返回旧候选。跨批核对遵守相同预算、取消和版本检查。结果仅在调用期间保留，不推进旧提炼游标，不新增持久状态，不创建写入备份。中断后需重新请求；不声称已有重启恢复。

旧上下文隔离尚未实现，所以结果固定标为预览且禁止保存。该门槛来自首批计划 D5。后续接入界面和保存前，必须先补齐遗忘及删除保护，再验收真实写入。引用校验只能证明原文存在，不能证明模型概括语义正确。

2026-10-30 使用 `gpt-6.1-sol`、`gpt-6.1-terra`、`gpt-6-luna` 和 `gpt-6-astra` 运行服务级真实模型集成测试，各 44/44 通过。每个模型覆盖提取 20 项、整理 20 项、回忆链路 1 项，以及取消和 Agent 隔离等运行保护 3 项。测试包含主题实际合并、删除和完整恢复，未把空修改算作合并成功。

测试复用生产记忆服务、真实 SQLite 和文件；只在 AiService 边界替换为真实 HTTP 调用，完成事件和 worker 由夹具驱动。结果不代替完整桌面聊天、真实定时调度、多平台、大容量或打包验收，也不能证明模型永不误分类。

## 条目状态的模型读取

模型读取通过 `MemoryStore.modelRead()`，先检查整个作用域的白名单活动文件，再按用途过滤。当前回答排除过期条目，历史读取保留过期状态与适用时间。已遗忘条目、同来源消息的副本及已知派生链不返回；来源版本变化不解除限制。损坏格式、重复 ID 或缺失派生来源拒绝读取。无法区分的旧正文在受保护范围内拒绝读取。

`MemoryService` 用主进程登记的编辑器身份区分人工原文和模型视图。模型不能通过参数取得原文权限。结构化范围不给整文件覆盖凭据；普通旧 Markdown 保留原契约。Pi 的 `memoryPurpose: historical` 只开放历史用途，不解除遗忘过滤。Pi edit 同样重新读取过滤视图。

候选提炼绑定实际消息来源，并在每次模型请求前后复查作用域文件集、哈希、权限和代次。未知来源的过期或遗忘状态会暂停该范围提炼。自动摘录仍需要完整覆盖凭据，因此结构化范围暂不保存；结构化整理也明确拒绝。读取状态总预算为 20 MiB，超限拒绝模型读取，不能只读开头后假定末尾没有遗忘标记。

这些检查只保护新组装的受控输入。旧消息、工具结果和摘要的运行时隔离仍待接入；状态操作、候选保存和原文召回未开放。外部文件工具与 Shell 不在本模块保护范围内。

### 运行时拒绝策略（增量）

`assertRuntimeSafe()` 检查持久条目状态。范围存在过期、遗忘或损坏状态时，当前运行时拒绝整次请求。Pi 与 Claude Code 在连接和提交处检查，并在受控失效时关闭旧连接。Claude 原生启动/提交钩子返回停止结果。AI SDK 的真实 provider fetch 同样检查；网关用认证后的 Agent 会话身份绑定，覆盖原生工具轮次和压缩请求。共享开关关闭不解除持久状态检查。

本批没有重建干净上下文。受保护范围中的新持久会话也会被保守拒绝。临时无记忆请求不受影响。持久暴露签名、精确的新会话准入、单纯撤权后的跨进程历史隔离仍需补齐。旧纯 Markdown 清空已保留持久遗忘标记。已发给服务商的内容无法撤回。Claude 订阅登录的完整原生取消时序尚未验收。保存门禁和评测暂停保持不变。


Claude 预热按主进程会话身份持有记忆守卫。准备配置、启动等待、消费等待和驱动移交期间均检查。条目离开预热缓存后仍由消费集合跟踪，失效后不能移交。驱动在原生打开和观察建立后再次检查；同步移交前检查两个守卫，再由连接守卫继续负责取消。该路径不依赖网关，也适用于订阅登录。

预热关闭先撤销守卫，再等待启动结果、SDK dispose 和进程退出信号。关闭失败或缺少退出证明时保留失败条目，拒绝复用和冷启动回退；显式 close 可重试。清理回调捕获异常，避免未处理的 Promise。测试使用真实记忆文件和 SQLite，但原生进程启动、退出信号及运行时接收器为可控替身，不能当作真实 CLI 取消验收。
