# 记忆存储底座

本模块实现文件提交、访问权限、入口加载、编辑、最近操作恢复、旧 FACT 迁移和 Dreaming。Pi 和 Claude Code 已接入受控读取、写入和编辑。本文描述当前实现；目标设计见[共享记忆 Spec](../../../../.agents/notes/proposed/feature/2026-10-29-shared-memory.md)。

- `MemoryStore.ts`：一个作用域由一个实例串行提交。调用方身份使用主进程创建并持有的 `MemoryAccess` 对象。
- `MemoryService.ts`：生命周期服务。按作用域复用存储实例，绑定调用方凭据，提供暂停、排空和恢复失效入口。
- `memoryAuthority.ts`：从主进程会话、实体配置和受管理窗口确定权限，每次操作重查数据库。
- `memoryPrompt.ts`：按当前权限读取入口，标明截断和未加载的主题。组装引用时复查权限和读取快照，随后释放会话。
- `memoryTarget.ts`：识别请求路径和真实目标中的受管理文件，阻止通过普通文件工具读取恢复备份。
- `MemoryEditorService.ts`：把编辑会话和凭据绑定到主窗口，窗口关闭后释放会话。
- `MemoryMigrationService.ts`：串行迁移私有 FACT，备份原文并核对目标后才启用。`legacyMemoryPlan.ts` 保留完整 Markdown 小节，不能安全拆分时停止迁移。含引用式链接或图片的 FACT 超出入口容量时保留原文件并停止迁移，避免引用与定义分离；能完整放入入口时仍按原文迁移。
- `MemoryDreamingService.ts`：维护单个全局整理队列、代次、取消和空闲检查。`memoryDreamingState.ts` 独占永久复核元数据；模型调用与提案校验分别在 `memoryDreamingModel.ts`、`memoryDreamingPlan.ts`。
- `memoryRecall.ts`：通过 `memory_search` 按需回查同一助手或 Agent 的聊天原文，复用现有 FTS5 索引。
- `memoryTime.ts`：按来源消息当地日期保存时间依据，保留模糊精度和目标条件。
- `memoryRuntimeState.ts`：在 `app_state` 保存每个会话和作用域首次通过检查的保护状态指纹，不保存正文。旧会话不能用新指纹覆盖原记录。
- `memoryFiles.ts`：管理文件白名单、真实路径、完整读取、容量检查和文件替换。
- `memoryBackups.ts`：保存原始字节、预期哈希和逐项结果。备份位于活动目录之外。

服务从路径注册表获取根目录。私有范围检查现有 Agent 目录。人工 `read()` 返回完整正文与调用方绑定的凭据。模型 `read()` 返回按用途过滤的视图；结构化范围不给覆盖凭据。`entry()` 可能截断，因此不返回编辑凭据。

启动监听与开放服务使用 `override onReady()`。测试通过 `_doInit()` 和 `_doStop()` 验证生命周期入口。

Agent 的 `configuration.shared_memory_enabled` 缺省为开启。持久助手的 `settings.enableSharedMemory` 缺省为关闭。临时、辅助和普通 headless 助手不开放记忆。渠道 Agent 只能访问所属私有范围。编辑器要求真实的主窗口身份。Pi 在新轮次、结束和关闭时释放文件会话及读取关联。

关闭共享开关后，旧会话凭据不会因重新开启而恢复。实体数据服务只发布权限失效事件，文件操作仍归本模块。完整备份已接入 `pause()` 和 `drainInFlight()`；恢复提交启动日志后调用 `invalidateAll()`，只使当前会话凭据失效。写入持续暂停直到重启。恢复库启用后，提炼服务重建准入边界并丢弃备份中的旧任务。

Pi 在每次模型请求前替换 `cherry_memory` 系统区块，保留其他提示词和工具声明。Claude Code 在 `UserPromptSubmit` 和 `SessionStart` 提供完整引用，空引用撤回先前内容。助手入口仅接受持久聊天 owner 创建的主进程 `memoryContext`，每次 `prepareStep` 携带同一会话快照，覆盖压缩后的请求。

Pi 的原生 `read`、`write`、`edit` 在执行入口调用原有审批器。受管理完整读取返回 `memoryReceipt`，修改必须显式带回同一轮次、同一文件的凭据。编辑继续使用 SDK 的替换算法，但最终保存归 `MemoryService`。审批带准确的完整提案；流式审批先刷新工具输入，再发出审批请求，卡片以只读正文展示拟保存内容和文件名。模型传入的预览字段不作为审批依据。审批中编辑输入后需重新发起操作，不能沿用旧提案。最终替换前检查权限、取消、工具开关和审批模式。普通文件继续走原工具。

Claude Code 复用原生 Read、Write 和 Edit。主进程校验身份后，把执行路径改为会话内的临时副本。完整 Read 才建立已有文件的编辑基线；新文件由主进程读取缺失基线。Write 和 Edit 仍使用原生实现，正式文件由 MemoryService 按现有审批模式提交。读取凭据留在主进程，模型参数保持原样。同文件的重叠调用返回可重试冲突；轮次结束和会话销毁清理副本。

Claude SDK 的 PostToolUse 输出改写保留原生工具结构。正式保存失败时，原生结果仍指向临时副本，钩子附加未确认保存的说明并停止本轮。Cherry 将这种结果显示为失败，历史回放也识别临时路径。只有确认提交后，结果才改回正式路径。Read 验证失败时替换正文，避免返回已失效内容。

Claude Code 仍拒绝其他未受控文件操作及包含记忆的目录搜索。没有调用方身份的内置 filesystem MCP 也拒绝受管理目标、恢复备份和相关目录操作。

Pi 的可选 grep、find 和 ls 也拒绝受管理目标及其祖先目录，防止 SDK 动态启用这些工具后绕过主题读取边界。审批中改动搜索目标后再次检查。

设置中的共享记忆位于“工具”分类，与 MCP 和技能并列。共享页提供生成、整理、清空与最近操作恢复。Agent/Assistant 基础表单的开关名为“共享记忆”；Agent 行位于心跳检测之前。清空、恢复和实际反馈走 `memory.*` IpcApi，实体开关走 DataApi。具体界面、旧文件页与受管理文件的区别见[记忆概述](../../../../docs/dev/references/memory/overview.md#settings-and-the-existing-agent-memory-tab)。

渠道停用、删除或变更所属 Agent 后，原渠道会话永久失效；重新启用需重新读取。Agent 删除同样使已打开的私有编辑器失效，恢复 Agent 不恢复旧凭据。渠道更名和无关渠道变更不撤销当前会话。

模型入口先在 20 MiB 预算内核对完整作用域状态，再按完整行截取至 25,000 字节。超出检查预算时保留原文件并拒绝注入。完整原文读取同样受 20 MiB 预算限制。

`commit()` 向权限层提供不可修改的准确提案。权限层返回授权存续检查。自动批准仍需此检查。调用方权限由 `MemoryAccess.assertAuthorized()` 的会话存续检查撤销；清空、恢复或删除作用域时使整个作用域失效。

授权存续检查必须同步执行，临时文件准备完毕、替换前再次调用。最后一轮异步验证后仍核对提案原始代次，并显式传入写入流程，不能重新取得当前代次。清空和恢复仅在验证后允许推进一次代次；备份写入期间发生的额外撤销仍使操作失效。整理提交通过 `readReceipts` 绑定全部输入，即使其中部分文件不修改或整批无需修改。

`previewClear()` 只保留已核对的文件集、哈希和读取凭据。`clear()` 在作用域锁内复查文件集和版本；新出现的受管理文件会使确认失效。清空移除正文，为非空旧正文保留无来源 forgotten 标记。未知文件、历史文件和备份继续保留。撤销最近一次清空时，预览和确认都核对清空后的作用域版本。版本匹配时按备份还原正文及清空前的保护状态。部分清空仅撤销已写入的文件。恢复中断后再次确认会继续原批次。清空和恢复在写文件前持久保存批次号及原版本。重启先核对实际文件。已有改动时丢弃旧提炼队列，所有文件仍是原版本时保留队列。

原生工具适配器将每次编辑绑定到对应的完整读取凭据。截断读取仅供参考。

同批次在审批前和写锁内按文件实际标识排除别名，包含大小写不敏感卷和硬链接。最新恢复批次记录入口删除时，初始化保留缺失状态；用户后来创建的同名文件仍按冲突处理。崩溃批次复核为全未修改时，恢复预览继续选择上一份有效批次。

Agent 目录已存在 `.memories/` 时，目录初始化不自行补建缺失入口；由记忆存储结合恢复历史判断，避免早于存储初始化破坏删除基准。

备份清单使用 JSON，原始字节以 Base64 保存。20 MiB 限额按实际清单字节计算，包含编码开销。文件与 SQLite 不构成同一事务。恢复检查磁盘结果，不重放旧操作。

混合已提交、未提交或冲突的批次保留为 partial，不进入自动配额清理。恢复前也先保护原批次。只有全部恢复成功且没有冲突时才解除该保护，避免新恢复批次取代它后丢失剩余原文。准入时为新旧批次都预留最长状态文本的空间，避免恢复状态变长后超过容量。

迁移批次可额外保存旧 FACT 的原始字节和哈希，仍计入同一容量限制。旧 FACT 原文作为迁移资料保存，与新入口的恢复基准分开。提交前和锁内都检查旧 FACT 基准。`initializeMemoryFiles()` 统一初始化活动文件，供 Agent 目录 owner 复用，并保留已有正文。

完整备份在首个写入前落盘，结果在批次完成或失败时保存。避免每写一个文件就重复序列化整批原文。崩溃留下的 pending 步骤按实际哈希复核，不重放。只读旧 FACT 回退可复用有界入口读取，不产生编辑凭据。

迁移状态由本模块独占的 `app_state` 键保存，只有文件名、哈希、批次引用和状态。完整迁移退出旧 FACT 注入。失败保留只读旧事实，新私有范围不启用；不会重放部分完成的旧计划。相对链接、片段链接、HTML 链接和 wiki 链接需人工复核，不自动搬迁或拆分；绝对链接及代码中的示例保持原文。重启时如原始 FACT、备份和每个目标版本均匹配，服务会撤销本次迁移已写入的文件，再重新迁移。版本冲突时保留现场。迁移成功后，设置页中的旧 FACT 仅供查看。旧 Agent Memory MCP 停止挂载，JOURNAL 不再追加；原生文件和内置 filesystem 工具也拒绝历史目录。旧文件、身份文件、独立图谱 MCP 和知识库保留。

“聊天中生成记忆”和“自动整理记忆”是两个独立全局开关，默认均开，分别保存为 `feature.memory.generation.enabled` 和 `feature.memory.dreaming.enabled`。关闭生成只停止提炼并撤销其未提交输出，不影响已有记忆的自动或手动整理。关闭自动整理仍允许生成和手动整理。

`memoryExtraction.ts` 从主进程成功完成事件接收新桌面对话。Agent 仍需开启共享访问，Assistant 必须明确开启。渠道、后台、临时、合成消息和跨会话投递不参与。核对当前归属、回复作者快照、消息版本和访问开关，只向模型传同一分支的可见用户与助手文本，以及共享入口和主题。助手文字只用于理解上下文。普通名称、模型或提示词修改保留已登记消息；撤权和归属变化仍使用持久边界撤销旧任务。

提炼与整理共用一个物理互斥锁和 `memory.dreaming` worker。每个对话当前分支累计八个新成功用户／助手轮次后触发，剩余轮次在系统当地时间 21:00 触发。前台忙时延期。`memoryExtractionState.ts` 在 app_state 保存已登记消息引用、固定批次终点、处理位置、重试时间和提交哈希，不存正文。普通重启保留待处理任务，错过每日时间后补处理已登记内容，不扫描历史。旧游标升级时建立新边界。关闭生成、清空、恢复和明确取消撤销旧任务；相关撤权边界也持久保存。

提炼指纹绑定消息内容、回复、所属实体和授权边界，不使用会话的通用更新时间。自动命名或单纯改标题不丢弃任务。Topic 删除或变更所属助手、Agent Session 删除后，由数据服务提交后的事件撤销相关任务；恢复原会话或原归属也不会复活旧任务。

自动窗口以固定批次末轮的成功回复为终点，先沿父节点限定最近十六条可见用户／助手消息，包含最后的回复，首次提交用户消息时绑定当时的共享访问和生成权限。重新生成只能更新已有准入凭据的轮次。组装模型输入时逐轮核对用户消息、回复和版本。未获准或已编辑的轮次只保留缺口。失败或停止的整轮不作为证据，缺口位置进入模型输入和指纹，不向前补足消息。总量最多 32,000 UTF-8 字节，单条最多 8,000 字节。预算不足时移除最旧完整轮次，记录预算跳过数量。单轮超限时明确跳过，不阻塞后续批次。被边界或预算截断的前文标为不完整；已有共享记忆提供背景，指代不明时返回证据不足，不自动补读更早聊天。推理开始时绑定完整片段哈希，提交前复查。

自动提炼复用下文的多轮候选、证据校验和跨批核对。读取共享入口和全部主题，最多 40 个文件、32,000 字节。保存个人范围的 `add` 正文及明确 `correct` 纠错。纠错须引用唯一完整旧条目，区分后来变化、原先记错和补充例外；未确认冲突保持原样。目标尚未实现或分类不确定，不等于原话证据不足。正文保留条件和来源日期，不追加解析时区说明。任务结果包含保存数、候选动作和各批原因。保存复用完整读取凭据、备份、文件集和最终同步授权检查。容量不足时整次保存失败。受控纠错记录支持继续提炼与整理；其他结构化条目和遗忘保护仍按原规则限制自动保存。来源引用用于本次核验，正文以普通 Markdown 持久保存。

Dreaming 使用应用默认模型。`memory.dreaming` 处理器在初始化时注册，恢复策略为 abandon，所有作用域共用并发为 1 的队列。每分钟唤醒检查；调度不重放错过的每次唤醒，提炼自己检查持久的每日截止时间。整理每次轮转检查一个作用域的入口和最多九个主题，优先处理已变化且符合条件的文件。未选中文件不推进已处理标记。

十次受控内容修改、最早待处理变化七天、变化后的容量预警或手动请求触发整理。旧文件观察使用哈希，不从哈希推算修改次数。无修改、失败、Dreaming 和恢复不增加计数。每份未变输入最多尝试两次，间隔十分钟；新内容、明确手动请求或更换默认模型提供新的机会。永久标记只存哈希、时间、计数、代次和短状态，不依赖任务历史，也不保存正文。

模型输入不超过十个完整文件和 50,000 UTF-8 字节。入口必须完整保留，主题按模型上下文、输入和输出上限逐个装入。单独也无法与入口装入的主题标记为预算阻塞，继续处理较小主题；仅因当前批次已满而未选中的文件留待后续。预算阻塞不会反复尝试，新内容、手动请求或更换默认模型可重新检查。每批只调用一次模型，关闭工具、自动重试和上下文裁剪，不传聊天、JOURNAL、身份文件或其他作用域内容。推理不持有文件写锁。

提交复查全部输入凭据。删除还在锁内复查完整活动文件集，要求源和目标是不同主题，禁止以 `MEMORY.md` 作为删除源或转移目标；原文含空白字符须逐字保存在完整写出的主题目标，并检查剩余 Markdown 和 wiki 链接；HTML 链接交给人工处理。先写目标和链接，再删来源。成功文件才更新进度，失败保留恢复资料。

清空、恢复、暂停和完整恢复通过 `MemoryService.onInvalidated` 先撤销尚未提交的维护输出。关闭生成只使旧提炼失效；关闭自动整理只影响整理。手动取消和 Agent 删除撤销相关任务。重启丢弃未提交模型输出，保留提炼待处理引用。前台对话开始后取消模型调用，提炼延期且不消耗失败次数。整理同样不消耗尝试次数，约一分钟后等待空闲重试，并保留手动请求；计数恢复核对文件版本与任务代次，不覆盖并发更新。模型、网络或输出校验失败后，每隔十分钟重试，最多两次；之后等下个当地时间 21:00。只有成功核验才完成批次，包括无合格事实；预算、失效来源和冲突跳过分别统计，不标为成功。失效末轮退出后，已到期批次继续处理原范围内的有效部分。保存前记录来源及文件前后哈希，确认写入后补记进度并保留实际保存告警，避免重复追加。明确未写入时清除旧意图并按原节奏重试；结果不明且当前文件已成为其他版本时，跳过原批次并继续后续任务，保留用户当前文件。冲突跳过同时记录原批次的来源时间边界及同时间消息 ID，后续自动窗口不再携带这些旧证据。最近结果使用现有任务结果和 lastResult 反馈。

该保护只覆盖经过本模块的写入。外部编辑、Shell 和其他直接磁盘访问不受作用域锁约束。当前测试覆盖 Windows；其他平台原生文件检查仍需补齐。

文件保存复用通用原子写入。临时文件排他创建并使用 0600 权限。异步路径校验结束后，先同步检查权限，再发起 rename；权限检查和系统文件替换分两步执行。

## 受保护内容

整理可读取由受控纠错生成的失效记录。模型须在原文件逐字保留记录及时间依据，不把旧事实写回当前正文；含这些记录的主题暂不转移或删除。存储层拒绝删除或改写失效元数据的提案。

明确纠错通过绑定完整读取版本的内部提案保存。旧事实作为过期条目保留失效原因、替代正文及纠错证据。纠错记录与普通正文共存，不触发遗忘保护。当前读取隐藏旧记录，历史读取标明原先记错、后来变化或原规则补充了条件；原生编辑保存时保留隐藏记录，拒绝重新添加相同失效事实。恢复同样拒绝把已纠正正文重新变为有效事实。未知结构与遗忘继续使用原有严格保护。

当前读取同时排除同一作用域中与失效事实完全相同的正文副本。部分纠错已保存时，其他文件中的旧副本也退出当前记忆。后续用户明确改变回旧值时，依据纠错来源时间保留最新有效值；这不改变早先记录的历史含义。

`memoryEntries.ts` 校验结构化条目和来源引用。模型读取过滤过期及遗忘正文。撤销清空会保留清空前已有的遗忘标记。未知或损坏结构拒绝读取。存储层提供保护状态指纹，由上层绑定具体会话。未绑定会话的读取仍使用严格检查。

完整读取、文件集和版本核验绑定到本次操作。修改前验证全部模型输入；受保护内容不能通过普通覆盖绕开。`memoryHash` 对已有字节返回字符串，对缺失文件返回 null。

模型读取通过 MemoryService 绑定验证函数，在后续使用前复查输入。运行时保护检查接收主进程回调；访问层不解释会话身份。编辑器和迁移读取使用受控原文入口。

受管理文件读写由 AI 工具和后台维护使用。Agent 现有“记忆”页通过 `agent.memory.*` 操作 SOUL、USER、旧 FACT 和只读 JOURNAL，使用旧编辑器的保存机制。迁移失败后保留原文，源文件内容改变后，下次访问会重新检查迁移。

## 指定片段的候选提炼

自动摘录、候选提炼、跨批核对和文件整理的输出 token 遵循服务商默认值和模型容量。容量检查中的输出估算用于给输入留出空间。返回正文仍需通过字节限制、结构及证据校验。

`MemoryDreamingService.previewExtraction()` 通过 `memory.dreaming.preview_extraction` 提供主窗口专用的候选预览 API，仅返回本次候选。后台自动提炼复用该候选引擎，并通过受控流程保存文件。

调用方给出首条用户消息及末轮成功回复。预览沿父节点读取同一分支，最多 64 条、64,000 UTF-8 字节，每条最多 8,000 字节。读取范围从首次升级、生成开关变化、清空及实体授权边界之后开始。输入包含用户与助手的可见文本，用户原话作为事实证据。超出范围时报告预算不足。

每批最多 16,000 字节消息，保留最多两条完整重叠消息。读取共享入口及所有主题，最多 40 个文件、32,000 字节，超限时停止。输出包含完整正文、主体、条件、时间、用途、动作及逐字证据。模型返回消息 ID、旧文件路径和逐字引文；程序从读取快照补齐消息和文件版本，再校验完整候选。返回前复查来源、文件集、文件版本和权限；无效引用或来源变更使预览失败。候选须写明后续用途，例如减少重复询问、改善建议、跟进计划、回忆重要事件或避免重复错误。个人事实、经历、计划、决定和约束均可参与提炼；项目与客户候选标为范围不符。相同内容、明确纠错、未确认冲突、证据不足和无合格内容分别返回。用户明确补充例外时，将原规则和例外写在同一条，并标记为 qualified。明确纠错须区分这三种原因，引用完整旧条目及用户纠正原话。

提示词按后续理解和帮助的价值选取信息，包括具体事件与临时状态。提炼保留原话的主体、时间、条件和确定程度。事件时间依据正文判断。程序保留来源消息日期及解析时区；直接相对年月日按来源日期转换，含糊时间或多日期证据保留原表述及日期依据，不补造具体日期。

提示词要求一条候选只说一件事，并保留必要条件。当前活动、愿望、未来目标和已作出的决定分别记录。

多批产生多条候选时，再调用一次模型核对全部候选及其证据。证据附带主进程来源快照中的消息时间，供解释相对时间。程序先按主体、范围、分类、动作、条件和时间的精确值划分可合并组。模型在组内判断语义重复，同时检查所有候选之间的冲突。明确重复的候选才合并，并保留全部来源和旧记忆引用。部分重叠、跨组、单条或引用合并超限的候选保留原来已验证的内容。

冲突或关系不明时保留各条正文，将原本的新增或已存在动作降为证据不足。候选编号须完整且唯一。核对超预算、返回结构错误、编号缺失或重复等问题使整次预览失败。不同时间或条件下可以同时成立的事实保持独立。纠正关系由 reason 说明改正了什么。冲突或关系不明的候选各自保留原有证据和旧记忆引用。

提炼复用原互斥锁和默认模型，模型工具关闭。来源编辑、手工改记忆、撤权、清空、取消、前台抢占或调用窗口失效后，旧候选作废。跨批核对遵守相同预算、取消和版本检查。结果仅在调用期间保留，文件和自动提炼游标保持原样。中断后需重新请求。

## 条目状态的模型读取

模型读取通过 `MemoryStore.modelRead()`，先检查整个作用域的白名单活动文件，再按用途过滤。当前回答排除过期条目，历史读取保留过期状态与适用时间。已遗忘条目、同来源消息的副本及已知派生链不返回；来源版本变化不解除限制。损坏格式、重复 ID 或缺失派生来源拒绝读取。无法区分的旧正文在受保护范围内拒绝读取。

`MemoryService` 用主进程登记的编辑器身份区分人工原文和模型视图。模型不能通过参数取得原文权限。结构化范围不给整文件覆盖凭据；普通旧 Markdown 保留原契约。Pi 的 `memoryPurpose: historical` 只开放历史用途，不解除遗忘过滤。Pi edit 同样重新读取过滤视图。

候选提炼绑定实际消息来源，并在每次模型请求前后复查作用域文件集、哈希、权限和代次。未知来源的过期或遗忘状态会暂停该范围提炼。自动摘录和整理需要完整覆盖凭据，受控纠错记录允许继续操作，其他结构化范围保持原有限制。读取状态总预算为 20 MiB，超限拒绝模型读取。

模型视图过滤保护新组装的受控输入。旧消息、工具结果和摘要通过下节的整次请求拒绝策略隔离。自动候选保存和聊天原文回查同样遵守条目状态检查。

### 运行时拒绝策略

`assertRuntimeSafe()` 检查持久条目状态及会话的隔离边界。过期或遗忘状态发生变化时，旧会话拒绝整次请求。损坏状态始终拒绝。Pi 与 Claude Code 在连接和提交处检查，并在受控失效时关闭旧连接。Claude 原生启动/提交钩子返回停止结果。AI SDK 的真实 provider fetch 同样检查；网关用认证后的 Agent 会话身份绑定，覆盖原生工具轮次和压缩请求。共享开关关闭不解除旧上下文保护。

清空后的新会话可以建立新的隔离边界，只读取过滤后的内容。已有历史却没有边界记录的会话仍会被拦截。边界记录在重启后保留。聊天原文回查仍采用严格状态检查，不能用新会话回查已受保护的旧内容。临时无记忆请求独立处理。

运行时状态检查可以查看迁移尚未完成的私有范围，但不会启用该范围。FACT 迁移失败时仍可使用只读旧事实；私有范围中的遗忘或损坏状态仍接受检查。

Claude 预热按主进程会话身份持有记忆守卫。准备配置、启动等待、消费等待和驱动移交期间均检查。条目离开预热缓存后仍由消费集合跟踪，失效后不能移交。驱动在原生打开和观察建立后再次检查；同步移交前检查两个守卫，再由连接守卫继续负责取消。该路径不依赖网关，也适用于订阅登录。

同一会话的预热串行检查和登记，相同配置复用同一进程。关闭会等待尚未登记的预热任务。随后撤销守卫，再等待启动结果、SDK dispose 和进程退出信号。关闭失败或缺少退出证明时保留失败条目，拒绝复用和冷启动回退；显式 close 可重试。清理回调捕获异常，避免未处理的 Promise。测试使用真实记忆文件和 SQLite，原生进程启动、退出信号及运行时接收器使用可控替身。

核心记忆按产品话题或 Agent 会话及范围缓存。首次有权限的请求加载入口；后续步骤、轮次、重连和压缩复用同一快照。普通写入在新会话生效。快照缓存在内存中，应用重启后重新加载。权限和遗忘状态在使用前检查。

## 聊天原文回查

每次回答最多执行4次历史回查，关键词搜索和按消息ID展开共用次数。普通助手达到上限后移除 memory_search，让模型用已有证据回答；Agent 后续调用只返回停止搜索的提示。新回答重新计数。

开启实体的共享记忆后，普通助手、Pi 和 Claude Code 向模型提供 `memory_search`。模型按需选择关键词。涉及之前的对话、决定或当前上下文缺少的人和项目时，提示词要求先搜索。助手只查自己的话题；Agent 只查自己的桌面主会话。排除渠道、后台、子会话、转发消息、失败消息和已删除会话。搜索命中仅来自当前选中分支中的成功用户消息；补充上下文可包含成功的助手正文，并标明角色。

主进程传入本轮回复的消息 ID，据其父节点定位当前提问。搜索命中、上下文补充和按 ID 展开都排除这条提问；同会话更早的消息及其他会话里的同文提问仍可回查。

查询由模型提供，最长512字符。任一关键词命中即可进入候选。纯长词查询复用 trigram MATCH 与 BM25。含短词时合并 MATCH 和转义后的 LIKE 命中，先按命中的不同词数排序，再优先较短、较新的消息；重复关键词不重复计分。最多读取64个候选，保留前6个有效命中。只展开排名第一的命中：前后各5条，加上所在选中分支开头、结尾各3条。按成功且有正文的用户和助手消息计数，不足时取实际条数。展开内容按分支顺序排列，与其余命中按消息ID去重，最多22条。沿完整父链读取节点标识和资格，只加载选中消息的正文，保证长会话也能取到真实开头。

超过2000字符的正文使用已有片段算法。结果附会话ID、消息ID、角色、消息时间和截断标记；搜索命中另附排名。助手回复提供上下文，用户消息提供事实依据。

原文作为工具结果返回，供本次回答参考。模型可以换词重搜，或传回 `conversationId` 与 `messageId` 展开另一条消息。展开仍检查归属、选中分支与删除状态。既有跨 Agent 的 `session_search` 保持原行为。权限关闭、删除或遗忘状态会阻止后续回查。

纠错提交在 app_state 中记录各目标文件的写前和写后哈希，不保存正文。部分文件已写入时，复核来源与全部文件版本，再处理未完成目标；未生成未完成目标的提案时保留待重试任务。确认全部写入才补记完成。会话入口在纠错记录变化后刷新，普通新增仍保持原有快照策略。历史召回附带最多 4,000 字节的已知纠错关系，并标明截断。
