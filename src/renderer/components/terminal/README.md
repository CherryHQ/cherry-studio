# Conversation terminal pane

The Agent right pane presents files, browser pages and individual terminals in one `RightPaneTabs` strip. `TerminalResourcesProvider` reads Main's bounded resource projection through SWR; renderer memory retains only tab order, names, selection and explicitly hidden views. Each domain keeps ownership of its content and lifetime. `TerminalPane` renders the selected resource without a nested header or tab list. Closing a terminal tab or choosing Close terminal stops its managed process scope and removes the view only after confirmed cleanup. Repeated close requests join the same operation; rejected or unconfirmed cleanup keeps the tab and retry entry visible. Hiding the whole pane or switching tabs preserves execution and input ownership. Reopening a user-controlled terminal restores its input view when no other view holds it; Agent-controlled terminals still require explicit takeover. New user terminals explicitly acquire input control, start the user's configured shell and load its existing configuration; colors and input highlighting come from the shell and programs.

The file-browser shortcut and the plus menu's Files item open the same in-app view. When no file is selected, a Files tab represents that browser; choosing a file shows its tab instead. Its directory tree belongs only to file views.

The unified strip reuses file and Browser domain actions for attachment, copying and external opening. Every resource shares Close tab, Close others, Close to the right and Close all, using the order of the entire strip. Right-click does not activate the chosen resource. Group closure waits for each domain owner: file edit protection and terminal process confirmation still apply. Cancellation or unresolved cleanup stops the remaining closes; already confirmed closures stay closed.

Closing a terminal with unresolved process cleanup first asks for confirmation that its shell and processes will stop. Cancel leaves execution and the tab untouched; an already cleaned-up terminal closes without a prompt. All close entry points join the same confirmation and stop operation. After confirmation, the tab shows Closing while cleanup runs, and other tabs remain usable. A pending confirmation cannot stop resources after the conversation changes, and an accepted close uses the latest observed control revisions.

An unconfirmed stop retains its close intent for the original resource and Host generation. Observation continues while that close is unresolved, including when the pane is hidden; a later cleanup confirmation removes the tab and clears its close error without another stop. A user-selected sibling tab keeps selection. Closing or non-running views reject new and queued input/resize actions locally, while output observation remains available; late action rejections cannot replace the cleanup status with an obsolete error.

Native pipe tool cards can open output or promote a running Bash call while its result is still pending. Promotion uses the existing resource and never reruns the command; pipe output stays read-only. The selected terminal's More button in the shared header and its context menu provide the same takeover, copying, interruption, explicit close and cursor settings without a persistent footer. Opening the menu does not send its pointer gesture to the running program; closing it restores input focus. The active terminal view supplies its header menu through the same action slot as file controls; switching to another resource removes that menu.

The plus menu creates resources without a running/exited terminal history list. It and the terminal opener retain a warning while profile-wide cleanup is unconfirmed. This includes detached user terminals and records recovered after restart or conversation purge. Selecting a record shows its retained directory and retry action. Retry without a verified original scope leaves the warning and directory protection in place.

`TerminalCanvas` draws window-bound cell frames from the authoritative Host Ghostty core. It has no VT parser or renderer-side WASM instance. Terminal text uses the application code-font setting for both cell measurement and drawing, including any Nerd Font selected there. Content and cursor/selection use separate Canvas layers; dirty rows render in animation frames. The real textarea handles keyboard input, paste and IME, with a bounded accessible viewport log. Canvas/key normalization derives from T3 Code revision `0a8aaa3ccb944dadb70054ae4ef2e29897b0db03`; see the [asset provenance and licenses](../../../../resources/terminal/ghostty/README.md).

Viewport sizing preserves the observed content box's fractional CSS dimensions. Rounding the viewport up can create overflow and make automatic scrollbars repeatedly change the available size. Canvas pixel buffers resize only during painting; CSS sizes still update when a subpixel change leaves the pixel dimensions unchanged.

The terminal menu saves cursor shape (block, bar or underline) and blinking as application preferences. Visible views send these defaults with their theme to the Host's native Ghostty core; changes apply live while the cursor uses defaults. Explicit application cursor sequences take precedence, and DECSCUSR reset restores the latest saved defaults. An unfocused cursor remains hollow.

Each view has its own scroll position, selection and attachment identity. Only a controlling view can resize or send input. Creating a user terminal includes explicit control intent. Reattaching a user-controlled terminal without another controlling view preserves that intent; it does not transfer resource control or take input away from another view. The return action appears only while the terminal remains bound to a live Agent runtime; releasing control does not start an Agent turn. Control revision and geometry epoch travel with queued input. Stale submissions fail without automatic replay. Composition commits once, and a control/view change rejects the old composition.

Input stays read-only after takeover until the current viewport has been measured and its resize acknowledged. A pending control transition disables another takeover/return action; an unconfirmed or rejected resize cannot enable typing.

Queued resizes use the preceding acknowledged geometry epoch; keyboard input retains the epoch of its displayed frame. A controlling view clips the old grid during resize so transient scrollbars cannot feed back into viewport measurement. Observing views retain scrolling over the authoritative grid.

Frames use compact style dictionaries, bounded chunks and an explicit baseline revision. Missing or stale frames reset presentation and request a baseline. Final screens can be served from Main after Host retirement; when unavailable, the pane shows the retained raw suffix. Visible viewport selection clears when its text changes rather than copying different output at stale coordinates. Links require an explicit modified click and resolve through the Host before the existing external-link policy.

`useTerminalView` is the single attachment, frame and input owner extracted from `TerminalCanvas`. `terminalBlockLayout` maps the original terminal rows plus sibling DOM control rows; drawing, cursor, links, mouse, IME and selection share that mapping. Only reliable completed whole-row output folds. Running, alternate-screen and uncertain regions stay continuous. Provider-held presentation stores bounded collapse, viewport, selection and find intent, without cell text or native handles.

The Host supplies the last occupied source row, including the cursor and styled blank cells. The block projection excludes unused trailing grid padding from scroll height, so a short terminal keeps its first controls visible without losing content below a moved cursor or changing PTY geometry.

`TerminalBlockControls` supplies the same actions to its More menu and the terminal context menu. Semantic selection captures the exact block revision; ordinary selection copies only visible terminal cells, skipping folded output and DOM labels. Alt-drag rectangular selection stops at a layout discontinuity. The shared `TerminalFindBar` overlays the viewport without resizing the PTY, wraps in narrow panes and contributes its measured height when revealing matches. Query typing is coalesced; Escape closes the query and restores terminal focus. Enter navigates matches only from the input; buttons retain native activation, and the scope button exposes its visible current range as its accessible name.

Block menus use the shared menu's focus restoration, so Escape returns to the trigger. Mouse motion and release queue behind their press acknowledgement, preserving fast gestures without reporting a gesture that the terminal declined or replaying it into another view. Entering the alternate screen hides normal-screen controls without pruning their collapse intent; returning reconciles that intent against the surviving normal-screen block index.

Attach uses the typed generated-text request in `EventService`. The active `AgentComposer` claims the conversation and draft generation before requesting an immutable snapshot, deduplicates its intent and cancels unfinished insertion on draft replacement or unmount. It creates a normal Blob-backed attachment; existing Composer file processing owns ingestion on send. The terminal creates no temporary file and sends no Agent message. Pipe/retained output reuses bounded text copy, attach and find without mounting a live PTY view.
