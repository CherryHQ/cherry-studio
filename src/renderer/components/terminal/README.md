# Conversation terminal pane

The Agent right pane presents files, browser pages and individual terminals in one `RightPaneTabs` strip. `TerminalResourcesProvider` reads Main's bounded resource projection through SWR; renderer memory retains only tab order, names, selection and explicitly hidden views. Each domain keeps ownership of its content and lifetime. `TerminalPane` renders the selected resource without a nested header or tab list. Closing a terminal tab or choosing Close terminal stops its managed process scope and removes the view only after confirmed cleanup. Repeated close requests join the same operation; rejected or unconfirmed cleanup keeps the tab and retry entry visible. Hiding the whole pane or switching tabs preserves execution and input ownership. Reopening a user-controlled terminal restores its input view when no other view holds it; Agent-controlled terminals still require explicit takeover. New user terminals explicitly acquire input control, start the user's configured shell and load its existing configuration; colors and input highlighting come from the shell and programs.

The file-browser shortcut and the plus menu's Files item open the same in-app view. When no file is selected, a Files tab represents that browser; choosing a file shows its tab instead. Its directory tree belongs only to file views.

The unified strip reuses file and Browser domain actions for attachment, copying and external opening. Every resource shares Close tab, Close others, Close to the right and Close all, using the order of the entire strip. Right-click does not activate the chosen resource. Group closure waits for each domain owner: file edit protection and terminal process confirmation still apply. Cancellation or unresolved cleanup stops the remaining closes; already confirmed closures stay closed.

Closing a terminal with unresolved process cleanup first asks for confirmation that its shell and processes will stop. Cancel leaves execution and the tab untouched; an already cleaned-up terminal closes without a prompt. All close entry points join the same confirmation and stop operation. After confirmation, the tab shows Closing while cleanup runs, and other tabs remain usable. A pending confirmation cannot stop resources after the conversation changes, and an accepted close uses the latest observed control revisions.

An unconfirmed stop retains its close intent for the original resource and Host generation. Observation continues while that close is unresolved, including when the pane is hidden; a later cleanup confirmation removes the tab and clears its close error without another stop. A user-selected sibling tab keeps selection. Closing or non-running views reject new and queued input/resize actions locally, while output observation remains available; late action rejections cannot replace the cleanup status with an obsolete error.

Native pipe tool cards can open output or promote a running Bash call while its result is still pending. Promotion uses the existing resource and never reruns the command; pipe output stays read-only. The selected terminal's More button in the shared header and its context menu provide the same takeover, copying, interruption, explicit close and cursor settings without a persistent footer. Opening the menu does not send its pointer gesture to the running program; closing it restores input focus. The active terminal view supplies its header menu through the same action slot as file controls; switching to another resource removes that menu.

The plus menu opens or creates terminals, browser pages and the file browser. Workspace cleanup journals remain internal to Main and do not create resource tabs, menu entries or opener badges. An unresolved close stays visible on the affected terminal; removing historical cleanup entries from the UI does not release workspace directory protection.

`TerminalCanvas` draws window-bound cell frames from the authoritative Host Ghostty core. It has no VT parser or renderer-side WASM instance. Terminal text uses the application code-font setting for both cell measurement and drawing, including any Nerd Font selected there. Content and cursor/selection use separate Canvas layers; dirty rows render in animation frames. The real textarea handles keyboard input, paste and IME, with a bounded accessible viewport log. Canvas/key normalization derives from T3 Code revision `0a8aaa3ccb944dadb70054ae4ef2e29897b0db03`; see the [asset provenance and licenses](../../../../resources/terminal/ghostty/README.md).

Viewport sizing preserves the observed content box's fractional CSS dimensions. Rounding the viewport up can create overflow and make automatic scrollbars repeatedly change the available size. Canvas pixel buffers resize only during painting; CSS sizes still update when a subpixel change leaves the pixel dimensions unchanged. The shared `ScrollArea` owns scrolling over the full virtual row range, while a sticky Canvas surface paints the viewport. Wheel input, scrollbar dragging and search reveal share that position; a pending frame cannot rewind a newer scroll intent. The content container has no theme-colored focus frame; terminal cursor styling conveys input focus.

The terminal menu saves cursor shape (block, bar or underline) and blinking as application preferences. Visible views send these defaults with their theme to the Host's native Ghostty core; changes apply live while the cursor uses defaults. Explicit application cursor sequences take precedence, and DECSCUSR reset restores the latest saved defaults. An unfocused cursor remains hollow.

Each view has its own scroll position, selection and attachment identity. Only a controlling view can resize or send input. Creating a user terminal includes explicit control intent. Reattaching a user-controlled terminal without another controlling view preserves that intent; it does not transfer resource control or take input away from another view. The return action appears only while the terminal remains bound to a live Agent runtime; releasing control does not start an Agent turn. Control revision and geometry epoch travel with queued input. Stale submissions fail without automatic replay. Composition commits once, and a control/view change rejects the old composition.

Input stays read-only after takeover until the current viewport has been measured and its resize acknowledged. A pending control transition disables another takeover/return action; an unconfirmed or rejected resize cannot enable typing.

Queued resizes use the preceding acknowledged geometry epoch; keyboard input retains the epoch of its displayed frame. Geometry measures the scroll viewport independently of the virtual content height. Observing views project normal-screen rows into their visible height without resizing the authoritative grid; unused trailing rows add no scroll range. Oversized alternate screens retain native grid panning and application mouse-wheel handling.

The pane shell reports maximize/restore animation and splitter dragging. During these transitions the Canvas follows the viewport while PTY resizing and input wait; the settled viewport then supplies one final geometry before typing resumes. Intermediate layout widths never become shell resize events.

Frames use compact style dictionaries, bounded chunks and an explicit baseline revision. Missing or stale frames reset presentation and request a baseline. Final screens can be served from Main after Host retirement; when unavailable, the pane shows the retained raw suffix. Visible viewport selection clears when its text changes rather than copying different output at stale coordinates. Links require an explicit modified click and resolve through the Host before the existing external-link policy.

`useTerminalView` is the single attachment, frame and input owner extracted from `TerminalCanvas`. `terminalBlockLayout` maps the original terminal rows plus sibling DOM control rows; drawing, cursor, links, mouse, IME and selection share that mapping. Running and unknown output stays continuous. Reliably bounded completed output longer than half the visible terminal rows shows that many output rows followed by Show more. The view projection skips only whole output rows; shared boundary rows and the following prompt remain visible. Show more preserves the source reading anchor and stays expanded in that view across tab/pane detach. Native history, Copy and Attach keep the original source; search reveal and semantic selection expand hidden targets before projecting them. Expansion never resizes the PTY. Provider-held presentation stores bounded viewport, selection and find intent, without cell text or native handles.

When a block-row projection is rejected after terminal content changes, the receive baseline advances without replacing the visible layout. Cells, controls and input coordinates stay together until a coherent replacement arrives. Refreshing that projection never replays terminal input.

Scrolling, accepted input and search/selection reveal wake the view's frame pump on the next animation frame instead of waiting for its idle poll. The pump keeps one frame assembly in flight, coalesces pending intent and resumes idle polling after it catches up. Detach cancels both the idle timer and queued animation frame.

The current block's metadata header stays at the top while its output scrolls; the next block pushes it away. The clipped, opaque control layer retains only the current and visible headers and uses the same virtual row mapping. The find bar floats above the viewport without moving the metadata headers. Search navigation checks the actual match cells against its rectangle and the sticky header. Header positioning never inserts source rows, resizes the PTY or sends terminal input.

The first metadata header and terminal row start at the viewport edge without an extra top gutter. Content, cursor, selection, mouse conversion and IME share that vertical origin; the horizontal gutter and row geometry remain unchanged. Metadata keeps enough height for its shared icon-button targets.

The Host supplies the last occupied source row, including the cursor and styled blank cells. The block projection excludes unused trailing grid padding from scroll height, so a short terminal keeps its first controls visible without losing content below a moved cursor or changing PTY geometry. Trimming that padding cannot move the live viewport above the native screen origin: prompt-aware clear may keep previous rows in scrollback, which remain above the live view. A completed final block header stops at its end boundary instead of pinning over the new screen.

`TerminalBlockControls` supplies the same actions to its More menu and the terminal context menu. Semantic selection captures the exact block revision; ordinary selection copies only visible terminal cells, skipping DOM labels. Alt-drag rectangular selection stops at a layout discontinuity. `TerminalFindBar` reuses the message-list and editor `FindBarControls` for its input, fixed-width match counter and navigation. Search progress does not change the input width; query options stay with the consumer that implements them. Canvas paints the selected match separately with an accent background and contrasting outline, including when it falls outside the bounded list of other highlights. Match numbers follow terminal reading order; Next moves down and Previous moves up. Navigation keeps the selected match visible without moving unobstructed cells. The terminal adapter anchors a compact find bar in the top-right corner, clamping its width to narrow panes. Shared controls wrap their navigation group below the input when needed instead of squeezing the text field. Opening find reserves no rows. A visible match outside the bar stays in place. Navigation first uses existing history to reveal an obscured match; only a match too close to the first source row adds the missing leading scroll space. That space scrolls away normally and is released when the next match does not need it, the query/scope changes, geometry changes or find closes. Search never resizes the PTY, and opening find preserves the native screen origin after clear. Query text and match counts do not change the bar width. Query typing is coalesced; Escape closes the query and restores terminal focus. Enter navigates matches only from the input; buttons retain native activation. Ctrl/Cmd+F and terminal-level Find always search the entire terminal, including when block find is already open. A compact pressed-state icon inside the shared input switches between the whole terminal and an explicitly selected block, preserving query text. Without a selected block, block scope is unavailable rather than guessed. A block menu explicitly opens “Find in this command block”. A plain click selects a block and, during block find, retargets that query; text drags, modified clicks and native program mouse handling keep their existing behavior. While block find is open, Canvas tints its exact command/output target with the code-selection theme token, independently of text selection and the stronger active match. Closing find or switching to terminal-wide find clears that tint. The remembered current block is only a scope-switch target, not a persistent selection; metadata headers never inherit its tint. Block find has no extra scope/command caption or target metadata row: its row projection removes that header and its reserved rows. Other block metadata stays available, and completed headers stop at their own end boundary. The icon tooltip and accessible description identify the target command. Editing the query keeps that exact block ID; retirement reports it unavailable without choosing another command or widening the query.

Block More and context menus share navigation to the targeted block’s top/header or last occupied row, and to the previous or next retained block in source reading order. Missing neighbors and unavailable boundaries are disabled; navigation never wraps or substitutes an evicted block. A running block’s bottom follows its current output end. Navigation updates only this view’s scroll intent through the common row projection, without terminal input, control transfer or PTY resize.

Block menus use the shared menu's focus restoration, so Escape returns to the trigger. Choosing block find instead transfers focus to the search field after the menu closes. Mouse motion and release queue behind their press acknowledgement, preserving fast gestures without reporting a gesture that the terminal declined or replaying it into another view. Entering the alternate screen hides normal-screen controls; returning restores the surviving normal-screen block index.

Block metadata shows the complete directory when it fits, applying layout ellipsis only when the available width is insufficient. The complete path remains available on hover. Successful exits use a quiet check; failures and running state remain explicit. Known command timing stays visible beside the status: running headers update once per second, and completion freezes a localized duration with millisecond precision. Only visible controls own display timers; elapsed display never changes PTY geometry. Unknown completion hides timing rather than inventing an end time. Copy output and Attach appear on hover or keyboard focus and stay visible while the block menu is open. The quick copy action reuses the shared `CopyButton`, reads output only when activated and shows success only after the clipboard write completes. A subtle Canvas guide marks reliably bounded output using the same source-row projection, without inserting rows or changing terminal geometry. The first visible block at the viewport top shares the tab strip boundary instead of drawing a second separator.

Attach uses the typed generated-text request in `EventService`. The active `AgentComposer` claims the conversation and draft generation before requesting an immutable snapshot, deduplicates its intent and cancels unfinished insertion on draft replacement or unmount. It creates a normal Blob-backed attachment; existing Composer file processing owns ingestion on send. The terminal creates no temporary file and sends no Agent message. Pipe/retained output reuses bounded text copy, attach and find without mounting a live PTY view.

Terminal tabs use the Host-reported running command when available and restore the shell title at the prompt. Text-selection context menus expose only copying the captured selection and finding that text. Block context menus contain block actions; the terminal menu retains management and cursor settings.
