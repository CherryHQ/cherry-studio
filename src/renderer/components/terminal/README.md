# Conversation terminal pane

The Agent right pane presents files, browser pages and individual terminals in one `RightPaneTabs` strip. `TerminalResourcesProvider` reads Main's bounded resource projection through SWR; renderer memory retains only tab order, names, selection and explicitly hidden views. Each domain keeps ownership of its content and lifetime. `TerminalPane` renders the selected resource without a nested header or tab list. Closing its tab or the whole pane leaves the process running; the open/create menu reopens it in observation mode. New user terminals explicitly acquire input control, start the user's configured shell and load its existing configuration; colors and input highlighting come from the shell and programs.

Native pipe tool cards can open output or promote a running Bash call while its result is still pending. Promotion uses the existing resource and never reruns the command; pipe output stays read-only. Takeover lives in the terminal footer, alongside its own menu for copying, interrupting, closing and cursor settings. No terminal control appears in the shared resource header.

The open/create menu and the terminal opener retain a warning while profile-wide cleanup is unconfirmed. This includes detached user terminals and records recovered after restart or conversation purge. Selecting a record shows its retained directory and retry action. Retry without a verified original scope leaves the warning and directory protection in place.

`TerminalCanvas` draws window-bound cell frames from the authoritative Host Ghostty core. It has no VT parser or renderer-side WASM instance. Terminal text uses the application code-font setting for both cell measurement and drawing, including any Nerd Font selected there. Content and cursor/selection use separate Canvas layers; dirty rows render in animation frames. The real textarea handles keyboard input, paste and IME, with a bounded accessible viewport log. Canvas/key normalization derives from T3 Code revision `0a8aaa3ccb944dadb70054ae4ef2e29897b0db03`; see the [asset provenance and licenses](../../../../resources/terminal/ghostty/README.md).

Viewport sizing preserves the observed content box's fractional CSS dimensions. Rounding the viewport up can create overflow and make automatic scrollbars repeatedly change the available size. Canvas pixel buffers resize only during painting; CSS sizes still update when a subpixel change leaves the pixel dimensions unchanged.

The terminal menu saves cursor shape (block, bar or underline) and blinking as application preferences. Visible views send these defaults with their theme to the Host's native Ghostty core; changes apply live while the cursor uses defaults. Explicit application cursor sequences take precedence, and DECSCUSR reset restores the latest saved defaults. An unfocused cursor remains hollow.

Each view has its own scroll position, selection and attachment identity. Only an explicitly controlling view can resize or send input. Creating a user terminal includes that explicit control intent; passive attach/reopen does not. Control revision and geometry epoch travel with queued input. Stale submissions fail without automatic replay. Composition commits once, and a control/view change rejects the old composition.

Input stays read-only after takeover until the current viewport has been measured and its resize acknowledged. A pending control transition disables another takeover/return action; an unconfirmed or rejected resize cannot enable typing.

Queued resizes use the preceding acknowledged geometry epoch; keyboard input retains the epoch of its displayed frame. A controlling view clips the old grid during resize so transient scrollbars cannot feed back into viewport measurement. Observing views retain scrolling over the authoritative grid.

Frames use compact style dictionaries, bounded chunks and an explicit baseline revision. Missing or stale frames reset presentation and request a baseline. Final screens can be served from Main after Host retirement; when unavailable, the pane shows the retained raw suffix. Visible viewport selection clears when its text changes rather than copying different output at stale coordinates. Links require an explicit modified click and resolve through the Host before the existing external-link policy.
