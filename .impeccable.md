## Design Context

### Users
People running agents against real project directories need to set up tools and
services, understand what is ready, and recover from connection failures without
editing configuration files. This surface is an operational desktop settings UI.

### Brand Personality
Calm, precise, utilitarian. Follow DESIGN.md and the existing settings vocabulary.

### Aesthetic Direction
Preserve The Boss's neutral, content-first layout and shared semantic tokens in
both themes. Use SettingsPrimitives and @cherrystudio/ui. Prefer grouped rows and
progressive disclosure over dashboard decoration. Do not introduce a new palette.

### Design Principles
1. Show the effective state and a useful next action, not just configuration values.
2. Keep basic setup short; disclose provider credentials and advanced options on demand.
3. Preserve keyboard operation, visible focus, accessible names, and non-color status cues.
4. Make long paths, translations, errors, and narrow windows readable without overflow.
5. Keep work asynchronous and cancellable; retain entered values when an operation fails.
6. Production implementation precedes the packaging build. Installed Windows acceptance
   is the functional gate; do not introduce intermediate design-review or testing loops.
