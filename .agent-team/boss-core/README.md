# The Boss development team

Ten project-specific roles are defined in [team.json](team.json); use [routing.md](routing.md) to select them. Product and UX have their own responsibilities and acceptance artifacts. Default execution is lead + one specialist + independent verifier, maximum four active including lead. These files configure native roles; they do not start running agents or register a UAR service.

The shared `.agent-team/project-routing.json` selects this existing team for code
work. Reviewers activate at the completed implementation phase. UI tasks use the
shared routing catalog through `prometheus-ui-ux`; completed UI review uses
`prometheus-ui-review`. Read [design-playbook.md](design-playbook.md) before changing
visible flows. Preserve existing native permissions, models and ownership.

## Start in a harness

Run from the repository root with Node 22+:

- Codex: node .agent-team/boss-core/launch.mjs codex
- Claude Code: node .agent-team/boss-core/launch.mjs claude --agent boss-lead
- Kimi Code: node .agent-team/boss-core/launch.mjs kimi --agent boss-lead
- OpenCode: node .agent-team/boss-core/launch.mjs opencode --agent boss-lead
- MiniMax CLI: node .agent-team/boss-core/launch.mjs minimax

Ask the parent: “Use boss-lead and the project routing guide for this task; delegate only the bounded roles needed.” Codex has no assumed --agent flag. OpenCode specialists are subagents. Kimi defaults to the locally configured kimi-code/k3 alias unless a model argument is supplied. MiniMax mcode 0.5.4 is installed: definitions are under .minimax/agents, and the launcher sets child-only MINIMAX_DATA_DIR to this project's .minimax. For npm installations with an adjacent Node executable, it uses that executable to avoid the observed Node 26 / Node 24 native SQLite ABI mismatch. The installed loader source recognizes canonical agent.md files in this directory. Native selection and inference with these custom agents remain unverified; this CLI has no --agent flag. Isolated MiniMax login/provider configuration is separate; do not copy global credentials.

## Working agreements

Read [repository-map.md](repository-map.md), [handoffs.md](handoffs.md), [model-policy.md](model-policy.md), [design-playbook.md](design-playbook.md) and [review-protocol.md](review-protocol.md) as relevant. Native schedulers, permissions, tools and credential stores remain authoritative. Keep KBD position unchanged until its actual workflow advances it. Team state is a local coordination ledger, not a replacement for KBD or authorization.

Use .agents/skills/agent-team-creator/scripts/cli.mjs with the JSON requests documented in its references. Validate team-request.json, update existing state via team-update with expectedRevision, then export to a new directory and deliberately merge reviewed files. Export never installs over existing configuration. Retain installation and verification receipts; do not rewrite live task state by rerunning init.

Finish project creation or refresh with `install-project --project . --team boss-core`
using that CLI. `--dry-run` previews writes; `--check` reports drift without writing.
Existing native files are preserved. The managed pointer is shared through the
existing AGENTS.md link to CLAUDE.md; this operation does not add new symlinks.

## Acceptance and limitations

Configuration verification is recorded in verification.json. Graph evidence is partial, native invocation/inference is not proved by file installation, and cross-model review depends on an available judge. Model cost/capability metadata may be unknown. No application behavior or release certification is implied by this setup.

`reconciliation.json` records the inherited team source. Existing research,
exports and verification/completion receipts describe that earlier setup, not
validation of the new UI routing phase. `ui-routing-installation.json` records
the project-instruction installation only; runtime acceptance is recorded by the
cross-repository phase gate.
